# Версия дистрибутива и ядра как ориентир для PrivEsc

## Контекст и базовые понятия: роль информации о среде в пост-эксплуатации

Пост-эксплуатация (Post-Exploitation) в контексте тестирования на проникновение представляет собой этап, на котором атакующий, уже обладающий начальной точкой входа (Initial Access) и базовой учетной записью, стремится расширить свои привилегии до уровня root (или SYSTEM в Windows) и переместиться по сети. Ключевым этапом этого процесса является разведка (Enumeration). Информация о версии ядра Linux (`uname -r`) и дистрибутива (`cat /etc/os-release`) является фундаментальным индикатором для выбора вектора повышения привилегий (Privilege Escalation, PrivEsc).

Ядро Linux является монолитным (или модульным монолитом), и его уязвимости часто приводят к локальному повышению привилегий. Каждая версия ядра содержит специфичный набор патчей, исправлений и, потенциально, известных уязвимостей (CVE). Дистрибутив же определяет не только версию ядра, но и набор доступных библиотек, конфигурацию безопасности (AppArmor, SELinux), доступные инструменты и политику обновления.

Разграничение понятий:
1.  **Версия ядра (Kernel Version):** Определяет внутреннее состояние ядра, наличие исправлений для конкретных CVE, доступные sysctls и модули. Это прямой индикатор применимости ядреных эксплойтов (например, Dirty Pipe, Dirty Cow, Netfilter UAF).
2.  **Версия дистрибутива (Distribution Version):** Определяет экосистему. Например, Ubuntu 22.04 LTS и RHEL 8.5 могут использовать одно и то же ядро 5.15, но иметь разные версии утилит, разные политики AppArmor и разные репозитории. Это влияет на доступность инструментов для атакующего и на конфигурацию среды.
3.  **Патч-уровень (Patch Level):** В рамках одной версии дистрибутива (например, Ubuntu 20.04) ядро может обновляться через HWE (Hardware Enablement) или стандартные обновления безопасности. Атакующий должен знать точный номер сборки (build number), так как эксплойт может работать на 5.4.0-42 и не работать на 5.4.0-150.

Почему это критично?
*   **Сужение области поиска:** Вместо перебора сотен потенциальных векторов (SUID, cron, capabilities, sudo, writable configs) атакующий может сразу проверить наличие известных эксплойтов для текущей версии ядра.
*   **Избежание сбоев:** Использование эксплойта, несовместимого с архитектурой (x86_64 vs ARM) или версией ядра, может привести к краху системы (Kernel Panic) или потере доступа к shell.
*   **Обход защит:** Некоторые дистрибутивы (например, Alpine Linux) используют musl libc вместо glibc, что ломает многие стандартные эксплойты, написанные для glibc.

| Параметр | Что определяет | Влияние на PrivEsc | Примеры источников |
| :--- | :--- | :--- | :--- |
| **Ядро (Kernel)** | Внутренние структуры, syscalls, модули, CVE-фиксы | Применимость ядреных эксплойтов (UAF, Race Condition, Buffer Overflow) | `uname -r`, `/proc/version` |
| **Дистрибутив (Distro)** | Пакетный менеджер, политики безопасности, версии библиотек | Доступность инструментов, обход AppArmor/SELinux, совместимость бинарников | `/etc/os-release`, `lsb_release -a` |
| **Архитектура (Arch)** | Разрядность (32/64 бит), порядок байт (Endianness) | Совместимость кода эксплойта, размер указателей, структура стека | `uname -m` |
| **Пользователь (User)** | UID, GID, группы, sudo-права | Применимость векторов на основе прав (SUID, Capabilities, Sudo) | `id`, `whoami`, `sudo -l` |

## Внутреннее устройство: Анализ версии ядра и дистрибутива как вектора атаки

### Механизм формирования вектора PrivEsc через версию ядра

Ядро Linux обрабатывает системные вызовы (syscalls) и управляет памятью. Уязвимости в ядре обычно возникают в:
1.  **Управлении памятью:** Use-After-Free (UAF), Double-Free, Buffer Overflow.
2.  **Логике обработки сетевых пакетов:** Netfilter, Traffic Control.
3.  **Механизмах изоляции:** User Namespaces, Cgroups, Capabilities.

Версия ядра является ключом к базе данных известных уязвимостей. Например, уязвимость **CVE-2024-1086** (Netfilter UAF) затрагивает ядра от 3.15 до 6.8-rc1. Если атакующий видит версию ядра `5.15.0-91-generic`, он знает, что вектор через `nf_tables` потенциально применим. Если же версия `6.1.76`, вектор закрыт.

Дистрибутив влияет на то, как ядро скомпилировано. Флаги компиляции (`CONFIG_DEBUG_INFO`, `CONFIG_KASAN`) могут сделать эксплойт нестабильным или обнаружить его. Также дистрибутив определяет, какие модули загружены. Например, если модуль `nf_tables` не загружен, эксплойт, зависящий от него, не сработает.

### Влияние дистрибутива на инструменты и окружение

Разные дистрибутивы имеют разные подходы к безопасности:
*   **RHEL/CentOS:** Строгая политика обновлений, использование SELinux по умолчанию. SELinux может блокировать выполнение эксплойтов даже при наличии root-прав, если контекст не разрешен.
*   **Ubuntu/Debian:** Частые обновления ядра, использование AppArmor. AppArmor может блокировать доступ к файлам или выполнение бинарников.
*   **Alpine Linux:** Использует musl libc и BusyBox. Многие эксплойты, написанные для glibc, не будут компилироваться или работать. Инструменты вроде `linpeas` могут выдавать ложные срабатывания или не работать корректно.
*   **Kali/Parrot:** Инструментарий предустановлен, но система может быть менее "жесткой" с точки зрения политик безопасности, что упрощает тестирование.

### Структура данных для анализа

Для точного определения уязвимости атакующий собирает:
1.  **Полную строку версии ядра:** `uname -r` (например, `5.15.0-91-generic`).
2.  **Версию сборки:** `cat /proc/version` (содержит GCC version, timestamp, config flags).
3.  **Версию дистрибутива:** `cat /etc/os-release` (ID, VERSION_ID, VERSION_CODENAME).
4.  **Архитектуру:** `uname -m` (x86_64, aarch64, etc.).

Эти данные используются для поиска в базах данных (Exploit-DB, CVE Details) и для выбора подходящего эксплойта.

| Аспект | Значение для атакующего | Пример влияния |
| :--- | :--- | :--- |
| **Kernel Version** | Поиск CVE, совместимость эксплойта | CVE-2021-4034 (PwnKit) работает на ядрах < 5.13.13.2 |
| **Distro ID** | Выбор инструментов, обход защит | Alpine: musl libc (нет glibc exploits). RHEL: SELinux |
| **Compiler Flags** | Стабильность эксплойта | `CONFIG_DEBUG_INFO` может помочь в отладке, но и в обнаружении |
| **Loaded Modules** | Наличие зависимостей | `nf_tables` нужен для CVE-2024-1086 |

## Применение и работа с предметом: Сбор информации и выбор вектора

### Этапы разведки версии ядра и дистрибутива

1.  **Сбор базовой информации:**
    *   `uname -a`: Быстрый способ получить версию ядра, архитектуру и hostname.
    *   `cat /proc/version`: Более детальная информация, включая версию GCC и дату сборки.
    *   `cat /etc/os-release`: Стандартный способ получения информации о дистрибутиве.
    *   `lsb_release -a`: Альтернативный способ для Debian/Ubuntu.

2.  **Анализ доступных инструментов:**
    *   Проверка наличия `gcc`, `make`, `python3` для компиляции эксплойтов на месте.
    *   Проверка наличия `strings`, `grep`, `awk` для анализа бинарников.
    *   Проверка наличия `sudo` и прав его использования.

3.  **Поиск уязвимостей:**
    *   Использование скриптов автоматизации: `LinPEAS`, `LinuxExploitSuggester2`, `LinEnum`.
    *   Ручной поиск в Exploit-DB по версии ядра.
    *   Проверка наличия известных эксплойтов для текущего дистрибутива.

### Примеры команд и артефактов

**Сбор информации:**
```bash
# Получение полной информации о ядре
uname -a
# Вывод: Linux target 5.15.0-91-generic #101-Ubuntu SMP Tue Nov 14 13:30:08 UTC 2023 x86_64 x86_64 x86_64 GNU/Linux

# Получение информации о дистрибутиве
cat /etc/os-release
# Вывод:
# NAME="Ubuntu"
# VERSION="22.04.3 LTS (Jammy Jellyfish)"
# ID=ubuntu
# ID_LIKE=debian
# VERSION_ID=22.04
# VERSION_CODENAME=jammy

# Проверка загруженных модулей
lsmod | grep nf_tables
# Вывод: nf_tables 163840 0
# Если модуль загружен, эксплойты, зависящие от него, могут быть применимы
```

**Автоматизированный анализ:**
```bash
# Запуск LinuxExploitSuggester2
./linux-exploit-suggester-2.pl
# Вывод (иллюстративный):
# [+] CVE-2024-1086
#     URL: https://www.cve.org/CVERecord?id=CVE-2024-1086
#     Details: Netfilter UAF
#     Version: 3.15 <= kernel < 6.8-rc1
#     Status: Potentially Vulnerable
#     Score: 7.8
```

### Типичные ошибки и подводные камни

1.  **Игнорирование архитектуры:** Попытка запустить x86_64 эксплойт на ARM-системе.
2.  **Неверная интерпретация версии ядра:** Использование версии ядра из `/etc/os-release` вместо `uname -r`. Дистрибутив может иметь старое ядро в репозитории, но установленное ядро может быть обновлено.
3.  **Отсутствие компилятора:** Попытка запустить эксплойт, требующий компиляции, без `gcc`.
4.  **Игнорирование политик безопасности:** Попытка выполнить эксплойт в среде с SELinux/AppArmor без предварительного анализа политик.

## Сквозной практический пример: Эксплуатация CVE-2024-1086 на Ubuntu 22.04

### Исходные условия
*   **Среда:** Виртуальная машина с Ubuntu 22.04 LTS.
*   **Доступ:** Низкопривилегированная учетная запись `user` (UID 1000).
*   **Цель:** Повышение привилегий до root.
*   **Инструменты:** `LinPEAS`, `LinuxExploitSuggester2`, исходный код эксплойта для CVE-2024-1086.

### Шаги

**Шаг 1: Сбор информации о ядре и дистрибутиве**

Действие: Атакующий выполняет команды для определения версии ядра и дистрибутива.

```bash
# Проверка версии ядра
uname -r
# Вывод: 5.15.0-91-generic

# Проверка дистрибутива
cat /etc/os-release | grep VERSION
# Вывод: VERSION="22.04.3 LTS (Jammy Jellyfish)"

# Проверка загруженных модулей
lsmod | grep nf_tables
# Вывод: nf_tables 163840 0
```

Результат: Ядро `5.15.0-91-generic` попадает в диапазон уязвимости CVE-2024-1086 (3.15 <= kernel < 6.8-rc1). Модуль `nf_tables` загружен, что является необходимым условием для эксплуатации.

**Шаг 2: Автоматизированный поиск уязвимостей**

Действие: Атакующий запускает `LinuxExploitSuggester2` для подтверждения уязвимости.

```bash
./linux-exploit-suggester-2.pl
# Вывод (фрагмент):
# [+] CVE-2024-1086
#     URL: https://www.cve.org/CVERecord?id=CVE-2024-1086
#     Details: Netfilter UAF
#     Version: 3.15 <= kernel < 6.8-rc1
#     Status: Potentially Vulnerable
#     Score: 7.8
```

Результат: Инструмент подтверждает, что текущая версия ядра уязвима к CVE-2024-1086.

**Шаг 3: Подготовка и компиляция эксплойта**

Действие: Атакующий загружает исходный код эксплойта и компилирует его.

```bash
# Загрузка эксплойта (предположим, что он доступен в /tmp/exploit.c)
gcc -o exploit /tmp/exploit.c -Wall -O2
# Вывод: (если компиляция успешна, ошибок нет)
```

Результат: Бинарный файл `exploit` создан.

**Шаг 4: Эксплуатация**

Действие: Атакующий запускает эксплойт.

```bash
./exploit
# Вывод (иллюстративный):
# [+] Exploiting CVE-2024-1086...
# [+] Sending crafted netlink messages...
# [+] Triggering UAF...
# [+] Gaining root shell...
# id
# uid=0(root) gid=0(root) groups=0(root)
```

Результат: Атакующий получил root-доступ.

### Ожидаемый вывод
Пример демонстрирует, как точное определение версии ядра и дистрибутива позволило атакующему быстро сузить область поиска до одной конкретной уязвимости (CVE-2024-1086) и успешно ее эксплуатировать. Без этой информации атакующий мог бы потратить время на перебор других векторов, которые не сработали бы на данной системе.

## Аналитический вывод

Версия дистрибутива и ядра Linux является критическим ориентиром для повышения привилегий на скомпрометированном хосте. Она определяет применимость известных уязвимостей, доступность инструментов и особенности конфигурации безопасности. Атакующий должен всегда начинать пост-эксплуатацию с точного определения этих параметров, используя как ручные команды, так и автоматизированные скрипты. Игнорирование этой информации приводит к неэффективности атаки и потенциальным сбоям. Для защитников важно регулярно обновлять ядро и дистрибутив, а также мониторить новые CVE, связанные с ядром Linux.
