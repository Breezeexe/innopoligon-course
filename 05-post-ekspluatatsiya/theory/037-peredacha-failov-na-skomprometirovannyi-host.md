# Передача файлов на скомпрометированный хост в контексте пост-эксплуатации

## Контекст и базовые понятия: место передачи файлов в жизненном цикле атаки

Передача файлов на скомпрометированный хост является критическим этапом пост-эксплуатации, обеспечивающим материализацию дальнейших действий атакующего. На этапе получения первоначального доступа (Initial Access) злоумышленник обычно доставляет малый полезный груз (payload), который обеспечивает выполнение команд или открытие обратного соединения (reverse shell). Однако этот первичный доступ часто ограничен по функциональности, объему данных или стабильности. Передача файлов позволяет доставить более сложные инструменты: скрипты для автоматизации сбора данных, модули для повышения привилегий, вредоносное ПО для шифрования (ransomware) или инструменты для горизонтального перемещения (lateral movement).

В рамках модели MITRE ATT&CK передача файлов классифицируется в тактике **Command and Control (T1071)** через подтехнику **Application Layer Protocol: File Transfer Protocols (T1071.002)**. Это означает, что атакующий использует легитимные протоколы прикладного уровня, предназначенные для передачи файлов, для маскировки вредоносной активности под нормальный сетевой трафик. Ключевое отличие от других методов доставки (например, T1105 Artifact Staged) заключается в том, что файл не просто сохраняется на диск, а активно перемещается через сеть с использованием специфических протокольных команд, что оставляет характерные сетевые индикаторы.

Важно разграничить понятия «передача файла» и «загрузка полезной нагрузки». Загрузка полезной нагрузки (T1105) — это более широкий термин, включающий HTTP, SMB, FTP и другие методы. Передача файлов в контексте пост-эксплуатации часто подразумевает интерактивное или полуавтоматизированное взаимодействие с уже установленным каналом связи (C2-каналом), где атакующий выбирает конкретные файлы для переноса на целевую систему.

Для понимания контекста необходимо разграничить три основных сущности, часто путаемых в литературе:
1.  **Payload Delivery (Доставка полезной нагрузки):** Одноразовая акция для получения доступа (например, скачивание exe-файла по HTTP).
2.  **C2 Communication (Командно-управляющая связь):** Постоянный канал, по которому передаются команды и результаты. Передача файлов может быть частью этого канала.
3.  **Lateral Movement (Горизонтальное перемещение):** Использование переданных файлов (например, скриптов или исполняемых модулей) для атаки на другие узлы.

| Протокол | Уровень модели OSI | Типичное использование в легитимной среде | Риски обнаружения при пост-эксплуатации | Особенности маскировки |

Подозрительно только при использовании на хостах, где SSH-доступ не предусмотрен политикой. | Высокая степень доверия в Unix-средах. Часто используется администраторами, что затрудняет детекцию. |

*Иллюстративная схема разграничения:*
```text
[Атакующий] ──(Payload/Tool)──▶ [Целевой хост]
       │                           │
       │ (1. Initial Access)       │ (2. Post-Exploitation)
       ▼                           ▼
[Внешняя сеть]              [Внутренняя сеть / C2]
       │                           │
       └──(Протокол доставки)──────┘
            (SMB/HTTP/FTP/TFTP)
```

В современных условиях, особенно в облачных и гибридных средах, прямое использование FTP или TFTP становится редкостью из-за строгих политик безопасности периметра. Атакующие предпочитают использовать HTTP/HTTPS или легитимные облачные сервисы (например, Amazon S3, Google Cloud Storage) как промежуточные точки для хранения и передачи файлов, что относится к техникам T1105 (Ingress Tool Transfer) и T1567 (Exfiltration Over Web Service). Однако в контексте локальной пост-эксплуатации, особенно в доменах Active Directory, SMB остается доминирующим протоколом для передачи файлов между узлами.

## Внутреннее устройство: механизмы передачи файлов через протоколы прикладного уровня

Передача файлов в пост-эксплуатации не является монолитным процессом; она реализуется через специфические команды и структуры данных каждого протокола. Понимание внутреннего устройства этих механизмов необходимо для создания точных правил детекции и понимания того, как злоумышленники обходят средства защиты.

### Архитектура взаимодействия при передаче файлов

Процесс передачи файлов можно разделить на три логических этапа:
1.  **Инициализация соединения:** Установление TCP-соединения с целевым портом протокола.
2.  **Аутентификация и согласование:** Проверка прав доступа (если требуется) и выбор режима передачи (например, режим файла или режим каталога в FTP).
3.  **Перенос данных:** Непосредственная передача байтов полезной нагрузки. На этом этапе данные могут быть зашифрованы (FTPS, SFTP, HTTPS) или переданы в открытом виде (FTP, TFTP, SMB без подписи).

Рассмотрим детальное устройство двух наиболее релевантных для пост-эксплуатации протоколов: SMB и HTTP.

#### 1. SMB (Server Message Block) как инструмент передачи файлов

SMB — это сетевой протокол обмена файлами, принтерами и другими ресурсами. В контексте пост-эксплуатации (техника T1071.002) атакующие используют SMB не только для чтения файлов, но и для записи (upload) и выполнения кода.

**Структура SMB-пакета (упрощенно):**
SMB использует структуру заголовка, которая включает в себя несколько ключевых полей. Для передачи файлов часто используются команды `SMB2_CREATE` (открытие файла) и `SMB2_WRITE` (запись данных).

```text
[ SMB2 Header ]
| Protocol ID (0xFF534D42) |
| Message Size             |
| Command (e.g., 0x05 for WRITE) |
| Session ID             |
| Tree ID                |
| Flags                  |
| ...                    |

[ SMB2 WRITE Request ]
| File Handle            |
| Offset                 |
| Data Offset            |
| Data Length            |
| Remaining Bytes        |
| [ Payload Data ]       | <-- Здесь находится полезная нагрузка (файл)
```

Атакующие могут использовать легитимные утилиты, такие как `smbclient` или `psexec`, или собственные реализации, чтобы создать сессию SMB, открыть файл на удаленном сервере и записать в него данные. Ключевая особенность SMB в пост-эксплуатации — возможность использования **Named Pipes** для туннелирования трафика (как в случае с Cobalt Strike), что позволяет передавать файлы через канал, который выглядит как локальное межпроцессное взаимодействие.

#### 2. HTTP/HTTPS как универсальный транспорт

HTTP/HTTPS является наиболее гибким протоколом для передачи файлов. В пост-эксплуатации он часто используется для загрузки загрузчиков (downloader) или модулей C2.

**Структура HTTP-запроса для загрузки файла (POST):**
```http
POST /upload.php HTTP/1.1
Host: victim-server.com
User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64)
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Length: 12345

------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="file"; filename="malware.exe"
Content-Type: application/octet-stream

[Binary Data of malware.exe]
------WebKitFormBoundary7MA4YWxkTrZu0gW--
```

В случае HTTPS, данные инкапсулируются в TLS-запись. Для детекции аномалий в этом случае анализируются метаданные TLS: длина записи, время рукопожатия, сертификаты. Атакующие могут использовать **TLS-туннелирование** (например, через `stunnel` или встроенные функции в C2-фреймворках), чтобы скрыть содержимое HTTP-трафика внутри зашифрованного канала.

#### 3. TFTP и FTP: специфика и ограничения

**TFTP (Trivial FTP)** использует UDP и не имеет механизма аутентификации. Его структура пакета очень проста:
-  _opcode_ (1 байт): 1 (RRQ) или 2 (WRQ) для запроса чтения/записи.
-  _filename_ (строка).
-  _mode_ (строка).
-  _data_ (для пакетов ACK и DATA).

Из-за отсутствия аутентификации TFTP часто используется для загрузки прошивок или конфигураций в IoT-устройствах. В пост-эксплуатации он может быть использован для быстрой передачи небольших файлов без необходимости установки сложного соединения.

**FTP** требует двух каналов: управляющего (порт 21) и данных (порт 20 или динамический). В режиме **Active FTP** сервер подключается к клиенту, что может быть проблемой за NAT. В режиме **Passive FTP** клиент подключается к серверу на случайный порт, что легче обходит фаерволы, но оставляет следы в логах подключения.

### Индикаторы наличия (IoC) передачи файлов

Для детекции несанкционированной передачи файлов необходимо отслеживать следующие индикаторы:
1.  **Аномальные размеры пакетов:** Передача больших объемов данных по протоколам, которые обычно используются для коротких команд (например, ICMP или DNS).
2.  **Необычное время активности:** Передача файлов в нерабочие часы.
3.  **Аномальные User-Agent или заголовки:** Использование нестандартных или пустых заголовков в HTTP-запросах.
4.  **Сетевые соединения с несвязанными хостами:** Попытки установить SMB-соединение между хостами, которые не должны обмениваться файлами (например, между рабочей станцией и внешним IP).
5.  **Использование нестандартных портов:** Протокол SMB на порту 8080 или HTTP на порту 445.

## Применение и работа с предметом: инструменты и методы передачи файлов

На практике передача файлов в пост-эксплуатации реализуется с помощью специализированных фреймворков, скриптов и встроенных утилит операционных систем. Выбор инструмента зависит от целевой платформы, доступных привилегий и требований к скрытности.

### Инструментарий и его функциональное назначение

1.  **Metasploit Framework (Meterpreter):**
    Meterpreter — это продвинутый пост-эксплуатационный модуль, который предоставляет богатый набор команд для работы с файловой системой. Команда `upload` позволяет передавать файлы с атакующей машины на целевую.
    *   *Функция:* Загрузка файлов через инъецированный код в памяти (memory-only), что снижает вероятность обнаружения антивирусами, так как файл не записывается на диск до момента выполнения.
    *   *Применение:* Когда требуется скрытность и нет доступа к стандартным утилитам.

2.  **Cobalt Strike (Beacon):**
    Beacon — это агент C2, который использует встроенные команды `upload` и `download`.
    *   *Функция:* Поддержка разрывов соединения (jitter) и маскировки под легитимный трафик.
    *   *Применение:* В корпоративных средах, где требуется длительное присутствие и периодическая передача данных.

3.  **SCP/SFTP (OpenSSH):**
    Стандартные утилиты Linux/Unix.
    *   *Функция:* Безопасная передача файлов через SSH-туннель.
    *   *Применение:* В Unix-средах, где SSH-доступ легитимен, но требуется передать файл на другой узел.

4.  **SMBClient / PsExec:**
    Утилиты для работы с SMB.
    *   *Функция:* Запись файлов на удаленные шары.
    *   *Применение:* В доменах Active Directory, где SMB-доступ разрешен для администрирования.

5.  **Python/Netcat:**
    Скрипты на Python или утилиты Netcat могут быть использованы для создания кастомных скриптов передачи файлов через сокеты.
    *   *Функция:* Гибкость и возможность обхода специфических ограничений.
    *   *Применение:* Когда стандартные утилиты отсутствуют или заблокированы.

### Типичные ошибки и подводные камни

1.  **Оставление следов на диске:** Использование утилит, которые записывают временные файлы в каталоги с высоким уровнем доступа (например, `/tmp` или `C:\Windows\Temp`), может быть обнаружено EDR-системами.
2.  **Аномалии в сетевом трафике:** Передача больших файлов по протоколам, не предназначенным для этого (например, DNS), может вызвать подозрения у SIEM-систем.
3.  **Отсутствие шифрования:** Использование FTP или HTTP вместо FTPS или HTTPS делает данные уязвимыми для перехвата.
4.  **Неправильные права доступа:** Передача файлов с неправильными правами может привести к невозможности их выполнения или, наоборот, к несанкционированному доступу.

### Пример правила детекции (Sigma) для передачи файлов по SMB

Ниже приведен пример структуры правила детекции для обнаружения аномальной передачи файлов по SMB.

```yaml
title: Anomalous SMB File Upload
id: 12345678-1234-1234-1234-123456789012
status: experimental
description: Detects potential file upload via SMB to a remote host
references:
    - https://attack.mitre.org/techniques/T1071/002/

    product: windows

            - 'put'
            - 'upload'
            - 'write'
    condition: selection
falsepositives:
    - Legitimate administration
level: high
```

## Сквозной практический пример: Передача полезной нагрузки через SMB в доменной среде

**Исходные условия:**
*   **Среда:** Корпоративная сеть с доменом Active Directory.
*   **Цель:** Сервер `FILESRV01` (Windows Server 2019) с открытым шаром `Backups` (доступен для чтения/записи для группы `IT_Admins`).
*   **Атакующий:** Имеет доступ к рабочей станции `WORKSTATION01` с правами члена группы `IT_Admins`.
*   **Инструменты:** `smbclient` (из пакета Samba на Kali Linux), `mimikatz.exe` (для сбора учетных данных, если потребуется).
*   **Сценарий:** Атакующий хочет передать файл `mimikatz.exe` на сервер `FILESRV01` для последующего повышения привилегий.

**Шаг 1: Проверка доступа к шару**

Атакующий проверяет, доступен ли шар `Backups` и можно ли в него записать файлы.

```bash
# Команда для проверки доступа к шару
smbclient //FILESRV01/Backups -U IT_Admins

# Ожидаемый вывод (если доступ разрешен):
# Try "help" to get a list of possible commands.
# smb: \>
```

**Шаг 2: Передача файла (Upload)**

Атакующий использует команду `put` для передачи файла `mimikatz.exe` на сервер.

```bash
# Команда для передачи файла
put mimikatz.exe

# Ожидаемый вывод:
# put file mimikatz.exe -> Backups/mimikatz.exe (100%, 1234567 bytes)
```

**Шаг 3: Верификация передачи**

Атакующий проверяет, успешно ли файл был записан на сервер.

```bash
# Команда для проверки наличия файла на сервере
ls

# Ожидаемый вывод:
# drwxrwxrwx    0      0           0       Oct 10 12:00 .
# drwxrwxrwx    0      0           0       Oct 10 12:00 ..
# -rwxrwxrwx    0      0     1234567       Oct 10 12:01 mimikatz.exe
```

**Шаг 4: Выполнение файла (если есть права на выполнение)**

Если атакующий имеет права на выполнение кода на сервере (например, через RDP или PsExec), он может выполнить файл.

```powershell
# Пример команды для выполнения файла на сервере (через PsExec)
psexec \\FILESRV01 -u domain\user -p password cmd.exe
# В консоли на сервере:
cd C:\Backups
.\mimikatz.exe
```

**Ожидаемый вывод:**
Файл `mimikatz.exe` успешно передан на сервер `FILESRV01` и готов к выполнению. В логах сервера `FILESRV01` будет зафиксировано событие входа по SMB и создание файла `mimikatz.exe`. В логах файервола будет зафиксировано соединение с порта 445.

**Вывод по примеру:**
Этот пример демонстрирует, как легитимный доступ к шарам может быть использован для передачи вредоносного ПО. Ключевым индикатором является создание нового исполняемого файла в каталоге, который обычно не используется для хранения исполняемых файлов (например, `Backups`).

## Аналитический вывод

Передача файлов на скомпрометированный хост является фундаментальной операцией в пост-эксплуатации, позволяющей атакующим расширить свое присутствие в сети. Использование легитимных протоколов прикладного уровня, таких как SMB, HTTP и FTP, позволяет маскировать вредоносную активность под нормальный сетевой трафик, что затрудняет ее обнаружение средствами защиты периметра. Ключевым фактором успеха атакующих является использование легитимных учетных данных и сервисов, что делает трафик неотличимым от обычного административного.

Для эффективной защиты необходимо внедрять многоуровневый подход:
1.  **Мониторинг сетевой активности:** Анализ аномалий в использовании протоколов (например, SMB-трафик между несвязанными хостами).
2.  **Контроль целостности файлов:** Использование EDR-систем для отслеживания создания новых исполняемых файлов в нестандартных каталогах.
3.  **Сегментация сети:** Ограничение доступа к критическим ресурсам и шарам только для авторизованных администраторов.
4.  **Шифрование и аутентификация:** Использование HTTPS, FTPS и SMB3 с подписью для предотвращения перехвата и подмены данных.

Понимание механизмов передачи файлов и их индикаторов наличия позволяет специалистам по безопасности разрабатывать более точные правила детекции и реагировать на инциденты быстрее.
