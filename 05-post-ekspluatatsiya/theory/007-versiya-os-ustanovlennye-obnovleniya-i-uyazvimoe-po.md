# Разведка на скомпрометированном Windows-хосте: Версия ОС, обновления и уязвимое ПО

## Контекст и базовые понятия: Инвентаризация как фундамент пост-эксплуатации

В рамках этапа пост-эксплуатации (Post-Exploitation) разведка на скомпрометированном хосте (Host Reconnaissance) представляет собой процесс сбора структурированной информации о целевой системе для оценки текущего состояния безопасности и планирования дальнейших действий. Ключевые элементы этой фазы — определение версии операционной системы (OS), анализ установленных обновлений (Patches) и инвентаризация программного обеспечения (Software Inventory). Эти данные формируют «цифровой след» системы, который определяет доступные векторы атаки, возможность использования локальных эксплойтов и уровень видимости для защитных систем.

Понятие «версия ОС» в контексте Windows не ограничивается просто номером сборки (Build Number). Оно включает в себя архитектуру (x64/x86/ARM), тип установки (Client/Server/Core), редакцию (Enterprise, Pro, Datacenter) и статус активации. Версия ОС критична для выбора подходящих инструментов эксплойтации, так как многие уязвимости ядра (Kernel) или подсистем (например, LSASS, Win32k) зависят от конкретных патч-таейлов (Patch Tuesday).

«Установленные обновления» — это набор исправлений безопасности (Security Updates) и накопительных обновлений (Cumulative Updates), примененных к системе. В отличие от версий ОС, которые меняются редко, обновления устанавливаются ежемесячно (Patch Tuesday) или внепланово (Out-of-Band). Анализ установленных обновлений позволяет определить «окно уязвимости»: если на хосте отсутствует критическое исправление (например, KB5005463 для PrintNightmare), это открывает прямой путь к повышению привилегий. Отсутствие обновлений также указывает на возможные проблемы с обслуживанием (Maintenance) или намеренное отключение обновлений злоумышленником для предотвращения перезагрузок.

«Уязвимое ПО» — это программное обеспечение, установленное на хосте, которое содержит известные уязвимости (CVE). Инвентаризация ПО сложнее, чем определение версии ОС, из-за фрагментарности методов установки. Как отмечается в исследованиях, современные системы могут иметь несколько версий одного приложения, установленных через разные механизмы (APT, MSI, Snap, portable-версии), что создает «слепые зоны» для сканеров уязвимостей. Злоумышленник, получивший доступ, должен выявить не только текущие процессы, но и скрытые или устаревшие бинарные файлы, которые могут быть использованы для атак типа «перехват загрузки» (DLL Hijacking) или эксплуатации известных уязвимостей.

Разграничение понятий:
*   **Версия ОС** определяет *платформу* и доступные API/ядро.
*   **Обновления** определяют *состояние защиты* платформы.
*   **ПО** определяет *прикладной слой* и дополнительные векторы атаки.

| Параметр разведки | Определение | Влияние на атаку | Источники данных (Windows) |
|---|---|---|---|
| **Версия ОС** | Базовая платформа (Windows 10/11, Server 2016/2019/2022) | Выбор эксплойтов ядра, совместимость инструментов | `winver`, `Get-CimInstance`, `reg query` |
| **Установленные обновления** | Набор KB-номеров (Security Patches) | Доступность локальных эксплойтов, стабильность системы | `wmic qfe`, `Get-HotFix`, реестр |
| **Уязвимое ПО** | Прикладные приложения с известными CVE | Удаленная эксплуатация, горизонтальное перемещение | Реестр, файловая система, EDR-агенты |

## Внутреннее устройство: Механизмы сбора и хранения информации

Внутреннее устройство разведки на Windows хосте базируется на трех основных источниках данных: системных API, реестре Windows и файловой системе. Понимание того, как Windows хранит и обновляет эти данные, позволяет злоумышленнику выбрать наиболее надежный и незаметный метод сбора информации.

### Версия ОС: Иерархия идентификации

Версия ОС определяется через несколько уровней абстракции. На уровне ядра (Kernel) информация хранится в структуре `KUSER_SHARED_DATA`, которая отображается в адресное пространство каждого процесса. На уровне пользовательского режима (User Mode) доступ осуществляется через API `GetVersionEx` (устаревший) или `RtlGetVersion` (недокументированный, используется для обхода проверки версии антивирусами).

Ключевые идентификаторы:
1.  **Major/Minor/Build Number:** Базовая версия. Например, Windows 10 имеет Major 10, Build 19041+ (2004) или 22000+ (21H2).
2.  **CSDVersion:** Service Pack (в современных Windows обычно пуст).
3.  **ProductType:** `VER_NT_WORKSTATION` (клиентская ОС) или `VER_NT_SERVER` (серверная ОС). Это критично для атак на контроллеры домена.
4.  **SuiteMask:** Определяет набор функций (например, `VER_SUITE_ENTERPRISE` для серверов).

### Установленные обновления: Реестр и WMI

Информация об установленных обновлениях хранится в двух основных местах:
1.  **Реестр:** Ключ `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` содержит список всех установленных пакетов. Для обновлений Windows используется специфический формат GUID.
2.  **WMI (Windows Management Instrumentation):** Класс `Win32_QuickFixEngineering` предоставляет структурированный доступ к списку установленных исправлений. Это предпочтительный метод для легитимных администраторов и злоумышленников, так как не оставляет следов в файловой системе.

Обновления также логируются в журнале событий Windows Event Log, в разделе `Microsoft-Windows-WindowsUpdateClient/Operational`. Однако доступ к этому журналу часто ограничен, и он может быть очищен.

### Уязвимое ПО: Фрагментация инвентаризации

Уязвимое ПО определяется через анализ установленных приложений. В Windows это сложно из-за множества путей установки:
1.  **Реестр (Uninstall Keys):** `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall` и `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall`.
2.  **Файловая система:** Папки `Program Files`, `Program Files (x86)`, `AppData`, `Temp`.
3.  **Системные пакетные менеджеры:** Если установлены Chocolatey, Winget или Scoop, информация хранится в их локальных базах.
4.  **Скрытые/Portable приложения:** Не регистрируются в реестре. Требуют сканирования файловой системы по известным именам исполняемых файлов.

Проблема «скрытых пакетов» заключается в том, что сканеры уязвимостей могут видеть только одну версию приложения, в то время как на диске могут находиться другие, уязвимые версии. Злоумышленник должен учитывать этот факт, проверяя не только зарегистрированные приложения, но и файловую систему.

| Источник данных | Тип информации | Достоверность | Сложность доступа |
|---|---|---|---|
| **API (GetVersionEx)** | Версия ОС, Service Pack | Высокая | Низкая (легитимный вызов) |
| **WMI (Win32_QuickFixEngineering)** | Список KB-номеров | Высокая | Средняя (требует прав) |
| **Реестр (Uninstall)** | Список ПО, версии, пути | Средняя (может быть подделан) | Низкая |
| **Файловая система** | Бинарные файлы, версии | Высокая (факт наличия) | Высокая (сканирование) |

## Применение и работа с предметом: Инструменты и методы разведки

На практике разведка версии ОС, обновлений и ПО выполняется с помощью набора инструментов, от встроенных команд до специализированных фреймворков. Выбор инструмента зависит от уровня привилегий (User/Admin) и необходимости обхода EDR.

### Встроенные средства (Native Tools)

Встроенные средства предпочтительны для первоначальной разведки, так как они не требуют загрузки внешних бинарных файлов, что снижает риск обнаружения.

1.  **PowerShell:** Основной инструмент для сбора информации.
    *   `Get-CimInstance Win32_OperatingSystem`: Получение детальной информации об ОС.
    *   `Get-HotFix`: Получение списка установленных обновлений.
    *   `Get-ItemProperty HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*`: Получение списка установленных приложений.

2.  **Command Prompt (cmd.exe):**
    *   `systeminfo`: Вывод сводной информации об ОС, времени загрузки, хотфиксах.
    *   `wmic qfe list brief`: Альтернатива `Get-HotFix` в cmd.
    *   `reg query HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall`: Вывод списка ПО.

3.  **WMIC (Windows Management Instrumentation Command-line):**
    *   `wmic product get name,version`: Получение списка ПО и его версий.

### Специализированные инструменты (Third-Party)

Для более глубокой разведки используются инструменты, такие как:
*   **BloodHound:** Для анализа доменной инфраструктуры, но также может собирать информацию о хостах.
*   **Seatbelt:** Набор правил безопасности от Ghostpack, который собирает информацию о конфигурации системы, включая версии ОС, установленные обновления и ПО.
*   **Sherlock:** Поиск известных уязвимостей локальных эксплойтов на основе установленного ПО и версии ОС.
*   **Nmap:** Для сканирования сети и определения версии ОС по сетевым ответам (OS Fingerprinting).

### Паттерны использования и подводные камни

1.  **Обход EDR:** Некоторые EDR блокируют вызовы `Get-HotFix` или `Get-ItemProperty` из PowerShell. В таких случаях можно использовать `cmd.exe` или напрямую обращаться к WMI через COM-объекты.
2.  **Ложные срабатывания:** Реестр может содержать артефакты от удаленных приложений. Необходимо проверять наличие файлов по указанным путям.
3.  **Скрытые обновления:** Некоторые обновления могут быть установлены, но не отображаться в `Get-HotFix` из-за ошибок в реестре. В таких случаях необходимо проверять журнал Windows Update.
4.  **Производительность:** Сканирование файловой системы для поиска ПО может быть медленным и вызывать нагрузку на систему. Рекомендуется использовать кэшированные данные из реестра.

```powershell
# Пример сбора информации о версии ОС и установленных обновлениях
# Используем PowerShell для сбора данных

# 1. Получение информации об ОС
$OSInfo = Get-CimInstance Win32_OperatingSystem
Write-Host "OS Version: $($OSInfo.Caption)"
Write-Host "OS Build: $($OSInfo.BuildNumber)"
Write-Host "OS Architecture: $($OSInfo.OSArchitecture)"
Write-Host "Product Type: $(if($OSInfo.ProductType -eq 1) {'Workstation'} else {'Server'})"

# 2. Получение списка установленных обновлений
$HotFixes = Get-HotFix | Sort-Object InstalledOn -Descending
Write-Host "Installed Updates:"
$HotFixes | Format-Table -Property HotFixID, Description, InstalledOn -AutoSize

# 3. Получение списка установленных приложений
$InstalledApps = Get-ItemProperty HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*, HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\* -ErrorAction SilentlyContinue |
    Where-Object { $_.DisplayName } |
    Select-Object DisplayName, DisplayVersion, InstallLocation
Write-Host "Installed Applications:"
$InstalledApps | Format-Table -Property DisplayName, DisplayVersion -AutoSize
```

## Сквозной практический пример: Разведка на скомпрометированном хосте

**Исходные условия:**
*   **Среда:** Корпоративная сеть с контроллером домена (DC) и рабочими станциями на базе Windows 10 и Windows Server 2019.
*   **Инструменты:** PowerShell, BloodHound, Sherlock.
*   **Роль:** Пентестер, получивший доступ к рабочей станции пользователя через фишинг.
*   **Цель:** Определить версию ОС, установленные обновления и уязвимое ПО для планирования повышения привилегий и перемещения.

**Шаг 1: Определение версии ОС и типа системы**

*Действие:* Использование PowerShell для получения детальной информации об ОС.

```powershell
# Получение информации об ОС
$OS = Get-CimInstance Win32_OperatingSystem
$OS | Select-Object Caption, Version, BuildNumber, ProductType, OSArchitecture
```

*Ожидаемый вывод:*
```text
Caption             : Microsoft Windows 10 Pro
Version             : 10.0.19044
BuildNumber         : 19044
ProductType         : 1
OSArchitecture      : 64-bit
```
*Результат:* Определено, что система — Windows 10 Pro, сборка 19044 (21H2). ProductType 1 указывает на рабочую станцию.

**Шаг 2: Анализ установленных обновлений**

*Действие:* Получение списка установленных обновлений для поиска известных уязвимостей.

```powershell
# Получение списка обновлений
$Updates = Get-HotFix | Sort-Object InstalledOn -Descending
$Updates | Select-Object HotFixID, Description, InstalledOn | Format-Table -AutoSize
```

*Ожидаемый вывод:*
```text
HotFixID   Description           InstalledOn
--------   -----------           -----------
KB5005463  Security Update       2021-06-15
KB5004244  Security Update       2021-05-11
KB5003173  Security Update       2021-04-13
...
```
*Результат:* Обнаружено, что обновление KB5005463 (исправляющее PrintNightmare) установлено. Это означает, что локальный эксплойт для PrintNightmare не сработает.

**Шаг 3: Инвентаризация уязвимого ПО**

*Действие:* Сбор списка установленных приложений и проверка их на наличие известных уязвимостей.

```powershell
# Получение списка приложений
$Apps = Get-ItemProperty HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\*, HKLM:\SOFTWARE\WOW6432Node\Microsoft\Windows\CurrentVersion\Uninstall\* -ErrorAction SilentlyContinue |
    Where-Object { $_.DisplayName } |
    Select-Object DisplayName, DisplayVersion, InstallLocation

# Вывод списка приложений
$Apps | Format-Table -Property DisplayName, DisplayVersion -AutoSize
```

*Ожидаемый вывод:*
```text
DisplayName              DisplayVersion
-----------              --------------
Adobe Acrobat Reader DC  21.001.20098
Google Chrome            91.0.4472.114
Mozilla Firefox          89.0.1
...
```
*Результат:* Определены версии установленных приложений.

**Шаг 4: Проверка на известные уязвимости**

*Действие:* Использование инструмента Sherlock для поиска известных локальных уязвимостей.

```powershell
# Запуск Sherlock
.\Sherlock.exe
```

*Ожидаемый вывод:*
```text
[!] Possible LPE: CVE-2021-34481
[!] Possible LPE: CVE-2021-34527
[!] Possible LPE: CVE-2021-40533
```
*Результат:* Обнаружены потенциальные уязвимости для повышения привилегий.

**Ожидаемый вывод:**
Пример демонстрирует полный цикл разведки: от определения версии ОС до выявления уязвимого ПО. Это позволяет пентестеру выбрать наиболее эффективный вектор атаки.

## Аналитический вывод

Разведка версии ОС, установленных обновлений и уязвимого ПО на скомпрометированном Windows-хосте является критическим этапом пост-эксплуатации, определяющим дальнейшие возможности атакующего. Точное определение версии ОС позволяет выбрать подходящие эксплойты и инструменты, анализ обновлений помогает избежать неработающих векторов атаки, а инвентаризация ПО выявляет дополнительные уязвимости. Использование встроенных средств, таких как PowerShell и WMI, обеспечивает незаметный сбор данных, в то время как специализированные инструменты, такие как BloodHound и Sherlock, углубляют анализ. Важно учитывать фрагментарность установки ПО и возможность наличия скрытых версий приложений, которые могут быть использованы для атак. Регулярный мониторинг и обновление информации о состоянии хостов позволяют защитникам своевременно выявлять и устранять уязвимости.
