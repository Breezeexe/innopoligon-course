# Разведка на скомпрометированном Windows-хосте в контексте Active Directory

## Контекст и базовые понятия: Позиционирование разведки в пост-эксплуатации

Разведка (Reconnaissance/Enumeration) на этапе пост-эксплуатации представляет собой систематический сбор информации о скомпрометированной среде с целью картирования инфраструктуры, выявления уязвимых объектов и планирования дальнейших действий. В отличие от фазы первоначального доступа (Initial Access), где фокус направлен на обход периметра, пост-эксплуатационная разведка оперирует уже имеющимися легитимными учетными данными и сетевой связностью. Ключевая особенность данного этапа заключается в использовании легитимных протоколов (LDAP, SMB, Kerberos, WinRM) для сбора данных, что позволяет атакующему маскироваться под нормальный административный или пользовательский трафик.

В среде Active Directory (AD) разведка делится на два фундаментальных типа: пассивную и активную. Пассивная разведка предполагает сбор информации без прямого взаимодействия с целевыми системами или с минимальным воздействием на них (например, анализ DNS-запросов, перехват LDAP-трафика, анализ метаданных файлов). Активная разведка включает прямые запросы к контроллерам домена (DC), опрос локальных систем через WMI/SMB, сканирование портов и использование специализированных инструментов сбора данных (SharpHound, NetExec).

Важно разграничивать понятия **Enumeration** (перечисление) и **Reconnaissance** (разведка). В контексте пост-эксплуатации Windows-хоста:
*   **Enumeration** — это локальный сбор данных с текущего хоста (пользователи, группы, службы, реестр, открытые порты).
*   **Reconnaissance** — это сетевое картирование домена (доверительные отношения, глобальные группы, SPN, ACL).

Для специалиста по защите понимание этих различий критично, так как механизмы детекции для локальной и сетевой разведки различаются. Локальная разведка часто детектируется через EDR (мониторинг создания процессов, инъекции в память), тогда как сетевая разведка требует анализа событий контроллеров домена (Sysmon, Windows Event Logs).

| Характеристика | Локальная разведка (Host-Based) | Сетевая разведка (Domain-Based) |
| :--- | :--- | :--- |
| **Цель** | Понимание текущего контекста привилегий и окружения | Картирование всей инфраструктуры домена |
| **Основные источники** | Локальный реестр, SAM, LSASS, локальные группы, файлы | LDAP, Global Catalog, Kerberos, SMB-шары |
| **Типичные инструменты** | `whoami`, `systeminfo`, `net localgroup`, WinPEAS, PowerUp | BloodHound (SharpHound), NetExec, ADRecon, GetUserSPNs.py |
| **Ключевые протоколы** | WMI (локально), Registry API, Local Security Authority | LDAP (389/636), SMB (445), Kerberos (88), WinRM (5985/5986) |
| **Индикаторы компрометации (IoC)** | Создание подозрительных процессов, чтение ключей реестра, дамп памяти | Аномальный объем LDAP-запросов, сканирование SPN, доступ к `\\DC\SYSVOL` |
| **Зависимость от привилегий** | Требует локального доступа (даже стандартного пользователя) | Требует доменных учетных данных (даже Domain Users) |

Разведка на скомпрометированном хосте не является самоцелью. Она служит мостом между первоначальным доступом и эскалацией привилегий. Без точных данных о структуре домена (кто входит в какие группы, какие права делегированы) попытки эскалации будут хаотичными и легко обнаруживаемыми. Современная практика пентеста и Red Teaming требует автоматизации сбора данных, однако понимание внутренней структуры AD необходимо для интерпретации результатов и обхода защитных механизмов (например, понимания, почему BloodHound не видит определенные пути эскалации из-за ограничений репликации или фильтрации ACL).

```text
[Атакующий]
     │
     ▼ (Первоначальный доступ: Фишинг / Эксплуатация уязвимости)
[Скомпрометированный хост (Workstation/Server)]
     │
     ├──► Локальная разведка (WinPEAS, whoami, netstat)
     │    └──► Определение локальных прав, служб, уязвимых путей
     │
     └──► Сетевая разведка (SharpHound, NetExec, LDAP-запросы)
          ├──► Сбор данных о домене (LDAP)
          ├──► Сбор сессий (SMB/LDAP)
          ├──► Сбор ACL (LDAP)
          └──► Визуализация в BloodHound (Neo4j)
```

## Внутреннее устройство разведки: Архитектура сбора данных в Active Directory

Разведка в Active Directory базируется на использовании легитимных механизмов каталогов и аутентификации. Архитектура сбора данных делится на несколько ключевых компонентов, каждый из которых предоставляет уникальный набор информации. Понимание внутренней структуры этих компонентов необходимо для выбора оптимальных методов сбора и обхода защит.

### 1. LDAP и Global Catalog (GC)
LDAP (Lightweight Directory Access Protocol) является основным протоколом для взаимодействия с AD. Контроллеры домена слушают порт 389 (TCP) для незашифрованного трафика и 636 (TCP) для LDAPS. Global Catalog (порт 3268/3269) содержит частичную реплику всех объектов леса, что позволяет искать объекты без знания точного домена.

Атакующий использует LDAP для:
*   **Перечисления пользователей и групп:** Запросы к `CN=Users,DC=domain,DC=com` или `CN=Computers,DC=domain,DC=com`.
*   **Поиска SPN (Service Principal Names):** SPN — это уникальный идентификатор службы, привязанный к учетной записи. Наличие SPN позволяет атакующему инициировать запрос AS-REP (Kerberos pre-authentication attack), если у службы слабый пароль или отключена предварительная аутентификация.
*   **Анализа ACL:** Чтение атрибутов `dACL` (Discretionary Access Control List) объектов для поиска путей эскалации привилегий (например, `WriteDacl`, `ForceChangePassword`).

### 2. SMB и Named Pipes
Протокол Server Message Block (SMB) используется для доступа к файлам, принтерам и именованным каналам. В контексте разведки SMB критичен для:
*   **Сбора сессий:** SharpHound использует SMB для подключения к именованным каналам `\\DC\netlogon` и `\\DC\SYSVOL` для получения информации о текущих сессиях пользователей.
*   **Доступа к реестру и службам:** Через SMB можно удаленно опрашивать реестр других машин (Remote Registry) или получать список служб.
*   **Сбора локальных администраторов:** Запросы к `\\DC\ADMIN$` или использованию WMI через SMB для получения списка локальных администраторов на всех машинах домена.

### 3. Kerberos и Ticket Granting
Kerberos является протоколом аутентификации. Разведка через Kerberos включает:
*   **Сбор TGT (Ticket Granting Ticket):** Если атакующий имеет доступ к памяти процесса (например, LSASS), он может извлечь TGT.
*   **AS-REP Roasting:** Запрос AS-REP для пользователей с отключенной предварительной аутентификацией.
*   **Kerberoasting:** Запрос TGS для сервисных учетных записей с SPN. Полученный TGS можно офлайн-брутить.

### 4. WinRM и PowerShell Remoting
WinRM (Windows Remote Management) использует SOAP поверх HTTP/HTTPS (порты 5985/5986). Он позволяет выполнять команды удаленно, как если бы они выполнялись локально. В разведке WinRM используется для:
*   **Удаленного выполнения скриптов:** Запуск PowerShell-скриптов на множестве хостов без установки агентов.
*   **Сбора данных о конфигурации:** Получение информации о политиках, установленных обновлениях, настройках брандмауэра.

### 5. Инструментарий сбора данных
*   **SharpHound:** Основной сборщик данных для BloodHound. Собирает 5 категорий данных: локальные администраторы, членство в группах, сессии, свойства объектов и ACL. Данные упаковываются в JSON-файлы и ZIP-архив.
*   **NetExec (nxc):** Универсальный инструмент для взаимодействия с протоколами SMB, WinRM, LDAP, MSSQL. Позволяет быстро выполнять модули сбора данных (например, сбор хешей, перечисление пользователей, сканирование SPN).
*   **PowerView:** PowerShell-модуль для работы с AD. Содержит сотни функций для перечисления объектов, поиска уязвимых ACL и латерального перемещения.

## Применение и работа с предметом: Практика сбора данных и детекции

На практике разведка на скомпрометированном хосте требует сочетания локального и сетевого сбора. Специалист по тестированию на проникновение должен уметь не только запускать инструменты, но и интерпретировать их вывод, а также понимать, какие события генерируются в системе, что позволяет SOC-аналитикам обнаруживать атаку.

### Локальная разведка: Быстрый старт
Первым делом после получения доступа (shell, RDP, WinRM) необходимо определить контекст привилегий. Команда `whoami /all` показывает текущую учетную запись, SID, группы и токены. Это позволяет понять, есть ли потенциал для локальной эскалации (например, наличие права `SeImpersonatePrivilege` или `SeDebugPrivilege`).

Далее используется сбор информации о системе: `systeminfo` (версия ОС, патчи), `net localgroup administrators` (локальные администраторы), `schtasks /query /fo LIST /v` (запланированные задачи). Автоматизированные инструменты, такие как **WinPEAS** или **PowerUp**, сканируют систему по сотням чек-поинтов:
*   Неправильные права на файлы и реестр.
*   Всегда устанавливаемые бинарники (AlwaysInstallElevated).
*   Службы с уязвимыми путями к исполняемым файлам.
*   Сохраненные учетные данные в реестре или файлах конфигурации.

### Сетевая разведка: Картирование домена
После локального анализа начинается сетевая разведка. Если атакующий имеет доменные учетные данные, он может использовать **SharpHound** для сбора данных о всем домене.

```powershell
# Пример запуска SharpHound через PowerShell (fileless)
# Сбор всех категорий данных с указанием домена и выходной директории
Invoke-BloodHound -CollectionMethod All -Domain contoso.local -OutputDirectory C:\Temp\BH

# Альтернатива: запуск исполняемого файла SharpHound.exe
.\SharpHound.exe -c All -d contoso.local
```

Собранные данные экспортируются в ZIP-архив, который затем загружается в **BloodHound**. BloodHound использует графовую базу данных Neo4j для визуализации путей эскалации привилегий. Например, он может показать путь: `User -> Group -> GPO -> DC -> Domain Admins`.

Для быстрого перечисления без загрузки в BloodHound используется **NetExec (nxc)**. Он позволяет быстро опрашивать домен по различным протоколам.

```bash
# Пример использования NetExec для перечисления пользователей через LDAP
# -u: пользователь, -p: пароль (или хэш), -d: домен
nxc ldap 192.168.1.10 -u low_priv -p 'Password123' -d contoso.local --users

# Пример сканирования SPN для Kerberoasting
nxc ldap 192.168.1.10 -u low_priv -p 'Password123' -d contoso.local --kerberoasting

# Пример сбора локальных администраторов через SMB
nxc smb 192.168.1.0/24 -u low_priv -p 'Password123' -d contoso.local --local-adm
```

### Детекция разведки в SOC
Разведка генерирует специфические события в Windows Event Logs. Ключевые события для детекции:

1.  **Event ID 5145 (SMB Share Access):** SharpHound и NetExec активно используют SMB для доступа к именованным каналам (`\srvsvc`, `\lsarpc`, `\samr`) и системным шарам (`ADMIN$`, `SYSVOL`). Аномально высокий объем обращений к этим ресурсам от одной учетной записи является сильным индикатором.
    *   *Правило детекции:* `event.code: "5145" AND (winlog.event_data.RelativeTargetName: "srvsvc" OR winlog.event_data.RelativeTargetName: "lsarpc") AND NOT user.name: *$`
2.  **Event ID 4662 (Object Access):** При чтении ACL и свойств объектов в LDAP генерируются события 4662. Если включен расширенный аудит (SACL), массовые запросы будут видны.
3.  **Event ID 4768/4769 (Kerberos TGT/TGS Request):** Запросы на получение билетов. Аномалии: множество запросов TGS для разных SPN (Kerberoasting) или запросы AS-REP для пользователей с отключенной pre-auth.
4.  **Event ID 4624 (Logon) с типом 3 (Network):** Сетевые логины. Важно анализировать источник (IP) и тип учетной записи.

```text
# Пример логики детекции SharpHound в SIEM (SPL-подобный синтаксис)
index=wineventlog event_code=5145 
| stats count by user_name, src_ip, RelativeTargetName 
| where count > 50 
| where RelativeTargetName IN ("srvsvc", "lsarpc", "samr") 
| where user_name NOT LIKE "*$"
```

## Сквозной практический пример: Разведка домена после получения доступа через RDP

**Исходные условия:**
*   **Среда:** Корпоративный домен `corp.local` с контроллером домена `DC01.corp.local` (IP: 10.10.10.5) и рабочей станцией `WS01.corp.local` (IP: 10.10.10.20).
*   **Роль:** Пентестер, имеющий доступ к RDP на `WS01` от имени пользователя `j.doe` (член группы `Domain Users`, локальный администратор на `WS01`).
*   **Цель:** Собрать данные о домене для поиска путей эскалации привилегий и выявить индикаторы компрометации.

### Шаг 1: Локальная разведка и определение контекста
Пентестер выполняет базовые команды для понимания текущих привилегий и окружения.

```powershell
# Проверка текущей учетной записи и групп
whoami /all

# Вывод (иллюстративный):
# USER INFORMATION
# ----------------
# User Name     SID
# ============  ==============================================
# corp\j.doe    S-1-5-21-...-1105

# GROUP INFORMATION
# -----------------
# Group Name                           Type             SID          Attributes
# ==================================== ================ ============ ============
# BUILTIN\Remote Desktop Users         Alias            S-1-5-32-555 ...
# BUILTIN\Administrators               Alias            S-1-5-32-544 ...
# ...
```

Пентестер видит, что `j.doe` является локальным администратором на `WS01`, но не входит в привилегированные доменные группы (например, `Domain Admins`). Это подтверждает необходимость сетевой разведки.

### Шаг 2: Сбор данных о домене с помощью SharpHound
Пентестер загружает `SharpHound.exe` на `WS01` и запускает сбор данных.

```powershell
# Запуск SharpHound для сбора всех категорий данных
.\SharpHound.exe -c All -d corp.local -o C:\Temp\loot

# Ожидаемый результат:
# [2023-10-27 10:15:00] [INFO] Starting collection session...
# [2023-10-27 10:15:05] [INFO] Collecting Local Admins...
# [2023-10-27 10:15:10] [INFO] Collecting Group Membership...
# [2023-10-27 10:15:15] [INFO] Collecting Sessions...
# [2023-10-27 10:15:20] [INFO] Collecting ACLs...
# [2023-10-27 10:15:25] [INFO] Collection complete!
```

Собранные файлы (JSON) упаковываются в ZIP-архив `loot.zip`.

### Шаг 3: Анализ данных в BloodHound
Пентестер загружает `loot.zip` в BloodHound. В графе обнаруживается путь эскалации:
`j.doe` -> `HelpDesk` -> `Server Operators` -> `DC01` (через членство в группе `Server Operators`, которая имеет право на выполнение команд на контроллерах домена).

### Шаг 4: Быстрое перечисление через NetExec
Для подтверждения данных и сбора дополнительной информации пентестер использует NetExec.

```bash
# Сбор списка пользователей домена через LDAP
nxc ldap 10.10.10.5 -u j.doe -p 'Password123' -d corp.local --users

# Вывод (фрагмент):
# LDAP       10.10.10.5    389    DC01.corp.local  [+] corp.local\j.doe:Password123
# LDAP       10.10.10.5    389    DC01.corp.local  [+] User: j.doe
# LDAP       10.10.10.5    389    DC01.corp.local  [+] User: admin
# LDAP       10.10.10.5    389    DC01.corp.local  [+] User: svc_backup
# ...

# Сканирование SPN для Kerberoasting
nxc ldap 10.10.10.5 -u j.doe -p 'Password123' -d corp.local --kerberoasting

# Вывод:
# LDAP       10.10.10.5    389    DC01.corp.local  [+] Found SPN: MSSQLSvc/DB01.corp.local:1433
# LDAP       10.10.10.5    389    DC01.corp.local  [+] Found SPN: HTTP/EX01.corp.local
```

### Шаг 5: Выявление индикаторов компрометации (SOC-перспектива)
SOC-аналитик, анализируя логи DC01, видит аномальную активность.

```text
# Пример события 5145 на DC01
EventID: 5145
Subject: j.doe
ShareName: \\DC01\SYSVOL
RelativeTargetName: corp.local\Policies
AccessList: ReadData (File/Data)
...

# Анализ:
# Пользователь j.doe сделал более 1000 обращений к SYSVOL и SAMR за 5 минут.
# Это нехарактерно для обычного пользователя и указывает на автоматизированный сбор данных.
```

**Ожидаемый вывод:**
Пример демонстрирует полный цикл разведки: от локального определения контекста до сетевого картирования домена. SharpHound предоставил графовую модель путей эскалации, а NetExec позволил быстро верифицировать данные и найти цели для Kerberoasting. Для защиты критически важно мониторить события 5145 и 4662 на контроллерах домена, а также использовать AMSI для блокировки выполнения PowerShell-скриптов разведки.

## Аналитический вывод

Разведка на скомпрометированном Windows-хосте в среде Active Directory является критическим этапом пост-эксплуатации, определяющим успешность дальнейших действий атакующего. Ключевая особенность данного этапа заключается в использовании легитимных протоколов (LDAP, SMB, Kerberos) для сбора данных, что затрудняет обнаружение традиционными сигнатурными методами. Локальная разведка позволяет определить текущие привилегии и уязвимости на хосте, в то время как сетевая разведка картирует всю инфраструктуру домена, выявляя пути эскалации привилегий и латерального перемещения.

Инструменты вроде SharpHound и NetExec стандартизировали процесс разведки, автоматизируя сбор данных о членстве в группах, ACL, сессиях и SPN. Однако эта автоматизация генерирует специфические индикаторы компрометации, такие как аномальный объем LDAP-запросов, обращения к именованным каналам SMB и массовые запросы Kerberos. Для эффективной защиты необходимо внедрение комплексного мониторинга событий Windows Event Logs (особенно 5145, 4662, 4768/4769), использование AMSI для блокировки PowerShell-скриптов разведки и регулярный аудит прав доступа в Active Directory. Понимание механизмов разведки необходимо не только для пентестеров, но и для SOC-аналитиков, чтобы отличать легитимную административную активность от злонамеренного сбора данных.
