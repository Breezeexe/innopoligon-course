# Пассивная разведка через архивы веб-контента: Wayback Machine и альтернативные источники

## Контекст и базовые понятия

Пассивная разведка (Passive Reconnaissance) в рамках тестирования на проникновение (Pentest) и сбора разведывательных данных (OSINT) представляет собой процесс получения информации о цели без прямого взаимодействия с её активными сервисами, способного вызвать срабатывание систем обнаружения вторжений (IDS/IPS) или оставить следы в лог-файлах веб-сервера. Ключевым отличием пассивных методов от активных является отсутствие отправки сетевых пакетов, запросов или сканирований на целевой хост. Вместо этого специалист оперирует данными, уже опубликованными в открытых источниках (Open Source Intelligence) или сохраненными сторонними инфраструктурами.

В контексте веб-приложений и инфраструктуры одной из наиболее ценных категорий данных является удаленный или измененный контент. Веб-сайты динамичны: страницы удаляются, конфигурации меняются, старые API-эндпоинты закрываются, а уязвимые файлы (бэкапы, конфигурационные файлы, логи) могут быть случайно оставлены в публичном доступе на ранних этапах жизненного цикла проекта. Архивные копии позволяют восстановить эту «цифровую историю», выявляя потенциальные векторы атаки, которые недоступны при прямом сканировании текущего состояния системы.

Центральным инструментом в этой области выступает **Wayback Machine** (WM), часть проекта **Internet Archive** (IA). Internet Archive — некоммерческая библиотека, основанная в 1996 году Брертоном Кауфманом, которая сохраняет исторические копии веб-страниц, книг, программного обеспечения и мультимедиа. Wayback Machine предоставляет интерфейс и API для доступа к этим снимкам (snapshots).

Важно разграничивать понятия **архивирования** и **резервного копирования**. Резервное копирование (Backup) предназначено для восстановления данных в случае их потери или повреждения и обычно хранится в закрытом контуре организации. Архивирование в контексте OSINT (например, через Wayback Machine) — это публичное сохранение состояния веб-ресурса для исторического, исследовательского или юридического учета. Для атакующего разница заключается в доступе: бэкапы скрыты, архивы — открыты.

Существует путаница между терминами **Web Archive** (общий класс технологий и организаций, сохраняющих веб-контент) и **Wayback Machine** (конкретный сервис Internet Archive). Также важно отличать **CDX API** (индексный API, возвращающий метаданные о снимках) от **ARC/MCD API** (API доступа к самому контенту/бинарным данным снимка). CDX не содержит тела страницы, только ссылки и хэши.

Для наглядного разграничения сущностей, используемых в пассивной разведке через архивы, приведена сравнительная таблица.

| Сущность | Тип / Класс | Основная функция в контексте Pentest | Уровень доступа | Пример использования |
| :--- | :--- | :--- | :--- | :--- |
| **Wayback Machine (WM)** | Публичный веб-архив | Поиск удаленных страниц, старых версий кода, скрытых эндпоинтов. | Публичный (Web + API) | Поиск бэкапа `.sql` файла, удаленного с сайта 3 года назад. |
| **Internet Archive (IA)** | Некоммерческая организация / Инфраструктура | Владелец WM, хранящий данные на серверах по всему миру. | Публичный (для WM) | Источник данных для WM. |
| **Archive.today (Archiveteam)** | Публичный веб-архив | Сохранение "мгновенных" снимков (snapshot-on-demand). Часто содержит контент, заблокированный для WM. | Публичный (Web) | Просмотр страницы, которая была заблокирована `robots.txt` для WM, но сохранена в Archive.today. |
| **CDX API** | Программный интерфейс (API) | Получение списка всех сохраненных URL и временных меток для автоматизации поиска. | Публичный (HTTP GET) | Скрипт на Python, собирающий список всех поддоменов, когда-либо существовавших на домене. |
| **Web Archive API (MCD)** | Программный интерфейс (API) | Получение бинарных данных (HTML, JS, CSS) конкретного снимка. | Публичный (HTTP GET) | Загрузка исходного кода страницы для анализа на наличие скрытых скриптов. |
| **SecurityTrails / DNS History** | Коммерческий/Публичный сервис | Отслеживание истории DNS-записей (A, MX, CNAME) для выявления новых поддоменов. | Публичный/Платный | Выявление тестового поддоона `dev.target.com`, который больше не резолвится, но имеет архивные копии. |
| **Google Cache** | Кэш поисковой системы | Быстрый доступ к последней проиндексированной версии страницы. | Публичный (Web) | Просмотр страницы, если оригинал недоступен, но Google сохранил копию. |

Таким образом, предмет темы — это не просто «просмотр старых сайтов», а систематизированный процесс извлечения индикаторов компрометации (IoC), устаревших технологий и скрытой инфраструктуры из публично доступных исторических данных.

## Внутреннее устройство предмета

Внутреннее устройство пассивной разведки через архивы базируется на двух основных компонентах: механизмах сбора и индексации данных (со стороны архива) и методах запроса и фильтрации этих данных (со стороны исследователя).

### 1. Механизм сбора и хранения Internet Archive

Internet Archive использует распределенную сеть веб-краулеров. Основной краулер WM называется `ia_archiver` (или его современные аналоги, такие как `archive.org_bot`). Процесс сбора данных включает следующие этапы:

1.  **Обход (Crawling):** Краулер посещает URL, соблюдая правила `robots.txt` (хотя IA исторически игнорировала некоторые ограничения для сохранения исторической полноты, в последние годы политика ужесточилась).
2.  **Захват (Capture):** Страница преобразуется в статический формат (чаще всего HTML, но также сохраняются ресурсы: CSS, JS, изображения).
3.  **Индексация (Indexing):** Метаданные снимка (URL, временная метка, MIME-тип, размер, статус-код) записываются в индексную базу данных. Эта база данных доступна через **CDX API**.
4.  **Хранение (Storage):** Бинарные данные снимка хранятся в формате ARC или MCD (Multi-Content Data) на серверах IA. Доступ к ним осуществляется через API или прямые ссылки.

Важно понимать, что WM не сохраняет всё. Частота обхода зависит от авторитета домена, трафика и настроек владельца сайта. Новые сайты могут не иметь снимков месяцами. Кроме того, WM не выполняет JavaScript по умолчанию (в ранних версиях), поэтому динамический контент, загружаемый через AJAX, может быть потерян, если он не был захвачен в момент выполнения сервером (SSR).

### 2. Структура CDX API

CDX API (CDX Index API) является основным инструментом для программной работы с архивом. Он возвращает данные в виде таблицы (TSV — Tab-Separated Values) или JSON.

Структура ответа CDX API (TSV формат) состоит из следующих колонок:

| Колонка | Описание | Пример значения |
| :--- | :--- | :--- |
| `urlkey` | URL в формате для сортировки (нижний регистр, без http/https) | `com,example)/index.html` |
| `timestamp` | Временная метка снимка в формате `YYYYMMDDHHmmss` | `20231015143022` |
| `original` | Оригинальный URL запроса | `http://example.com/index.html` |
| `mimetype` | MIME-тип захваченного контента | `text/html` |
| `statuscode` | HTTP-статус-код, возвращенный краулером | `200` |
| `digest` | Хэш контента (MD5) для дедупликации | `A1B2C3D4...` |
| `length` | Размер захваченного контента в байтах | `15432` |

Фильтрация запросов к CDX API осуществляется через параметры URL:
*   `url=`: Целевой URL или маска (поддерживает `*` как wildcard).
*   `collapse=`: Группировка результатов. Например, `collapse=urlkey` возвращает только первый снимок для каждого уникального URL, что полезно для получения хронологии изменений.
*   `from=` / `to=`: Фильтрация по временному диапазону (формат `YYYY`, `YYYYMM`, `YYYYMMDD`).
*   `filter=`: Фильтрация по полям. Например, `filter=mimetype:text/html` или `filter=statuscode:200`.
*   `output=`: Формат вывода (`json`, `csv`, `tsv`).

### 3. Альтернативные архивы и их особенности

Помимо Wayback Machine, существуют другие источники, которые критически важны для полноты разведки, так как они могут содержать данные, отсутствующие в WM.

**Archive.today (и его форки, такие as Archive.is, Archive.ph):**
*   **Механизм:** Работает по принципу "snapshot-on-demand". Пользователь отправляет URL, и сервис делает снимок в момент запроса.
*   **Преимущество:** Часто сохраняет контент, который WM не смог захватить из-за блокировок `robots.txt`, CAPTCHA или динамической природы страницы.
*   **Недостаток:** Нет глубокой исторической базы для старых сайтов (если их не сохраняли вручную в разные даты). Нет мощного API для массового перебора, как у WM.

**Google Cache:**
*   **Механизм:** Кэш поисковой системы Google.
*   **Преимущество:** Доступ к последней версии страницы, проиндексированной Google.
*   **Недостаток:** Кэш быстро устаревает, не хранит старые версии (только последнюю актуальную), ограничен политикой Google.

**SecurityTrails / DNS History:**
*   **Механизм:** Хранение истории DNS-записей.
*   **Преимущество:** Позволяет выявить поддомены, которые больше не существуют (NXDOMAIN), но могут иметь архивные копии в WM.

Для визуализации архитектуры взаимодействия исследователя с архивами представлена схема потоков данных.

```text
[Исследователь / Pentester]
       │
       ├──▶ 1. Поиск индекса (CDX API WM)
       │      GET https://web.archive.org/cdx/search/cdx?url=*.target.com
       │      ↓
       │      [Ответ: Список URL + Timestamps]
       │
       ├──▶ 2. Фильтрация и выбор целей
       │      (Выявление .env, .git, backup.zip, старых API)
       │
       ├──▶ 3. Запрос контента (Web Archive API / Direct Link)
       │      GET https://web.archive.org/web/20231015143022id_/http://target.com/.env
       │      ↓
       │      [Ответ: HTML/Текст удаленного файла]
       │
       ├──▶ 4. Параллельный поиск в альтернативах
       │      GET https://archive.today/URL
       │      GET https://securitytrails.com/domain/target.com/history
       │
       └──▶ 5. Анализ и извлечение IoC
              (Парсинг HTML, поиск ключей, паролей, путей)
```

Таким образом, внутреннее устройство предмета включает не только сам архив, но и экосистему инструментов для доступа к нему, фильтрации и интерпретации данных.

## Применение и работа с предметом

На практике работа с архивами для пентеста включает несколько типовых операций: поиск удаленных файлов, анализ эволюции инфраструктуры, выявление устаревших технологий и поиск скрытых эндпоинтов.

### 1. Автоматизация поиска через CDX API

Ручной просмотр через веб-интерфейс WM неэффективен для крупных целей. Специалист использует скрипты (Python, Bash) для запроса CDX API.

**Типичная задача:** Найти все файлы с расширением `.bak` или `.sql`, которые когда-либо существовали на домене `target.com`.

**Реализация на Python:**

```python
import requests
import sys

def find_archived_files(domain, extension):
    # Формируем URL для CDX API
    # collapse=urlkey гарантирует, что мы получим только один снимок для каждого уникального URL
    # filter=mimetype:text/html ограничивает поиск HTML-страницами (опционально)
    # Но для поиска файлов нам нужно смотреть на original URL
    
    url = f"https://web.archive.org/cdx/search/cdx?url={domain}/*&collapse=urlkey&output=json"
    
    response = requests.get(url)
    if response.status_code != 200:
        print("Ошибка запроса к CDX API")
        return []
    
    data = response.json()
    archived_urls = []
    
    # data[0] - это заголовки колонок
    headers = data[0]
    rows = data[1:]
    
    for row in rows:
        original_url = row[2] # original
        timestamp = row[1]    # timestamp
        
        # Проверяем, содержит ли URL нужный нам тип файла
        if original_url.endswith(extension):
            archived_urls.append({
                "url": original_url,
                "timestamp": timestamp,
                "link": f"https://web.archive.org/web/{timestamp}id_/{original_url}"
            })
            
    return archived_urls

# Пример использования
results = find_archived_files("example.com", ".sql")
for res in results:
    print(f"[!] Found: {res['link']}")
```

**Ожидаемый результат:** Список ссылок на удаленные SQL-бэкапы, которые могут быть доступны для скачивания.

### 2. Анализ изменений инфраструктуры

Изменение DNS-записей или IP-адресов на сайте может указывать на миграцию инфраструктуры, смену провайдера или попытку скрыть реальный сервер.

**Метод:** Использование `SecurityTrails` или `DNSDumpster` для получения истории DNS, а затем поиск архивных копий старых IP-адресов или поддоменов.

**Пример команды для поиска поддоменов через WM:**

```bash
# Получаем список всех уникальных URL для поддоменов target.com
curl -s "https://web.archive.org/cdx/search/cdx?url=*.target.com&collapse=urlkey&output=json" | \
python3 -c "import sys, json; data=json.load(sys.stdin); print('\n'.join([row[2] for row in data[1:]]))" | \
sort -u > subdomains.txt
```

Этот список можно затем использовать для проверки доступности старых поддоменов или поиска их архивных копий.

### 3. Поиск уязвимых конфигурационных файлов

Часто разработчики оставляют конфигурационные файлы (`config.php`, `.env`, `database.yml`) в публичном доступе на ранних этапах разработки. Даже если файл удален сейчас, он может быть в архиве.

**Стратегия:** Поиск по ключевым словам в URL или в содержимом архивных страниц.

**Пример запроса к CDX API для поиска файлов конфигурации:**

```bash
# Ищем все файлы, содержащие 'config' или 'env' в URL
curl -s "https://web.archive.org/cdx/search/cdx?url=*.target.com/*config*&collapse=urlkey&output=json" | \
python3 -c "import sys, json; data=json.load(sys.stdin); [print(row[2]) for row in data[1:]]"
```

### 4. Работа с альтернативными архивами

Если WM не содержит нужных данных, необходимо проверить Archive.today.

**Инструмент:** `waybackpy` (Python-библиотека для WM) или `archivebox` (локальный архиватор).

**Пример использования `waybackpy`:**

```python
from waybackpy import WaybackMachineCDXAPI

# Инициализация API
wayback = WaybackMachineCDXAPI('example.com', 'user@example.com')

# Получение всех снимков
snapshots = wayback.all_snapshots()

for snapshot in snapshots:
    print(f"URL: {snapshot.url}, Timestamp: {snapshot.timestamp}")
```

### 5. Типичные ошибки и подводные камни

1.  **Игнорирование `robots.txt`:** WM может не иметь снимков страниц, заблокированных `robots.txt` в момент захвата. Однако, если страница была проиндексирована до блокировки, снимок может существовать.
2.  **Динамический контент:** WM не всегда корректно захватывает SPA (Single Page Applications). Контент, загружаемый через JavaScript, может отсутствовать в архиве.
3.  **Ложные срабатывания:** Наличие файла в архиве не означает, что он актуален или содержит рабочие учетные данные. Требуется верификация.
4.  **Юридические риски:** Хотя WM является публичным источником, массовый сбор данных может нарушать условия использования IA. Рекомендуется использовать API с ограничениями по частоте запросов.

## Сквозной практический пример: Поиск удаленной конфигурации и старых эндпоинтов

**Исходные условия:**
*   **Цель:** Веб-приложение `target-app.com`.
*   **Роль:** Пентестер, проводящий пассивную разведку.
*   **Инструменты:** `curl`, `python3`, `waybackpy`, браузер.
*   **Сценарий:** Необходимо найти удаленные конфигурационные файлы или старые API-эндпоинты, которые могут быть уязвимы или содержать чувствительные данные.

### Шаг 1: Получение списка всех уникальных URL через CDX API

Используем CDX API для получения списка всех URL, когда-либо существовавших на домене `target-app.com`.

**Действие:** Запрос к CDX API с фильтрацией по домену и группировкой по URL.

```bash
curl -s "https://web.archive.org/cdx/search/cdx?url=target-app.com/*&collapse=urlkey&output=json" > target_urls.json
```

**Ожидаемый вывод:** Файл `target_urls.json` содержит массив данных, где каждый элемент представляет собой уникальный URL, посещенный краулером WM.

### Шаг 2: Фильтрация потенциально уязвимых файлов

Фильтруем список URL для поиска файлов, которые часто содержат чувствительные данные: `.env`, `.git`, `.sql`, `.bak`, `config.php`.

**Действие:** Использование Python для парсинга JSON и фильтрации.

```python
import json

with open('target_urls.json', 'r') as f:
    data = json.load(f)

# Пропускаем заголовки
headers = data[0]
rows = data[1:]

sensitive_patterns = ['.env', '.git', '.sql', '.bak', 'config.php', 'backup']
found_files = []

for row in rows:
    original_url = row[2]
    timestamp = row[1]
    
    for pattern in sensitive_patterns:
        if pattern in original_url.lower():
            found_files.append({
                "url": original_url,
                "timestamp": timestamp,
                "link": f"https://web.archive.org/web/{timestamp}id_/{original_url}"
            })
            break

# Вывод результатов
for f in found_files:
    print(f"[!] Found: {f['link']}")
```

**Ожидаемый вывод:** Список ссылок на потенциально уязвимые файлы. Например:
```
[!] Found: https://web.archive.org/web/20210515120000id_/http://target-app.com/.env
[!] Found: https://web.archive.org/web/20201201100000id_/http://target-app.com/backup.sql
```

### Шаг 3: Проверка доступности и содержания архивных файлов

Проверяем, доступны ли найденные файлы и что они содержат.

**Действие:** Запрос к архивной копии файла `.env`.

```bash
curl -s "https://web.archive.org/web/20210515120000id_/http://target-app.com/.env"
```

**Ожидаемый вывод:** Содержимое файла `.env` на момент 15 мая 2021 года.

```text
DB_HOST=localhost
DB_USER=admin
DB_PASS=super_secret_password_123
AWS_ACCESS_KEY_ID=AKIAIOSFODNN7EXAMPLE
AWS_SECRET_ACCESS_KEY=wJalrXUtnFEMI/K7MDENG/bPxRfiCYEXAMPLEKEY
```

**Анализ:** Обнаружены учетные данные для базы данных и AWS. Это критическая находка.

### Шаг 4: Поиск старых API-эндпоинтов

Иногда старые API-эндпоинты, такие как `/api/v1/users`, могут быть удалены, но их документация или примеры запросов могут быть сохранены в архиве.

**Действие:** Поиск URL, содержащих `/api/`.

```bash
curl -s "https://web.archive.org/cdx/search/cdx?url=target-app.com/api/*&collapse=urlkey&output=json" | \
python3 -c "import sys, json; data=json.load(sys.stdin); [print(row[2]) for row in data[1:]]"
```

**Ожидаемый вывод:** Список старых API-эндпоинтов.

```
http://target-app.com/api/v1/users
http://target-app.com/api/v1/admin/login
http://target-app.com/api/v2/health
```

### Шаг 5: Анализ контента старого API

Проверяем, есть ли документация или примеры запросов для старого API.

**Действие:** Запрос к архивной копии страницы `/api/v1/admin/login`.

```bash
curl -s "https://web.archive.org/web/20200101000000id_/http://target-app.com/api/v1/admin/login"
```

**Ожидаемый вывод:** HTML-страница с формой входа или JSON-ответом, содержащим примеры запросов.

```html
<form method="POST" action="/api/v1/admin/login">
    <input type="text" name="username">
    <input type="password" name="password">
    <button type="submit">Login</button>
</form>
```

**Анализ:** Обнаружен старый эндпоинт административной панели. Хотя он может быть недоступен сейчас, он может быть восстановлен или использоваться в других контекстах.

**Ожидаемый вывод примера:**
Пример демонстрирует, как пассивная разведка через архивы позволяет выявить критические уязвимости (утечку учетных данных) и скрытую инфраструктуру (старые API-эндпоинты), которые недоступны при прямом сканировании. Это подчеркивает важность мониторинга архивных данных для как атакующих, так и защитников.

## Аналитический вывод

Пассивная разведка через архивы веб-контента, в частности через Wayback Machine и альтернативные источники, является мощным инструментом в арсенале специалиста по кибербезопасности. Она позволяет восстановить удаленный или измененный контент, выявить устаревшие технологии, скрытые эндпоинты и утечки чувствительных данных. Ключевым преимуществом этого метода является отсутствие прямого взаимодействия с целью, что снижает риск обнаружения. Однако, эффективность разведки зависит от полноты архивных данных, которые могут быть ограничены политикой `robots.txt`, динамической природой веб-приложений и частотой обхода краулеров. Для достижения максимальной полноты необходимо комбинировать данные из нескольких источников (Wayback Machine, Archive.today, SecurityTrails) и использовать автоматизированные инструменты для анализа. Защитникам организаций также важно регулярно мониторить свои архивные копии, чтобы своевременно удалять или закрывать доступ к устаревшим и потенциально уязвимым ресурсам.
