# Активная разведка:Enumeration поддоменов в рамках тестирования на проникновение

## Контекст и базовые понятия

Enumeration поддоменов (subdomain enumeration) — это процесс систематического выявления всех активных и неактивных поддоменов, связанных с целевым доменом. В контексте тестирования на проникновение и bug bounty это критический этап сбора информации, направленный на расширение поверхности атаки. Организация редко использует только один домен; инфраструктура обычно включает множество поддоменов для различных сервисов: разработки (`dev`), тестирования (`staging`), API (`api`), контента (`cdn`), региональных сервисов (`us`, `eu`) и устаревших систем. Каждый из этих поддоменов представляет собой потенциальную точку входа, которая может иметь отличные от основного домена конфигурации безопасности, уязвимости или открытые порты.

Активная разведка (active reconnaissance) в данном контексте подразумевает прямое взаимодействие с DNS-инфраструктурой цели. В отличие от пассивной разведки, которая собирает данные из сторонних источников (сертификаты TLS, поисковые системы, архивы) без отправки запросов к цели, активные методы генерируют сетевой трафик, направленный непосредственно на DNS-серверы организации. Это позволяет получить актуальные данные о текущем состоянии инфраструктуры, но повышает риск обнаружения средствами защиты (IDS/IPS, WAF, SIEM).

Ключевое разграничение в теме enumeration поддоменов проводится между двумя основными подходами:

| Характеристика | Пассивная разведка (Passive) | Активная разведка (Active) |
| :--- | :--- | :--- |
| **Взаимодействие с целью** | Отсутствует. Запросы направляются в сторонние БД (Shodan, Censys, crt.sh). | Прямое. Запросы отправляются на DNS-серверы цели (NS, SOA, AXFR, A/AAAA). |
| **Обнаруживаемость** | Низкая. Трафик не попадает в логи целевой инфраструктуры. | Высокая. Генерируется значительный объем DNS-запросов, детектируемый средствами защиты. |
| **Актуальность данных** | Историческая. Данные могут быть устаревшими (записи удалены, но остались в логах). | Текущая. Отображает реальное состояние DNS-зоны на момент сканирования. |
| **Основные методы** | Certificate Transparency (CT), OSINT, архивы интернета, публичные DNS-зоны. | DNS Brute-force, Zone Transfer (AXFR), Reverse DNS, DNS Permutation. |
| **Инструменты** | Subfinder (режим passive), Amass (режим passive), crt.sh, Wayback Machine. | GoBuster, dnsrecon, dnsenum, puredns, feroxbuster (DNS mode), Nmap. |
| **Применимость** | Начальный этап, обход строгих политик безопасности, сбор первичного инвентаря. | Углубленный анализ, поиск скрытых/забытых сервисов, валидация пассивных данных. |

Путаница часто возникает между понятиями *сканирования портов* и *enumeration поддоменов*. Сканирование портов (port scanning) работает на транспортном уровне (L4) и выявляет открытые сервисы на известных IP-адресах. Enumeration поддоменов работает на прикладном уровне (L7/DNS) и выявляет новые доменные имена, которые затем резолвятся в IP-адреса для последующего сканирования. Таким образом, enumeration является предшественником сканирования портов в пайплайне разведки.

Важно различать *брутфорс* (brute-force) и *пермутацию* (permutation). Брутфорс использует статический или динамический список слов (wordlist) для перебора возможных префиксов. Пермутация генерирует варианты на основе лингвистических правил или паттернов, характерных для конкретной организации (например, использование названий городов, внутренних кодов отделов), что позволяет находить поддомены, не присутствующие в стандартных списках.

## Внутреннее устройство предмета

Активная enumeration поддоменов опирается на несколько фундаментальных механизмов взаимодействия с DNS-протоколом. Понимание внутренней работы этих механизмов необходимо для выбора правильного инструментария и интерпретации результатов.

### 1. DNS Zone Transfer (AXFR)

Zone Transfer — это механизм синхронизации данных между первичным (Primary) и вторичным (Secondary) DNS-серверами. Если сервер настроен небезопасно, он может позволить любому клиенту запросить полную копию DNS-зоны. Это самый эффективный, но и самый редкий метод, так как современные DNS-серверы (BIND, Windows DNS, Cloudflare) по умолчанию блокируют AXFR для внешних клиентов.

*   **Механизм:** Клиент отправляет запрос типа `AXFR` к целевому NS-серверу. Если сервер разрешает передачу, он отправляет весь контент зоны в виде последовательности DNS-пакетов.
*   **Необходимые условия:** Злоумышленник должен знать IP-адрес NS-сервера. Сервер должен иметь разрешающую запись `allow-transfer` для `any` или для IP-адреса атакующего.
*   **Индикаторы:** Ответ сервера содержит множество записей `A`, `MX`, `CNAME` и других типов сразу после одного запроса.
*   **Контрмеры:** Ограничение `allow-transfer` только IP-адресами реплицируемых вторичных серверов.

### 2. DNS Brute-Force (Брутфорс поддоменов)

Наиболее распространенный метод активной разведки. Основан на переборе префиксов поддомена с использованием wordlist.

*   **Механизм:** Генерация запросов типа `A` (или `AAAA`) для комбинаций `prefix.target_domain`. Анализ ответа сервера.
*   **Типы ответов:**
    *   `NOERROR` с IP-адресом: поддомен существует и резолвится.
    *   `NXDOMAIN`: поддомен не существует.
    *   `SERVFAIL`: ошибка на стороне сервера (возможно, защита от DDoS или rate-limiting).
*   **Проблема Wildcard DNS:** Если домен настроен с wildcard-записью (`*.target_domain` резолвится в один IP), стандартный брутфорс генерирует ложноположительные результаты (False Positives). Инструменты активной разведки должны уметь детектировать wildcard и фильтровать такие записи, проверяя, резолвится ли конкретный поддомен в тот же IP, что и wildcard, или в уникальный.
*   **Скорость и параллелизм:** Эффективный брутфорс требует многопоточности (threading) и асинхронных запросов для обработки тысяч запросов в секунду.

### 3. Reverse DNS Lookups (PTR-записи)

Используется, когда известен диапазон IP-адресов (CIDR) организации.

*   **Механизм:** Для каждого IP из диапазона запрашивается PTR-запись. PTR-запись содержит доменное имя, ассоциированное с IP.
*   **Ограничения:** Работает только для IP, у которых настроены PTR-записи. Не все организации используют PTR для своих сервисов.
*   **Индикаторы:** Ответ содержит поле `PTR` с доменным именем.

### 4. DNS Permutation and Generation

Генерация вариантов поддоменов на основе контекста цели, а не случайного перебора.

*   **Механизм:** Использование лингвистических правил, названий городов, внутренних кодов, паттернов из пассивной разведки.
*   **Инструменты:** `dnsgen`, `goaltdns`, `gotator`.
*   **Преимущество:** Позволяет находить поддомены, которые не являются "стандартными" (не `www`, `mail`, `api`), но используются в конкретной организации.

### Сравнительная таблица методов активной enumeration

| Метод | Принцип действия | Сложность реализации | Эффективность | Риск обнаружения | Требует авторизации |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **AXFR (Zone Transfer)** | Запрос полной копии DNS-зоны | Низкая (1 команда) | Очень высокая (100% покрытие) | Средний (редкий трафик) | Нет (если уязвимость есть) |
| **DNS Brute-Force** | Перебор префиксов из wordlist | Средняя (нужен wordlist) | Высокая (зависит от wordlist) | Высокий (большой объем трафика) | Нет (в рамках договора) |
| **Reverse DNS** | Запрос PTR для IP-диапазона | Низкая | Низкая/Средняя | Низкий | Нет |
| **DNS Permutation** | Генерация вариантов по паттернам | Высокая (нужен контекст) | Средняя/Высокая | Средний | Нет |
| **Nmap DNS Scripts** | Использование NSE скриптов | Низкая | Средняя | Высокий | Нет |

## Применение и работа с предметом

На практике специалист по тестированию на проникновение не полагается на один инструмент. Процесс активной enumeration обычно включает несколько этапов: валидация NS-серверов, попытка AXFR, запуск многопоточного брутфорса с фильтрацией wildcard, а затем пермутация для расширения списка.

### Инструментарий и его функции

1.  **`dnsrecon`**: Универсальный инструмент для Linux/Windows. Поддерживает AXFR, обратные зоны, поиск NS/MX записей и брутфорс. Полезен для быстрого анализа структуры DNS.
2.  **`dnsenum`**: Аналог `dnsrecon`, но с возможностью генерации отчетов в HTML. Менее гибок в настройке потоков, но прост в использовании.
3.  **`GoBuster` (DNS mode)**: Высокопроизводительный инструмент от OJ Reeves. Использует Go для параллельных запросов. Требует указания wordlist (например, из `SecLists`). Эффективен для быстрого перебора.
4.  **`puredns`**: Современный инструмент от ProjectDiscovery. Специализируется на быстром резолве и фильтрации wildcard. Позволяет объединять результаты из нескольких источников (пассивных и активных) и резолвить их в одном потоке, отбрасывая дубликаты и невалидные записи.
5.  **`Nmap` (NSE scripts)**: Скрипты `dns-brute` и `dns-zone-transfer` позволяют интегрировать enumeration в общий сканер. Полезно, если уже запущен сканер портов.

### Типичные ошибки и подводные камни

*   **Игнорирование Wildcard DNS:** Запуск брутфорса без предварительной проверки на wildcard приводит к тысячам ложноположительных результатов. Всегда проверяйте, резолвится ли `randomstring12345.target.com` в тот же IP, что и `*.target.com`.
*   **Отсутствие rate-limiting:** Слишком быстрые запросы могут привести к бану IP-адреса атакующего со стороны DNS-сервера или WAF. Использование инструментов с поддержкой throttle или proxy необходимо.
*   **Недостаточный охват wordlist:** Стандартные wordlist (например, `common.txt`) часто не содержат специфичных для организации префиксов. Необходимо использовать кастомные wordlist, сгенерированные на основе пассивной разведки (например, из `Subfinder` или `Amass`).
*   **Игнорирование IPv6:** Многие современные сервисы используют IPv6. Запросы должны включать тип `AAAA`.

### Пример конфигурации и команды

Для эффективной активной enumeration рекомендуется использовать комбинацию инструментов. Например, сначала проверить AXFR, затем запустить брутфорс с фильтрацией wildcard.

```bash
# Проверка Zone Transfer для NS-серверов
dnsrecon -d target.com -t axfr

# Брутфорс с GoBuster (фильтрация wildcard требует дополнительной логики)
gobuster dns -d target.com -w /usr/share/seclists/Discovery/DNS/bitquark_subdomains_top100000.txt -t 50 -o gobuster_results.txt

# Использование puredns для быстрого резолва и фильтрации
echo "sub1.target.com" | puredns resolve --wildcard-filter --output valid_subdomains.txt
```

## Сквозной практический пример: Enumeration поддоменов для цели `example.com`

**Исходные условия:**
*   **Цель:** `example.com` (публичный домен, используемый для тестирования).
*   **Роль:** Пентестер, имеющий письменное разрешение на тестирование.
*   **Среда:** Kali Linux.
*   **Инструменты:** `dnsrecon`, `GoBuster`, `puredns`, `dig`.
*   **Сценарий:** Активная разведка для выявления всех активных поддоменов перед началом сканирования портов.

### Шаг 1: Определение NS-серверов и проверка Zone Transfer

Первым делом необходимо найти authoritative DNS-серверы домена. Это точки входа для AXFR.

**Действие:** Запрос NS-записей через `dig`.

```bash
dig ns example.com +short
```

**Ожидаемый вывод:**
```text
ns1.example.com.
ns2.example.com.
```

**Действие:** Попытка Zone Transfer для каждого NS-сервера.

```bash
dnsrecon -d example.com -t axfr
```

**Ожидаемый вывод:**
Если AXFR разрешен:
```text
[*] Zone Transfer for example.com.
[*]     A       example.com.    3600    IN      A       93.184.216.34
[*]     A       www.example.com. 3600    IN      A       93.184.216.34
[*]     MX      example.com.    3600    IN      MX      10 mail.example.com.
... (полный список записей)
```
Если AXFR запрещен:
```text
[-] Zone Transfer failed for example.com.
[-]     Transfer failed: REFUSED
```
*В данном примере AXFR будет запрещен, так как `example.com` настроен корректно.*

### Шаг 2: Проверка на Wildcard DNS

Перед запуском брутфорса необходимо определить, использует ли домен wildcard.

**Действие:** Запрос несуществующего поддомена.

```bash
dig randomstring12345.example.com +short
```

**Ожидаемый вывод:**
Если wildcard включен:
```text
93.184.216.34
```
(Тот же IP, что и у `example.com`).

Если wildcard выключен:
```text
;; connection timed out; no servers could be reached
```
или
```text
;; NXDOMAIN
```

*Предположим, что wildcard включен и резолвится в `93.184.216.34`. Это означает, что любой поддомен, резолвящийся в этот IP, может быть как реальным, так и ложноположительным. Требуется фильтрация.*

### Шаг 3: Активный DNS Brute-Force с GoBuster

Запуск брутфорса с использованием wordlist и фильтрацией wildcard.

**Действие:** Запуск GoBuster с параметром `-w` для wordlist и `-t` для потоков.

```bash
gobuster dns -d example.com -w /usr/share/seclists/Discovery/DNS/bitquark_subdomains_top100000.txt -t 50 -o gobuster_results.txt
```

**Ожидаемый вывод (фрагмент лога):**
```text
===============================================================
Gobuster v3.6
by OJ Reeves (@TheColonial) & Contributers
===============================================================
[+] Domain:   example.com
[+] Threads:  50
[+] Wordlist: /usr/share/seclists/Discovery/DNS/bitquark_subdomains_top100000.txt
[+] Status:   no wildcard detected (или detected, но мы фильтруем)
===============================================================
[+] Status:   no wildcard detected
[+] Mode:     dns
[+] Output File: gobuster_results.txt
[+] Timeout:  10s
[+] Verbose:  false
[+] Delay:    0
===============================================================
Starting gobuster in DNS mode
===============================================================
www                 Status: 200 (Resolved: 93.184.216.34)
mail                Status: 200 (Resolved: 93.184.216.34)
ftp                 Status: 200 (Resolved: 93.184.216.34)
...
```

*Примечание: В случае wildcard GoBuster не фильтрует автоматически. Необходимо использовать `puredns` или скрипт для постобработки.*

### Шаг 4: Фильтрация и резолв с помощью puredns

Объединение результатов GoBuster с пассивными данными (например, из `Subfinder`) и фильтрация wildcard.

**Действие:** Создание списка всех найденных поддоменов (пассивных и активных) и их резолв.

```bash
# Объединение результатов (пример)
cat gobuster_results.txt | grep "Status: 200" | awk '{print $1}' > active_subs.txt
subfinder -d example.com -o passive_subs.txt
cat active_subs.txt passive_subs.txt | sort -u > all_subs.txt

# Резолв с фильтрацией wildcard
puredns resolve all_subs.txt --wildcard-filter --output valid_subs.txt
```

**Ожидаемый вывод (файл `valid_subs.txt`):**
```text
www.example.com
mail.example.com
ftp.example.com
api.example.com
staging.example.com
```
*Здесь `randomstring12345.example.com` был отфильтрован, так как резолвился в тот же IP, что и wildcard, но не был найден в активных источниках или не имел уникального IP.*

### Шаг 5: Анализ результатов

**Действие:** Проверка уникальных IP-адресов для выявления новых сервисов.

```bash
puredns resolve valid_subs.txt --output-with-ip
```

**Ожидаемый вывод:**
```text
www.example.com -> 93.184.216.34
mail.example.com -> 192.0.2.1
ftp.example.com -> 192.0.2.2
api.example.com -> 198.51.100.1
staging.example.com -> 203.0.113.1
```

**Ожидаемый вывод:**
Пример демонстрирует полный цикл активной enumeration: от определения NS-серверов до фильтрации ложноположительных результатов. Выявлены новые IP-адреса (`192.0.2.1`, `198.51.100.1`, `203.0.113.1`), которые не совпадают с основным IP домена (`93.184.216.34`). Это указывает на наличие отдельных сервисов (почта, FTP, API, staging), которые требуют дальнейшего сканирования портов и уязвимостей.

## Аналитический вывод

Активная enumeration поддоменов является неотъемлемой частью современного тестирования на проникновение, позволяющей выявить скрытые активы, которые не видны при пассивном сборе информации. Ключевым вызовом в этой области является баланс между полнотой охвата и риском обнаружения. Методы, такие как AXFR, предоставляют исчерпывающие данные, но их применимость ограничена устаревшими конфигурациями. DNS Brute-Force, напротив, универсален, но требует тщательной настройки wordlist и фильтрации wildcard для избежания ложноположительных результатов.

Современный подход к активной разведке предполагает использование гибридных инструментов, таких как `puredns` или `Amass`, которые объединяют пассивные и активные методы, а также включают механизмы пермутации и генерации вариантов. Это позволяет максимизировать покрытие поверхности атаки. Важно помнить, что активные методы генерируют детектируемый трафик, поэтому в рамках реальных пентестов необходимо соблюдать этические нормы и получать явное разрешение на сканирование. Результаты активной enumeration служат фундаментом для последующих этапов: сканирования портов, fingerprinting и эксплуатации уязвимостей.
