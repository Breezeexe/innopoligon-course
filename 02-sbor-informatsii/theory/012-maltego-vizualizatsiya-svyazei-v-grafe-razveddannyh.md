# Maltego: Визуализация связей в графе разведданных при пассивной разведке

## Контекст и базовые понятия: OSINT, графовая модель и место Maltego в экосистеме

Maltego представляет собой платформу для анализа связей (link analysis) и сбора открытой информации (OSINT), которая преобразует разрозненные данные в интерактивный граф. В контексте тестирования на проникновение (pentest) и пассивной разведки инструмент используется для построения карты цифрового следа цели без прямого взаимодействия с её инфраструктурой (за исключением запросов к публичным API и поисковым системам). Ключевая ценность Maltego заключается не в скорости сбора данных по сравнению с скриптами на Python, а в способности выявлять скрытые корреляции между сущностями (entities) через визуализацию графов.

Основная сущность в Maltego — это **Entity** (сущность). Каждая сущность имеет тип (например, `person`, `email`, `domain`, `ipAddress`, `phoneNumber`) и атрибуты (значения). Связи между сущностями называются **Transforms** (преобразованиями). Transform — это скрипт или API-запрос, который берет одну сущность на входе и возвращает новые сущности на выходе, создавая ребро графа. Например, трансформ `To Website [using Search Engine]` берет сущность `person` и возвращает сущности `url`, связанные с этим человеком в открытых источниках.

Важно разграничивать Maltego от смежных инструментов. Maltego не является сканером уязвимостей (как Nessus) и не является инструментом активного эксплойта (как Metasploit). Это инструмент разведки. Также необходимо различать Maltego Desktop (клиентское приложение для сложного анализа) и Maltego One (веб-платформа для быстрого поиска и мониторинга). В рамках пассивной разведки на этапе подготовки к тестированию на проникновение используется именно Desktop-версия для глубокого анализа инфраструктуры цели.

Для понимания архитектуры Maltego необходимо ввести понятие **Transform Hub**. Это репозиторий трансформов, который позволяет подключать внешние данные (OSINT-провайдеры, внутренние базы данных, API) к графу. Без трансформов Maltego является просто пустым холстом для рисования связей.

| Характеристика | Maltego (Link Analysis) | Классические OSINT-скрипты (Python/Bash) | Пассивные сканеры (Shodan/Censys API) |
| :--- | :--- | :--- | :--- |
| **Основная парадигма** | Графовая (узлы и ребра) | Линейная/Итеративная | Запрос-Ответ (REST) |
| **Визуализация** | Встроенная, интерактивная, иерархическая | Отсутствует (требует внешних библиотек) | Отсутствует (текстовые/JSON-выводы) |
| **Выявление связей** | Автоматическое через Transforms | Ручное сопоставление полей | Ручное сопоставление по IP/Domain |
| **Масштабируемость** | Ограничена RAM и производительностью GUI | Высокая (параллельные потоки) | Высокая (лимиты API провайдеров) |
| **Типичное применение** | Глубокий анализ цепочек, отчетность | Быстрый сбор больших объемов сырых данных | Мониторинг инфраструктуры, проверка экспозиции |
| **Порог входа** | Высокий (необходимо понимание типов сущностей) | Средний (требует навыков программирования) | Низкий (достаточно знания API) |

Путаница часто возникает между понятиями "OSINT" и "OSINT-инструмент". OSINT — это методология сбора данных из публичных источников. Maltego — это инструмент, который автоматизирует применение этой методологии через визуальные трансформы. В отличие от специализированных инструментов для сбора данных (например, SpiderFoot), Maltego фокусируется на *анализе* уже собранных данных, позволяя исследователю "путешествовать" по графу связей.

В современной практике пентеста Maltego интегрируется в более широкий процесс. Он не заменяет инструменты для сбора DNS-записей (dig/nslookup) или Whois-запросов, но агрегирует их результаты в единое представление. Это критически важно на этапе разведки, когда необходимо понять архитектуру компании, выявить сотрудников, домены, поддомены и связанные IP-адреса до начала активного сканирования.

## Внутреннее устройство: Архитектура графа, типы сущностей и механизм трансформов

Архитектура Maltego Desktop базируется на клиент-серверной модели взаимодействия с локальным движком обработки трансформов. Клиент (GUI) отвечает за отображение графа и управление сущностями, в то время как трансформы выполняются либо локально (скрипты на Python, Perl, Bash), либо удаленно (через API провайдеров данных).

### Типы сущностей (Entities) и их иерархия

Maltego использует строгую типизацию сущностей. Каждая сущность имеет уникальный идентификатор (UUID) и набор атрибутов. Типы сущностей делятся на базовые (встроенные) и кастомные (пользовательские). Базовые типы включают:

*   `person`: Имя, фамилия, должность.
*   `email`: Адрес электронной почты.
*   `domain`: Доменное имя.
*   `ipAddress`: IPv4 или IPv6 адрес.
*   `url`: Полный URL.
*   `phoneNumber`: Номер телефона.
*   `company`: Название организации.
*   `location`: Географические координаты или адрес.

Кастомные типы создаются пользователями для специфических нужд (например, `internal:employee_id` или `vendor:software_version`). Важно, что трансформы могут принимать только определенные типы сущностей на вход и возвращать определенные типы на выход. Это обеспечивает целостность графа и предотвращает логические ошибки (например, попытка запустить DNS-трансформ от сущности `person` без предварительного преобразования в `email` или `domain`).

### Механизм трансформов (Transforms)

Трансформы — это ядро Maltego. Они представляют собой исполняемые модули, которые запрашивают данные из внешних источников. Трансформы классифицируются по источникам данных:

1.  **Standard Transforms:** Встроенные в Maltego трансформы, использующие публичные поисковые системы (Google, Bing, Yahoo) и базовые протоколы (Whois, DNS, ASN). Они не требуют ключей API, но имеют ограничения по частоте запросов и глубине данных.
2.  **Data Provider Transforms:** Трансформы, использующие коммерческие или специализированные базы данных (например, Shodan, VirusTotal, Have I Been Pwned, LinkedIn, Twitter/X). Для их работы требуются API-ключи, приобретенные через Maltego Data Pass или интегрированные вручную.
3.  **Custom Transforms:** Скрипты, написанные пользователями для интеграции внутренних корпоративных баз данных или специфических API.

Процесс выполнения трансформы выглядит следующим образом:
1.  Исследователь перетаскивает трансформ на сущность в графе.
2.  Maltego отправляет запрос к источнику данных с параметрами сущности.
3.  Источник возвращает результат в формате JSON или XML.
4.  Maltego парсит результат, создает новые сущности и добавляет их в граф, соединяя ребрами с исходной сущностью.
5.  Новые сущности могут быть использованы как входные данные для других трансформов, что позволяет строить цепочки разведки.

### Структура графа и визуализация

Граф в Maltego — это динамическая структура данных, хранящаяся в памяти приложения и сохраняемая в файлах `.mtgx`. Каждый узел графа может быть свернут (collapsed) в "супер-узел" для уменьшения визуального шума. Это позволяет исследователю работать с большими объемами данных, скрывая второстепенные связи.

Визуализация настраивается через стили сущностей (icons) и цветовую кодировку. Например, сущности `email` могут быть окрашены в синий цвет, а `ipAddress` — в красный. Это позволяет быстро идентифицировать типы узлов в плотных кластерах.

| Компонент графа | Описание | Функция в разведке |
| :--- | :--- | :--- |
| **Node (Узел)** | Сущность с типом и значением | Представление конкретного объекта разведки (домен, человек, IP) |
| **Edge (Ребро)** | Связь между узлами, созданная трансформом | Отображение отношения (например, "owns", "hosts", "associated_with") |
| **Transform** | Действие, создающее ребро и новые узлы | Источник данных для расширения графа |
| **Graph** | Коллекция узлов и ребер | Артефакт разведки, представляющий карту инфраструктуры цели |
| **Case** | Контейнер для одного или нескольких графов | Организация расследований, хранение истории и заметок |

### Инварианты и ограничения

При работе с графом необходимо учитывать несколько технических ограничений:
*   **Память:** Каждый узел и ребро потребляют оперативную память. Графы с десятками тысяч узлов могут привести к деградации производительности GUI.
*   **Лимиты API:** Большинство трансформов, использующих внешние API, имеют квоты на запросы. Превышение лимитов приводит к ошибкам выполнения трансформов (обычно HTTP 429 Too Many Requests).
*   **Достоверность данных:** Данные из публичных источников могут быть устаревшими или намеренно ложными (honeypots). Maltego не верифицирует достоверность данных, это задача исследователя.

## Применение и работа с предметом: Практика пассивной разведки с Maltego

Работа с Maltego в рамках пассивной разведки требует понимания не только интерфейса, но и логики построения цепочек трансформов. Типичный процесс включает настройку среды, выбор начальных точек (seed entities) и построение графа связей.

### Настройка среды и интеграция данных

Перед началом разведки необходимо обеспечить доступ к необходимым источникам данных. В Maltego это делается через **Transform Hub** или **Data Pass**. Для пентестера критически важно иметь доступ к трансформам, которые предоставляют данные о DNS, WHOIS, SSL-сертификатах и утечках данных.

Настройка трансформов включает:
1.  Открытие окна Transform Hub.
2.  Поиск необходимых трансформов (например, `To DNS Records`, `To Whois Info`).
3.  Установка трансформов и ввод API-ключей, если требуется.
4.  Проверка работоспособности трансформов через тестовый запуск на известной сущности.

### Построение цепочек разведки

Основной метод работы — построение цепочек трансформов. Исследователь начинает с известной сущности (например, доменное имя компании) и последовательно применяет трансформы для расширения графа.

Типичная цепочка для пассивной разведки домена:
1.  **Seed:** `domain` (целевой домен).
2.  **Transform 1:** `To DNS Records` (получение IP-адресов, MX-записей, TXT-записей).
3.  **Transform 2:** `To Whois Info` (получение данных о регистраторе, контактах, датах регистрации).
4.  **Transform 3:** `To ASN` (получение информации об автономной системе, хостинг-провайдере).
5.  **Transform 4:** `To IP Address` (переход к IP-адресам для поиска связанных доменов через reverse DNS).

Каждый шаг расширяет граф, выявляя новые сущности. Например, из TXT-записей DNS можно извлечь SPF-данные, которые указывают на провайдеров email-услуг. Из Whois-данных можно получить имена администраторов, которые затем могут быть использованы для поиска их профилей в социальных сетях.

### Анализ и фильтрация графа

По мере роста графа он становится сложным для анализа. Maltego предоставляет инструменты для фильтрации и организации данных:
*   **Filter:** Позволяет скрыть узлы, не соответствующие определенным критериям (например, скрыть все IP-адреса, не принадлежащие целевой ASN).
*   **Group:** Позволяет группировать узлы по типам или источникам данных.
*   **Collapse:** Позволяет свернуть ветки графа, чтобы уменьшить визуальную нагрузку.

### Типичные ошибки и подводные камни

1.  **Слепое доверие данным:** Данные из публичных источников могут быть устаревшими. Например, Whois-данные могут быть скрыты за GDPR-защитой или WhoisGuard.
2.  **Перегрузка графа:** Запуск трансформов без фильтрации может привести к созданию миллионов узлов, что сделает граф бесполезным. Всегда используйте лимиты и фильтры.
3.  **Игнорирование контекста:** Maltego показывает связи, но не объясняет их смысл. Исследователь должен интерпретировать связи самостоятельно. Например, связь между IP-адресом и доменом может быть временной (динамический IP) или постоянной (выделенный сервер).

### Пример конфигурации трансформов

Ниже приведен пример структуры трансформов, используемых для пассивной разведки домена. Этот список не является исчерпывающим, но отражает базовый набор для пентеста.

```json
{
  "transform_chain": [
    {
      "name": "To DNS Records",
      "source_entity": "domain",
      "target_entities": ["ipAddress", "mxRecord", "txtRecord"],
      "data_source": "Standard DNS Resolver",
      "api_key_required": false
    },
    {
      "name": "To Whois Info",

    {

    {
      "name": "To SSL Certificate",
      "source_entity": "ipAddress",
      "target_entities": ["domain", "person"],
      "data_source": "Shodan or Censys",

    }
  ]
}
```

## Сквозной практический пример: Пассивная разведка инфраструктуры целевой компании

**Исходные условия:**
*   **Роль:** Пентестер, проводящий пассивную разведку.
*   **Цель:** Компания `example-corp.com`.
*   **Инструменты:** Maltego Graph (Desktop), доступ к стандартным трансформам и API Shodan.
*   **Сценарий:** Сбор информации о доменной инфраструктуре, связанных поддоменах и потенциальных точках входа до начала активного сканирования.

### Шаг 1: Инициализация графа и поиск доменных записей

Начинаем с добавления сущности `domain` в граф. Запускаем трансформ `To DNS Records` для получения основных записей.

```bash
# В Maltego GUI:
# 1. Drag 'domain' entity to graph.
# 2. Right-click -> Add Transform -> 'To DNS Records'.
# 3. Execute.
```

**Ожидаемый вывод:**
Граф расширяется новыми узлами: `ipAddress` (A-записи), `mxRecord` (почтовые серверы), `txtRecord` (SPF, DKIM).

```json
{
  "entity_type": "domain",
  "value": "example-corp.com",
  "dns_records": {
    "A": ["93.184.216.34"],
    "MX": ["mail.example-corp.com"],
    "TXT": ["v=spf1 include:_spf.google.com ~all"]
  }
}
```

### Шаг 2: Расширение через Whois и ASN

Добавляем трансформ `To Whois Info` к сущности `domain` и `To ASN` к сущности `ipAddress`.

```bash
# В Maltego GUI:
# 1. Right-click 'domain' -> Add Transform -> 'To Whois Info'.
# 2. Right-click 'ipAddress' -> Add Transform -> 'To ASN'.
# 3. Execute.
```

**Ожидаемый вывод:**
Получены данные о регистраторе домена и автономной системе (ASN). Это помогает определить хостинг-провайдера и географическое положение инфраструктуры.

```json
{
  "whois_info": {
    "registrar": "Example Registrar Inc.",
    "registrant_email": "admin@example-corp.com",
    "creation_date": "2010-01-01"
  },
  "asn_info": {
    "asn": "AS15169",
    "name": "Google LLC",
    "country": "US"
  }
}
```

### Шаг 3: Интеграция с внешними данными (Shodan)

Используем трансформ `To SSL Certificate` с API Shodan для получения информации о сертификатах, связанных с IP-адресами.

```bash
# В Maltego GUI:
# 1. Right-click 'ipAddress' -> Add Transform -> 'To SSL Certificate' (Shodan).
# 2. Enter API Key when prompted.
# 3. Execute.
```

**Ожидаемый вывод:**
Получены данные о SSL-сертификатах, которые могут содержать дополнительные доменные имена (SAN - Subject Alternative Names).

```json
{
  "ssl_certificate": {
    "subject": "example-corp.com",
    "san": ["mail.example-corp.com", "api.example-corp.com", "dev.example-corp.com"],
    "issuer": "Let's Encrypt",
    "validity": "2023-01-01 to 2024-01-01"
  }
}
```

### Шаг 4: Анализ связанных доменов и сотрудников

Добавляем трансформ `To Domain` к сущностям `san` из SSL-сертификата и `To Person` к сущности `registrant_email`.

```bash
# В Maltego GUI:
# 1. Right-click 'san' entities -> Add Transform -> 'To Domain'.
# 2. Right-click 'registrant_email' -> Add Transform -> 'To Person'.
# 3. Execute.
```

**Ожидаемый вывод:**
Граф показывает дополнительные поддомены и потенциальных сотрудников компании. Это позволяет выявить скрытые сервисы и цели для социальной инженерии.

```json
{
  "related_domains": ["api.example-corp.com", "dev.example-corp.com"],
  "person": {
    "name": "John Doe",
    "email": "admin@example-corp.com",
    "role": "System Administrator"
  }
}
```

### Ожидаемый вывод

В результате пассивной разведки построен граф, содержащий:
1.  Основные домены и поддомены.
2.  IP-адреса и ASN-информацию.
3.  Данные Whois и SSL-сертификатов.
4.  Контактную информацию администраторов.

Этот граф служит основой для дальнейшего активного тестирования, позволяя пентестеру сосредоточиться на наиболее релевантных целях и избежать случайного сканирования несвязанных ресурсов.

## Аналитический вывод

Maltego является мощным инструментом для визуализации и анализа связей в рамках пассивной разведки, позволяя исследователям эффективно собирать и структурировать данные из множества открытых источников. Его ключевая сила заключается в графовом представлении данных, которое упрощает выявление скрытых корреляций и построение цепочек разведки. Однако использование Maltego требует понимания механизмов трансформов, ограничений внешних API и необходимости верификации данных. В контексте тестирования на проникновение Maltego служит важным этапом подготовки, позволяя сформировать точную карту инфраструктуры цели и выявить потенциальные векторы атаки до начала активного сканирования. Интеграция с коммерческими и публичными источниками данных расширяет возможности инструмента, но также требует управления лицензиями и лимитами запросов.
