# Удалённое выполнение через SMB: механика, детекция и защита

## Контекст и базовые понятия

Горизонтальное перемещение (Lateral Movement) представляет собой тактику пост-эксплуатации, при которой злоумышленник, получив начальный доступ к одной из систем сети, использует скомпрометированные учётные данные или уязвимости для распространения на другие узлы. В контексте тестирования на проникновение и защиты корпоративных инфраструктур Windows, протокол Server Message Block (SMB) является основным вектором для этой цели. SMB — это сетевой протокол прикладного уровня, предназначенный для предоставления общего доступа к файлам, принтерам и последовательным портам между узлами. Однако его архитектурная особенность — возможность выполнения удалённых процедур (RPC) и доступа к административным ресурсам — делает его идеальным инструментом для создания «червей» и скрытного перемещения.

Ключевая проблема детектирования горизонтального перемещения через SMB заключается в том, что легитимное администрирование и атака выглядят идентично с точки зрения сетевого трафика и базовых событий операционной системы. Администраторы регулярно используют административные шары (`C$`, `ADMIN$`) для установки обновлений, копирования конфигурационных файлов и запуска скриптов. Злоумышленник, обладающий валидными учётными данными (или их хешами), имитирует это поведение, используя те же механизмы.

Для понимания предмета необходимо разграничить смежные понятия, которые часто путаются в литературе и инструментарии.

**Разграничение понятий: SMB, SMBExec, PsExec и WMIExec**

| Понятие | Уровень реализации | Механизм действия | Индикаторы присутствия | Легитимность использования |
| :--- | :--- | :--- | :--- | :--- |
| **SMB (Protocol)** | Сетевой уровень (L7) | Протокол обмена файлами и IPC. Используется для передачи данных между клиентами и серверами. | Порты TCP 445/139, заголовки SMB2/SMB3. | Высокая (основа файлового обмена в Windows). |
| **Windows Admin Shares** | Файловая система | Встроенные скрытые шары (`C$`, `ADMIN$`, `IPC$`), создаваемые ОС автоматически для администрирования. | События Event ID 5140/5145, доступ к путям `\\host\C$`. | Высокая (требуется для удалённого администрирования). |
| **PsExec** | Приложение (Tool) | Утилита из набора Sysinternals. Копирует исполняемый файл (`PSEXESVC.EXE`) в `ADMIN$`, регистрирует службу через SCM, запускает её. | Событие создания службы (Event ID 7045), процесс `PSEXESVC.EXE`, именованные каналы. | Средняя (легитимный инструмент, часто блокируется EDR). |
| **SMBExec (SMBShell)** | Метод/Скрипт (Impacket) | Не использует службу SCM. Копирует временный BAT-файл в `ADMIN$`, запускает его через `atexec` или RPC, удаляет после выполнения. | Временные файлы в `ADMIN$`, отсутствие создания службы, события 4688 с `cmd.exe`. | Низкая (инструмент атаки, не является частью ОС). |
| **WMI (Win32_Process)** | API ОС | Использование Windows Management Instrumentation для создания процессов на удалённом хосте без передачи файлов. | Процесс `wmiprvse.exe`, события WMI, отсутствие файлов на диске. | Высокая (используется скриптами и мониторингом). |

**Почему SMB эффективен для атакующих?**
1.  **Отсутствие необходимости в эксплойтах:** При наличии валидных учётных данных (или хешей NTLM) не требуется эксплуатация уязвимостей (в отличие от CVE-2020-0796/SMBGhost).
2.  **Living-off-the-Land:** Использование встроенных механизмов Windows (SCM, RPC, SMB) позволяет избежать детектирования антивирусами, ориентированными на сигнатуры вредоносного ПО.
3.  **Широкая доступность:** SMB включён по умолчанию во всех версиях Windows Server и Client, порты 445/135 открыты для внутреннего трафика.
4.  **Привилегии:** Доступ к `ADMIN$` требует прав локального администратора, что часто совпадает с требованиями для выполнения системных задач.

**Разграничение с другими векторами:**
В отличие от RDP (T1021.001), который требует графического интерфейса и оставляет следы в виде сессий входа, SMB-перемещение работает на уровне процессов и служб, оставаясь «невидимым» для пользователя. В отличие от WinRM (T1021.006), который использует HTTP/HTTPS и требует настройки службы, SMB опирается на устоявшуюся инфраструктуру файлового обмена, что делает его менее заметным в настройках сети.

## Внутреннее устройство предмета

Для понимания механики горизонтального перемещения через SMB необходимо рассмотреть три ключевых компонента: архитектуру административных шаров Windows, механизм взаимодействия PsExec (как наиболее репрезентативного примера) и протокольные взаимодействия RPC/SMB.

### Архитектура Windows Admin Shares

Windows автоматически создаёт скрытые административные шары при запуске службы Server. Эти шары не отображаются в сетевом окружении и доступны только при явном указании пути.

*   **`ADMIN$`**: Скрытый шар, указывающий на каталог установки Windows (обычно `C:\Windows`). Используется для копирования исполняемых файлов и конфигурационных данных.
*   **`C$`** (или другой диск): Скрытый шар, указывающий на корень диска. Позволяет полный доступ к файловой системе.
*   **`IPC$`**: Специальный шар, используемый для межпроцессного взаимодействия (Inter-Process Communication) и аутентификации. Не содержит файлов, но необходим для установления сессии RPC.

Доступ к этим шарам контролируется политикой безопасности Windows. По умолчанию только члены группы «Administrators» имеют полный доступ. В доменной среде это часто означает, что любой доменный администратор может получить доступ к `ADMIN$` любой машины в домене, если знает локальный пароль администратора (или если пароли синхронизированы/используется один и тот же локальный админ).

### Механизм работы PsExec через SMB

PsExec демонстрирует классический паттерн горизонтального перемещения. Процесс можно разделить на фазы:

1.  **Аутентификация и подключение:** Клиент устанавливает соединение с `IPC$` на целевом хосте, используя предоставленные учётные данные (NTLM/Kerberos).
2.  **Загрузка полезной нагрузки:** Клиент копирует исполняемый файл `PSEXESVC.EXE` в директорию `ADMIN$` на целевой машине.
3.  **Регистрация службы:** Через RPC (порт 135) клиент обращается к Service Control Manager (SCM) целевой машины и создаёт новую службу (обычно с именем `PSEXESVC` или случайным). В качестве пути к исполняемому файлу указывается `C:\Windows\PSEXESVC.EXE`.
4.  **Запуск службы:** SCM запускает службу, которая начинает прослушивать именованный канал (Named Pipe) на целевой машине.
5.  **Установка сессии:** Клиент подключается к именованному каналу на целевой машине. Через этот канал передаются команды, их вывод и файлы.
6.  **Завершение:** После выполнения команд служба удаляется, а файл `PSEXESVC.EXE` может быть удалён (в зависимости от настроек).

### Протокольные взаимодействия и события

Взаимодействие PsExec опирается на два основных протокола:
*   **SMB (TCP 445):** Отвечает за передачу файлов (копирование `PSEXESVC.EXE`) и доступ к шарам.
*   **RPC (TCP 135 + динамические порты):** Отвечает за управление службами (SCM) и создание именованных каналов.

С точки зрения операционной системы, легитимная административная сессия через PsExec оставляет специфичный набор событий журнала безопасности Windows.

| Событие (Event ID) | Источник | Описание | Значение для детекции |
| :--- | :--- | :--- | :--- |
| **4624** | Security | Успешный вход в систему. | Тип входа (Logon Type) 3 (Network) указывает на сетевой доступ. |
| **4672** | Security | Назначение специальных привилегий. | Подтверждает, что вход выполнен от имени администратора. |
| **5140** | Security | Доступ к сетевому ресурсу. | Фиксирует факт подключения к шару (например, `ADMIN$`). |
| **5145** | Security | Детальный доступ к сетевому ресурсу. | Показывает, какие файлы были открыты в шаре (важно для анализа действий). |
| **7045** | Service Control Manager | Создание новой службы. | **Критический индикатор:** появление службы с путём к `ADMIN$` или временным файлом. |
| **4688** | Security | Создание процесса. | Запуск `cmd.exe`, `powershell.exe` или `PSEXESVC.EXE` с указанием родительского процесса. |

**Иллюстративная схема потока данных PsExec:**

```text
[Атакующий/Клиент]                          [Целевой хост (Server)]
       |                                          |
       |--- (1) SMB Connect to IPC$ ------------->|
       |    (Auth: NTLM/Kerberos)                 |
       |<-- (2) Session Established --------------|
       |                                          |
       |--- (3) SMB Write ADMIN$/PSEXESVC.EXE --->|
       |    (Copy binary)                         |
       |                                          |
       |--- (4) RPC Call to SCM ----------------->|
       |    (Create Service: PSEXESVC)            |
       |<-- (5) Service Created ------------------|
       |                                          |
       |--- (6) SCM Start Service --------------->|
       |                                          |
       |<-- (7) PSEXESVC listens on Named Pipe --|
       |                                          |
       |--- (8) Connect to Named Pipe ----------->|
       |    (Execute Commands)                    |
       |<-- (9) Command Output -------------------|
       |                                          |
       |--- (10) Delete Service ----------------->|
       |                                          |
       |--- (11) Delete PSEXESVC.EXE ------------>|
       |                                          |
```

**Альтернативные методы на базе SMB:**
Помимо PsExec, существуют методы, не оставляющие следов в SCM:
*   **SMBExec (Impacket):** Копирует временный BAT-файл в `ADMIN$`, запускает его через `atexec` (планировщик заданий) или RPC, удаляет файл. Не создаёт службу.
*   **Winexe:** Аналог PsExec, но использует протокол RPC напрямую без создания службы, копируя исполняемый файл в `ADMIN$`.

## Применение и работа с предметом

На практике работа с горизонтальным перемещением через SMB делится на две парадигмы: offensive (тестирование на проникновение) и defensive (детекция и защита).

### Offensive: Инструментарий и паттерны

В рамках тестирования на проникновение специалисты используют инструменты для эмуляции атакующих. Выбор инструмента зависит от наличия учётных данных (пароли, хеши, токены) и желаемой «тишины» (stealth).

**1. Impacket Suite (Python)**
Набор скриптов для работы с протоколами Microsoft.
*   `psexec.py`: Эмуляция классического PsExec. Требует пароля или хеша.
*   `smbexec.py`: Метод без создания службы (fileless-ish). Копирует BAT-файл.
*   `wmiexec.py`: Использование WMI для выполнения команд. Не копирует файлы, но требует прав администратора.

**2. CrackMapExec (CME)**
Фреймворк для автоматизации аудита сетей. Позволяет быстро перебирать учётные данные на множестве хостов.
*   Команда: `cme smb <target_ip> -u <user> -p <password> -x "whoami"`
*   Функция: Автоматизирует попытку подключения к `ADMIN$` и выполнение команды.

**3. Metasploit Framework**
Модуль `exploit/windows/smb/psexec`.
*   Используется для автоматизации атаки, включая загрузку полезной нагрузки (payload) и создание обратной связи (reverse shell).

**Типичные ошибки при использовании:**
*   **Игнорирование антивируса:** Загрузка `PSEXESVC.EXE` в `ADMIN$` часто блокируется EDR-системами, так как это известная техника.
*   **Ошибки аутентификации:** Использование неверного формата хешей (NTLM vs LM) или отсутствие доверенных отношений между доменами.
*   **Блокировка портов:** Если порт 135 (RPC) закрыт фаерволом, PsExec не сработает, даже если SMB (445) открыт.

### Defensive: Детекция и защита

Защита от горизонтального перемещения через SMB строится на трёх уровнях: сетевом, системном и поведенческом.

**1. Сетевой уровень**
*   **Микросегментация:** Ограничение доступа к порту 445 только между необходимыми узлами (например, только от серверов управления к рабочим станциям).
*   **Блокировка внешних IP:** Запрет входящих SMB-соединений из интернета.
*   **Отключение SMBv1:** Уязвимый протокол, используемый в атаках типа WannaCry.

**2. Системный уровень**
*   **Ограничение административных шаров:** Через групповые политики (GPO) можно отключить автоматическое создание `ADMIN$` или ограничить доступ к ним.
*   **Усиление локальных паролей:** Использование уникальных сложных паролей для локального администратора на каждой машине (LAPS — Local Administrator Password Solution).
*   **Отключение SMB2/SMB3 compression:** Мера против уязвимости SMBGhost (CVE-2020-0796).

**3. Поведенческий уровень (EDR/SIEM)**
*   **Мониторинг создания служб:** Детектирование создания служб с путями в `ADMIN$` или временных каталогах.
*   **Анализ процессов:** Выявление подозрительных дочерних процессов от `svchost.exe`, `wmiprvse.exe` или `PSEXESVC.EXE`.
*   **Анализ логов:** Корреляция событий 4624 (вход), 5140/5145 (доступ к шарам) и 7045 (создание службы).

**Пример правила детекции (Sigma-формат) для PsExec:**

```yaml
title: Suspicious PsExec Service Creation
id: 12345678-1234-1234-1234-123456789012
status: experimental
logsource:
  category: service_creation
  product: windows
detection:
  selection:
    Image|endswith: '\PSEXESVC.EXE'
  condition: selection
falsepositives:
  - Legitimate administration (if PsExec is approved)
level: high
```

## Сквозной практический пример: Имитация атаки и детекция

**Исходные условия:**
*   **Среда:** Домашний лабораторный стенд с двумя виртуальными машинами Windows 10.
    *   `Attacker`: IP `192.168.56.101`, установлен Python 3.9, библиотека `impacket`.
    *   `Target`: IP `192.168.56.102`, локальный администратор `admin` с паролем `P@ssw0rd123`.
*   **Роль:** Тестировщик на проникновение (Red Teamer).
*   **Цель:** Выполнить произвольную команду на целевой машине, используя технику SMBExec (имитация атаки без создания службы).

**Шаг 1: Проверка доступности SMB и аутентификации**
Перед запуском полезной нагрузки необходимо убедиться, что целевой хост доступен по SMB и учётные данные валидны.

```bash
# Использование smbclient для проверки доступа к ADMIN$
smbclient //192.168.56.102/ADMIN$ -U admin%P@ssw0rd123 -c "ls"
```

*Ожидаемый вывод:*
```text
Try "help" to get a better shell prompt.
smb: \> ls
  .                                   D        0  Wed Oct 25 10:00:00 2023
  ..                                  D        0  Wed Oct 25 10:00:00 2023
  ...
18681503 blocks of size 4096. 10000000 blocks available
```
*Результат:* Доступ к `ADMIN$` получен. Аутентификация успешна.

**Шаг 2: Выполнение команды через smbexec**
Используем скрипт `smbexec.py` из пакета Impacket. Этот метод копирует временный BAT-файл в `ADMIN$`, запускает его и удаляет, не создавая службу.

```bash
# Запуск команды whoami через smbexec
python3 smbexec.py admin:P@ssw0rd123@192.168.56.102
```

*Ожидаемый вывод (фрагмент):*
```text
Impacket v0.10.0 - Copyright 2022 SecureAuth Corporation

[*] Getting terminal (SMB) session to ADMIN$ of 192.168.56.102
[*] Uploading file 4KgFqQwQ.bat
[*] Getting output of command...
[*] Deleting file 4KgFqQwQ.bat

C:\Users\admin>whoami
nt authority\system
[*] Smbsession.py exiting...
```
*Результат:* Команда выполнена от имени `SYSTEM`. Файл был удалён, что усложняет форензику.

**Шаг 3: Анализ логов на целевой машине (Target)**
Для детекции атаки необходимо проанализировать журнал безопасности Windows на `192.168.56.102`.

```powershell
# PowerShell команда для поиска событий создания службы (если бы использовался PsExec)
Get-WinEvent -FilterHashtable @{LogName='Security'; ID=7045} | Select-Object -First 5 | Format-List *
```

*Ожидаемый вывод (если бы использовался PsExec):*
```text
Message        : A service was created on the system.
               : Service Name: PSEXESVC
               : Service File Name: C:\Windows\PSEXESVC.EXE
               : Service Type: user_mode_service
               : Service Start Type: auto_start
               : Service Account: LocalSystem
```

*Ожидаемый вывод (для smbexec):*
Событие 7045 **отсутствует**. Вместо этого будут события:
1.  **Event ID 5145:** Доступ к `ADMIN$` с IP `192.168.56.101`.
2.  **Event ID 4688:** Создание процесса `cmd.exe` с временным файлом BAT.
3.  **Event ID 4656/4663:** Открытие/удаление временного файла в `ADMIN$`.

**Ожидаемый вывод примера:**
Пример демонстрирует, что техника SMBExec оставляет менее заметные следы в SCM, чем PsExec, но оставляет чёткие следы в журналах доступа к файлам (5145) и создания процессов. Для детекции SMBExec необходимо коррелировать события доступа к `ADMIN$` с созданием временных BAT-файлов и последующим выполнением `cmd.exe`.

## Аналитический вывод

Горизонтальное перемещение через SMB остаётся одним из наиболее критичных векторов атак в инфраструктурах Windows благодаря своей эффективности и способности маскироваться под легитимное администрирование. Ключевая сложность защиты заключается в том, что базовые механизмы SMB и административные шары являются неотъемлемой частью функциональности Windows, и их полное отключение нарушает работу многих бизнес-процессов.

Эффективная защита требует многоуровневого подхода. На сетевом уровне необходима микросегментация для ограничения east-west трафика. На системном уровне критически важно внедрение LAPS для уникализации локальных паролей администратора, что делает невозможным использование украденных хешей для массового распространения. На уровне детекции необходимо сместить фокус с поиска сигнатур вредоносного ПО на поведенческий анализ: мониторинг создания служб в `ADMIN$`, аномального доступа к именованным каналам и корреляцию событий входа (4624) с доступом к ресурсам (5145).

Для специалистов по тестированию на проникновение понимание различий между PsExec, SMBExec и WMIExec позволяет выбирать оптимальный метод обхода защитных механизмов в рамках этического аудита. Однако в реальных условиях эксплуатации эти техники активно блокируются современными EDR-системами, которые анализируют не только факт выполнения, но и контекст (источник, время, частоту вызовов). Таким образом, будущее защиты от SMB-перемещения лежит в области Zero Trust архитектуры, где доверие не предоставляется автоматически на основе сетевого положения, а проверяется для каждого запроса.
