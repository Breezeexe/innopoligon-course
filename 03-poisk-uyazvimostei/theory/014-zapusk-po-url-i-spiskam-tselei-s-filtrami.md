# Запуск Nuclei по URL и спискам целей с фильтрами: архитектура, синтаксис и оптимизация

## Контекст и базовые понятия

Nuclei (разрабатывается командой ProjectDiscovery) представляет собой сканер уязвимостей на основе шаблонов, использующий YAML-формат для определения логики проверки. В отличие от классических сканеров, которые полагаются на фиксированные базы сигнатур или эвристические алгоритмы, Nuclei делегирует логику детектирования внешним шаблонам. Это обеспечивает мгновенное покрытие новых уязвимостей (CVE) сразу после публикации шаблона в репозитории `projectdiscovery/nuclei-templates`.

Ключевое понятие в контексте запуска по URL и спискам — **Target Input**. Nuclei поддерживает множество форматов входных данных: одиночный URL, файл со списком URL (по одному на строку), CIDR-диапазоны, ASN, IP-адреса, а также экспорты из Burp Suite, OpenAPI/Swagger спецификаций. Выбор формата ввода определяет режим парсинга и стратегию маршрутизации запросов.

Разграничение между **URL** и **Host/IP** критически важно для понимания поведения сканера.
*   **URL (`-u`)**: Требует полного URI (scheme + host + port + path). Nuclei ожидает HTTP/HTTPS трафик. Если схема не указана, по умолчанию используется `http`.
*   **Host/IP (`-l` с файлом)**: Если в файле указаны только домены или IP, Nuclei автоматически выполняет DNS-разрешение и пытается установить соединение на стандартные порты (80, 443, 8080 и др.), либо требует указания порта явно (например, `example.com:8080`).

Путаница часто возникает между понятиями **Template** и **Workflow**.
*   **Template**: Атомарная единица проверки (один запрос/ответ или набор запросов для одной уязвимости).
*   **Workflow**: Набор шаблонов, объединенных в YAML-файл для выполнения многошаговых сценариев (например, обнаружение технологии -> проверка версии -> запуск эксплойта).

Для автоматизации массового сканирования (Mass Scanning) используется концепция **Template Clustering**. Nuclei группирует шаблоны, отправляющие идентичные запросы (одинаковый метод, путь, заголовки), в один сетевой вызов. Результаты одного HTTP-ответа затем распределяются между всеми кластеризованными шаблонами для проверки условий (matchers). Это фундаментально отличает Nuclei от последовательных сканеров и объясняет его высокую производительность.

| Характеристика | Запуск по одиночному URL (`-u`) | Запуск по списку целей (`-l`) |
| :--- | :--- | :--- |
| **Входной формат** | Строка URI (`https://target.com/path`) | Файл (TXT, JSONL, Burp XML, OpenAPI) |
| **Обработка DNS** | Выполняется один раз перед сканированием | Выполняется для каждой записи в списке |
| **Параллелизм** | Высокий (по шаблонам и поддоменам) | Высокий (по целям и шаблонам) |
| **Основной риск** | DoS целевого сервера | DoS инфраструктуры сканера (RAM/CPU) |
| **Типичное применение** | Ручной аудит, детальный анализ | Массовый скан, CI/CD пайплайны, Bug Bounty |
| **Фильтрация** | По тегам, severity, автору | По тегам, severity, автору + входному формату |

## Внутреннее устройство предмета: Архитектура ввода и фильтрации

Архитектура обработки ввода в Nuclei состоит из трех основных слоев: **Input Parser**, **Template Engine** и **Execution Engine**.

### 1. Input Parser и форматы данных
При указании `-l` Nuclei не просто читает файл построчно. Он анализирует расширение и содержимое файла для определения режима (`-im`, `--input-mode`).
*   **list** (default): Каждая строка парсится как URL или хост. Поддерживается авто-добавление `https://` если схема отсутствует.
*   **burp**: Парсит XML-экспорт Burp Suite. Извлекает URL, заголовки, cookies и параметры из истории запросов. Позволяет сканировать уже известные эндпоинты с контекстом аутентификации.
*   **jsonl**: Ожидает JSON Lines формат. Каждый объект может содержать поля `url`, `host`, `ip`, `port`, `headers`. Это стандарт для интеграции с другими инструментами ProjectDiscovery (например, `httpx`, `subfinder`).
*   **openapi/swagger**: Парсит спецификацию API. Генерирует целевые URL на основе путей (`paths`) и методов (`GET`, `POST`), автоматически подставляя параметры из спецификации.

### 2. Система фильтрации шаблонов
По умолчанию Nuclei загружает все шаблоны из директории `~/nuclei-templates/`. Однако запуск всех ~8000+ шаблонов против одной цели неэффективен. Система фильтрации работает на этапе инициализации шаблонов.

Фильтры применяются к метаданным шаблона (YAML front-matter):
*   **Tags (`-tags`)**: Группировка по типу уязвимости (`cve`, `misconfig`, `exposure`, `tech-detect`) или технологии (`php`, `wordpress`, `nginx`).
*   **Severity (`-severity`)**: Фильтрация по уровню критичности (`info`, `low`, `medium`, `high`, `critical`).
*   **Author (`-author`)**: Фильтрация по автору шаблона (полезно для доверенных источников или тестирования новых шаблонов).
*   **Exclusions**: Использование файла `.nuclei-ignore` или флага `-exclude` для исключения конкретных шаблонов или тегов.

### 3. Template Clustering и Execution Strategy
Движок Nuclei анализирует все загруженные шаблоны и группирует их по **HTTP Signature** (метод, URL, заголовки, тело запроса).
*   Если 100 шаблонов требуют `GET /login.php`, Nuclei отправляет **один** запрос.
*   Ответ парсится один раз.
*   100 шаблонов проверяют ответ независимо.

Стратегия сканирования (`-ss`) определяет порядок обхода:
*   **host-spray**: Для каждой цели запускаются все шаблоны. (Рекомендуется для глубокого аудита одной цели).
*   **template-spray**: Для каждого шаблона сканируются все цели. (Рекомендуется для массового сканирования, лучше для кэширования DNS и соединений).
*   **auto**: Автоматический выбор на основе количества целей и шаблонов.

| Параметр фильтрации | Синтаксис | Пример использования | Эффект |
| :--- | :--- | :--- | :--- |
| **Тег** | `-tags <tag>` | `-tags cve,2024` | Запуск только шаблонов с тегом `cve` или `2024` |
| **Критичность** | `-severity <sev>` | `-severity high,critical` | Игнорирование `info`, `low`, `medium` |
| **Автор** | `-author <name>` | `-author projectdiscovery` | Запуск только шаблонов от PD |
| **Исключение** | `-exclude <tag>` | `-exclude fuzzing` | Отключение всех шаблонов с тегом `fuzzing` |
| **Входной режим** | `-im <mode>` | `-im burp` | Парсинг Burp XML вместо списка URL |

## Применение и работа с предметом: Команды, опции и оптимизация

Практическая работа с Nuclei требует понимания баланса между скоростью, нагрузкой на сеть и полнотой покрытия.

### 1. Базовые сценарии запуска

**Запуск по одиночному URL:**
```bash
nuclei -u https://example.com -t cves/ -t exposures/
```
Здесь явно указаны директории шаблонов. Если директории не указаны, запускаются все HTTP-шаблоны.

**Запуск по списку целей (TXT):**
```bash
nuclei -l targets.txt -o results.json -j
```
Флаг `-j` включает JSON-вывод, что критично для парсинга результатов скриптами.

**Запуск по списку целей с Burp экспортом:**
```bash
nuclei -l burp_export.xml -im burp -t technologies/tech-detect.yaml
```
Этот сценарий часто используется для обнаружения технологий на уже найденных эндпоинтах.

### 2. Оптимизация производительности (Concurrency и Rate Limiting)

Для массового сканирования (тысячи целей) стандартные значения параллелизма могут исчерпать ресурсы или быть заблокированы WAF.

*   `-c, --concurrency`: Количество активных шаблонов, запускаемых одновременно. По умолчанию зависит от CPU.
*   `-bs, --bulk-size`: Количество целей, обрабатываемых параллельно для одного шаблона.
*   `-rl, --rate-limit`: Лимит запросов в секунду (RPS). **Критически важен** для избежания банов.
*   `-timeout`: Таймаут ответа (по умолчанию 10с).

**Пример оптимизированной команды для 1000 целей:**
```bash
nuclei -l targets.txt -c 50 -bs 50 -rl 100 -timeout 15 -ss host-spray -o output.jsonl
```

### 3. Фильтрация и автоматический выбор

**Автоматический выбор шаблонов (`-as`):**
Nuclei анализирует ответы сервера (заголовки, мета-теги) и включает только релевантные шаблоны.
```bash
nuclei -u https://example.com -as
```
Это значительно сокращает время сканирования, но может пропустить уязвимости, не связанные с обнаруженной технологией.

**Использование только новых шаблонов (`-nt`):**
```bash
nuclei -u https://example.com -nt
```
Полезно для быстрого поиска свежих CVE сразу после публикации.

### 4. Интеграция в пайплайн (CI/CD)

В CI/CD пайплайнах (GitHub Actions, GitLab CI) часто используется комбинация `httpx` и `nuclei`:
```bash
cat targets.txt | httpx -silent | nuclei -t cves/ -severity critical -json -o vulns.json
```
Здесь `httpx` фильтрует только живые HTTP-сервисы, экономя время Nuclei на недоступных хостах.

## Сквозной практический пример: Аудит поддоменов с фильтрацией по критичности

**Исходные условия:**
*   **Среда:** Kali Linux с установленным `nuclei` (v3.x) и `httpx`.
*   **Роль:** Пентестер, проводящий аудит безопасности программы Bug Bounty.
*   **Цель:** Домен `target.com`.
*   **Инструменты:** `subfinder` (поиск поддоменов), `httpx` (проверка живости), `nuclei` (сканирование).
*   **Задача:** Найти только критические и высокие уязвимости в живых поддоменах, исключив шаблоны фаззинга и информационные проверки.

**Шаг 1: Сбор и фильтрация живых целей**
Сначала получаем список поддоменов и фильтруем только те, которые отвечают на HTTP/HTTPS запросы. Результат записывается в файл `live_targets.txt`.

```bash
subfinder -d target.com -silent | httpx -silent -o live_targets.txt
```
*Ожидаемый результат:* Файл `live_targets.txt` содержит ~500 URL (например, `https://api.target.com`, `https://dev.target.com`), отфильтрованных от неработающих доменов.

**Шаг 2: Запуск сканирования с фильтрами**
Запускаем Nuclei против списка живых целей. Применяем строгие фильтры: только `critical` и `high` severity, исключаем теги `fuzzing` и `info`, используем стратегию `host-spray` для полноты.

```bash
nuclei -l live_targets.txt \
       -severity critical,high \
       -tags fuzzing,info \
       -exclude fuzzing \
       -c 100 \
       -bs 100 \
       -rl 150 \
       -ss host-spray \
       -json \
       -o results_critical.json
```

*Разбор флагов:*
*   `-severity critical,high`: Игнорируем `medium`, `low`, `info`.
*   `-tags fuzzing,info`: **Внимание:** В Nuclei фильтр `-tags` работает как `AND` или `OR` в зависимости от версии, но обычно для исключения используется `-exclude`. Правильнее использовать `-exclude fuzzing` и `-severity critical,high`. Если нужно оставить только определенные теги, используется `-tags cve,misconfig`. В данном примере мы исключаем шум.
*   `-rl 150`: Ограничиваем нагрузку, чтобы не получить бан от WAF.
*   `-json`: Вывод в структурированном формате для дальнейшей обработки.

**Шаг 3: Анализ результатов**
Проверяем файл `results_critical.json` на наличие ложных срабатываний и подтверждаем уязвимости.

```bash
cat results_critical.json | jq -r '. | select(. | has("matched-at")) | .matched-at' | sort -u
```
*Ожидаемый результат:* Список уникальных URL, где были найдены критические уязвимости. Например:
```json
{
  "id": "cve-2024-1234",
  "matched-at": "https://api.target.com/v1/exploit",
  "info": {
    "name": "CVE-2024-1234",
    "severity": "critical",
    "description": "Remote Code Execution in API endpoint"
  }
}
```

**Ожидаемый вывод:**
Пример демонстрирует, как комбинация `-l` (список целей), `-severity` (фильтр по критичности) и `-rl` (контроль нагрузки) позволяет эффективно масштабировать сканирование, фокусируясь на значимых угрозах и избегая блокировок.

## Аналитический вывод

Запуск Nuclei по URL и спискам целей с фильтрами представляет собой не просто выполнение команды, а настройку сложной системы балансировки между полнотой покрытия и ресурсными ограничениями. Ключевым отличием Nuclei от традиционных сканеров является его шаблонная архитектура и механизм кластеризации запросов, что позволяет обрабатывать тысячи целей с минимальным сетевым оверхедом.

При работе со списками целей критически важно предварительное очищение входных данных (например, через `httpx`), так как сканирование неработающих хостов генерирует ложные таймауты и засоряет логи. Фильтрация по тегам и severity должна применяться на этапе инициализации шаблонов, а не после сканирования, чтобы сэкономить CPU. Для массового сканирования обязательным является использование `-rl` (rate-limit) и `-ss` (scan strategy), иначе сканер либо исчерпает оперативную память, либо будет заблокирован сетевыми средствами защиты. Интеграция Nuclei в пайплайны требует использования JSONL-вывода для последующей автоматической обработки результатов.
