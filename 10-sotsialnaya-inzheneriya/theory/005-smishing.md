# Smishing

## Феномен смишинга: место среди социальной инженерии

Смишинг (smishing) — вектор атаки социальной инженерии, реализуемый через службу коротких сообщений (SMS) или мессенджеры с целью обмана получателя и получения конфиденциальной информации (учётных данных, платёжных реквизитов) либо инициации вредоносной активности. Термин образован слиянием «SMS» и «phishing». В отличие от почтового фишинга смишинг эксплуатирует высокий уровень доверия к мобильным текстовым каналам: согласно отраслевым данным, открываемость SMS-сообщений достигает 98 % против 10–20 % у электронной почты [Guardiandigital.com](https://guardiandigital.com/content/how-to-prevent-smishing).

Популярность смишинга среди злоумышленников растёт по нескольким причинам:
- Простота массовой рассылки через SMS-шлюзы, арендованные виртуальные номера или ботнеты. Автоматизированные инструменты позволяют генерировать сообщения по диапазонам телефонных номеров, типичным для конкретного региона (например, в США — формат 3-4-3).
- Мобильные номера широко утекают из маркетинговых баз, социальных сетей и даркнет-маркетов, предоставляя злоумышленникам готовые списки для целевых атак.
- Сжатый объём SMS (до 160 символов) вынуждает сокращать текст до «призыв — ссылка», что психологически снижает критичность восприятия: пользователь не ищет признаков подделки в двух строчках.
- В отличие от электронных писем, мобильные сообщения реже проходят контентную фильтрацию на стороне оператора, хотя на корпоративных устройствах политика MDM (Mobile Device Management) может частично закрыть этот канал.

Смишинг часто путают с другими формами фишинга. Ниже представлена сравнительная таблица, фиксирующая ключевые разграничения.

| Вектор атаки | Коммуникационный канал | Типичное содержание | Психологический триггер | Пример (схематичный) |
|--------------|------------------------|---------------------|-------------------------|-----------------------|
| **Smishing** (SMS phishing) | SMS, RCS, iMessage, мессенджеры | Короткое сообщение с URL, номером телефона для обратного звонка или кодом подтверждения | Срочность, угроза блокировки услуги, страх пропустить доставку/выигрыш | «Ваш пакет задерживается. Уточните адрес: http://bit.ly/…» |
| **Phishing** (email-based) | Электронная почта | HTML-письмо с логотипами, встроенными формами или вложениями | Авторитет организации, финансовая выгода, страх потери доступа | Письмо от «службы безопасности банка» с просьбой подтвердить учётную запись |
| **Vishing** (voice phishing) | Голосовой вызов (GSM, VoIP) | Сценарий разговора, часто с IVR, подменой номера, синтезом речи | Прямое давление оператора, эффект авторитетного голоса, неожиданность | Звонок «из банка»: «С вашей карты совершается подозрительная операция, назовите CVV для отмены» |

Во всех трёх случаях злоумышленник эксплуатирует человеческий фактор, но инструментарий и механизмы доставки различаются, что требует разных контрмер. Для специалиста по безопасности важно понимать эту разницу, так как детектирование smishing-атаки на уровне сети или конечной точки строится на иных признаках, чем фильтрация почтового трафика.

Смишинг также пересекается с понятием «спам» — массовой нежелательной рассылки. Не каждое спам-SMS является смишингом, но любое смишинг-сообщение — вредоносный спам. Чёткую грань проводит наличие явного намерения получить доступ к информации или установить вредоносное ПО. Если сообщение просто рекламирует сомнительный сервис без сбора данных, его относят к спаму; если содержит ссылку на фишинговую страницу или просьбу переслать код из SMS — это смишинг [ESET](https://www.eset.com/ua-ru/support/information/entsiklopediya-ugroz/sotsialnaya-inzheneriya). Дополнительным отягчающим фактором выступает рост целевого (spear) смишинга: атакующий обладает именем, должностью или контекстом жертвы, что многократно повышает вероятность успеха.

Таким образом, смишинг — самостоятельная дисциплина в портфеле социальной инженерии, требующая понимания как психологических механизмов, так и технической реализации цепочки атаки.

## Архитектура атаки и разновидности смишинга

Любая смишинг-кампания реализуется в несколько последовательных фаз, которые объединяют технологии рассылки, социальную психологию и инфраструктуру фишингового сайта. Понимание этих фаз необходимо для реконструкции атаки и выработки контрмер.

```text
Фаза 1                Фаза 2                    Фаза 3                Фаза 4
Сбор номеров    →    Генерация претекста  →   Массовая рассылка →   Эксплуатация
(утечки, OSINT)      (шаблон + контекст)     (SMS-шлюз, SIM-ферма)  (переход по ссылке,
                                                                    ввод данных, загрузка APK)
```

**Фаза 1: сбор номеров.** Злоумышленник получает базы мобильных номеров через утечки данных (дампы из маркетплейсов даркнета), парсинг открытых профилей в соцсетях, либо сканирование диапазонов нумерации мобильных операторов. В целевых атаках (spear smishing) номер конкретного лица часто находят по утечкам с корпоративных порталов, на whitepages-сервисах или через перебор по привязанному к номеру аккаунту Telegram.

**Фаза 2: подготовка претекста.** Текст сообщения проектируется так, чтобы вызвать немедленное действие. Используются:
- **Императивные глаголы:** «подтвердите», «срочно обновите», «отмените».
- **Легитимный бренд:** подмена отправителя (алфавитно-цифровой идентификатор) или номер из доверенного диапазона.
- **Актуальная тема:** доставка посылок, налоговые уведомления в сезон деклараций, предупреждения безопасности от банков, фальшивые коды MFA.
- **Сокращённые ссылки** (bit.ly, tinyurl) или домены с опечатками (typosquatting), которые обходят беглый визуальный контроль.

**Фаза 3: массовая рассылка.** Рассылка выполняется через арендованные SMS-шлюзы (SMS gateways), ботнеты из заражённых устройств, либо SIM-фермы — банки модемов с SIM-картами, автоматически отправляющие сообщения. Для подмены номера отправителя атакующие эксплуатируют недостатки сигнального протокола SS7 или используют недобросовестных агрегаторов.

**Фаза 4: эксплуатация.** Жертва переходит по ссылке и попадает на фишинговую страницу, которая может имитировать страницу входа банка, форму ввода платёжных данных или скачивает вредоносный APK-файл. На этом этапе могут применяться методы обхода многофакторной аутентификации через перехват одноразовых кодов (OTP) с помощью одновременного социального воздействия (атакующий просит жертву продиктовать полученный код). В результате злоумышленник получает учётные данные, платёжную информацию или полный контроль над учётной записью.

### Классификация смишинг-атак

Ниже представлена таблица основных видов смишинг-атак, построенная на основе анализа инцидентов [Cynet](https://www.cynet.com/security-foundations/cybersecurity/5-types-of-smishing-attacks-and-5-ways-to-prevent-them) и дополненная примерами из реальной практики.

| Тип атаки | Ключевые признаки | Типичный индикатор | Контрмера |
|-----------|-------------------|-------------------|-----------|
| **Банковская тревога** | Текст от имени известного банка, упоминание «подозрительной операции», «блокировки карты», ссылка на «верификацию» | Домен, не совпадающий с официальным, использование URL-shortener, требование ввести CVV или PIN | Никогда не переходить по ссылкам из SMS; звонить по номеру, напечатанному на карте, а не указанному в сообщении |
| **Проблема с доставкой** | Информация якобы от служб доставки (DHL, FedEx, Почта России) о задержке или необходимости уточнить адрес; ссылка ведёт на поддельный трекинг | Короткая ссылка, ошибки в названии перевозчика, сообщение получено без активного заказа | Проверять статус заказа через официальное приложение или сайт, входя в аккаунт вручную |
| **MFA-бомбинг / верификация** | Сообщение, запрашивающее код подтверждения, который был запрошен злоумышленником; может сопровождаться звонком с просьбой назвать код | Поступление кода без инициированного входа пользователем; позже сообщение с просьбой «продиктовать код для отмены заявки» | Никогда не передавать коды третьим лицам; немедленно сменить пароль при подозрении на компрометацию |
| **Выигрыш / акция** | Уведомление о выигрыше в лотерею или эксклюзивном предложении, требующее перехода по ссылке и ввода персональных данных | Ссылка на несуществующий или недавно зарегистрированный домен; отсутствие информации об акции на официальном сайте организатора | Проверять информацию через официальные каналы; помнить, что бесплатный сыр бывает только в мышеловке |
| **Компрометация аккаунта** | Сообщение от имени соцсети или почтового сервиса о несанкционированном входе, предлагающее срочно «восстановить доступ» по ссылке | Домен с опечаткой (faceb00k.com), отсутствие HTTPS, обобщённое обращение вместо личного имени пользователя | Входить в учётную запись напрямую, набирая адрес в браузере, и проверять раздел безопасности |

Эти категории не изолированы — атакующие комбинируют элементы, например, банковская тревога с одновременным звонком (vishing) для усиления давления. В 2025 году отмечен рост использования генеративного ИИ для создания персонализированных претекстов на основе данных из социальных сетей жертвы [Gen 2025 Threat Report](https://www.gendigital.com/blog/insights/reports/threat-report-q3-2025). Такой spear smishing значительно сложнее детектировать только по текстовым сигнатурам.

## Применение и работа с угрозой смишинга в практике защиты

Специалист по кибербезопасности взаимодействует со smishing в трёх ролях: предотвращение атак на сотрудников, расследование инцидентов и тестирование устойчивости организации методом симулированного смишинга (в рамках согласованного пентеста). В каждом случае инструментарий и подходы различаются.

### Анализ подозрительных ссылок

Первый этап реагирования на сообщение о подозрительном SMS — безопасное извлечение и анализ URL. На корпоративных устройствах запрещается открывать ссылки напрямую — используется изолированная песочница или сервисы типа [urlscan.io](https://urlscan.io/), [VirusTotal](https://www.virustotal.com/). Рассмотрим пример исследования ссылки с помощью интерфейса командной строки, который позволяет сохранить доказательную базу и не полагаться на графический браузер.

Извлечённую ссылку (например, `hxxps://bit[.]ly/3XyzAbC`) необходимо сначала развернуть, чтобы увидеть финальный URL. Сокращённый URL часто скрывает фишинговый домен. Команда `curl` с опциями `-L` (следовать редиректам) и `-s` (без вывода прогресса) позволяет отследить цепочку перенаправлений:

```bash
curl -s -L -o /dev/null -w "Исходный URL: %{url_effective}\nКод ответа: %{http_code}\nРедиректы: %{num_redirects}\nФинальный URL: %{url}\n" "https://bit.ly/3XyzAbC"
```

Пример вывода (иллюстративная схема):

```
Исходный URL: https://bit.ly/3XyzAbC
Код ответа: 200
Редиректы: 2
Финальный URL: https://secure-banking-portal.tk/login.php
```

Данный вывод показывает, что после двух редиректов пользователь попадает на домен верхнего уровня `.tk`, часто используемый в фишинге из-за бесплатной регистрации. Далее следует провести анализ этого домена.

### Проверка репутации и инфраструктуры

С помощью API VirusTotal или его CLI-инструмента можно быстро получить отчёт о домене или IP-адресе. Допустим, установлен официальный клиент `vt`:

```bash
vt domain secure-banking-portal.tk
```

Вывод в формате JSON (схематичный):

```json
{
  "data": {
    "attributes": {
      "last_analysis_stats": {
        "malicious": 12,
        "suspicious": 3,
        "harmless": 38,
        "undetected": 23
      },
      "categories": {
        "Comodo Valkyrie": "phishing",
        "Forcepoint ThreatSeeker": "phishing"
      },
      "creation_date": 1735689600,
      "dns_records": [
        {"type": "A", "address": "192.0.2.10"}
      ]
    }
  }
}
```

Статистика `malicious: 12` при общем числе движков, детектирующих фишинг, убедительно свидетельствует о вредоносном назначении. Далее можно выгрузить список IP-адресов и сетевых связей для блокировки на межсетевом экране. В реальных SOC-процессах такой индикатор компрометации (IoC) немедленно добавляется в блок-листы прокси-серверов и почтовых шлюзов.

### Детектирование и предотвращение на уровне организации

Защита от смишинга строится на нескольких уровнях:
1. **Технический:** фильтрация SMS на корпоративных устройствах с помощью профилей MDM (например, блокировка сообщений с незнакомых номеров, отключение предпросмотра ссылок). На сетевом уровне — мониторинг DNS-запросов к подозрительным доменам и блокировка известных фишинговых URL через корпоративный прокси или DNS filtering (Cisco Umbrella, NextDNS и др.).
2. **Процедурный:** регламент сообщения о подозрительных сообщениях, обязательное направление скриншота в SOC.
3. **Образовательный:** регулярные тренинги, включающие симулированные смишинг-кампании. Сотрудники должны быть научены распознавать типовые сценарии и не реагировать на просьбы передать коды из SMS.

Пример правила для SIEM (Splunk), выявляющего попытки посещения фишингового домена после SMS-рассылки, может использовать корреляцию событий прокси и EDR:

```spl
index=proxy sourcetype=access_combined
| where uri_host IN ("secure-banking-portal.tk", "update-profile.info")
| table _time, user, src_ip, uri
| sendalert smishing_detected
```

Это правило (иллюстративная схема) инициирует алерт при обращении пользователя на заранее известный вредоносный домен. При интеграции с threat intelligence платформами список доменов может обновляться автоматически.

### Типичные ошибки при анализе и защите

- **Просмотр ссылок в основном браузере** без изоляции. Даже фишинговая страница может содержать эксплойты для браузера.
- **Слепая вера в VirusTotal:** если детектирование низкое, это может означать свежую кампанию, а не безопасность URL. Необходимо проводить дополнительный анализ.
- **Игнорирование мессенджеров:** современный смишинг всё чаще приходит через WhatsApp, Telegram, Viber — те же принципы, но сложнее блокировать централизованно.
- **Отсутствие процесса эскалации:** если сотрудник только удалил сообщение и не сообщил SOC, организация остаётся уязвимой, ведь на то же самое сообщение попадутся другие.

## Сквозной практический пример: расследование подозрительного SMS в учебной лаборатории

### Исходные условия

Студенческая лаборатория по кибербезопасности: виртуальная машина Kali Linux, изолированная от продуктивной сети. В рамках упражнения преподаватель рассылает этичное smishing-сообщение через сконфигурированный SMS-шлюз (симулятор). Сообщение получено на подконтрольный мобильный эмулятор. Роль студента — провести анализ сообщения и задокументировать индикаторы компрометации, не взаимодействуя с реальной вредоносной инфраструктурой (все ссылки указывают на локально развёрнутые песочницы).

Текст сообщения:
«Visa Secure. Для карты ****8432 зафиксирована подозрительная операция. Требуется верификация: https://tinyurl.com/secure-card-check».

### Шаг 1. Сохранение артефакта

Студент делает скриншот сообщения и извлекает текстовую информацию в структурированном виде. В реальном инциденте эта информация служит точкой отсчёта для журнала расследования.

```bash
echo "SMS received: 'Visa Secure. ... https://tinyurl.com/secure-card-check', sender +1234567890, timestamp: 2025-06-01T09:15:00Z" > ./evidence/sms_initial.txt
```

### Шаг 2. Разворачивание сокращённой ссылки

Используется утилита `curl` для отслеживания цепочки редиректов без выполнения JavaScript, который может быть на фишинговой странице:

```bash
curl -s -L -o /dev/null -w "URL: %{url_effective}\nHTTP Code: %{http_code}\nRedirects: %{num_redirects}\nTime: %{time_total}s\n" "https://tinyurl.com/secure-card-check" 2>/dev/null
```

Вывод:

```
URL: http://192.168.56.105/phishing/visa_verify.php
HTTP Code: 200
Redirects: 2
Time: 0.253s
```

Сокращённая ссылка ведёт на локальный IP — это тренировочная фишинговая страница, развёрнутая в лабораторной сети. В реальном расследовании таким образом выясняется финальный домен.

### Шаг 3. Анализ фишинговой страницы

С помощью `curl` извлекаются заголовки и содержимое, чтобы выявить сборщик данных. Осторожно: в реальном случае эту операцию выполняют в изолированной среде.

```bash
curl -s -I http://192.168.56.105/phishing/visa_verify.php
```

Вывод заголовков:

```
HTTP/1.1 200 OK
Date: Sat, 01 Jun 2025 09:16:00 GMT
Server: Apache/2.4.56 (Debian)
X-Powered-By: PHP/7.4.33
Set-Cookie: PHPSESSID=abcdef12345; path=/
Content-Type: text/html; charset=UTF-8
```

Скачивание тела страницы для анализа:

```bash
curl -s http://192.168.56.105/phishing/visa_verify.php | grep -E "(action=|input)" | head -n 5
```

Пример вывода:

```html
<form method="POST" action="save_credentials.php">
<input type="text" name="card_number" placeholder="Card number">
<input type="password" name="cvv" placeholder="CVV">
```

Обнаружена форма, пересылающая данные на `save_credentials.php`. Это подтверждает фишинговый характер ресурса.

### Шаг 4. Сбор данных DNS и WHOIS (эмулируется для локального домена)

Для настоящего домена студент выполнил бы:

```bash
whois secure-card-check.com
dig +short secure-card-check.com
```

В лаборатории можно показать эмуляцию на локальном DNS:

```bash
dig +short @192.168.56.1 secure-card-check.com
```

Результат:

```
192.168.56.105
```

### Шаг 5. Документирование IoC и блокировка

На основе анализа формируется список индикаторов компрометации:

```json
{
  "ioc": [
    {
      "type": "url",
      "value": "https://tinyurl.com/secure-card-check"
    },
    {
      "type": "domain",
      "value": "secure-card-check.com"
    },
    {
      "type": "ip",
      "value": "192.168.56.105"
    },
    {
      "type": "email_artifacts",
      "value": "save_credentials.php endpoint"
    }
  ]
}
```

Далее эти IoC могут быть добавлены в блок-листы корпоративных средств защиты. Шаги демонстрируют полный цикл реагирования на smishing-атаку, от получения первичного артефакта до формализации индикаторов для предотвращения последующих инцидентов.
