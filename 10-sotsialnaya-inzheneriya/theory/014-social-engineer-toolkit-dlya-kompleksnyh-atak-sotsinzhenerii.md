# Social-Engineer Toolkit (SET): Архитектура, векторы атак и применение в фишинговых кампаниях

## Контекст и базовые понятия

Социальная инженерия (Social Engineering, SE) представляет собой совокупность тактик, направленных на манипулирование людьми с целью получения конфиденциальной информации, доступа к системам или выполнения действий, нарушающих политику безопасности. В отличие от технических уязвимостей (CVE), социальная инженерия эксплуатирует человеческий фактор: доверие, страх, любопытство или чувство срочности. Согласно отчету Verizon Data Breach Investigations Report (DBIR) за 2023 год, человеческий фактор остается ключевым элементом в подавляющем большинстве инцидентов, связанных с компрометацией учетных данных.

**Social-Engineer Toolkit (SET)** — это фреймворк с открытым исходным кодом, разработанный компанией TrustedSec (основатель David Kennedy) для автоматизации атак социальной инженерии. SET не является самостоятельным эксплойтом; это оркестратор, который объединяет другие инструменты (такие как Metasploit, Python-скрипты, веб-серверы) для создания комплексных сценариев атаки. Основная цель SET в контексте пентеста — симуляция реалистичной фишинговой кампании для оценки устойчивости организации.

Ключевое разграничение необходимо провести между понятиями, которые часто путают в контексте SET:

1.  **Credential Harvester (Сборщик учетных данных):** Это механизм перехвата. Он создает поддельную страницу входа, которая принимает ввод пользователя и перенаправляет его на оригинальный сайт (или оставляет на месте), сохраняя логин и пароль. Это пассивный вектор.
2.  **Site Cloner (Клонер сайтов):** Это инструмент репликации. Он скачивает структуру целевого веб-ресурса и адаптирует его для локального хостинга. Сам по себе клон не собирает данные, если не интегрирован с Credential Harvester или не содержит вредоносного скрипта.
3.  **Spear-Phishing Generator (Генератор целевого фишинга):** Это механизм доставки. Он формирует тело письма, заголовок и вложения, используя шаблоны, и отправляет их через SMTP. Без инфраструктуры (веб-сервера или эксплойта) письмо не приведет к компрометации.
4.  **Infectious Media Generator (Генератор зараженных носителей):** Это механизм доставки через физический или виртуальный носитель (USB, ISO, CD). Он создает образ диска, который при монтировании автоматически запускает payload (часто через автозапуск или эксплойт драйвера).

Путаница возникает из-за того, что SET предоставляет эти функции как единое меню, но технически они работают на разных этапах kill chain: Разведка → Подготовка (клонирование/генерация) → Доставка (письмо/носитель) → Эксплуатация (перехват/эксплойт) → Действия.

| Сущность | Основная функция | Техническая реализация в SET | Зависимость от других компонентов |
| :--- | :--- | :--- | :--- |
| **Credential Harvester** | Перехват логина/пароля | Python-скрипт, перехватывающий POST-запросы к локальному веб-серверу | Требует работающего веб-сервера (Apache/Python HTTP) и страницы-приманки |
| **Site Cloner** | Репликация целевого URL | `wget`/`curl` с флагами конвертации ссылок, парсинг DOM | Часто используется в связке с Harvester для создания "живой" копии |
| **Spear-Phishing Gen** | Формирование письма | Шаблонизатор Jinja2 (или аналог), SMTP-клиент | Требует адреса жертвы и ссылки на вектор атаки (URL или файл) |
| **Infectious Media** | Создание загрузочного носителя | Генерация ISO-образа, интеграция с AutoRun.inf или эксплойтами | Требует скомпилированного payload (например, Meterpreter reverse_tcp) |

SET также различается по уровням абстракции:
*   **High-Level (Меню):** Пользователь выбирает опцию "Website Attack Vectors" → "Credential Harvester". SET сам поднимает веб-сервер, генерирует страницу и запускает listener.
*   **Low-Level (Модули):** Доступ к исходному коду в директории `modules/`. Позволяет создавать кастомные векторы, не предусмотренные разработчиками, что критично для обхода современных EDR-систем, ожидающих стандартных паттернов SET.

## Внутреннее устройство предмета

SET представляет собой модульную архитектуру, построенную на Python. Понимание внутреннего устройства необходимо для анализа того, как именно генерируются артефакты атаки и как они могут быть детектированы.

### Архитектура и модульная структура

Код SET разделен на несколько ключевых директорий:
*   `src/`: Основной код ядра, обработка CLI, логика выбора векторов.
*   `modules/`: Содержит скрипты для каждого конкретного вектора атаки. Например, `credential_harvester.py` или `site_cloner.py`.
*   `seproxy/`: Подсистема для создания прокси-серверов, позволяющая просматривать трафик между жертвой и сервером SET в реальном времени.
*   `seautomate/`: Инструмент для автоматизации кампаний, позволяющий запускать сценарии без интерактивного ввода.

При запуске SET инициализирует конфигурационный файл `set.conf`, где хранятся параметры по умолчанию: IP-адрес атакующего (LHOST), порт, выбор веб-сервера (Apache или встроенный Python HTTP), настройки SMTP и пути к шаблонам.

### Вектор атаки: Credential Harvester и Site Cloner

Рассмотрим наиболее распространенный сценарий: клонирование сайта и перехват учетных данных.

1.  **Сбор структуры (Reconnaissance):** SET использует инструменты вроде `wget` с флагом `--mirror` или кастомные парсеры для скачивания HTML, CSS, JS и изображений целевого сайта.
2.  **Адаптация (Adaptation):** Скрипт модифицирует скачанные файлы:
    *   Заменяет абсолютные ссылки на относительные или локальные.
    *   Внедряет JavaScript-код, который перехватывает событие `submit` формы.
    *   Перенаправляет POST-запросы на локальный обработчик (Harvester).
3.  **Обработка данных (Harvesting):** Когда жертва вводит данные, JavaScript отправляет их на локальный endpoint. Python-скрипт перехватывает запрос, извлекает поля (обычно `username` и `password`), записывает их в лог и перенаправляет пользователя на оригинальный сайт, чтобы не спугнуть жертву.

### Вектор атаки: Payload Generation и Metasploit Integration

SET часто используется как фронтенд для Metasploit Framework. Это позволяет не только собирать учетные данные, но и получать удаленный доступ.

1.  **Генерация Payload:** SET вызывает `msfvenom` (или `msfcli` в старых версиях) для создания исполняемого файла или скрипта.
2.  **Конфигурация Listener:** SET автоматически настраивает `exploit/multi/handler` в Metasploit с параметрами `LHOST` и `LPORT`, соответствующими настройкам SET.
3.  **Доставка:** Payload может быть внедрен в:
    *   DOC-файл с макросами (Office Attack Vector).
    *   PDF-документ с эксплойтом (PDF Attack Vector).
    *   ISO-образ (Infectious Media).

### Структура артефактов атаки

Артефакты, генерируемые SET, имеют специфические признаки, которые могут быть использованы для детекции.

| Компонент | Техническая особенность | Индикатор компрометации (IoC) |
| :--- | :--- | :--- |
| **Веб-сервер** | Часто использует Python HTTP Server или Apache с кастомными скриптами | Заголовки `Server: Werkzeug` или `Apache/2.4` с нестандартными MIME-типами |
| **JavaScript** | Внедренный код перехвата форм | Наличие `document.forms[0].onsubmit`, отправка данных через `fetch` или `XMLHttpRequest` на локальный IP |
| **Payload** | Скомпилированный бинарник или скрипт | Подписи от `msfvenom`, странные имена процессов, попытки подключения к C2 |
| **Письмо** | SMTP-трафик | Отсутствие SPF/DKIM/DMARC, использование доменов-двойников, ссылки на IP-адреса вместо доменов |

### Инварианты и ограничения

SET имеет ряд технических ограничений, которые влияют на его применение в современных условиях:
*   **Статические сигнатуры:** Многие модули SET используют стандартные шаблоны, которые антивирусы и EDR-системы (CrowdStrike, SentinelOne) уже имеют в базах.
*   **Отсутствие обфускации:** Код JavaScript в клонированных сайтах часто не обфусцирован, что позволяет аналитикам быстро выявить логику перехвата.
*   **Зависимость от зависимостей:** SET требует установленного Metasploit, Python-библиотек и системных утилит. Сбой в одной зависимости может привести к неработоспособности всего вектора.

## Применение и работа с предметом

На практике использование SET для фишинговых кампаний требует понимания не только самого инструмента, но и инфраструктуры доставки. Пентестер должен настроить окружение, сгенерировать вектор, доставить его и проанализировать результаты.

### Типовая процедура настройки и запуска

1.  **Инициализация:** Запуск `setoolkit` в терминале.
2.  **Выбор вектора:** Выбор `Social-Engineering Attacks` → `Website Attack Vectors` → `Credential Harvester Attack Method` → `Site Cloner`.
3.  **Ввод целевого URL:** Ввод адреса сайта для клонирования (например, `https://login.microsoftonline.com`).
4.  **Настройка LHOST:** Указание IP-адреса атакующего. Это критический шаг, так как все запросы будут перенаправлены сюда.
5.  **Запуск:** SET поднимает веб-сервер, клонирует сайт и запускает listener.

### Работа с SMTP и доставкой

Для успешной кампании одного клонированного сайта недостаточно. Необходимо доставить ссылку жертве. SET предоставляет встроенный SMTP-клиент.

*   **Настройка:** В меню SET выбирается `Email Attacks` → `Spear-Phishing Attack Vectors` → `Site Cloner Attack Method`.
*   **Конфигурация:** Ввод SMTP-сервера (часто используется Gmail API или локальный Postfix), адреса отправителя и получателя.
*   **Шаблоны:** SET предлагает стандартные шаблоны (HR, IT Support, CEO Fraud). Пентестер должен кастомизировать текст, чтобы он соответствовал контексту организации.

### Анализ результатов

SET предоставляет простой интерфейс для просмотра перехваченных данных. Однако для глубокого анализа требуется работа с логами.

*   **Логи SET:** Файлы в директории `~/set/data/` или `/var/log/set/`. Содержат временные метки, IP-адреса жертв, перехваченные учетные данные.
*   **Логи веб-сервера:** Если используется Apache, логи доступа (`access.log`) покажут запросы к клонированному сайту.
*   **Трафик:** Использование `seproxy` позволяет просматривать HTTP-запросы в реальном времени, что полезно для отладки кастомных векторов.

### Типичные ошибки и подводные камни

1.  **Неправильная настройка DNS:** Если DNS не настроен на IP атакующего, жертва может попасть на оригинальный сайт или получить ошибку.
2.  **SSL/TLS сертификаты:** Современные браузеры блокируют незащищенные HTTP-соединения для форм входа. SET генерирует самоподписанные сертификаты, что вызывает предупреждения в браузере, снижающие конверсию атаки.
3.  **Обход антивирусов:** Payload, сгенерированный SET, часто детектируется. Пентестер должен использовать техники обфускации или упаковщики (UPX, custom packers) перед доставкой.
4.  **Игнорирование MFA:** Credential Harvester перехватывает только логин и пароль. Если включена MFA, атака терпит неудачу, если не используется продвинутый прокси (например, Evilginx2), который SET сам по себе не поддерживает.

### Пример конфигурации и команды

Ниже приведен пример структуры конфигурационного файла `set.conf` и команды для обновления SET.

```bash
# Обновление SET через PTF (PenTesters Framework)
root@kali:~# ptf update

# Запуск SET
root@kali:~# setoolkit

# Пример вывода при выборе вектора
[---]        The Social-Engineer Toolkit (SET)         [---]
[---]        Created by: David Kennedy (ReL1K)         [---]
                      Version: 8.0.3
                    Codename: 'Maverick'
[---]        Follow us on Twitter: @TrustedSec         [---]

   Select from the menu:
   
   1) Social-Engineering Attacks
   2) Penetration Testing (Fast-Track)
   3) Third Party Modules
   4) Update…
```

При выборе `Site Cloner` SET запрашивает URL. Важно понимать, что SET не клонирует динамические сайты с сложной аутентификацией (например, Google или Microsoft) полностью. Он клонирует только статическую часть. Для обхода сложных систем аутентификации требуется использование прокси-инструментов, таких как Evilginx2, которые не входят в стандартный комплект SET.

## Сквозной практический пример: Симуляция фишинговой кампании с перехватом учетных данных

**Исходные условия:**
*   **Среда:** Kali Linux (VM) с установленным SET и Metasploit Framework.
*   **Цель:** Симуляция атаки на сотрудников компании, имитирующая уведомление о смене пароля от службы поддержки.
*   **Роль:** Пентестер (Red Team).
*   **Инфраструктура:** Атакующий IP: `192.168.1.100`. Жертва находится в той же подсети для упрощения демонстрации.

### Шаг 1: Инициализация и выбор вектора Credential Harvester

Пентестер запускает SET и выбирает вектор атаки на веб-сайты.

```bash
root@kali:~# setoolkit

# В меню SET:
# 1) Social-Engineering Attacks
# 1) Website Attack Vectors
# 2) Credential Harvester Attack Method
# 2) Site Cloner
```

SET запрашивает целевой URL. Для примера используется локальный тестовый сайт или публичный сервис с простой формой входа (например, GitHub или локальный Apache). В данном примере используется локальный Apache для контроля.

```bash
# Ввод целевого URL
[?] Enter the URL to clone: http://192.168.1.100/login.html
```

SET клонирует сайт и настраивает веб-сервер.

### Шаг 2: Настройка перехвата и генерация ссылки

После клонирования SET предлагает отправить фишинговое письмо.

```bash
# В меню SET:
# 1) Send a Spear-Phishing Attack
# 1) Site Cloner Attack Method
```

SET запрашивает SMTP-данные. Для демонстрации используется локальный SMTP-сервер (например, `mailhog` или `postfix`).

```bash
[?] Enter your SMTP Server (e.g., smtp.gmail.com): 192.168.1.100
[?] Enter your SMTP Username (if required): user@example.com
[?] Enter your SMTP Password (if required): password
[?] Enter the email address to send from: attacker@example.com
[?] Enter the email address to send to: victim@example.com
```

### Шаг 3: Запуск атаки и мониторинг

SET отправляет письмо. Пентестер переключается на просмотр логов.

```bash
# В другом терминале или внутри SET
# Просмотр перехваченных данных
root@kali:~# tail -f /root/set/data/credentials.txt
```

### Шаг 4: Действие жертвы и фиксация результата

Жертва открывает письмо, переходит по ссылке, вводит логин и пароль.

**Ожидаемый вывод в логе SET:**

```text
[+] Credential Harvesting Mode Activated
[+] Web Server Started
[+] Site Cloned Successfully
[+] Sending Spear-Phishing Email...
[+] Email Sent Successfully

# После ввода данных жертвой:
[+] New Credential Found!
[+] Username: victim_user
[+] Password: P@ssw0rd123!
[+] IP Address: 192.168.1.50
[+] Timestamp: 2023-10-27 14:32:15
```

**Ожидаемый вывод в логе веб-сервера (Apache):**

```apache
192.168.1.50 - - [27/Oct/2023:14:32:10 +0000] "POST /login.php HTTP/1.1" 200 1234 "-" "Mozilla/5.0..."
```

### Ожидаемый вывод

Данный пример демонстрирует полный цикл атаки социальной инженерии с использованием SET: от клонирования сайта до перехвата учетных данных. Пентестер получает подтверждение успешной компрометации, что позволяет оценить уязвимость пользователей и эффективность технических средств защиты (почтовых шлюзов, антивирусов).

## Аналитический вывод

Social-Engineer Toolkit остается фундаментальным инструментом в арсенале специалистов по кибербезопасности, однако его роль эволюционировала от средства для "быстрых атак" к образовательному и исследовательскому фреймворку. Ключевая ценность SET заключается в его модульности и способности автоматизировать сложные цепочки атак, объединяя веб-технологии, SMTP и эксплойты. Однако, в современных условиях использования SET для прямых атак на защищенные системы имеет ограниченный эффект из-за развитых механизмов детекции сигнатур, анализа поведенческих аномалий и внедрения MFA.

Для эффективного применения SET в пентестах необходимо понимать его внутреннее устройство и ограничения. Пентестеры должны кастомизировать векторы атаки, обфусцировать payload и использовать кастомные шаблоны, чтобы избежать детекции. Кроме того, SET не заменяет более продвинутые инструменты для обхода MFA, такие как Evilginx2, которые требуются для атак на современные облачные сервисы.

Основной вывод для студентов и специалистов: SET является отличным инструментом для обучения принципам социальной инженерии и понимания векторов атаки, но его использование в реальных условиях требует глубокого знания контекста, инфраструктуры и методов обхода современных средств защиты. Этическое использование SET должно строго ограничиваться рамками согласованных тестов на проникновение с письменным разрешением владельца инфраструктуры.
