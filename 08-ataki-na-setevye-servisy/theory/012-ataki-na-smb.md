# Атаки на протокол SMB: Архитектура, векторы эксплуатации и методы детекции

## Контекст и базовые понятия

Протокол Server Message Block (SMB) является фундаментальным компонентом корпоративных сетей Microsoft, обеспечивающим обмен файлами, принтерами и межпроцессное взаимодействие (IPC) между узлами. В контексте тестирования на проникновение и оценки уязвимостей SMB представляет собой один из наиболее критичных векторов атак из-за его повсеместного распространения, глубокой интеграции в операционные системы и исторически сложившейся архитектуры, ориентированной на доверие внутри локальной сети. Понимание SMB требует четкого разграничения его версий, так как эволюция протокола неразрывно связана с эволюцией угроз.

Существует три основные версии протокола, кардинально различающиеся по архитектуре безопасности и механизмам аутентификации:

1.  **SMB 1.0 (CIFS):** Протокол, разработанный в конце 1980-х годов. Характеризуется отсутствием шифрования трафика на уровне приложения, слабой аутентификацией (LAN Manager / NTLM) и сложным состоянием сессии. Именно уязвимости SMB 1.0 (такие как EternalBlue, MS17-010) стали причиной самых массовых в истории кибербезопасности инцидентов (WannaCry, NotPetya).
2.  **SMB 2.0:** Введен в Windows Vista и Windows Server 2008. Добавил поддержку больших MTU, дифференциации приоритетов, шифрования (в некоторых реализациях) и улучшенную обработку ошибок. Однако базовая модель аутентификации (NTLM) осталась уязвимой к ретрансляции.
3.  **SMB 3.0 и выше:** Введен в Windows 7 и Windows Server 2008 R2. Ключевым нововведением стало встроенное шифрование данных (SMB Encryption), поддержка многоканальности (Multi-channel) для агрегации пропускной способности и, что критично для безопасности, обязательная поддержка аутентификации на основе подписей (SMB Signing) для защиты от атак типа "человек посередине" (MitM).

Разграничение понятий "SMB" и "SMB Signing" является критическим для специалиста по безопасности. SMB — это протокол передачи данных. SMB Signing — это механизм криптографической подписи пакетов, использующий хеш-функцию HMAC-MD5 (или более современные аналоги в зависимости от версии) для обеспечения целостности и аутентичности сообщений. Отсутствие SMB Signing позволяет атакующему модифицировать пакеты в реальном времени или перенаправлять их (relay attack).

Путаница часто возникает между понятиями "SMB Direct" (RDMA) и "SMB Multichannel". SMB Multichannel — это логическая агрегация нескольких сетевых путей (NICs) для увеличения пропускной способности и отказоустойчивости. SMB Direct (или RDMA over Converged Ethernet - RoCE) — это физический/транспортный уровень, позволяющий передавать данные в обход ядра ОС, снижая нагрузку на CPU. Для атакующего SMB Multichannel может представлять интерес как способ обхода ограничений брандмауэра или увеличения скорости эксфильтрации данных, тогда как SMB Direct требует специализированного сетевого оборудования.

Следующая таблица фиксирует ключевые различия между версиями протокола с точки зрения векторов атаки и механизмов защиты:

| Характеристика | SMB 1.0 (CIFS) | SMB 2.x / 3.x (Modern) |
| :--- | :--- | :--- |
| **Аутентификация** | LAN Manager (LM), NTLMv1, NTLMv2 | NTLMv2, Kerberos, AES-CMAC |
| **Шифрование трафика** | Отсутствует (открытый текст) | Опционально (2.x), Обязательно/Встроено (3.0+) |
| **Целостность данных** | Отсутствует (нет подписей по умолчанию) | SMB Signing (обязательно в доменах) |
| **Типичные уязвимости** | Remote Code Execution (RCE) через структуру пакетов (EternalBlue) | Relay Attacks (NTLM Relay), Pass-the-Hash, Misconfigurations |
| **Порты** | NetBIOS over TCP (139), Raw SMB over TCP (445) | Raw SMB over TCP (445) |
| **Статус в современных ОС** | Отключен по умолчанию, считается устаревшим | Стандарт де-факто |

Важно отметить, что даже современные версии SMB (3.1.1) не являются абсолютно безопасными "из коробки". Их безопасность зависит от конфигурации домена (Active Directory), политик групповой безопасности (GPO) и настроек брандмауэра. Атаки на SMB в современном контексте редко сводятся к эксплуатации уязвимостей нулевого дня в самом протоколе; чаще они используют легитимные механизмы аутентификации (NTLM/Kerberos) для обхода защитных контролей.

## Внутреннее устройство предмета

Архитектура SMB базируется на модели клиент-сервер, где клиент инициирует запросы, а сервер обрабатывает их, возвращая ответы или ошибки. Понимание внутреннего устройства необходимо для анализа трафика, написания правил детекции и разработки эксплойтов. Протокол работает поверх TCP (порт 445) или NetBIOS (порты 137-139). В современных сетях используется прямой SMB over TCP (port 445), так как NetBIOS считается устаревшим и менее безопасным.

### Структура пакета SMB

Каждое сообщение в SMB состоит из заголовка (Header) и тела (Body). Заголовок имеет фиксированную структуру, что позволяет анализаторам трафика идентифицировать протокол даже без глубокого инспекции содержимого.

```text
+----------------+----------------+----------------+----------------+
| Protocol Header| Command        | Status         | Flags          |
| (4 bytes)      | (1 byte)       | (4 bytes)      | (2 bytes)      |
+----------------+----------------+----------------+----------------+
| Flags2         | PID High       | Session ID     | Tree ID        |
| (2 bytes)      | (2 bytes)      | (4 bytes)      | (2 bytes)      |
+----------------+----------------+----------------+----------------+
| Parameter Data | Data           |
| (Variable)     | (Variable)     |
+----------------+----------------+
```

*   **Protocol Header:** Всегда содержит последовательность байт `\xFF` `SMB` (0x53, 0x4D, 0x42). Это первый индикатор наличия SMB-трафика.
*   **Command:** Определяет тип операции (например, `0x73` для SMB_COM_NEGOTIATE, `0x72` для SMB_COM_SESSION_SETUP, `0x2F` для SMB2_NEGOTIATE).
*   **Status:** Код завершения операции. Успешные операции возвращают `0x00000000`. Ошибки аутентификации или доступа имеют специфические коды (например, `0xC000006D` - NT_STATUS_LOGON_FAILURE).
*   **Flags/Flags2:** Битовые маски, управляющие поведением пакета (например, флаг `0x18` в Flags2 указывает на использование расширенных атрибутов).
*   **Tree ID:** Идентифицирует конкретное дерево (share) подключенной сессии.
*   **Session ID:** Идентифицирует сессию пользователя.

### Жизненный цикл SMB-соединения

Процесс установки SMB-соединения состоит из нескольких фаз, каждая из которых может быть объектом атаки.

1.  **Negotiate Protocol (Согласование протокола):** Клиент отправляет список поддерживаемых версий SMB. Сервер выбирает наиболее подходящую (или самую старую, если настроено на совместимость). Эта фаза критична, так как атакующий может попытаться принудить сервер к использованию SMB 1.0, если тот поддерживает несколько версий.
2.  **Session Setup (Настройка сессии):** Клиент предоставляет учетные данные. В SMB2/3 используется структура `SMB2_SESSION_SETUP`. Если используется NTLM, здесь происходит обмен NTLM-челленджами. Если Kerberos — билет TGT.
3.  **Tree Connect (Подключение к дереву):** Клиент запрашивает доступ к конкретному ресурсу (share), например, `\\SERVER\ADMIN$`. Сервер проверяет права доступа.
4.  **File Create/Read/Write/Close:** Основная фаза передачи данных. В SMB 3.0+ эта фаза может быть зашифрована.

### Уязвимости аутентификации: NTLM и Relay

NTLM (NT LAN Manager) — это протокол аутентификации, который до сих пор широко используется в доменах Active Directory для обратной совместимости. Его главная слабость — отсутствие проверки подлинности сервера клиентом. Клиент доверяет любому серверу, который запрашивает аутентификацию.

Это позволяет проводить атаки **NTLM Relay**. Атакующий, находящийся в той же подсети, перехватывает NTLM-челлендж, инициированный жертвой, и ретранслирует его на другой сервер (например, на файловый сервер или веб-сервер с поддержкой NTLM), выдавая себя за жертву. Если учетная запись жертвы имеет права на целевом сервере, атакующий получает доступ.

В отличие от SMB 1.0, где уязвимости часто были связаны с переполнением буфера в обработчике пакетов (например, в функции `trans2open`), современные атаки на SMB 2/3 чаще направлены на обход механизмов подписи (SMB Signing) или эксплуатацию ошибок конфигурации (например, доступ к административным шарам `ADMIN$`, `C$`).

Следующая таблица описывает основные элементы атак на SMB в зависимости от версии протокола:

| Элемент атаки | SMB 1.0 | SMB 2.x / 3.x | Механизм воздействия |
| :--- | :--- | :--- | :--- |
| **Remote Code Execution** | Высокий риск (EternalBlue) | Низкий риск (редкие 0-day) | Эксплуатация ошибок в обработке пакетов |
| **NTLM Relay** | Применимо | Применимо | Перехват и ретрансляция NTLM-челленджей |
| **Pass-the-Hash** | Применимо | Применимо | Использование хеша NTLM без знания пароля |
| **SMB Signing Bypass** | Неприменимо (нет подписей) | Применимо при misconfig | Отключение SMB Signing на сервере или клиенте |
| **DCE/RPC Abuse** | Применимо | Применимо | Использование RPC-интерфейсов для выполнения команд |

## Применение и работа с предметом

На практике специалист по тестированию на проникновение работает с SMB через специализированные инструменты, которые автоматизируют сложные протокольные взаимодействия. Ключевые задачи включают: обнаружение уязвимых систем, сбор информации (enumeration), аутентификацию и выполнение команд.

### Инструментарий и его функции

1.  **SMBClient (Samba):** Кроссплатформенный клиент для работы с SMB. Используется для ручного тестирования, загрузки/выгрузки файлов и проверки прав доступа.
    *   *Применение:* Проверка доступности шаров, тестирование аутентификации.
2.  **Impacket (Python-библиотека):** Набор инструментов для работы с сетевыми протоколами. Включает скрипты `smbclient.py`, `psexec.py`, `wmiexec.py`, `smbexec.py`.
    *   *Применение:* Эксплуатация уязвимостей, запуск удаленных команд, извлечение хешей.
3.  **CrackMapExec (CME):** Фреймворк для автоматизации аудита сетей. Позволяет быстро проверять множество хостов на наличие общих паролей, уязвимостей и выполнять массовые команды.
    *   *Применение:* Масштабное сканирование, lateral movement.
4.  **Responder:** Инструмент для перехвата протоколов LLMNR, NBT-NS и mDNS. Используется для инициирования NTLM-челленджей от легитимных клиентов.
    *   *Применение:* Подготовка к NTLM Relay атакам.
5.  **BloodHound:** Инструмент для анализа графов доверия в Active Directory. Использует данные, собранные через SMB (через LDAP и другие протоколы), для выявления путей атаки.
    *   *Применение:* Анализ путей повышения привилегий.

### Типовые операции и команды

При тестировании SMB специалист выполняет следующие типовые операции:

1.  **Enumerate Shares:** Определение доступных ресурсов.
    ```bash
    smbclient -L //192.168.1.10 -N
    ```
    *   `-L`: Список шаров.
    *   `-N`: Не запрашивать пароль (анонимный доступ).
    *   *Ожидаемый результат:* Список доступных шаров (например, `IPC$`, `ADMIN$`, `Users`).

2.  **Mount Share:** Подключение шара к локальной файловой системе.
    ```bash
    mount -t cifs //192.168.1.10/share /mnt/share -o username=user,password=pass
    ```
    *   *Ожидаемый результат:* Доступ к файлам на удаленном сервере.

3.  **Execute Remote Command:** Выполнение команд на целевой системе.
    ```bash
    psexec.py user:pass@192.168.1.10
    ```
    *   *Механизм:* Использует сервис `Remote Procedure Call (RPC)` для создания службы на целевой машине и запуска исполняемого файла.
    *   *Ожидаемый результат:* Интерактивная командная строка на целевой системе.

4.  **Check SMB Signing:** Проверка включен ли SMB Signing.
    ```bash
    nmap --script smb-security-mode -p 445 192.168.1.10
    ```
    *   *Ожидаемый результат:* Информация о том, требуется ли подпись для сессии. Если `message_signing: disabled`, система уязвима к relay-атакам.

### Типичные ошибки и подводные камни

*   **Игнорирование SMB Signing:** Многие специалисты фокусируются только на уязвимостях нулевого дня, игнорируя конфигурацию SMB Signing. Если на сервере отключена подпись, атакующий может легко перехватить трафик.
*   **Неправильная работа с NTLM:** Использование NTLM-хешей без понимания их ограничений. NTLM не работает в современных доменах с включенным Kerberos, если не настроена обратная совместимость.
*   **Блокировка учетных записей:** Частые попытки аутентификации с неверными данными могут привести к блокировке учетной записи в Active Directory, что сделает дальнейшую атаку невозможной.
*   **Проблемы с антивирусами:** Современные EDR-системы активно мониторят процессы, созданные через SMB (например, `svchost.exe` или `lsass.exe`), и могут блокировать попытки выполнения кода.

## Сквозной практический пример: Аудит уязвимостей SMB в тестовой среде

**Исходные условия:**
*   **Среда:** Локальная сеть с двумя хостами: Атакующий (Kali Linux, IP: 192.168.1.100) и Целевой сервер (Windows Server 2019, IP: 192.168.1.10).
*   **Роль:** Специалист по тестированию на проникновение.
*   **Цель:** Определить версию SMB, наличие уязвимостей, доступность шаров и состояние SMB Signing.
*   **Инструменты:** `nmap`, `smbclient`, `crackmapexec`.

### Шаг 1: Определение версии SMB и открытых портов

Первым делом необходимо определить, какие версии SMB поддерживает целевой сервер и какие порты открыты. Это критично для выбора дальнейшей тактики.

```bash
nmap -p 445 --script smb-protocols,smb-os-discovery 192.168.1.10
```

**Ожидаемый вывод:**
```text
PORT    STATE SERVICE
445/tcp open  microsoft-ds

Host script results:
| smb-protocols: 
|   dialects:
|     SMB2_10
|     SMB2_10 (2:0x0002)
|     SMB3_00
|     SMB3_00 (3:0x0003)
|_  (Note: SMB1 is NOT supported)
| smb-os-discovery: 
|   OS: Windows Server 2019 (10.0)
|   Computer name: FILESERVER01
|   Domain name: TESTLAB.LOCAL
|_  Forest name: TESTLAB.LOCAL
```
*Анализ:* Целевой сервер поддерживает SMB 2.1 и 3.0, но SMB 1.0 отключен. Это снижает риск эксплуатации EternalBlue. Версия ОС — Windows Server 2019.

### Шаг 2: Проверка доступности шаров и анонимного доступа

Проверка наличия открытых шаров, доступных без аутентификации или с гостевым доступом.

```bash
smbclient -L //192.168.1.10 -N
```

**Ожидаемый вывод:**
```text
Sharename       Type      Comment
---------       ----      -------
ADMIN$          Disk      Remote Admin
C$              Disk      Default share
IPC$            IPC       Remote IPC
Users           Disk      
```
*Анализ:* Доступны стандартные административные шары (`ADMIN$`, `C$`) и пользовательский шар `Users`. Анонимный доступ к `Users` возможен (так как не запрошен пароль). Это может быть точкой входа, если в шаре есть чувствительные данные.

### Шаг 3: Проверка состояния SMB Signing

Определение, требует ли сервер подписи пакетов. Если подпись не требуется, система уязвима к NTLM Relay.

```bash
nmap --script smb-security-mode -p 445 192.168.1.10
```

**Ожидаемый вывод:**
```text
Host script results:
| smb-security-mode: 
|   account_used: guest
|   authentication_level: user
|   challenge_response: supported
|_  message_signing: disabled (dangerous, but default)
```
*Анализ:* **Критическая уязвимость.** `message_signing: disabled`. Это означает, что атакующий может перехватить NTLM-челлендж и ретранслировать его на этот сервер, если получит учетные данные пользователя с правами на доступ.

### Шаг 4: Тестирование аутентификации и прав доступа

Попытка подключения к шару `Users` с использованием известных учетных данных (например, из предыдущих этапов атаки или стандартных учетных записей).

```bash
smbclient //192.168.1.10/Users -U testuser%password123
```

**Ожидаемый вывод:**
```text
Try "help" to get a list of possible commands.
smb: \> ls
  .                                   D        0  Wed Jan 01 00:00:00 2023
  ..                                  D        0  Wed Jan 01 00:00:00 2023
  documents                           D        0  Wed Jan 01 00:00:00 2023
  secrets.txt                         A      100  Wed Jan 01 00:00:00 2023
```
*Анализ:* Аутентификация успешна. Пользователь `testuser` имеет права на чтение шара `Users`. Найден файл `secrets.txt`, который может содержать конфиденциальную информацию.

### Шаг 5: Проверка на наличие уязвимостей нулевого дня

Использование `crackmapexec` для быстрой проверки известных уязвимостей.

```bash
crackmapexec smb 192.168.1.10 -u testuser -p password123 --local-auth
```

**Ожидаемый вывод:**
```text
SMB         192.168.1.10    445    FILESERVER01     [*] Windows Server 2019 (10.0) build 17763 (name:FILESERVER01) domain:TESTLAB.LOCAL
SMB         192.168.1.10    445    FILESERVER01     [+] TESTLAB.LOCAL\testuser:password123 
SMB         192.168.1.10    445    FILESERVER01     [+] Enumerated credentials for user 'testuser'
```
*Анализ:* Учетные данные верны. `crackmapexec` не обнаружил известных уязвимостей нулевого дня (так как сервер обновлен), но подтвердил успешную аутентификацию.

**Ожидаемый вывод:**
Пример демонстрирует, что даже при отключенном SMB 1.0 и использовании современных версий протокола, система остается уязвимой из-за отключенной подписи пакетов (SMB Signing) и наличия доступных шаров. Атакующий может использовать перехваченные NTLM-хэши для доступа к другим системам в сети (Relay Attack) или напрямую получить доступ к файлам через `smbclient`.

## Аналитический вывод

Атаки на протокол SMB эволюционировали от эксплуатации уязвимостей нулевого дня в самом протоколе (SMB 1.0) к использованию легитимных механизмов аутентификации и конфигурационных ошибок. Современные версии SMB (2.x/3.x) обеспечивают лучшую безопасность за счет шифрования и подписи пакетов, однако их эффективность полностью зависит от правильной настройки домена Active Directory и политик групповой безопасности. Ключевой уязвимостью остается NTLM-аутентификация, которая не проверяет подлинность сервера, что делает возможным атаки типа NTLM Relay при отсутствии SMB Signing. Для специалистов по тестированию на проникновение критически важно проверять не только наличие уязвимостей в коде, но и состояние конфигурации: включен ли SMB Signing, отключен ли SMB 1.0, и какие шары доступны анонимно. Защита от атак на SMB требует комплексного подхода: отключение устаревших версий протокола, обязательное включение SMB Signing, использование Kerberos вместо NTLM и строгий контроль доступа к административным шарам.
