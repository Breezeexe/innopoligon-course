# Pass-the-Hash через RDP Restricted Admin Mode: Механизмы, векторы и детекция

## Контекст и базовые понятия

Pass-the-Hash (PtH) — это техника атаки, при которой злоумышленник использует хеш пароля пользователя (NTLM-хеш) для аутентификации на удаленной системе без необходимости расшифровки самого пароля. В контексте Windows NTLM-хеш представляет собой результат одностороннего хеширования пароля алгоритмом MD4. Поскольку NTLM использует хеши для хранения и проверки учетных данных, а не сами пароли, возможность использования захваченного хеша напрямую создает критическую уязвимость, если аутентификация не защищена механизмами, предотвращающими повторное использование хеша (replay attacks).

Remote Desktop Protocol (RDP) — протокол удаленного рабочего стола Microsoft, позволяющий устанавливать графические сеансы с удаленными компьютерами. RDP поддерживает несколько методов аутентификации: Network Level Authentication (NLA), который требует аутентификации до установки сеанса, и стандартную аутентификацию уровня сеанса, которая происходит после установления соединения.

Restricted Admin Mode (RAM) — функция, введенная в RDP 8.0 и выше, которая позволяет администраторам подключаться к серверу, используя NTLM-хеш, без передачи самого хеша в открытом виде на целевую машину. Вместо этого клиент шифрует хеш локально, и сервер проверяет его, не имея доступа к исходному значению хеша. Это создает иллюзию того, что аутентификация прошла успешно, но на самом деле RAM предназначен для легитимных административных задач, когда администратор не имеет пароля, но имеет хеш (например, в сценариях "break-glass" или при работе с учетными записями, пароли которых неизвестны).

Однако, если злоумышленник уже получил NTLM-хеш администратора (например, через дамп памяти LSASS), он может использовать RAM для подключения к серверу, минуя NLA. Это особенно опасно, так как многие организации полагаются на NLA как на основную защиту от PtH-атак. Если NLA отключен или если злоумышленник может обойти его, использование RAM позволяет ему получить доступ к системе, используя только хеш.

Ключевое разграничение между легитимным использованием RAM и атакой PtH через RAM заключается в контексте и намерении. Легитимное использование RAM обычно происходит в рамках административных процедур, когда администратор имеет право на доступ, но не имеет пароля. Атака PtH через RAM происходит, когда злоумышленник использует украденные учетные данные для несанкционированного доступа.

| Характеристика | Легитимное использование RAM | Атака PtH через RAM |
| :--- | :--- | :--- |
| **Источник хеша** | Известен администратору, получен легально | Украден из памяти, дампов, логов |
| **Намерение** | Администрирование, восстановление доступа | Несанкционированный доступ, персистентность |
| **Контекст** | Задокументированные процедуры | Скрытые, неавторизованные действия |
| **Индикаторы** | Известные IP, время, действия | Аномальные IP, время, действия |
| **Защита** | Политики доступа, аудит | Мониторинг аномалий, ограничение прав |

Важно отметить, что Restricted Admin Mode не предотвращает PtH-атаки сам по себе; он лишь изменяет способ передачи учетных данных. Если злоумышленник уже имеет хеш, он может использовать RAM для подключения, если на целевой системе включена поддержка RAM и отключен NLA. Таким образом, понимание механизмов работы RAM и условий, при которых он может быть использован для атаки, критически важно для специалистов по информационной безопасности.

## Внутреннее устройство предмета

Restricted Admin Mode (RAM) в RDP представляет собой механизм, который позволяет клиенту аутентифицироваться на сервере, используя NTLM-хеш, без передачи самого хеша в открытом виде. Это достигается за счет использования симметричного шифрования, где хеш используется как ключ для шифрования challenge, отправленного сервером.

### Механизм работы Restricted Admin Mode

Процесс аутентификации с использованием RAM можно разделить на несколько этапов:

1.  **Инициализация соединения:** Клиент RDP инициирует соединение с сервером. Если NLA отключен, аутентификация происходит на уровне сеанса.
2.  **Отправка challenge:** Сервер генерирует случайный challenge (обычно 8 байт) и отправляет его клиенту.
3.  **Шифрование хеша:** Клиент берет NTLM-хеш пользователя и использует его как ключ для шифрования challenge с помощью алгоритма DES (в рамках протокола NTLM). Результатом является encrypted challenge.
4.  **Отправка encrypted challenge:** Клиент отправляет encrypted challenge обратно на сервер.
5.  **Проверка на сервере:** Сервер, имеющий доступ к NTLM-хешу (или его производным, в зависимости от конфигурации), дешифрует encrypted challenge, используя тот же хеш как ключ. Если результат совпадает с исходным challenge, аутентификация успешна.

Важно отметить, что в стандартном режиме NTLM аутентификации клиент отправляет ответ (response), который является результатом хеширования challenge с использованием хеша пароля. В режиме RAM вместо этого отправляется зашифрованный challenge. Это означает, что сервер должен иметь возможность дешифровать этот challenge, чтобы проверить аутентификацию.

### Архитектура компонентов

Архитектура взаимодействия между клиентом и сервером в контексте RAM включает следующие компоненты:

```text
[Клиент RDP] ──(Challenge)──▶ [Сервер RDP]
       │                           │
       │ (NTLM-хеш как ключ)       │ (NTLM-хеш как ключ)
       ▼                           ▼
[Шифрование challenge]    [Дешифровка challenge]
       │                           │
       ▼                           ▼
[Encrypted Challenge]   [Сравнение с исходным challenge]
       │                           │
       └───(Encrypted Challenge)──┘
```

Клиент RDP должен поддерживать RAM, что требует установки RDP 8.0 или выше. Сервер также должен быть настроен на поддержку RAM. В Windows Server 2008 R2 и Windows 7 SP1 поддержка RAM была добавлена через обновления RDP.

### Инварианты и ограничения

RAM имеет несколько инвариантов и ограничений:

*   **Требование к версии RDP:** Как клиент, так и сервер должны поддерживать RDP 8.0 или выше.
*   **Отсутствие NLA:** RAM обычно используется, когда NLA отключен. Если NLA включен, аутентификация происходит до установления сеанса, и RAM не применяется.
*   **Зависимость от NTLM:** RAM использует NTLM для аутентификации. Если NTLM отключен на сервере, RAM не может быть использован.
*   **Доступность хеша:** Для успешной аутентификации через RAM клиент должен иметь NTLM-хеш пользователя.

### Сравнение с другими методами аутентификации

| Метод аутентификации | Передача хеша | Защита от PtH | Требования |
| :--- | :--- | :--- | :--- |
| **NLA** | Нет (используется Kerberos или NTLM с NLA) | Да (если Kerberos) | Включен NLA |
| **Стандартный NTLM** | Да (в ответе) | Нет | Отключен NLA |
| **Restricted Admin Mode** | Нет (зашифрованный challenge) | Частично (скрывает хеш) | RDP 8.0+, отключен NLA |
| **Credential Guard** | Нет (хеш не доступен) | Да | Hardware support, GPO |

Restricted Admin Mode не предотвращает использование хеша, но скрывает его от сервера. Это означает, что если злоумышленник перехватит трафик, он не сможет получить хеш напрямую. Однако, если хеш уже украден, RAM не предотвращает его использование.

## Применение и работа с предметом

На практике специалисты по информационной безопасности сталкиваются с необходимостью обнаружения и предотвращения атак PtH через RAM. Это требует понимания того, как такие атаки выглядят в логах и трафике, а также использования инструментов для анализа.

### Инструменты и методы обнаружения

Для обнаружения атак PtH через RAM используются следующие инструменты и методы:

1.  **Анализ логов Windows:** Логи безопасности (Security Logs) на сервере могут содержать события, указывающие на успешную аутентификацию с использованием NTLM. Ключевые события включают Event ID 4624 (успешный вход в систему) с типом логина 3 (Network) и аутентификатором NTLM.
2.  **Анализ сетевого трафика:** Инструменты захвата трафика, такие как Wireshark, могут использоваться для анализа RDP-трафика. Однако, поскольку RAM шифрует challenge, прямой анализ трафика может быть затруднен. Вместо этого следует обращать внимание на аномалии в частоте подключений, источниках IP и времени.
3.  **EDR-решения:** Современные системы EDR могут обнаруживать аномальные действия, такие как подключение к серверу с использованием NTLM-хеша от необычных источников.
4.  **Threat Hunting:** Специалисты по threat hunting могут искать индикаторы компрометации (IoC), связанные с PtH-атаками, такие как наличие NTLM-хешей в памяти процессов, необычные сетевые подключения и т.д.

### Типичные ошибки и подводные камни

При настройке и использовании RAM специалисты могут столкнуться со следующими проблемами:

*   **Неправильная настройка политик:** Если политики безопасности настроены неправильно, RAM может быть использован для несанкционированного доступа. Например, если NLA отключен, а RAM включен, злоумышленник может использовать украденный хеш для подключения.
*   **Недостаточный мониторинг:** Отсутствие мониторинга аномальных подключений может привести к тому, что атака останется незамеченной.
*   **Неправильное понимание защиты:** Некоторые специалисты могут ошибочно полагать, что RAM защищает от PtH-атак. На самом деле, RAM лишь скрывает хеш от сервера, но не предотвращает его использование, если хеш уже украден.

### Паттерны использования и анализа

Для анализа атак PtH через RAM можно использовать следующие паттерны:

1.  **Поиск аномальных подключений:** Ищите подключения к серверам с использованием NTLM от источников, которые обычно не подключаются.
2.  **Анализ времени:** Обратите внимание на подключения, которые происходят в нерабочее время или в необычные дни.
3.  **Анализ источников IP:** Проверьте, не являются ли источники IP известными злоумышленниками или скомпрометированными системами.

### Пример правила детекции (Sigma)

Ниже приведен пример правила Sigma для обнаружения аутентификации с использованием NTLM через RDP:

```yaml
title: NTLM Authentication via RDP
id: 12345678-1234-1234-1234-123456789012
status: experimental
description: Detects NTLM authentication via RDP
references:
    - https://attack.mitre.org/techniques/T1550/002/
author: Security Researcher
date: 2023/10/01
logsource:
    category: process_creation
    product: windows
detection:
    selection:
        Image|endswith:
            - '\svchost.exe'
        CommandLine|contains:
            - 'RDP'
    condition: selection
falsepositives:
    - Legitimate RDP connections
level: medium
```

Это правило ищет процессы, связанные с RDP, и пытается обнаружить аутентификацию с использованием NTLM. Однако, для более точного обнаружения необходимо анализировать логи безопасности и сетевой трафик.

## Сквозной практический пример: Обнаружение атаки PtH через RAM

### Исходные условия

*   **Среда:** Корпоративная сеть с Windows Server 2019 и клиентами Windows 10.
*   **Инструменты:** Wireshark, Sysmon, Sigma-правила, PowerShell.
*   **Роль:** Специалист по SOC (Security Operations Center).
*   **Сценарий:** Злоумышленник получил NTLM-хеш администратора и пытается подключиться к серверу через RDP, используя Restricted Admin Mode.

### Шаги расследования

#### Шаг 1: Сбор данных о подключениях

Соберите логи безопасности с сервера, чтобы найти события успешной аутентификации через RDP.

```powershell
# PowerShell команда для поиска событий входа в систему через RDP
Get-WinEvent -FilterHashtable @{LogName='Security'; ID=4624} | Where-Object { $_.Properties[8].Value -eq 3 } | Select-Object TimeCreated, @{N='UserName';E={$_.Properties[5].Value}}, @{N='IpAddress';E={$_.Properties[18].Value}}
```

**Ожидаемый вывод:** Список событий входа в систему с типом логина 3 (Network), указывающим на сетевую аутентификацию. Обратите внимание на IP-адреса и имена пользователей.

#### Шаг 2: Анализ сетевого трафика

Используйте Wireshark для захвата RDP-трафика и анализа аномалий.

```bash
# Команда tcpdump для захвата RDP-трафика
tcpdump -i any port 3389 -w rdp_capture.pcap
```

**Ожидаемый вывод:** Файл pcap, содержащий RDP-трафик. В Wireshark отфильтруйте трафик по протоколу RDP и проанализируйте заголовки и payload. Обратите внимание на аномальные паттерны подключения, такие как частые попытки подключения с одного IP или необычное время подключения.

#### Шаг 3: Проверка на наличие NTLM-хешей в памяти

Используйте PowerShell для проверки наличия NTLM-хешей в памяти процессов.

```powershell
# PowerShell скрипт для поиска NTLM-хешей в памяти
Get-Process | ForEach-Object {
    $process = $_
    $memory = Get-ProcessMemoryInfo -ProcessId $process.Id
    if ($memory.PrivateMemorySize64 -gt 100MB) {
        Write-Host "Process: $($process.Name), Memory: $($memory.PrivateMemorySize64)"
    }
}
```

**Ожидаемый вывод:** Список процессов с большим объемом частной памяти, которые могут содержать NTLM-хеш. Обратите внимание на процессы, такие как lsass.exe, которые могут содержать учетные данные.

#### Шаг 4: Применение Sigma-правил

Примените Sigma-правила к логам безопасности для обнаружения аномалий.

```yaml
# Sigma-правило для обнаружения аномальных подключений RDP
title: Anomalous RDP Connection
id: 87654321-4321-4321-4321-210987654321
status: experimental
description: Detects anomalous RDP connections
references:
    - https://attack.mitre.org/techniques/T1021/001/
author: SOC Analyst
date: 2023/10/01
logsource:
    category: process_creation
    product: windows
detection:
    selection:
        Image|endswith:
            - '\mstsc.exe'
        CommandLine|contains:
            - '/v:'
    condition: selection
falsepositives:
    - Legitimate RDP connections
level: medium
```

**Ожидаемый вывод:** Список событий, соответствующих правилу. Проанализируйте эти события, чтобы определить, являются ли они легитимными или подозрительными.

#### Шаг 5: Корреляция данных

Сопоставьте данные из логов, сетевого трафика и анализа памяти, чтобы выявить паттерны атаки.

**Ожидаемый вывод:** Выявление связи между аномальными подключениями, наличием NTLM-хешей в памяти и подозрительными IP-адресами. Это может указывать на успешную атаку PtH через RAM.

### Ожидаемый вывод

В результате расследования специалист по SOC может выявить, что злоумышленник использовал NTLM-хеш администратора для подключения к серверу через RDP, используя Restricted Admin Mode. Это подтверждается аномальными подключениями, наличием NTLM-хешей в памяти и подозрительными IP-адресами. На основе этих данных можно принять меры по блокировке доступа и усилению защиты.

## Аналитический вывод

Pass-the-Hash через RDP Restricted Admin Mode представляет собой серьезную угрозу, особенно в средах, где NLA отключен или где NTLM-аутентификация остается основным методом. Restricted Admin Mode, будучи предназначенным для легитимного администрирования, может быть использован злоумышленниками для обхода некоторых механизмов защиты, если хеш уже скомпрометирован. Ключевым аспектом защиты является не только отключение NTLM в пользу Kerberos, но и строгий мониторинг аномалий в подключениях RDP, анализ логов безопасности и сетевого трафика, а также использование современных EDR-решений для обнаружения подозрительной активности. Понимание механизмов работы RAM и условий, при которых он может быть использован для атаки, критически важно для специалистов по информационной безопасности, позволяя им разрабатывать эффективные стратегии обнаружения и предотвращения таких инцидентов.
