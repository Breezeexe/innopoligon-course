# Null Session в протоколе SMB: Механизмы, векторы атаки и методы защиты

## Контекст и базовые понятия

Протокол Server Message Block (SMB) является фундаментальным компонентом инфраструктуры Microsoft Windows, обеспечивающим обмен файлами, принтерами и межпроцессное взаимодействие (IPC) в локальных сетях. Исторически SMB развивался в доверенных корпоративных средах, где периметрная защита считалась достаточной мерой безопасности. В ранних версиях протокола (SMBv1 и ранние реализации SMBv2) отсутствовала строгая аутентификация на этапе установления сессии для определенных типов соединений, что привело к появлению концепции «Null Session» (Пустая сессия).

Null Session — это механизм, позволяющий клиенту устанавливать соединение с сервером SMB без предоставления учетных данных (логина и пароля) или с использованием пустых строк в качестве учетных данных. Технически это реализуется через отправку пакета NEGOTIATE_PROTOCOL_REQUEST и SESSION_SETUP_REQUEST, где поля `UserName` и `Password` (или `SecurityBuffer`) остаются пустыми или заполнены нулями. Если политика безопасности сервера позволяет анонимный доступ к определенным ресурсам (в первую очередь к виртуальным IPC-шарам), сервер принимает сессию и предоставляет доступ к ограниченным наборам API.

Ключевое заблуждение среди начинающих специалистов заключается в отождествлении термина «Null Session» с понятием `NULL` в программировании (указатель на нулевой адрес) или с пустой строкой `""` в контексте SQL-инъекций. В контексте SMB это специфический протокольный механизм аутентификации, использующий пустые буферы безопасности. Важно разграничивать:
1.  **Анонимный доступ (Anonymous Access):** Разрешен на уровне файловой системы (Share Permissions), когда сервер разрешает доступ к конкретному шару любому пользователю, включая анонимных.
2.  **Null Session (IPC$):** Разрешен на уровне протокола и управления доступом (Access Control Lists, ACL). Даже если шар закрыт, IPC$ (Inter-Process Communication) часто остается открытым для обмена данными между процессами, и именно через него исторически эксплуатировались Null Sessions.

В современных версиях Windows (начиная с Windows Server 2003 и Windows XP SP2) по умолчанию анонимные соединения к IPC$ отключены, но уязвимость сохраняется в трех случаях:
1.  Намеренная конфигурация для совместимости со старыми системами (например, Windows 98, старые NAS, принтеры).
2.  Ошибки групповых политик (GPO), разрешающие анонимные перечисления.
3.  Уязвимости в реализации SMBv1, которые позволяют обойти проверки аутентификации на уровне ядра.

| Характеристика | Null Session (SMB) | Анонимный доступ к файлам | Аутентифицированная сессия |
| :--- | :--- | :--- | :--- |
| **Уровень реализации** | Протокол SMB / SAMR / LSARPC API | NTFS / Share Permissions | Kerberos / NTLM |
| **Необходимость учетных данных** | Нет (пустые буферы) | Нет (или гостевой аккаунт) | Да (логин/пароль/хеш) |
| **Основной вектор использования** | Перечисление пользователей, политик, доменов | Чтение/запись файлов | Полный доступ к ресурсам |
| **Типичный ресурс** | `\\target\IPC$` | `\\target\ShareName` | Любой доступный шар |
| **Статус в современных ОС** | Отключено по умолчанию (но может быть включено) | Зависит от настроек шары | Стандартный режим |

Понимание разницы между этими понятиями критично: Null Session — это не просто «отсутствие пароля», это возможность инициировать протокольный диалог, который затем используется для вызова удаленных процедур (RPC) через SAMR (Security Account Manager Remote) или LSARPC (Local Security Authority Remote Procedure Call).

## Внутреннее устройство механизма Null Session

Механизм Null Session базируется на архитектуре клиент-серверного взаимодействия SMB и подсистеме управления учетными записями Windows. Чтобы понять, как именно происходит утечка информации, необходимо рассмотреть структуру протокола, этапы установки сессии и API, доступные в рамках такой сессии.

### Протокольный уровень: Установка сессии без аутентификации

Процесс установки SMB-сессии состоит из нескольких фаз. При попытке подключения к `IPC$` без учетных данных клиент отправляет последовательность пакетов:

1.  **NEGOTIATE_PROTOCOL_REQUEST:** Клиент предлагает версии SMB (SMB1, SMB2, SMB3) и криптографические шифры.
2.  **NEGOTIATE_PROTOCOL_RESPONSE:** Сервер выбирает версию и шифр.
3.  **SESSION_SETUP_REQUEST:** Это ключевой этап. В поле `SecurityBuffer` (или `Password` в SMB1) клиент передает пустой буфер. В SMB2/3 это поле имеет длину 0.
4.  **SESSION_SETUP_RESPONSE:** Сервер проверяет локальную политику безопасности. Если политика разрешает анонимные соединения (через параметр `RestrictAnonymous` или `RestrictAnonymousSAM`), сервер отвечает кодом успеха `STATUS_SUCCESS` и устанавливает контекст сессии.

Если сервер настроен на строгую аутентификацию, он вернет ошибку `STATUS_ACCESS_DENIED` или `STATUS_LOGON_FAILURE`, и сессия будет разорвана. Однако, если доступ разрешен, клиент получает идентификатор сессии (Session ID), который используется для всех последующих запросов.

### Уровень API: SAMR и LSARPC

Получив сессию, атакующий не может сразу читать файлы. Ему необходимо использовать удаленные вызовы процедур (RPC) для взаимодействия с подсистемами безопасности Windows. Два основных протокола, эксплуатируемых через Null Session:

1.  **SAMR (Security Account Manager Remote):** Позволяет управлять учетными записями пользователей и групп. Через Null Session доступны только методы чтения (перечисления).
    *   `SamrEnumerateDomainsInSamServer`: Перечисление доменов.
    *   `SamrOpenDomain`: Открытие доступа к домену.
    *   `SamrEnumerateUsersInDomain`: Перечисление пользователей в домене.
    *   `SamrQueryInformationUser`: Получение информации о пользователе (имя, описание, SID, статус аккаунта).

2.  **LSARPC (Local Security Authority Remote Procedure Call):** Работает на более низком уровне, предоставляя доступ к политикам безопасности и локальным группам.
    *   `LsarEnumerateAccountsWithUserRight`: Перечисление прав (например, кто имеет право «Log on locally»).
    *   `LsarQueryInfoPolicy`: Получение информации о политике паролей, времени блокировки.
    *   `LsarLookupNames`: Преобразование имен пользователей в SID.

### Структура данных и индикаторы

Информация, извлекаемая через Null Session, имеет строгую структуру. Например, ответ от SAMR содержит массив записей пользователей. Каждая запись включает:
*   `RelativeId` (RID): Уникальный идентификатор пользователя в домене.
*   `UserName`: Имя учетной записи.
*   `FullName`: Полное имя (часто пусто).
*   `Description`: Описание учетной записи (часто содержит подсказки для администраторов).
*   `UserComment`: Комментарий пользователя.

Ошибки в конфигурации часто проявляются в том, что сервер возвращает полные данные вместо заглушек. В правильно настроенной системе запрос к `SamrQueryInformationUser` должен возвращать ошибку доступа или пустые значения.

| Компонент | Назначение в контексте Null Session | Уязвимость при неправильной настройке |
| :--- | :--- | :--- |
| **IPC$ (Inter-Process Communication)** | Виртуальный шар для обмена данными между процессами. Не содержит файлов, но предоставляет доступ к RPC. | Доступен для анонимных пользователей, служит «воротами» для атак. |
| **SAMR API** | Управление учетными записями домена. | Позволяет перечислять всех пользователей и их RID, даже если доступ к файлам закрыт. |
| **LSARPC API** | Доступ к локальным политикам безопасности. | Раскрывает политику паролей, права пользователей, членство в группах. |
| **RestrictAnonymous (Реестр)** | Параметр контроля доступа к анонимным сессиям. | Значение `0` разрешает полный доступ; `1` ограничивает; `2` блокирует. |
| **RestrictAnonymousSAM** | Контроль доступа к SAM через анонимные сессии. | Отключение этого параметра позволяет читать учетные записи через SAMR. |

### Архитектурные зависимости и границы доверия

Null Session работает благодаря принципу «доверия к сети». В классической модели Active Directory клиенты доверяют серверу аутентификации (PDC) и не требуют строгой проверки подлинности для внутренних служб. Это создает зону риска: если злоумышленник находится в той же подсети, он может использовать легитимные механизмы взаимодействия для разведки.

Важно отметить, что Null Session не позволяет выполнять код или изменять конфигурацию. Это исключительно канал **разведки (Reconnaissance)**. Он предоставляет информацию, которая затем используется для подбора паролей (brute-force) или атак на основе полученных данных (например, атаки Pass-the-Hash, если хеши будут получены позже через другие векторы).

## Применение и работа с предметом

На практике работа с Null Session осуществляется в рамках этапа разведки тестирования на проникновение. Специалисты используют специализированные инструменты, которые автоматизируют отправку RPC-запросов и парсинг ответов. Понимание того, как работают эти инструменты, позволяет не только проводить аудит, но и настраивать защиту.

### Инструментарий и методы эксплуатации

Основным инструментом для работы с Null Session является утилита `rpcclient` из пакета Samba (доступна в Linux) или `net view` / `nbtstat` в Windows. Также широко используются фреймворки Metasploit и скрипты на Python (например, `impacket`).

**1. Использование rpcclient (Linux/Windows via Samba)**

Команда `rpcclient` позволяет напрямую взаимодействовать с LSARPC и SAMR.

```bash
# Подключение к целевому хосту без учетных данных
rpcclient -U "" <IP_ADDRESS>

# Внутри консоли rpcclient:
# Перечисление доменов
enumdomdomains

# Перечисление пользователей в домене
enumdomusers

# Получение информации о конкретном пользователе (RID 500 - обычно Administrator)
queryuser 0x1f4

# Перечисление локальных групп
enumalsgroups local

# Получение информации о политике безопасности
getdompwinfo
```

Ожидаемый вывод `enumdomusers` при успешной эксплуатации:
```text
user:[Administrator] rid:[0x1f4]
user:[Guest] rid:[0x1f5]
user:[krbtgt] rid:[0x1f6]
user:[DefaultAccount] rid:[0x1f7]
...
```

**2. Использование Metasploit**

Модуль `auxiliary/scanner/smb/smb_enumusers` автоматически проверяет наличие уязвимости и перечисляет пользователей.

```bash
use auxiliary/scanner/smb/smb_enumusers
set RHOSTS <TARGET_IP>
set SMB_DOMAIN <DOMAIN_NAME>
run
```

**3. Использование Impacket (Python)**

Скрипт `rpcdump.py` или `smbclient.py` (с пустым паролем) может использоваться для более детального анализа.

```bash
# Проверка доступности RPC-сервисов
rpcdump.py <TARGET_IP>

# Попытка подключения к SAMR
smbclient.py -U '' <TARGET_IP>/IPC$
```

### Типичные ошибки конфигурации и настройки защиты

Администраторы часто отключают Null Session, но делают это неправильно. Основные ошибки:

1.  **Отключение только SMB1:** Удаление протокола SMB1 не отключает Null Session в SMB2/3, если политика доступа к IPC$ разрешена.
2.  **Неполная настройка реестра:** Установка только `RestrictAnonymous` без `RestrictAnonymousSAM` оставляет доступ к учетным записям через SAMR.
3.  **Игнорирование групповых политик:** Политики домена могут переопределять локальные настройки реестра.

**Рекомендуемые меры защиты:**

1.  **Настройка реестра (Local Policy):**
    *   `RestrictAnonymous = 2`: Запрещает анонимные перечисления.
    *   `RestrictAnonymousSAM = 1`: Запрещает анонимный доступ к SAM.
    *   `NullSessionPipes`: Очистка этого параметра (должен быть пустым или содержать только необходимые системные каналы, но не SAM/LSA).

2.  **Групповая политика (GPO):**
    *   Путь: `Computer Configuration -> Windows Settings -> Security Settings -> Local Policies -> Security Options`.
    *   Политика: `Network access: Sharing and security model for local accounts`. Установить в `Classic`.
    *   Политика: `Network access: Let Everyone permissions apply to anonymous users`. Установить в `Disabled`.
    *   Политика: `Network access: Restrict anonymous access to Named Pipes and Shares`. Установить в `Enabled`.

3.  **Блокировка на уровне сети:**
    *   Использование файрволов для блокировки входящих SMB-пакетов (порты 139, 445) от недоверенных сетей.
    *   Отключение SMBv1 на всех узлах (через `Disable-SmbServerChannelEncryption` или отключение роли SMB1 в Windows Features).

### Подводные камни и нюансы

*   **SMB Signing:** Подпись SMB (SMB Signing) не предотвращает Null Session, но защищает от подмены пакетов (MITM). Однако, если подпись не включена, атакующий может подменить ответ сервера.
*   **Encryption:** SMB3 поддерживает шифрование, но оно применяется после установления сессии. Если сессия установлена анонимно, трафик может быть зашифрован, но метаданные (заголовки) остаются видимыми.
*   **False Positives:** Некоторые антивирусы и системы мониторинга могут блокировать попытки подключения к IPC$, создавая ложное ощущение безопасности. Необходимо проверять доступность порта 445 и ответ сервера напрямую.

## Сквозной практический пример: Аудит уязвимости Null Session в тестовой среде

**Исходные условия:**
*   **Среда:** Виртуальная машина с Windows Server 2019 (целевой) и Kali Linux (атакующий).
*   **Роль:** Специалист по информационной безопасности, проводящий аудит.
*   **Инструменты:** `nmap`, `rpcclient` (Samba), `enum4linux`.
*   **Сценарий:** Проверка наличия уязвимости Null Session на целевом сервере, который, по утверждению администратора, защищен от внешних атак.

**Шаг 1: Сканирование портов и определение версии SMB**

Первым делом необходимо убедиться, что порт SMB (445) открыт и определить версию протокола.

```bash
# Использование nmap для сканирования портов и определения версии SMB
nmap -p 445 --script smb-protocols <TARGET_IP>
```

Ожидаемый вывод (фрагмент):
```text
PORT    STATE SERVICE
445/tcp open  microsoft-ds
Host script results:
| smb-protocols:
|   dialects:
|     SMB2_10
|     SMB3_00
|_    SMB3_11
```
*Анализ:* Порт открыт. Протокол SMB1 отключен, что является хорошим знаком, но не гарантирует отсутствие Null Session в SMB3.

**Шаг 2: Проверка доступности IPC$ и анонимного доступа**

Используем `rpcclient` для попытки подключения без учетных данных.

```bash
# Попытка подключения к IPC$ с пустым паролем
rpcclient -U "" <TARGET_IP>
```

Если подключение успешно, мы попадаем в консоль `rpcclient`. Если нет — получаем ошибку `Connection refused` или `Access denied`.

**Шаг 3: Перечисление пользователей через SAMR**

Внутри консоли `rpcclient` выполняем перечисление пользователей домена.

```bash
# Команда внутри rpcclient
enumdomusers
```

Ожидаемый вывод (при наличии уязвимости):
```text
user:[Administrator] rid:[0x1f4]
user:[Guest] rid:[0x1f5]
user:[krbtgt] rid:[0x1f6]
user:[svc_backup] rid:[0x1e9]
user:[web_admin] rid:[0x1ea]
```
*Анализ:* Получен список пользователей. Это критическая утечка информации, так как атакующий знает имена целей для последующего подбора паролей.

**Шаг 4: Получение информации о политике безопасности через LSARPC**

Проверяем, можно ли получить информацию о политике паролей.

```bash
# Команда внутри rpcclient
getdompwinfo
```

Ожидаемый вывод:
```text
Password complexity: Disabled
Password length minimum: 0
Password history length: 0
Lockout duration: 30
Lockout observation window: 30
Lockout threshold: 0
```
*Анализ:* Политика паролей слабая (нет сложности, нет минимальной длины, нет блокировки). Это значительно упрощает дальнейшие атаки.

**Шаг 5: Фиксация результатов и проверка локальных групп**

Проверяем локальные группы и права пользователей.

```bash
# Команда внутри rpcclient
enumalsgroups local
```

Ожидаемый вывод:
```text
group:[Administrators] rid:[0x220]
group:[Users] rid:[0x221]
group:[Guests] rid:[0x222]
group:[Print Operators] rid:[0x226]
```

**Ожидаемый вывод:**
Пример демонстрирует, что даже при отключенном SMB1 и наличии современных версий протокола, уязвимость Null Session сохраняется, если не настроена политика `RestrictAnonymous`. Атакующий получил полный список пользователей и информацию о слабой политике паролей, что является достаточным основанием для классификации инцидента как критического.

## Аналитический вывод

Null Session в протоколе SMB представляет собой исторически укоренившийся механизм, который в современных условиях является источником значительных рисков безопасности, несмотря на отключение по умолчанию в последних версиях Windows. Ключевая проблема заключается не в самом протоколе, а в его обратной совместимости и сложной модели доверия в инфраструктурах Active Directory. Уязвимость возникает не из-за ошибки в коде, а из-за конфигурационных решений, направленных на поддержку старых систем или упрощение администрирования.

Эксплуатация Null Session не требует сложных инструментов или уязвимостей нулевого дня; достаточно наличия открытого порта 445 и неправильной настройки политик безопасности. Полученная через этот канал информация (списки пользователей, RID, политики паролей) является критическим артефактом для последующих атак, таких как брутфорс или атаки Pass-the-Hash.

Защита от Null Session требует комплексного подхода: отключение SMBv1, настройка реестра (`RestrictAnonymous`, `RestrictAnonymousSAM`), применение групповых политик и сегментация сети. Важно понимать, что отключение SMB1 не является достаточной мерой защиты. Регулярный аудит конфигурации SMB и мониторинг попыток подключения к IPC$ являются обязательными элементами защиты корпоративной инфраструктуры.
