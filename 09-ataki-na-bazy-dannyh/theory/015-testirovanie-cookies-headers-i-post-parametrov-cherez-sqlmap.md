# Тестирование cookies, заголовков и POST-параметров с помощью sqlmap

## Контекст и базовые понятия: векторы инъекций в HTTP-протоколе

SQL-инъекция (SQLi) представляет собой класс уязвимостей веб-приложений, возникающих при некорректной обработке пользовательских данных на стороне сервера. Уязвимость возникает, когда вводимые пользователем значения включаются в SQL-запрос без должной санитизации или параметризации. Инструмент `sqlmap` является стандартом де-факто для автоматизации обнаружения и эксплуатации SQL-инъекций. Его ключевая особенность заключается в способности тестировать не только классические GET-параметры URL, но и любые другие места передачи данных в HTTP-запросе: куки (cookies), заголовки (headers) и тело POST-запроса.

Понимание различий между этими векторами критически важно для пентестера. GET-параметры передаются в URL, что делает их видимыми в истории браузера, логах прокси и сервера. POST-параметры передаются в теле запроса, что скрывает их от прямого просмотра в адресной строке, но делает их доступными для перехвата. Куки хранятся на стороне клиента и отправляются с каждым запросом к домену, часто содержа сессийные токены или предпочтения пользователя. Заголовки (headers) содержат метаданные запроса: информацию о браузере, типе контента, авторизации и т.д. Уязвимость в любом из этих мест позволяет атакующему манипулировать базой данных.

Разграничение понятий «вектор передачи» и «механизм инъекции» часто вызывает путаницу. Вектор передачи — это место, где находится вредоносный payload (например, в поле `Cookie` или в теле POST). Механизм инъекции — это то, как сервер интерпретирует эти данные (например, конкатенация строк в SQL-запросе). `sqlmap` абстрагирует этот процесс: пользователь указывает цель и место инъекции, а инструмент автоматически определяет тип уязвимости (boolean-based blind, time-based blind, error-based, UNION-based и др.).

Ключевое различие между тестированием этих векторов заключается в сложности формирования запроса и обработке ответов. Для GET-параметров URL кодируется стандартным образом. Для POST-параметров необходимо правильно сформировать тело запроса (application/x-www-form-urlencoded или multipart/form-data). Для куки и заголовков необходимо сохранить структуру HTTP-заголовка и внедрить payload в конкретное поле. `sqlmap` использует механизм `--level` для определения глубины тестирования. По умолчанию `sqlmap` тестирует только GET-параметры (уровень 1). Для тестирования куки, заголовков и POST-данных необходимо явно указать это через флаги или повысить уровень тестирования.

| Вектор передачи | Место в HTTP-запросе | Типичное назначение | Особенности тестирования в sqlmap |
|---|---|---|---|
| GET-параметры | URL (query string) | Передача данных в адресе | Тестируется по умолчанию (уровень 1). Простая инъекция в URL. |
| POST-параметры | Тело запроса (Body) | Отправка форм, файлов | Требует явного указания через `--data` или загрузки `.txt`/`.xml`. |
| Cookies | Заголовок `Cookie` | Сессии, токены, предпочтения | Требует указания через `--cookie`. Часто требует `--level 2+`. |
| HTTP Headers | Произвольные заголовки | Auth, User-Agent, Referer | Требует указания через `--headers`. Высокий уровень тестирования. |

Поведение `sqlmap` при тестировании разных векторов зависит от настроек. Например, при тестировании заголовков `sqlmap` может генерировать множество вариантов заголовков (User-Agent, Referer, X-Forwarded-For и др.) для поиска уязвимых полей. При тестировании куки инструмент может перебирать все куки, отправляемые сервером, или использовать только те, которые явно указаны пользователем. При тестировании POST-данных `sqlmap` должен корректно кодировать payload, не нарушая структуру формы (например, не ломая multipart-границы).

Важно различать «слепые» (blind) и «явные» (explicit) инъекции. При явной инъекции сервер возвращает данные напрямую в ответе. При слепой инъекции сервер не возвращает данные, но поведение приложения меняется (время отклика, содержимое страницы). `sqlmap` автоматически определяет тип инъекции и адаптирует стратегию тестирования. Для POST-запросов и куки слепые инъекции встречаются чаще, так как серверы часто не возвращают ошибки базы данных в ответ на такие запросы.

Тестирование заголовков и куки часто требует повышенного уровня тестирования (`--level 2` и выше), так как `sqlmap` по умолчанию не тестирует эти поля. Уровень 1 тестирует только GET-параметры. Уровень 2 добавляет тестирование куки. Уровень 3 добавляет тестирование заголовков User-Agent и Referer. Уровень 4 добавляет тестирование заголовка X-Forwarded-For. Уровень 5 добавляет тестирование заголовка X-Client-IP и X-Real-IP. Таким образом, для полного охвата всех векторов необходимо использовать `--level 5` или явно указывать целевые поля.

## Внутреннее устройство: архитектура обработки векторов в sqlmap

Архитектура `sqlmap` построена вокруг модульной системы, где каждый компонент отвечает за определенный этап тестирования: от парсинга цели до генерации payload и анализа ответа. Ключевым элементом, определяющим, какие векторы будут тестироваться, является объект `Request` и его атрибуты. При инициализии сессии `sqlmap` создает объект `Request`, который содержит все компоненты HTTP-запроса: URL, метод, заголовки, куки и тело данных.

Процесс определения уязвимых полей начинается с анализа исходного запроса. Если пользователь не указал конкретные поля для тестирования, `sqlmap` использует эвристики для определения потенциально уязвимых параметров. Для GET-параметров это просто все параметры в URL. Для POST-данных это все поля в теле запроса. Для куки это все куки, отправленные сервером (или указанные пользователем). Для заголовков это заголовки, указанные в `--headers`, или стандартные заголовки, если уровень тестирования достаточно высок.

Механизм генерации payload (`PayloadGenerator`) создает множество вариантов инъекции для каждого целевого поля. Для каждого поля `sqlmap` генерирует payload для различных типов инъекций: boolean-based, time-based, error-based, UNION-based и stack-based. Payload инкапсулируются в соответствующий вектор: если поле является куки, payload вставляется в значение куки; если поле является заголовком, payload вставляется в значение заголовка; если поле является POST-параметром, payload вставляется в тело запроса.

Важным аспектом является обработка ответов (`ResponseAnalysis`). `sqlmap` сравнивает ответы на нормальные запросы и ответы на запросы с payload. Для boolean-based инъекций он ищет изменения в содержимом страницы. Для time-based инъекций он измеряет время отклика. Для error-based инъекций он ищет ошибки базы данных в ответе. Для UNION-based инъекций он ищет совпадения в структуре ответа. Анализ ответов происходит независимо от вектора передачи, но сам вектор определяет, как был сформирован запрос.

Для POST-запросов `sqlmap` поддерживает несколько форматов данных: `application/x-www-form-urlencoded` (стандартные формы), `multipart/form-data` (загрузка файлов) и `application/json` (API). Для каждого формата существует свой парсер, который извлекает поля для тестирования. При тестировании `multipart/form-data` `sqlmap` должен сохранять границы multipart-запроса, что требует более сложной логики генерации payload.

Для заголовков `sqlmap` позволяет тестировать как стандартные заголовки (User-Agent, Referer, X-Forwarded-For), так и пользовательские. Пользовательские заголовки указываются через флаг `--headers` в формате `Key: Value`. `sqlmap` заменяет значение `Value` на payload. Важно, что заголовки могут быть чувствительны к регистру или специфическим символам, поэтому `sqlmap` использует URL-кодирование для безопасной вставки payload.

Для куки `sqlmap` позволяет тестировать как куки, отправленные сервером (через `Set-Cookie`), так и куки, указанные пользователем. Куки могут быть разделены точкой с запятой (`;`). `sqlmap` тестирует каждое куки отдельно, заменяя его значение на payload. Важно, что некоторые куки могут быть защищены флагами `HttpOnly` или `Secure`, но это не предотвращает SQL-инъекцию, если сервер некорректно обрабатывает эти куки.

| Компонент sqlmap | Функция | Влияние на векторы |
|---|---|---|
| `Request` | Хранение HTTP-запроса | Определяет, какие поля будут тестироваться (URL, Body, Headers, Cookies). |
| `PayloadGenerator` | Создание инъекций | Генерирует payload для каждого типа инъекции и вставляет их в целевое поле. |
| `ResponseAnalysis` | Анализ ответов | Определяет тип уязвимости на основе изменений в ответе. |
| `Parser` | Парсинг данных | Извлекает поля из POST-данных, куки и заголовков для тестирования. |
| `Technique` | Стратегия тестирования | Определяет, какие типы инъекций использовать (boolean, time, error, union). |

Особенностью обработки заголовков является возможность тестирования нескольких заголовков одновременно. `sqlmap` может генерировать запросы, в которых несколько заголовков содержат payload, чтобы определить, какой из них уязвим. Это требует значительных вычислительных ресурсов, поэтому по умолчанию тестируются только наиболее распространенные заголовки.

Обработка POST-данных требует учета кодирования. Если данные закодированы в UTF-8, `sqlmap` должен корректно кодировать payload. Если данные содержат специальные символы (например, амперсанды в multipart), `sqlmap` должен экранировать их, чтобы не нарушить структуру запроса. Ошибки в кодировании могут привести к ложным срабатываниям или пропуску уязвимостей.

Куки часто содержат сессийные токены, которые могут быть использованы для аутентификации. `sqlmap` может использовать эти токены для выполнения инъекций от имени авторизованного пользователя. Это требует, чтобы куки были отправлены в запросе. Если куки не отправляются, `sqlmap` не может тестировать их.

## Применение и работа: практические команды и настройки для векторов

Работа с `sqlmap` для тестирования cookies, headers и POST-параметров требует точного указания целевых полей и правильного формирования запросов. Рассмотрим практические примеры для каждого вектора.

### Тестирование POST-параметров

Для тестирования POST-параметров необходимо указать данные формы через флаг `--data`. Данные могут быть переданы как строка или из файла.

```bash
sqlmap -u "http://example.com/login" --data="username=admin&password=pass" --batch
```

Эта команда тестирует параметры `username` и `password` в теле POST-запроса. `sqlmap` отправит запрос с методом POST и телом `username=admin&password=pass`. Для каждого параметра будут сгенерированы payload.

Если данные содержат специальные символы или являются сложными (например, JSON), их лучше сохранить в файл.

```bash
# Файл data.txt
{"username": "admin", "password": "pass"}

sqlmap -u "http://example.com/api/login" --data="@data.txt" --headers="Content-Type: application/json" --batch
```

Флаг `@` перед именем файла указывает `sqlmap` читать данные из файла. Заголовок `Content-Type` должен быть указан явно, если он отличается от `application/x-www-form-urlencoded`.

Для multipart/form-data (загрузка файлов) `sqlmap` автоматически определяет границы, если данные переданы из файла.

```bash
# Файл upload.txt
------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="file"; filename="test.jpg"
Content-Type: image/jpeg

[бинарные данные файла]
------WebKitFormBoundary7MA4YWxkTrZu0gW
Content-Disposition: form-data; name="description"

test
------WebKitFormBoundary7MA4YWxkTrZu0gW--
```

```bash
sqlmap -u "http://example.com/upload" --data="@upload.txt" --batch
```

### Тестирование Cookies

Для тестирования куки необходимо указать их через флаг `--cookie`. Куки могут быть переданы как строка или из файла.

```bash
sqlmap -u "http://example.com/page" --cookie="sessionid=abc123; theme=dark" --batch
```

Эта команда тестирует куки `sessionid` и `theme`. `sqlmap` отправит заголовок `Cookie: sessionid=abc123; theme=dark` в запросе.

Если куки получены из файла (например, из браузера), их можно передать так:

```bash
sqlmap -u "http://example.com/page" --cookie="@cookies.txt" --batch
```

Важно указать уровень тестирования, если куки не тестируются по умолчанию.

```bash
sqlmap -u "http://example.com/page" --cookie="sessionid=abc123" --level 2 --batch
```

### Тестирование HTTP Headers

Для тестирования заголовков необходимо указать их через флаг `--headers`. Заголовки указываются в формате `Key: Value`.

```bash
sqlmap -u "http://example.com/page" --headers="X-Forwarded-For: 127.0.0.1" --batch
```

Эта команда тестирует заголовок `X-Forwarded-For`. `sqlmap` отправит этот заголовок в запросе.

Для тестирования нескольких заголовков:

```bash
sqlmap -u "http://example.com/page" --headers="X-Forwarded-For: 127.0.0.1; User-Agent: sqlmap" --batch
```

Для тестирования всех заголовков на уровне 3 и выше:

```bash
sqlmap -u "http://example.com/page" --level 3 --batch
```

Это включит тестирование заголовков User-Agent и Referer.

### Общие настройки

Для всех векторов можно использовать флаги для управления поведением:

- `--technique`: ограничение типов инъекций (например, `--technique=B` для boolean-based).
- `--time-sec`: время ожидания для time-based инъекций.
- `--delay`: задержка между запросами для обхода WAF.
- `--tamper`: использование скриптов для обхода WAF.

```bash
sqlmap -u "http://example.com/page" --cookie="sessionid=abc123" --technique=B --delay=1 --tamper=space2comment --batch
```

## Сквозной практический пример: комплексное тестирование уязвимого веб-приложения

**Исходные условия:**
Целевое веб-приложение `http://testphp.vulnweb.com` имеет уязвимости SQL-инъекции в нескольких местах: в GET-параметре `cat`, в POST-параметре `login` формы входа, в куки `cart` и в заголовке `User-Agent`. Аудитор имеет доступ к браузеру и может перехватывать запросы через Burp Suite. Роль: пентестер, проводящий аудит безопасности.

**Шаг 1: Тестирование GET-параметра (базовый контроль)**
Сначала проверим классический GET-параметр для подтверждения уязвимости.

```bash
sqlmap -u "http://testphp.vulnweb.com/listproducts.php?cat=1" --batch --technique=B
```

*Ожидаемый вывод:* `sqlmap` обнаружит boolean-based blind SQL-инъекцию в параметре `cat`.

**Шаг 2: Тестирование POST-параметра формы входа**
Перехватим запрос формы входа в Burp Suite и сохраним его в файл `login_request.txt`.

```http
POST /cart.php HTTP/1.1
Host: testphp.vulnweb.com
Content-Type: application/x-www-form-urlencoded

login=admin&password=pass
```

Запустим `sqlmap` с данными из файла.

```bash
sqlmap -u "http://testphp.vulnweb.com/cart.php" --data="@login_request.txt" --batch --technique=B
```

*Ожидаемый вывод:* `sqlmap` обнаружит уязвимость в параметре `login` или `password`.

**Шаг 3: Тестирование Cookies**
Получим куки из браузера или Burp Suite. Допустим, куки `cart=1%2C2%2C3`.

```bash
sqlmap -u "http://testphp.vulnweb.com/cart.php" --cookie="cart=1%2C2%2C3" --batch --technique=B
```

*Ожидаемый вывод:* `sqlmap` обнаружит уязвимость в куки `cart`.

**Шаг 4: Тестирование HTTP Headers**
Добавим тестирование заголовка `User-Agent`.

```bash
sqlmap -u "http://testphp.vulnweb.com/cart.php" --cookie="cart=1%2C2%2C3" --headers="User-Agent: sqlmap" --batch --technique=B
```

*Ожидаемый вывод:* `sqlmap` обнаружит уязвимость в заголовке `User-Agent`.

**Шаг 5: Комплексное тестирование с повышением уровня**
Для полного охвата используем высокий уровень тестирования и все векторы.

```bash
sqlmap -u "http://testphp.vulnweb.com/cart.php" --cookie="cart=1%2C2%2C3" --headers="User-Agent: sqlmap" --data="login=admin&password=pass" --level 5 --batch --technique=B
```

*Ожидаемый вывод:* `sqlmap` протестирует все указанные векторы и сообщит о всех обнаруженных уязвимостях.

**Ожидаемый вывод примера:**
Пример демонстрирует, как `sqlmap` может тестировать различные векторы передачи данных. В реальном сценарии пентестер должен тестировать каждый вектор отдельно, чтобы точно определить место уязвимости. Комплексное тестирование может быть ресурсоемким, поэтому рекомендуется использовать его только после предварительного анализа.

## Аналитический вывод

Тестирование cookies, заголовков и POST-параметров через `sqlmap` требует понимания структуры HTTP-запроса и возможностей инструмента. Каждый вектор имеет свои особенности: POST-данные требуют корректного кодирования, куки должны быть отправлены в запросе, а заголовки могут быть чувствительны к регистру. `sqlmap` предоставляет гибкие настройки для тестирования всех векторов, но требует правильного указания целевых полей. Повышение уровня тестирования (`--level`) необходимо для охвата куки и заголовков. В реальном пентесте важно тестировать каждый вектор отдельно, чтобы избежать ложных срабатываний и точно определить место уязвимости. Автоматизация через `sqlmap` значительно ускоряет процесс, но требует ручной проверки результатов и понимания контекста приложения.
