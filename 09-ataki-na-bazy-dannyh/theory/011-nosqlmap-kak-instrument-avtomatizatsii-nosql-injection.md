# Автоматизация атак на NoSQL: Архитектура и применение инструмента NoSQLMap

NoSQLMap — это специализированный инструмент с открытым исходным кодом, разработанный для автоматизации обнаружения, эксплуатации и извлечения данных из уязвимостей типа NoSQL Injection. В отличие от универсальных сканеров SQL-инъекций (таких как SQLmap), NoSQLMap ориентирован на специфику баз данных, не использующих реляционную модель (MongoDB, CouchDB, Redis, Cloudant, Google Cloud Datastore и др.). Инструмент функционирует как прокси-сервер или модуль для Burp Suite, перехватывая HTTP-запросы, модифицируя параметры передачи данных (GET/POST) в формате JSON и применяя эвристические алгоритмы для определения типа уязвимости и структуры базы данных.

## Контекст и базовые понятия

NoSQL (Not Only SQL) — это обобщающий термин для классов баз данных, которые не используют реляционную модель таблиц с фиксированными схемами. В контексте информационной безопасности термин «NoSQL Injection» относится к уязвимости, возникающей, когда приложение передает не доверенные данные в запрос к NoSQL-базе без надлежащей валидации или санитизации. В отличие от SQL-инъекций, где атака эксплуатирует синтаксис языка запросов (SQL), NoSQL-инъекции часто эксплуатируют особенности парсинга JSON-объектов или логику сравнения значений в движке базы данных.

Ключевое различие между SQL и NoSQL инъекциями заключается в механизме передачи аргументов. В реляционных базах данные передаются через строковые литералы в запросе `SELECT * FROM users WHERE username = 'admin'`. В NoSQL-базах (особенно MongoDB) данные часто передаются в теле HTTP-запроса в формате JSON, который затем десериализуется в объект, используемый для построения внутреннего запроса. Уязвимость возникает, когда разработчик использует методы, позволяющие внедрять произвольные операторы JavaScript или специальные конструкции (например, `$gt`, `$ne`, `$where`) непосредственно в значения полей.

Путаница в терминологии часто возникает между понятиями «NoSQL Injection» и «JSON Injection». JSON Injection — это более широкий класс уязвимостей, связанных с некорректной обработкой JSON-структур (например, изменение типа данных или добавление полей). NoSQL Injection является частным случаем JSON Injection, когда внедренные данные напрямую влияют на логику запроса к базе данных, позволяя обойти аутентификацию или извлечь данные.

Для понимания архитектуры атаки необходимо разграничить типы NoSQL-баз данных, так как механизмы инъекций для них различаются:

| Тип базы данных | Модель данных | Механизм хранения | Характерный вектор атаки | Пример уязвимой конструкции |
| :--- | :--- | :--- | :--- | :--- |
| **Document Store** (MongoDB) | Документы (JSON/BSON) | Коллекции, индексы | Использование операторов MongoDB (`$gt`, `$ne`, `$where`) | `{"username": {"$ne": null}}` |
| **Key-Value Store** (Redis) | Пары ключ-значение | Память (RAM) | Изменение ключа или значения для доступа к другим данным | `GET secret_key` (если ключ угадан) |
| **Document Store** (CouchDB) | Документы (JSON) | Реляционная логика на JSON | Использование встроенных функций MapReduce | `{"_id": "user:123"}` |
| **Graph Database** (Neo4j) | Узлы и рёбра | Графовая структура | Внедрение в запросы Cypher | `MATCH (n) RETURN n` |
| **Wide-Column Store** (Cassandra) | Колонки в строках | Распределенные таблицы | Ошибки парсинга CQL | `WHERE id = 1 OR 1=1` (редко) |

NoSQLMap автоматизирует процесс тестирования именно Document Store баз данных (преимущественно MongoDB), так как они наиболее распространены в веб-приложениях и наиболее подвержены сложным инъекциям. Инструмент не ограничивается простым перебором значений; он анализирует ответы сервера (HTTP status code, body length, time delay) для определения типа уязвимости: boolean-based blind, time-based blind или error-based.

## Внутреннее устройство предмета

NoSQLMap представляет собой комплексную систему, состоящую из нескольких взаимосвязанных модулей: движка сканирования, модуля анализа ответов, базы данных сигнатур и интерфейса взаимодействия с целевым приложением. Архитектура инструмента построена на языке Python, что обеспечивает кроссплатформенность и легкость интеграции с другими инструментами пентестинга.

### Модуль сканирования и генерации payloads

Ядром NoSQLMap является генератор payloads, который создает множество вариантов модификации входных параметров. Для каждой уязвимой точки (параметра GET/POST) инструмент генерирует набор тестовых векторов. В отличие от SQLmap, который использует сложные эвристические алгоритмы для обхода WAF, NoSQLMap фокусируется на специфичных для NoSQL операторах.

Основные категории генерируемых payloads:
1.  **Boolean-based:** Изменение логики сравнения для получения истинного/ложного ответа.
2.  **Time-based:** Внедрение функций задержки выполнения для определения уязвимости по времени отклика.
3.  **Error-based:** Вызов операций, приводящих к ошибкам сервера, если данные некорректны.
4.  **Schema-based:** Извлечение структуры базы данных (именей баз, коллекций, полей).

### Модуль анализа ответов (Response Analyzer)

После отправки каждого запроса NoSQLMap перехватывает HTTP-ответ и извлекает ключевые метрики:
*   `HTTP Status Code`: 200, 403, 500 и т.д.
*   `Content-Length`: длина тела ответа.
*   `Response Time`: время отклика сервера.
*   `Error Messages`: наличие текстовых сообщений об ошибках.

Анализатор сравнивает эти метрики с базовыми значениями (полученными при отправке валидного запроса). Если разница превышает заданный порог (threshold), запрос классифицируется как успешный. Например, если при внедрении `{"password": {"$ne": null}}` длина ответа становится значительно больше, чем при обычном вводе, инструмент делает вывод о возможности обхода аутентификации.

### База данных сигнатур и эвристик

NoSQLMap содержит встроенную базу данных известных уязвимостей и паттернов. Эта база включает:
*   Сигнатуры ошибок MongoDB (например, `BSONObj size: ...`).
*   Паттерны успешного обхода для различных версий MongoDB (2.x, 3.x, 4.x, 5.x).
*   Эвристические правила для определения типа базы данных по ответам (например, специфичные заголовки или ошибки Redis).

### Интерфейс и интеграция

Инструмент поддерживает два режима работы:
1.  **Standalone Mode:** Запуск через командную строку с указанием URL и параметров.
2.  **Proxy Mode:** Работа как прокси-сервер (по умолчанию на порту 8080), перехватывающий весь трафик от Burp Suite или ZAP.

Внутренняя структура конфигурации NoSQLMap определяется файлом `config.json` или параметрами командной строки. Основные параметры включают:
*   `--url`: Целевой URL.
*   `--data`: Данные POST-запроса.
*   `--type`: Тип базы данных (auto, mongo, couch, redis).
*   `--technique`: Техника эксплуатации (B, T, E).
*   `--level`: Уровень глубины сканирования (1-5).

```json
{
  "scan": {
    "techniques": ["boolean", "time"],
    "level": 3,
    "risk": 1,
    "threads": 10
  },
  "database": {
    "type": "auto",
    "timeout": 5
  },
  "proxy": {
    "host": "127.0.0.1",
    "port": 8080
  }
}
```

## Применение и работа с предметом

На практике NoSQLMap используется на этапе тестирования на проникновение для проверки уязвимостей в API веб-приложений, использующих NoSQL-базы данных. Типичный сценарий включает в себя идентификацию уязвимых параметров, определение типа базы данных, извлечение структуры данных и, при наличии критических уязвимостей, извлечение учетных данных пользователей.

### Подготовка окружения

Для работы с NoSQLMap требуется установленный Python 3 и зависимости, указанные в `requirements.txt`. Инструмент часто используется в связке с Burp Suite для перехвата и модификации запросов.

```bash
# Клонирование репозитория
git clone https://github.com/codingo/NoSQLMap.git
cd NoSQLMap
pip3 install -r requirements.txt
```

### Запуск сканирования

При использовании standalone-режима необходимо указать целевой URL и параметры. NoSQLMap автоматически определяет тип базы данных, если не указано иное.

```bash
# Пример запуска сканирования с автоопределением типа БД
python3 noSQLmap.py -u "http://target.com/api/login" --data='{"username":"test","password":"test"}' --level=3 --risk=1
```

### Анализ результатов

После сканирования NoSQLMap выводит отчет, содержащий:
*   Тип обнаруженной уязвимости.
*   Тип базы данных.
*   Извлеченные данные (если возможно).
*   Рекомендации по исправлению.

### Типичные ошибки и подводные камни

1.  **Ложные срабатывания:** Из-за динамической природы веб-приложений, изменение параметров может влиять на длину ответа по не связанным с инъекцией причинам (например, разные шаблоны страниц для разных пользователей). Необходимо настраивать пороговые значения (threshold) для анализа ответов.
2.  **Обход WAF:** Современные WAF могут блокировать специфичные операторы NoSQL (например, `$ne`). В таких случаях требуется использование техник обхода (encoding, double encoding) или ручная модификация запросов.
3.  **Ограничения MongoDB:** В новых версиях MongoDB (3.2+) некоторые уязвимости, такие как обход аутентификации через `{"$ne": null}`, были исправлены. NoSQLMap должен быть обновлен до последней версии для учета этих изменений.
4.  **Производительность:** Глубокое сканирование (уровень 4-5) может занять значительное время и создать высокую нагрузку на целевой сервер. Рекомендуется использовать параллельные потоки (threads) и ограничивать количество запросов.

### Паттерны использования

*   **Аудит API:** Проверка RESTful API на наличие уязвимостей NoSQL Injection.
*   **Тестирование аутентификации:** Попытка обхода форм входа в систему.
*   **Извлечение данных:** Извлечение информации о пользователях, конфигурациях и других чувствительных данных.

## Сквозной практический пример: Эксплуатация уязвимости аутентификации в MongoDB

**Исходные условия:**
*   **Цель:** Веб-приложение с формой входа, использующее MongoDB для хранения пользователей.
*   **Интерфейс:** HTTP POST-запрос к `/api/login` с телом `{"username":"<user>","password":"<pass>"}`.
*   **Инструмент:** NoSQLMap (версия 0.3.4+).
*   **Роль:** Пентестер, имеющий доступ к интерфейсу приложения.
*   **Сценарий:** Проверка возможности обхода аутентификации без знания учетных данных.

**Шаг 1: Идентификация уязвимого параметра**

Запускаем NoSQLMap в режиме standalone, указывая URL и данные POST-запроса. Инструмент автоматически отправляет серию запросов с различными модификациями параметров `username` и `password`.

```bash
python3 noSQLmap.py -u "http://192.168.1.100/api/login" --data='{"username":"admin","password":"admin"}' --level=3 --risk=1 --technique=B
```

**Шаг 2: Анализ ответа и определение типа уязвимости**

NoSQLMap перехватывает ответы сервера и анализирует их. При отправке параметра `username` со значением `{"$ne": null}` инструмент замечает, что HTTP-статус код изменился с `401 Unauthorized` на `200 OK`, а длина тела ответа увеличилась.

```json
{
  "id": "scan_001",
  "status": "success",
  "details": {
    "parameter": "username",
    "payload": "{\"$ne\": null}",
    "http_status": 200,
    "content_length": 1540,
    "comparison": {
      "normal_status": 401,
      "normal_length": 250
    }
  }
}
```

**Шаг 3: Подтверждение уязвимости**

Для подтверждения уязвимости NoSQLMap отправляет дополнительный запрос с параметром `password`, установленным в `{"$ne": null}`, чтобы убедиться, что обход работает для обоих полей.

```bash
# Проверка обхода по полю password
python3 noSQLmap.py -u "http://192.168.1.100/api/login" --data='{"username":"test","password":"{\"$ne\": null}"}' --level=3 --risk=1
```

**Шаг 4: Извлечение данных (опционально)**

Если уязвимость подтверждена, можно попробовать извлечь данные пользователей. NoSQLMap может попытаться перебрать имена коллекций или поля.

```bash
# Попытка извлечения имен коллекций
python3 noSQLmap.py -u "http://192.168.1.100/api/login" --data='{"username":"{\"$ne\": null}"}' --dbs --level=3 --risk=1
```

**Ожидаемый вывод:**
NoSQLMap сообщает о успешном обходе аутентификации через параметр `username` с использованием оператора `$ne`. Это означает, что приложение принимает любой объект, не равный null, как истинное значение, что позволяет войти в систему без знания пароля.

## Аналитический вывод

NoSQLMap является мощным инструментом для автоматизации тестирования на проникновение, специализирующимся на уязвимостях NoSQL Injection. Его основная ценность заключается в автоматизации генерации специфичных payloads и анализа ответов сервера, что значительно ускоряет процесс обнаружения уязвимостей. Однако, эффективность инструмента зависит от правильной настройки параметров сканирования и понимания специфики целевой базы данных.

Важно отметить, что NoSQLMap не является универсальным решением для всех типов NoSQL-баз данных. Он наиболее эффективен для MongoDB и других Document Store баз, использующих JSON-подобные структуры. Для других типов баз данных (Redis, Cassandra) могут потребоваться специализированные инструменты или ручное тестирование.

Кроме того, современные версии MongoDB и другие NoSQL-базы данных включают механизмы защиты от NoSQL Injection, такие как строгая типизация и валидация входных данных. Поэтому использование NoSQLMap должно сопровождаться анализом конфигурации сервера и применением дополнительных техник обхода, если это необходимо.

В контексте обучения студентов, изучающих кибербезопасность, понимание работы NoSQLMap и механизмов NoSQL Injection является критически важным для разработки безопасных веб-приложений и проведения эффективного аудита безопасности.
